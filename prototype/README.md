# StackChan · 原型方案交付索引

> 20 个**完全可点击**的 iOS App 视觉方案。打开 `variants/<编号>-<名称>.html` 即可。
> 每个方案都实现了 `CONTRACT.md` 定义的同一套结构与 10 项必点交互，**唯一差别是视觉语言** —— 所以它们是「同产品、不同皮肤」，可以直接横向比较。

---

## 一、怎么看

1. **直接双击打开** `variants/*.html`（无外部依赖、无网络请求、可离线）。
2. 每个方案包含 5 个可截图状态：`shot`（陪伴页）、`acts`（动作键浮现）、`sheet`（设置浮层）、`stack`（小栈页）、`interrupted`（六态-错误）。
3. 交互清单：状态条下滑隐藏 / 点气泡浮现动作键 / 3D 拖拽改姿态 / 六态切换 / 设置浮层 / 发送 / 麦克风。

## 三、我的推荐（如果不想自己挑）

**首选：18 深色 tuck** —— 唯一在 3 秒并排测试里能让人感觉"这台设备真的在面前"的方向。
气泡的 4pt 尖角 tuck 借鉴了 Character.AI 的做法（AI 气泡左上尖 / 用户右上尖），**不靠颜色区分说话人**，这是"高级感"的技术来源。

**次选：17 暖纸衬线** —— 排版品味最高，衬线正文 + 无衬线 UI 的混排很成熟。

**第三：01 暖纸陶土** —— 交互与"交付感"样本最完整（worker A 的完整实现），且设备渲染对比度已修好。

**如果要"最像成品 App"**：03 纯白留白。

## 四、怎么改

### 改单个方案
直接编辑 `variants/<编号>-<名称>.html`。每个文件是**自包含**的（内联 CSS/JS/SVG），没有构建步骤。

### 批量改
`03`–`16` 由生成器产出：

```powershell
# 重新生成全部（跳过已存在）
py -3.12 "prototype/tools/make_prototypes.py"

# 强制覆盖指定编号
py -3.12 "prototype/tools/make_prototypes.py" --force 03 04 05

# 改视觉：编辑 tools/make_prototypes.py 里的 VARIANTS token 表，再重跑
```

`01`/`02`/`17`–`20` 是手写稿（结构与生成器不同但契约一致），直接改文件。

### 检查
```powershell
py -3.12 "prototype/tools/check_prototypes.py"
```
输出 `docs/research/46-原型方案自动体检报告.md`。

⚠️ **体检器查不出几何遮挡**（Tab 栏盖住按钮、`setPointerCapture` 吞 click 这类）。
这类问题必须用**真实指针事件**验证 —— 本轮用的是 playwright + 系统 Chrome，见 `docs/research/47` 号审核报告的方法。

## 五、硬约束（改的时候别破坏）

来自 `CONTRACT.md`：

| 约束 | 值 |
|---|---|
| 一级元素 | 12 个，全部必须存在 |
| 字号阶梯 | 只允许 34 / 28 / 22 / 20 / 17 / 16 / 15 / 13 / 12（**不含 11**） |
| 同屏字号级数 | ≤ 3 |
| 动效时长 | 只允许 3 档：120 / 280 / 900 ms |
| 曲线族 | `cubic-bezier()` 最多 2 条 |
| 触感 | 一次交互 ≤ 1 次 |
| 玻璃 | `backdrop-filter` 只允许在 Tab 栏 / 顶部导航 / Sheet 浮层 |
| **小栈脸** | 陪伴页占**视觉面积 ≥ 40%** |
| 文字对比度 | 正文 ≥ 4.5:1（**按实际合成底色算，不是 token 声明值**） |
| 禁 | `transition:all` / bounce / elastic / emoji 当图标 / 积分·等级·进度条·连续天数 |

**AI 味反面清单**（02 号 §4.4）：C1 奶油沙色、C2 紫蓝强调、C3 弹跳动效、C4 渐变堆叠、C5 低对比灰字、C6 通用 clip-art 图标、C7 圆角过大、C8 阴影漂浮、C9 装饰性元素堆砌。

## 六点五、参数化表情渲染器（无色线框调试视图，不是第 21 个方案）

| 文件 | 是什么 | 为什么单独放 |
|---|---|---|
| `docs/spec/06-表情参数模型.md` | **平台无关的表情参数规范**：3 元素 × 5 参数定义、极性表、单位换算、0x03 / 0x14 的 JSON Schema、6 种官方情绪映射、渲染层级与几何事实表、三条覆盖事实的渲染含义 | 这是**数据契约 + 固件事实**，不是设计。换任何端（SwiftUI / HTML / Android）照抄 §1–§6 就能得到与设备一致的脸 |
| `prototype/components/expression-renderer.html` | 规范 §6.2 的**可执行版**：左「设备轨」320×240、右「App 轨」同一套几何函数另一比例尺，15 个参数实时改，**两轨同时变** | 20 个方案里的脸都是**静态 SVG**（贴纸式）。这里证明脸应该由参数驱动。⚠️ **它是无色线框调试视图，不是 UI 方案** —— 配色 / 圆角 / 阴影 / 字体 / 动效曲线 / 表情风格全部**待用户拍板**（规范 §9.2 的 P-1..P-6） |
| `prototype/tools/check_renderer.py` | 机器校验：默认值 / 极性 / 换算系数 / 元素基准位置 / JSON Schema / JS 函数存在性，外加 3 个变异用例 | 极性写反、系数写错、默认值漂移**必须被机器抓到**，不能靠肉眼 |
| `prototype/tools/extract_keyframes.py` | 从 r59 真实 292 帧 0x14 关键帧里等距抽 60 帧内联进 HTML | 让「播放这条时间轴」按钮有**真数据**可播，而不是假动画 |

直接双击 `components/expression-renderer.html` 即可，无需服务器，零外部依赖。

它把 docs/research/53 的三条硬事实做成了可点的演示：

1. 点「看它 2 秒后会怎样」→ 复现 **blink / idle_expression 覆盖远程表情**的全过程（blink 闭眼时写的是 weight=**25**，不是 0）
2. 点「设备端情绪覆盖（hello/hi/love）」→ 复现固件里 setEmotion **直接写同一批 weight/rotation**，2000 ms 后写回
3. 点「播放这条时间轴」→ 回放真实 0x14 关键帧，并标出**硬切之间那段插值是我们自己写的**

跑一遍机器校验：

```
py -3.12 prototype/tools/check_renderer.py
```

> ⚠️ 规范里对 docs/research/53 做了 **3 处公开订正**（见规范 §0.1），其中最关键的一条：53 号表头写「eye weight（眼睑下沉）」是**反的** —— weight 越大是**越睁开**。
