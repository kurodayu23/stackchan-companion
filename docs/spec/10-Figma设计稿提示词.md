# 10 · Figma 设计稿提示词集（手机端 Web App）

> **一句话**：这是可以直接粘进 Figma AI / 任何吃提示词的画图工具的一套提示词。
> 它对着**本仓库的真实 token** 写（不是通用模板），目标是让 Figma 产出**能被机器核**的稿子。
> 产出后用 `tools/figma_design_sync.py` 核一遍漂移。

- 适用对象：**手机端 Web App**（Safari + 「添加到主屏幕」的 PWA）
- ⛔ **不适用**：设备端 320×240 屏（官方固件才是真值，见 §6）
- 上游：`docs/spec/02`（交付感 11 条）、`docs/spec/01`（功能极简）、`docs/research/02`（设计契约）、
  `ios/StackChanCompanion/DesignSystem/`（token 真值）、`docs/research/90`（不上架路径裁决）

---

## §0 用法（3 步）

1. **先粘 P0（母提示词）**（§1）—— 它是设计系统总纲，**只粘一次**。
2. **再逐屏粘 P1~P7**（§2）—— 每一屏都是独立一段，粘在 P0 之后接着问。
3. **按 §3 建变量、§4 走验收** —— 变量名必须按 §3，这样稿子能被 `tools/figma_design_sync.py` 机器核。

⚠️ **一条重要的现实提醒**：本仓库上一轮已经实测过——
**Figma Connector 只有 2 个只读/导出工具（`get_figma_data` / `download_figma_images`）**，
**AI 不能替你画稿、不能改你的 Figma 文件**。所以这套提示词是**给人用**的：
你（或用 Figma 自己的 AI 功能）照着画，画完我这边用只读工具读回来做漂移体检。

> 如果你用别的工具（Midjourney / v0 / Lovable / Cursor…）也行，
> **P0 是最关键的一段**，粘它就够了；P1~P7 是同一套 token 下的分镜。

> ⭐⭐ **2026-10-27 用户拍板：视觉稿归 Figma AI，我不手绘。**
> ⇒ 分工固定为：**Figma AI 出稿 → 用户选方向 → 我把选定的配色/尺寸采纳为仓库 token
> → 我跑 `tools/figma_design_sync.py` 做数值体检（FD-01~FD-06）
> → 我把通过的数值回填进 `Tokens.swift` / `Shapes.swift` / `Typography.swift`。**
> ⇒ 本仓库**不再新增手绘稿**（2026-10-27 那张手绘方案板已被用户判「太丑」并撤掉，
> 归档在 `D:\AP\AP7000\ai-workspace\stackchan-research\r75\rejected-flow-board.png`，**不入库**）。
> ⇒ ⚠️ **体检顺序不能颠倒**：FD-06（颜色白名单）比对的是仓库 token，
> ⇒ 所以**必须先采纳 Figma 的配色为 token**，再跑体检，否则新配色会被整片判 FAIL。
> ⇒ 前提：稿子必须放在**你自己账号可见的 Figma 文件**里 —— Connector 读不到你看不到的文件
> （上一轮 10 次调用 9 次 `figma_not_found` 即因此，见 `docs/research/89`）。

## §1 P0 · 母提示词（设计系统总纲）

```text
你是一位为 Apple 平台做界面的资深设计负责人。请为「小栈」设计手机端界面。

【产品一句话】
小栈是一台放在桌面上的 AI 陪伴机器人（320×240 触摸屏 + 双舵机 + 头顶灯带）。
手机端是这个机器人的「遥控器 + 对话面板 + 陪伴记忆」，
但它**不喧宾夺主**：主界面是控制机器人的舵机与表情，聊天是二级页。

【目标设备与形态】
- 目标机型：iPhone 17 Pro（**逻辑分辨率以实际机型为准，不要写死画布尺寸**；
  ⚠️ 本仓库对 17 Pro 的屏幕尺寸/灵动岛尺寸**尚未核实** —— 写稿时用相对量与
  `env(safe-area-inset-*)`，不要硬编码像素）
- 形态：Safari 打开的 Web App，可「添加到主屏幕」成全屏 PWA
- 安全区：顶部用 `env(safe-area-inset-top)`、底部用 `env(safe-area-inset-bottom)`，**不写死数值**
- 内容最大宽度 320pt（Apple HIG 原文：Unfocused content width = 320 pt）—— 仅宽屏时生效
- 本 Web App **不采集麦克风**（iOS 只允许 https 页面用麦克风）⇒
  语音一律由机器人自己听；手机端只显示对话记录 + 打字发送 + 遥控

【设计基调：Apple 级，不是 Android 味】
- 大量留白、系统字阶、发丝级分隔线、连续的圆角曲率、克制的材质
- 禁止：Material 蓝大色块、elevation 阴影堆叠、胶囊按钮滥用、
  紫→蓝对角渐变、emoji 当图标、卡片套卡片
- 「有质感」= 减法 + 秩序 + 工艺，**不是**更精细的装饰

【字体】
- 字体：SF Pro（中文用苹方 PingFang SC）
- 字号**只允许**用下面这 11 个系统 text style（不要自造字级）：
  Large Title 34/41 Bold · Title 1 28/34 Bold · Title 2 22/28 Bold ·
  Title 3 20/25 Semibold · Headline 17/22 Semibold · Body 17/22 Regular ·
  Callout 16/21 · Subhead 15/20 · Footnote 13/18 · Caption 1 12/16 · Caption 2 11/13
  （数字、角度、时长、电量一律用等宽数字 tabular-nums）
- 同一屏最多 3 个字级；正文不得小于 11pt
- 截断只从尾部截；标题最多 1 行；正文最多 3 行；中文不做两端对齐

【色板：4 套方案，全部要】
每套 12 个槽位（canvas / surface / surfaceElevated / textPrimary / textSecondary /
textTertiary / separator / accent / onAccent / success / warning / danger / online）。
先全部建出来，最后再选一套深化。

  canvas #111113 · surface #1C1C1F · surfaceElevated #26262A
  textPrimary #ECECEE · textSecondary #B6B6BE · textTertiary #8D8D92
  separator #ECECEE 12% · accent #E3A857 · onAccent #1A1208
  success #53C780 · warning #E3A857 · danger #FF4242 · online #53C780

【圆角：连续曲率，6 档，只允许这 6 个值】
  icon 8（图标容器）· control 10（按钮/输入框）· tile 12（功能块）
  card 16（卡片）· sheet 20（抽屉/浮层）· capsule 999（完全圆角）
  直角容器（整屏/满幅底板）用 0。
  ⚠️ 不要出现 9 / 11 / 14 / 18 / 19 这类中间值。

【间距：6 档】
  4（图标与文字）· 8（同行元素）· 12（元素之间）· 16（分组之间）
  24（区块之间）· 32（页面级留白）
  页面左右边距 20 · 分组左右边距 16 · 卡片内边距 16

【分隔：只用一种手法 —— 描边】
  细线 0.5–1pt，用 separator 色。不要用阴影做层级，也不要用背景色差做分隔。
  （阴影只允许出现在真正浮起的浮层上，且只有一层、很淡。）

【材质】
  导航栏 / 标签栏 / 浮层可以用毛玻璃：
  浅色 rgba(255,255,255,0.72)，标签栏 rgba(248,248,250,0.72)；
  深色方案另定。内容区不使用毛玻璃。

【图标】
  一律 SF Symbols 语义（不要手画），24×24 网格、统一描边 1.9、圆头圆角。
  标签栏图标要有「填充/描边」两态。
  设备端屏幕表情用几何图形，不许用 emoji。

【动效：分两层】
  事件层（按下去有什么反应）——
  只允许 3 档时长：T1 瞬时 0.10–0.15s · T2 标准 0.25–0.35s · T3 叙事 0.6–1.2s
  只允许 2 种曲线：标准 spring（response 0.35 / damping 0.86）· 快速 spring（response 0.2 / damping 0.9）
  禁止 bounce / elastic / overshoot 回弹；禁止自定义 timingCurve。
  T3 全 App 最多 3 处。
  高频交互（点按/滑动/输入）不加自定义动效，或 ≤ 0.15s。
  环境层（底板与装饰）—— 见下一节「流动层」，**不计入上面的 3 档**。

【流动层：底板 ＋ 玻璃】
  这一层决定「有没有流动的感觉」，**必须画出来**，但要克制。

  · 流体底板：全屏一层柔光网格渐变（3–5 个柔边色斑叠加，不是线性渐变、不是彩虹）。
    色相跨度 ≤ 30°、饱和度 S ≤ 0.35、亮度极差 ≤ 6%。
    我们走**暖色相（陶土 ↔ 琥珀）**，不要紫→蓝。
  · 玻璃层：**只有 3 个「呼吸位」**有底板 ＋ 玻璃 ——
    R1 控制台顶部（设备实时预览 ＋ 连接状态）
    R2 对话输入区
    R3 动作库顶部（当前动作 / 舞台）
    其余屏**纯静态底板**，不要全屏玻璃化。
  · 玻璃卡：半透明 ＋ 背景模糊 ＋ 顶部边缘 1px 高光 ＋ 一层很淡的彩色外发光；
    圆角用登记档（12 / 16 / 20），**不要 24**。
  · 底板在稿上是**静态**的：在图外标注 3 个关键帧（起始 / 中段 / 结束），
    相邻关键帧色斑位移 ≤ 4% 视口、缩放 ≤ 1.02。**不要画成动画箭头或波浪线。**
  · 底板**不承载任何信息**：状态、文案、按钮一律在底板之上，且对比度按最差色相位仍需 ≥ 4.5:1。

【结构纪律】
- 一级可见元素 ≤ 12 个；不为每个功能新造一级入口
- 标签栏 ≤ 5 项，**永不出现「More」溢出标签**
- 一屏只有 1 处强调色；强调色只表达一件事（品牌或当前状态，二选一）
- 中性色阶不超过 6 档
- 可见即可用：0 个死按钮
- 触控目标短边 ≥ 44pt

【状态：13 态，每态都要有稿】
  加载 / 空 / 错 / 离线 / 权限被拒 / 首次启动 / 设备不在线
  配网中 / 正在听 / 正在想 / 正在说 / 等待你（你不在）/ 它低落
  其中 错、离线、权限被拒、首次 4 态**必须带恢复动作按钮**。
  设备离线时：App 不报错、不弹窗、不禁用聊天，只把设备相关入口收起。

【输出要求】
1. 用 Auto Layout；用 Figma Variables 承载颜色与数值（命名见下一节）
2. 每个 Frame 命名用「页.区块.元素」，例如「控制台.设备卡.状态条」
3. 每屏输出一张 iPhone 17 Pro 尺寸的 Frame（**逻辑分辨率以实际机型为准，不要写死画布尺寸**），深色方案另出一张
4. 不要画「设计说明文字」在画布上，说明写在图外
5. 最后给一张「13 态总览图」，所有状态并排
```

### P1 · 主控台（Tab 根页，60% 注意力）

```text
画「控制台」这一屏。它是 App 的主界面，重点是**控制机器人**，不是聊天。

从上到下：
1. 导航栏：左留空，中间标题「小栈」，右侧一个蓝牙/连接图标按钮（可点击，进连接页）
2. 设备卡（这是视觉重心）：
   - 卡片圆角 16，surface 色，无阴影或只有一层极淡阴影
   - 卡片内上方是**机器人屏幕的镜像预览**：横向 16:12（320:240），
     深色底 #0E1014（非纯黑），里面有一张极简几何脸
     （两只圆眼 + 一条嘴），表情区域占屏幕 ≥ 60%
   - 卡片底部一行状态：左侧「已连接」带一个小圆点（success 色），
     右侧「电量 82% · 1.0.0」，Footnote 13，等宽数字
   - 屏幕下方左右各 6 颗小圆点 = 身体信号灯（RGB LED），当前用 accent 色点亮其中几颗
3. 状态条（两枚 chip，圆角 capsule，高 28）：
   「在看你」「朝正前方」，chip 底色用 accent 10% 透明度，文字 textPrimary
4. 一个整宽的入口行「和它说话」，左侧一个聊天气泡图标，右侧一个 chevron，
   高度 52，圆角 10 —— 这是唯一通向聊天的入口
5. 分组「舵机」：一张分组卡片，内含
   - 一个 120×120 的摇杆底盘（圆形，浅色填充），里面一个 44 直径的圆把手
   - 右侧两行读数：「水平 0°」「垂直 0°」，数值用等宽数字，标签 Footnote
   - 下面一个「回正」按钮（次要样式，描边）
6. 分组「表情」：一行 6 个可横滑的 chip：
   平静 / 开心 / 兴奋 / 惊讶 / 困倦 / 生气
   选中态 = accent 底 + 白字；未选中 = surface 底 + textSecondary 字
7. 分组「动作」：一行 4 个图标+文字的按钮（竖排图标在上、文字在下）：

8. 底部是标签栏，浮动毛玻璃条，3 项：控制 / 对话 / 设置
   （⚠️ 对话虽然在这里，但「聊天」的实际内容是二级页，从控制台的「和它说话」进）
9. 底部留出 100pt 空白，标签栏是浮动的

约束：整屏只有「和它说话」那一处和 accent 底色，其余用中性色。
```

### P5 · 记忆与个性

```text
画「记忆」页。

1. 顶部一个「当前身份」卡：左边一个 56 直径头像圆（几何小栈脸），
   右边是名字「小栈」+ 身份描述（小字），右侧一个 chevron
2. 分组「个性与语气」：3 个开关行
   主动性 / 记住我的事 / 充电时自动亮屏
   开关用 iOS 开关样式（胶囊轨道 + 圆钮），开 = accent，关 = 20% 灰
3. 分组「记忆库」：列表行，左侧标签 + 右侧数量/状态值
4. 分组「对话记录」：一个开关「保存对话内容用于记忆与优化」+ 下方
   「最新提取的记忆」列表（3 条，每条一行，左侧时间 Footnote，右侧内容 Body 截断 1 行）
5. 分组「共同回忆」：时间线条目（昨天 / 前天 / 上周 / 第一次见面），
   每条左侧是时间标签（Subhead 15，textSecondary），右侧是内容（Body 17）
```

```text
在一张画布上并排画 13 个 iPhone 17 Pro 缩略 Frame，每帧标注状态名：
加载 / 空 / 错 / 离线 / 权限被拒 / 首次启动 / 设备不在线 /

每帧必须体现该态的**具体视觉差异**，不能只是换一行文字：
- 加载：内容区骨架块（2–3 行浅色占位块），不要用转圈菊花做满屏
- 空：插画/几何脸 + 引导文案 + 一个动作按钮
- 错：文字说明 + 一个主行动按钮（如「重试」）+ 一个次要按钮
- 离线：顶部状态条变「离线」，设备相关区块收起，只剩聊天

- 配网中：进度 + 当前步骤 + 可取消
- 正在听 / 正在想 / 正在说：状态条文字 + 图形不同，**不要**做动画
- 等待你：整体压暗（降低不透明度到 60%），「等你」状态
- 它低落：状态条 + 一次短消息 + 表情低垂
```

## §5 已知的坑（写稿前先知道）

| 坑 | 事实 | 怎么办 |
|---|---|---|
| **iOS Safari 6 个限制** | 只允许 https 页面用麦克风；不支持网页震动；不支持 Web Bluetooth；https 页面连 `ws://` 局域网会被混合内容拦截；`.local` 域名在手机端不一定能解析；第一次连局域网要弹「允许访问本地网络」 | 页面与 WebSocket **同源部署**（都在后端）；语音用机器人自己的麦克风；反馈用视觉不用震动；地址用 IP 或公网域名，不依赖 `.local` |
| **原型 CSS 的圆角是漂移的** | `prototype/ios/ios-light.html` 里在用 9 / 11 / 14 / 18 / 19 / 26 等中间值（气泡 18、输入框 19、segment 9/7） | **以 §1 的 6 档为准**；原型那批是待修的漂移，别沿用 |
| **字号档位歧义** | 仓库缓存的 HIG `typography.md` 里唯一的 Large 表是 iPad 档（Large Title 36/38.5…），与 iPhone 档（34/41…）不同 | 稿子按 **iPhone 档**（§1 那组）画；**实现时映射到系统 text style**，不手写 pt |
| **4 套方案都要出** | Q15（视觉终选）还没拍板 | 4 套各出一张深化，其余三套只出色板卡 |

## §6 红线（不要画的东西）

| ⛔ | 为什么 |
|---|---|
| **设备端 320×240 的「滑动软件启动界面」** | 官方固件才是真值；仓库规格锁死「屏幕 95% 是脸」「不做技能菜单」「绝不做可滚动内容」。改设备端要走 patch，不走设计稿 |
