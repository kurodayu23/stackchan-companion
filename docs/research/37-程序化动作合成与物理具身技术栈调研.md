### 2.2 ⭐ 表情能否连续插值/morph —— 官方**没有** morph，但参数空间**天然可插值**

**定论：官方表情引擎不做 morph，是离散切换；但因为表情本身就是连续参数向量，自造 morph 是「零驱动层改动」的可行升级。**

- **无 morph 证据**：
  - `setEmotion` 是 `switch` 硬编码赋值，一次到位，无过渡、无插值器、无 blend/tween 类结构：`firmware/main/stackchan/avatar/skins/default/eyes.cpp:102-123`。
  - `Element::setEmotion` 基类默认**空实现**（各 skin 自己实现）：`firmware/main/stackchan/avatar/avatar/elements/element.h:63-70`。
  - 全仓**不存在** morph / blend / tween / lerp / mix 相关类型；`Feature::setWeight` 直接赋值并立刻改 LVGL 属性：`firmware/main/stackchan/avatar/skins/default/eyes.cpp:71-78`。
  - 装饰器只有「添加/移除」语义，无混合：`firmware/main/stackchan/modifiers/head_pet.h:95-100`（`addDecorator` + `removeDecorator`）。
- **可插值证据（关键杠杆）**：
  - 表情的完整状态就是 15 个 int（3 Feature × {x,y,rotation,weight,size}），每个 setter 都是**纯函数式连续映射**（`map_range` 到像素/角度），因此对参数做线性插值 ⇒ 视觉上就是 morph。
  - BLE/WS 下发通道已是参数级：`firmware/main/stackchan/json/json_helper.cpp:14-39` `update_feature()` 逐项 `setPosition/setRotation/setWeight/setSize`。
  - ⚠️ **`rotation` 是 0~3600 的环形量**（`element.h:52-56` clamp 到 0~3600），插值必须走最短弧，否则 ±180° 会反向绕一整圈。`mouth.cpp:68-73` 用 `setRotation` 直接喂 LVGL。
  - ⚠️ `weight` 语义在「眼睑高度」和「嘴开合」上同号不同义（`eyes.cpp:75` 眼睑下移、`mouth.cpp:52-56` 嘴变宽变圆），跨五官插值需分开归一化。

### 2.3 修饰器叠加模型 —— **扁平池 + 后写覆盖（last-writer-wins）**，不是分层叠加

| 机制 | 事实 | 出处 |
|---|---|---|
| 容器 | `ObjectPool<Modifier> _modifier_pool`（扁平、无优先级、无分层） | `firmware/main/stackchan/stackchan.h:186` |
| 调度 | `update()` 遍历池 → 逐个 `modifier->_update(*this)` → 然后 avatar→motion→neon light | `firmware/main/stackchan/stackchan.h:130-145` |
| 修饰器基类 | `Modifier::Poolable`，只有 `_update(Modifiable&)` 一个钩子 | `firmware/main/stackchan/modifiable.h:39-44` |
| 可改对象 | `Modifiable` 暴露 `motion()` / `avatar()` / `hasAvatar()` / `leftNeonLight()` / `rightNeonLight()` | `firmware/main/stackchan/modifiable.h:23-39` |
| **加法叠加（唯一真叠加）** | `BreathModifier` 用**相对增量**写位置（`delta = new_offset - _last_applied_offset`），可与其它位移叠加 | `firmware/main/stackchan/modifiers/breath.h:70-88` |

| 眨眼冲突处理 | `BlinkModifier` 闭眼前**备份**当前 weight，闭眼用 25，睁眼恢复；外部改权重时用 `resyncEyeWeights()` 请求同步 | `firmware/main/stackchan/modifiers/blink.h:44-50, 76-100` |

**⭐⭐ 实时生成的两个必踩陷阱（源码注释直接点名）：**

1. **`setAutoAngleSyncEnabled` 与高频更新互斥** —— 官方头文件注释原文：
   > "If true: Prevents sudden 'jumps' when the servo is moved manually by external forces, but **may cause stuttering during high-frequency updates as it resets the animation's velocity**. If false: Maintains animation momentum and velocity for smooth, continuous motion, but may cause a 'snap'…"
   —— `firmware/main/stackchan/motion/servo.h:114-129`；默认 **true**（`servo.h:176`），实现在 `servo.cpp:112-114` 每次 `teleport(getCurrentAngle())` 重置弹簧速度。
   → **实时轨迹生成必须走 `false` 或另设"连续模式"**，否则官方默认配置下必然卡顿。
2. **目标角换算**：`mapped_angle = _zero_pos + angle * 16 / 5 / 10`（`hal_servo.cpp:76`），反算 `raw_pos_to_angle = (raw - zero) * 5 * 10 / 16`（`hal_servo.cpp:204-207`）⇒ **1 个 API 角度单位 = 0.1°**（16 raw = 5°）。yaw 限幅 `(-1280, 1280)` = ±128°（`hal_servo.cpp:340`），pitch `(30, 870)` = 3°~87°（`hal_servo.cpp:349`）。
   > 注：任务书写的「yaw 360°」与源码不符 —— 源码 yaw 限幅是 ±128°，pitch 是 3~87°。**以源码为准。**
3. **总线读回开销**：`getCurrentAngle()` 每次都走 SCS 总线 `ReadPos`（`hal_servo.cpp:89-103`）；`is_moving_impl()` 每次 `ReadMove`（`hal_servo.cpp:105-110`）。实时高频更新下需注意总线带宽（1 Mbaud）。

### 2.5 舵机运动学（已有的现成算法，不是纯 PWM 直写）

- **弹簧动画器**：`uitk::AnimateValue _angle_anim`（`servo.h:170`），依赖 `smooth_ui_toolkit`（`firmware/repos.json` → `https://github.com/Forairaaaaa/smooth_ui_toolkit.git` branch `v2.12.0`）。
- **速度→弹簧参数映射**（官方自研，可直接复用为「力度/缓动」控制）：
  - `k = 10 + (speed/1000)² × 640`（二次方映射；speed=500 → k≈170）
  - `d = 2√(m·k)`（**临界阻尼**，无过冲）
  - speed>800 时把 `restDelta/restSpeed` 提到 0.5，抑制离散计算抖动
  —— `firmware/main/stackchan/motion/servo.cpp:126-161`
- **更新频率**：舵机 `update()` 自限 **50 Hz**（`millis - last_tick < 20` 直接返回），用固定 `delta=0.02f` 推进弹簧：`servo.cpp:38-50`。
- **自动松扭矩**：静止 >200ms 且开了 `_auto_torque_release_enabled` 则 `setTorqueEnabled(false)`（省电/降温）：`servo.cpp:58-66`。
- **堵转保护**（pitch 舵机开启）：采样位置/电流/负载，连续 2 次确认卡死则收窄运行时限幅并停在该角：`hal_servo.cpp:223-318`。

### 2.7 语音链路现状（韵律驱动最大的缺口）

- 官方**没有**逐帧音频幅度/音高反馈。语音状态是**离散字符串**状态机：
  `StackChanAvatarDisplay::SetStatus(const char* status)` → `"LISTENING"` / `"STANDBY"` / `"SPEAKING"` / 其他（当作气泡文本）：`firmware/main/hal/board/stackchan_display.cc:480-533`。
- `"SPEAKING"` 时挂 `SpeakingModifier(0, 180, false)`：每 180ms 翻转嘴部开合权重（随机 40~80 / 0~20），**且 `enableMotion=false`（官方实际没开说话微动）**：`stackchan_display.cc:526`、`firmware/main/stackchan/modifiers/speaking.h:44-46, 76-88, 128-133`。
- `SpeakingModifier::perform_subtle_speaking_motion()`（`speaking.h:90-127`）里已经存在**「说话时的随机点头/摆头」**逻辑（±20~50 俯仰、±40 偏航、speed 100~200），带「外部大幅移动后重同步基线」的防 snap 处理（阈值 300 单位）：`speaking.h:96-110`。**这是官方最接近「韵律→舵机」的现成代码，可直接作为替换起点。**
- opus 音频走 WS 通道（`DataType::Opus = 0x01`，`firmware/main/hal/hal_ws_avatar.cpp:48-52`），实际解码/播放由 `xiaozhi-esp32` 组件承担（`firmware/repos.json` → `78/xiaozhi-esp32` branch `v2.2.4`，有本地 patch `firmware/patches/xiaozhi-esp32.patch`）。

## §三 ESP32 舵机与 PWM 驱动栈评估

### 3.0 ⚠️ 前置结论：StackChan 官方硬件**不是 PWM 舵机**

| 事实 | 出处 |
|---|---|
| 官方固件用 **Feetech SCSCL 串行总线舵机**，`_scs_bus.begin(UART_NUM_1, 1000000, 6, 7)`（UART1 @ **1 Mbaud**，TX=6 RX=7） | `firmware/main/hal/hal_servo.cpp:16, 335` |
| 舵机 ID：**yaw=1**、**pitch=2** | `hal_servo.cpp:338, 347` |
| 官方 README：机身含 "two feedback servos (**360-degree continuous rotation on the horizontal axis** and **90-degree movement on the vertical axis**), two rows totaling **12 RGB LEDs**, infrared transmitter and receiver, a **three-zone touch panel**, and a full-featured NFC module" | 仓库根 `README.md`（"The robot body" 段） |
| 驱动库：**FTServo_Arduino v2.0.0，MIT License**，Copyright (c) 2024 ftservo，上游 `https://github.com/ftservo/FTServo_Arduino` | `firmware/main/hal/drivers/FTServo_Arduino/LICENSE`、`library.properties` |
| 官方固件整体许可：**MIT License**，Copyright (c) 2026 M5Stack Technology CO LTD | `firmware/LICENSE` |

> **因此：ESP32Servo / arduino-esp32 Servo / LEDC / MCPWM 这条 PWM 路线，对官方硬件是「不适配」的**——StackChan 的舵机不接 PWM 信号线，而是走 UART 总线 + 位置/速度协议。以下评估仍然给出（因为二开换舵机或外接额外舵机时需要），但**采用决策是「不采用」**。

### 3.1 四条 PWM 路线的横向对比

| 项目 | ESP32Servo | arduino-esp32 `Servo` | ESP-IDF `ledc` | ESP-IDF `mcpwm` |
|---|---|---|---|---|
| 上游 | `github.com/megazuel/ESP32Servo` | `github.com/espressif/arduino-esp32` | ESP-IDF 组件 | ESP-IDF 组件 `esp_driver_mcpwm` |
| 许可 | **未取得**（仓库 URL 现返回 404 "Page not found"，无法核实 LICENSE） | **未取得**（`LICENSE.txt` 与 `libraries/Servo/src/Servo.h` 均 404，路径/分支未确认） | Apache-2.0（Espressif） | Apache-2.0（示例源码头 `SPDX-License-Identifier: Apache-2.0`） |
| 活跃度 | **未取得** | **未取得** | 随 IDF v5.5.4 发布 | 随 IDF v5.5.4 发布 |

### 3.2 ESP-IDF `ledc`（v5.5.4, ESP32-S3）实测要点

来源：https://docs.espressif.com/projects/esp-idf/en/v5.5.4/esp32s3/api-reference/peripherals/ledc.html （已抓取）

- **8 个通道**（`LEDC_CHANNEL_0..7`）、**4 个定时器**（`LEDC_TIMER_0..3`），"It has 8 channels which can generate independent waveforms that can be used, for example, to drive RGB LED devices."
- ⚠️ **ESP32-S3 只支持低速模式**："unlike ESP32, ESP32-S3 only supports configuring channels in 'low speed' mode"；"All the timers and channels in the ESP32-S3's LED PWM Controller only support low speed mode. **Any change of PWM settings must be explicitly triggered by software**."
- 源时钟：`APB_CLK` 80 MHz、`RC_FAST_CLK` ~20 MHz、`XTAL_CLK` 40 MHz；⚠️ **"For ESP32-S3, all timers share one clock source"** → 所有定时器必须同频，舵机 50Hz 与舵机 50Hz 可共享，舵机 50Hz + LED 5kHz 则必须分属不同芯片或用 MCPWM。
- 频率与分辨率互斥：`ledc_find_suitable_duty_resolution()` 给最大可用分辨率；分辨率 1~14 bit。
- ⚠️ **硬件警告**：S3 上定时器选到最大占空比分辨率时，占空比**不能**设成 `2**resolution`，否则硬件计数器溢出。
- **硬件淡入淡出**（可零 CPU 做渐变）：`ledc_set_fade_with_time()` / `ledc_set_fade_with_step()` / `ledc_set_fade()` + `ledc_fade_start()` + `ledc_fade_stop()` + `ledc_cb_register()`。

### 3.3 ESP-IDF `mcpwm`（v5.5.4）—— 唯一有**官方舵机示例**的 PWM 方案

来源：https://raw.githubusercontent.com/espressif/esp-idf/v5.5.4/docs/en/api-reference/peripherals/mcpwm.rst （已抓取 .rst 原文）

- 文档开篇即把 **"Digital motor control, e.g., brushed/brushless DC motor, RC servo motor"** 列为 MCPWM 的典型场景。
- 官方示例：**`peripherals/mcpwm/mcpwm_servo_control`** —— "demonstrates how to control a typical RC Servo by sending a PWM signal using the MCPWM driver, with the servo rotating from -60° to 60° and then turning back again."
- 子模块：Timer / Operator / Comparator / Generator / Fault / Brake / Sync / Dead Time / Carrier Modulation / Capture；事件可接 ETM。
- 线程安全：工厂函数线程安全；**`mcpwm_comparator_set_compare_value()` 和 `mcpwm_timer_set_period()` 可在 ISR 上下文调用**（驱动用临界区）；其余控制函数需互斥。
- Kconfig：`CONFIG_MCPWM_ISR_CACHE_SAFE`、`CONFIG_MCPWM_CTRL_FUNC_IN_IRAM`。

**官方舵机示例源码实测**（https://raw.githubusercontent.com/espressif/esp-idf/v5.5.4/examples/peripherals/mcpwm/mcpwm_servo_control/main/mcpwm_servo_control_example_main.c ，已抓取）：

```c
#define SERVO_MIN_PULSEWIDTH_US 500      // 最小脉宽(us)
#define SERVO_MAX_PULSEWIDTH_US 2500     // 最大脉宽(us)
#define SERVO_MIN_DEGREE        -90
#define SERVO_MAX_DEGREE        90
#define SERVO_TIMEBASE_RESOLUTION_HZ 1000000  // 1MHz → 1us/tick
#define SERVO_TIMEBASE_PERIOD        20000    // 20000 ticks = 20ms  → 50Hz

static inline uint32_t example_angle_to_compare(int angle) {
    return (angle - SERVO_MIN_DEGREE) * (SERVO_MAX_PULSEWIDTH_US - SERVO_MIN_PULSEWIDTH_US)
           / (SERVO_MAX_DEGREE - SERVO_MIN_DEGREE) + SERVO_MIN_PULSEWIDTH_US;
}
```
> 这是 **50Hz 舵机 PWM 的权威参考实现**：1µs 分辨率、20ms 周期、角度线性映射到脉宽。
> ⚠️ 例程的更新节奏是 `vTaskDelay(500ms)` 一次跳 2°，**不是**连续微调——舵机「微动」需要自己加插值层。

### 3.4 结论：舵机驱动栈的真正瓶颈不在 PWM，在**总线时序**

| 项 | 官方实测 |
|---|---|
| 总线 | UART1 @ 1 Mbaud（`hal_servo.cpp:335`） |
| 每帧写舵机 | `WritePos(id, pos, 20, 0)` — 参数 `(ID, Position, Time, Speed)`，`Time=20` 是**运行时间 ms**（`hal_servo.cpp:86`；`SCSCL.h:57`） |
| 每帧读舵机 | `getCurrentAngle()` → `ReadPos(id)`；`is_moving_impl()` → `ReadMove(id)`（`hal_servo.cpp:89-110`） |
| 频率上限 | `Servo::update()` 自限 **50Hz**（`servo.cpp:41-43`）；`NeonLight::update()` 同为 50Hz（`neon_light.cpp:29-31`） |

→ **官方已经把舵机刷新率定在 50Hz。** 这意味着「连续轨迹」的采样率上限就是 50Hz，不需要更高；这既是限制也是设计目标（人眼看着 50Hz 的头部运动已经足够顺滑）。

| 官方呼吸 | `BreathModifier`：正弦，周期 6600ms，幅度 16px，600ms 更新一次，**相对增量**写位置 | `modifiers/breath.h:22-88` |
| 官方随机动作的刻意不对称 | IdleMotion 概率分布 50/30/10/10（环视/小移/快瞥/回正） | `modifiers/idle_motion.h:70-80` |

### 6.2 特征提取（韵律 = 与内容无关的声学包络）

**采样参数**：PCM 16 kHz 单声道；窗长 20 ms（320 样本）、跳长 **20 ms**（= 50 Hz，与舵机刷新率**天然对齐**）。

| 特征 | 计算 | 成本 | 语义 |
|---|---|---|---|
| `energy` | RMS → dB → 归一化到 [0,1] | 320 次乘加 | 响度包络 |
| `zcr` | 过零率 | 320 次比较 | 清浊/摩擦音判别（可只用于排除噪声） |
| `f0`（音高） | 自相关 / YIN，搜索 80–500 Hz，插值细化 | ≈ 320×220 次 MAC（≈70k MAC/帧） | 语调轮廓 |
| `onset` | 短时能量一阶差分的半波整流 + 自适应中值阈值 | O(N) | 音节/重音起跳 |
| `voiced` | `f0` 峰值显著性 > 阈值 | — | 有声/无声 |
| `phraseEnd` | 连续静音 > 250 ms | — | 短语边界（用于「收势」） |
| `rate` | onset 计数 / 秒 | — | 语速 |

**算力预算**：70k MAC/帧 × 50 帧/s ≈ **3.5 MMAC/s**。ESP32-S3 240 MHz 双核带 FPU，占比 <2%，**完全可行**。栈内已有 `espressif/esp_codec_dev ~1.5.4`（`firmware/main/idf_component.yml`）可做 opus 解码，`smooth_ui_toolkit` 的 `src/tools/fpm/` 定点数学（21KB `fixed.hpp`）可在无 FPU 场景加速。

> ⭐ **更省事的路径（强烈建议先做）**：**在 TTS 服务端 / 手机 App 侧算好特征或直接算好轨迹**，固件只收轨迹。理由：(a) 官方固件里 opus 的解码与播放由 `xiaozhi-esp32` 组件负责，**固件侧拿不到干净的 PCM**（§2.7：只有离散状态串 LISTENING/STANDBY/SPEAKING）；(b) 服务端有原始文本与音频，能给出**音素级对齐**（Freeform 的 TextGrid 就是这个思路，§5.2），固件侧只能做能量/音高的粗对齐。

### 6.3 韵律 → 角度/参数的映射曲线

> 单位约定：下文所有角度均为 **API 单位（0.1°）**。

| 韵律特征 | 目标量 | 映射 | 依据 |
|---|---|---|---|
| `f0` 相对中位数 `f0_med` 的偏差（半音） | **俯仰 pitch** | `pitch = PITCH_CENTER + KP * (f0 - f0_ref)`，`KP ≈ 8~15`（=0.8°~1.5°/半音） | 音高上扬 ≈ 疑问/强调 ≈ 抬下巴。官方 `SpeakingModifier` 的点头幅度是 +20~50（2°~5°），量级一致 |
| `energy` | **嘴部开合** | `mouthWeight = map_range(energy, E_MIN, E_MAX, 0, 100)` | 官方说话嘴权重在 40~80 随机（`speaking.h:128-133`）；改成**连续**由能量驱动，去掉随机性 = 去机械感 |
| `energy` | **LED 亮度** | `lum = energy^0.7`（伽马压缩，暗部更敏感） | 人眼对亮度近似对数感知 |
| `onset` | **偏航 impulse** | `Δyaw = A_ONSET * onset * s`，`A_ONSET ≈ 30~60`（3°~6°），`s = ±1` 交替 | 重音 → 点头/小摆头。官方 Talking 用随机 ±40 偏航（`speaking.h:117`） |
| `onset`（连续） | **pitch impulse** | `Δpitch = A_ONSET_P * onset`，`A_ONSET_P ≈ 10~20` | 重音 → 微点头 |
| `phraseEnd` | **姿态收势** | 目标角向 baseline 收敛，`τ = 400 ms` | 句末回正，人工感强 |
| `voiced=0`（清音/摩擦） | 抑制 | `yaw/pitch` 贡献 ×0.3 | 摩擦音不该驱动大动作 |
| `energy < E_GATE` | **冻结** | 保持上一目标角（不更新） | 去死区，防噪声驱动的无意义抖动 |

**颜色映射**：`hue` 由**情绪/语义标签**（LLM 或服务端给出）慢变；`sat` 固定；`lum` 由能量驱动。官方 `NeonLight` 已内置 `AnimateRgb_t` 颜色缓动（默认 0.3s，`neon_light.cpp:14-17`），可直接当「颜色平滑器」用。

### 6.4 抖动 / 噪声叠加（三层，去机械感的核心）

真实人的头部运动 = **意图** + **生命感噪声** + **呼吸**。只做第一层必然机械。

```
θ(t) = baseline(t)                       ← 意图层（韵律驱动，低频 <2Hz）
     + A_idle · perlin1(t · f_idle)      ← 生命感（中频 0.3~0.8Hz，小幅）
     + A_micro · lp1(noise(t))           ← 微观抖动（高频，很小，消除"完全静止"）
     + A_breath · sin(2π t / T_breath)   ← 呼吸（超低频）
```

| 层 | 参数 | 建议值（API 单位） | 说明 |
|---|---|---|---|
| 呼吸 | `A_breath` | pitch ±12~18（1.2°~1.8°）；yaw ±6~10 | 与官方 `BreathModifier` 周期 6600 ms 对齐 → **T_breath = 6.6 s**；官方呼吸是纯屏幕位移，这里同时驱动舵机 |
| 呼吸叠加 | 幅度调制 | `A_breath' = A_breath · (1 + 0.6 · speakingGate)` | 说话时呼吸变浅变快 → 生命感 |
| 生命感 | `A_idle` | yaw ±25~35（2.5°~3.5°）；pitch ±15~25 | Perlin/value-noise，**必须非周期**（正弦会产生"钟摆感"） |
| 生命感频率 | `f_idle` | 0.30~0.80 Hz | 两条独立噪声通道（yaw/pitch）用不同相位 |
| 微观抖动 | `A_micro` | yaw ±4~6；pitch ±3~4 | 白噪声经一阶低通（τ≈30 ms） |
| 微观抖动只在运动时 | 门控 | `A_micro *= (0.3 + 0.7·‖dθ/dt‖)` | 静止时几乎为零，避免"嗡嗡" |

> **Perlin 未在栈内找到**：`smooth_ui_toolkit` 文件清单里**没有** noise/perlin 模块。→ 自造 1D value-noise（约 30 行，用栈内 `src/tools/random/random.hpp` 取随机数 + 一阶插值），或直接用 `src/core/animation/animate_vector/animate_vector2.hpp` 的多正弦叠加逼近。**成本极低，列入 §九「自造」。**

### 6.5 时间对齐（音频缓冲延迟多少）

**三层延迟来源**：

| 来源 | 量级 | 是否可控 |
|---|---|---|
| TTS 流式首包等待 | 100~400 ms | **服务端可控**（等满一句再发，最省事） |
| opus 解码帧长 | 20~60 ms（取决编码） | 部分可控 |
| 特征提取 lookahead | 1 帧 = 20 ms | 固定 |
| 舵机/LED 弹簧跟随 | 临界阻尼下 ~200~400 ms 达 95% | 可调 stiffness/damping |
| **建议总延迟** | **服务端流式：~150 ms；固件本地：~80 ms** | |

**推荐做法（服务端带时间戳）**：服务端生成轨迹时，每个采样点带 `t_ms`（相对 TTS 首帧的偏移），固件按 `t_ms` 对齐播放 → **对齐精度 = 服务端精度（±10 ms）**，且不受本地解码抖动影响。

**备选（固件本地）**：
1. 用栈内 `smooth_ui_toolkit` 的 **`src/tools/ring_buffer/ring_buffer.hpp`** 做**定长延迟环形缓冲**，把特征帧延后 `D = 4 帧 = 80 ms` 再消费；
2. 或者**提前驱动**：用 `t + Δ` 的特征（预测），把 Δ 折进平滑器的时间常数；
3. ⚠️ **不要**靠「固定 sleep」对齐 —— 帧率抖动会累积。

**采样率对齐**：特征帧 20 ms（50 Hz）== 舵机 `update()` 的 20 ms 节流 == LED `update()` 的 20 ms 节流 → **三者在同一 tick 内消费同一份特征帧**，天然同步，不需要额外对齐。

### 6.6 避免「机械感」的 8 条硬规则（每条都对应一个源码陷阱）

1. **不要每帧都重置弹簧**。官方 `moveWithSpeed` 每次调用都执行 `_angle_anim = angle`（`servo.cpp:115`），高频调用会让弹簧永远在追踪 → 永久微颤。→ **在轨迹层先做 C1 平滑**，下游只喂平滑后的目标角。
2. **必须 `setAutoAngleSyncEnabled(false)`**。官方注释已点名（`app_espnow_ctrl.cpp`）；开着的话每次 `teleport(getCurrentAngle())` 会重置速度，而且 `getCurrentAngle()` 每次都走总线 `ReadPos`（`hal_servo.cpp:89-103`），50 Hz × 2 舵机 = 100 次/秒阻塞式总线往返。
3. **自己做基线跟踪，别每帧 teleport**。抄官方 `SpeakingModifier` 的做法：记住上一次的基线角，若当前实测角与基线偏差 > 300 单位（30°），判定为「外部拖动」，才重置基线（`speaking.h:96-110`）。
4. **限幅单帧角速度**（如 ≤ 600 单位/s = 60°/s），避免能量尖峰造成猛甩。
5. **用 bezier/easing 而不是线性**。线性往返 = 机械感。栈内已有 `core/easing/cubic_bezier/cubic_bezier.hpp`（§4.2）。
6. **打破左右对称**。真实头动不对称；官方 IdleMotion 用 50/30/10/10 的概率分布刻意避免对称（`idle_motion.h:70-80`）。→ 韵律驱动时，两侧幅度加一个缓慢漂移的偏置。
7. **加入「预备动作」与「收势」**：发声前 150 ms 有一个轻微的反向预备，发声结束后 400 ms 缓慢回弹（官方 `phraseEnd` 逻辑）。
8. **静音门限 + 死区**：`energy < E_GATE` 时冻结目标角（§6.3），否则底噪会驱动无意义抖动。

### 6.7 伪代码（概念草图；本次调研**不修改任何产品代码**）

```cpp
// ============================================================
// ProsodyModifier：韵律驱动的连续头部轨迹（概念草图）
// 复用官方 stackchan::Modifier / Modifiable 接口（§2.3）
// 所有角度单位 = API 单位 = 0.1°
// ============================================================
class ProsodyModifier : public Modifier {

    struct Frame {                 // 20ms 一帧
        float energy;              // 0..1 归一化 RMS
        float pitchSemi;           // 相对中位数的半音偏差
        float onset;               // 0..1 起音强度
        bool  voiced;
    };

    // --- 状态 ---
    RingBuffer<Frame, 256> _fbuf;      // smooth_ui_toolkit src/tools/ring_buffer/
    int   _delayFrames   = 4;          // ≈80ms 对齐延迟（§6.5）
    float _yaw = 0, _pitch = 0;         // 平滑后的当前目标
    float _yawPrev = 0, _pitchPrev = 0;
    float _baseYaw = 0, _basePitch = 0; // 外部拖动后的基线
    uint32_t _lastTick = 0;
    double _t = 0;                     // 连续时间轴（秒）
    int    _parity = 0;                // 左右交替
    uint32_t _lastPhonemeTick = 0;
    bool   _speaking = false;

    // --- 常量（单位：API 单位 / 秒 / Hz）---
    static constexpr float KP_PITCH      = 12.0f;  // 0.1°/半音
    static constexpr float A_ONSET_YAW   = 45.0f;  // 4.5°
    static constexpr float A_ONSET_PITCH = 15.0f;  // 1.5°
    static constexpr float A_IDLE_YAW    = 30.0f;  // 3°
    static constexpr float A_IDLE_PITCH  = 20.0f;  // 2°
    static constexpr float A_MICRO_YAW   = 5.0f;   // 0.5°
    static constexpr float A_BREATH      = 15.0f;  // 1.5°
    static constexpr float T_BREATH      = 6.6f;   // 与官方 BreathModifier 对齐
    static constexpr float E_GATE        = 0.06f;  // 静音门限
    static constexpr float MAX_VEL       = 600.0f; // 60°/s 角速度限幅
    static constexpr int   YAW_MIN = -1280, YAW_MAX = 1280;
    static constexpr int   PITCH_MIN = 30,  PITCH_MAX = 870;

    void _update(Modifiable& sc) override {
        auto now = GetHAL().millis();
        if (now - _lastTick < 20) return;      // 50Hz，对齐 servo.cpp:41
        _lastTick = now;
        _t += 0.020;

        auto& motion = sc.motion();
        if (motion.isModifyLocked()) return;   // 学 idle_motion.h:70（IMU 事件会加锁）

        // ---------- 0) 取一帧（延迟对齐）----------
        Frame f = _fbuf.popDelayed(_delayFrames);
        if (!f.valid) { _applyHold(sc); return; }

        _speaking = (f.energy > E_GATE);

        // ---------- 1) 韵律主项（意图层）----------
        float pitchTarget = PITCH_CENTER + KP_PITCH * (f.pitchSemi);
        float mouthW      = map_range(f.energy, E_MIN, E_MAX, 0.0f, 100.0f);
        float onsetYaw    = A_ONSET_YAW   * f.onset * ((_parity++ & 1) ? +1.f : -1.f);
        float onsetPitch  = A_ONSET_PITCH * f.onset;
        float voicedGain  = f.voiced ? 1.0f : 0.3f;   // 摩擦音抑制

        // ---------- 2) 呼吸（超低频正弦，说话时加深）----------
        float breathAmp   = A_BREATH * (1.0f + 0.6f * (_speaking ? 1.f : 0.f));
        float breathPitch = breathAmp * sinf(2.0f * M_PI * _t / T_BREATH);

        // ---------- 3) Perlin 生命感 + 微观抖动 ----------
        float nYaw   = perlin1(_t * 0.5f)            * A_IDLE_YAW;
        float nPitch = perlin1(_t * 0.37f + 100.f)   * A_IDLE_PITCH;
        float mYaw   = lp1(white(), 0.03f)           * A_MICRO_YAW;

        // ---------- 4) 合成目标 ----------
        float rawYaw   = _baseYaw   + voicedGain * (onsetYaw) + nYaw + mYaw;
        float rawPitch = _basePitch + voicedGain * (pitchTarget + onsetPitch)
                       + breathPitch + nPitch;

        // ---------- 5) C1 平滑（一阶低通）+ 角速度限幅 ----------
        const float dt = 0.020f;
        float ny = lowpass(_yaw,   rawYaw,   TAU_YAW,   dt);
        float np = lowpass(_pitch, rawPitch, TAU_PITCH, dt);
        ny = limitVel(ny, _yaw,   MAX_VEL * dt);
        np = limitVel(np, _pitch, MAX_VEL * dt);
        _yaw = clampf(ny, (float)YAW_MIN,   (float)YAW_MAX);
        _pitch= clampf(np, (float)PITCH_MIN, (float)PITCH_MAX);

        // ---------- 6) 基线自愈（外部拖动检测，抄 speaking.h:96-110）----------
        auto cur = motion.getCurrentAngles();
        if (fabsf(cur.x - _baseYaw) > 300 || fabsf(cur.y - _basePitch) > 300) {
            _baseYaw = cur.x; _basePitch = cur.y;   // 只在大幅偏离时重同步
        }

        // ---------- 7) 下发目标角（目标已 C1 连续，弹簧只做最后一段润色）----------
        int speed = speedFromDelta(fabsf(_yaw - _yawPrev), fabsf(_pitch - _pitchPrev));
        motion.moveWithSpeed((int)_yaw, (int)_pitch, speed);   // 官方接口，§2.4
        _yawPrev = _yaw; _pitchPrev = _pitch;

        // ---------- 8) 表情：嘴部由能量连续驱动（替代 SpeakingModifier 的随机）----------
        sc.avatar().mouth().setWeight((int)mouthW);

        // ---------- 9) LED：亮度=能量，颜色=情绪（AnimateRgb 自带 0.3s 过渡）----------
        uint8_t lum = (uint8_t)(255.0f * powf(f.energy, 0.7f));
        sc.leftNeonLight().setColor(hsvToRgb(hue, sat, lum));
        sc.rightNeonLight().setColor(hsvToRgb(hue2, sat, lum));
    }

    void _applyHold(Modifiable& sc) {
        // 无新帧：保持上一目标角（冻结，不做无意义抖动）
        sc.motion().moveWithSpeed((int)_yaw, (int)_pitch, 100);
    }
};
```

**配套的基线漂移**（让机器人有「视点」）：`_baseYaw/_basePitch` 不应恒定，而应按官方 `IdleMotionModifier` 的方式缓慢漂移（可把 `IdleMotionModifier` 保留，让它写 baseline，Prosody 只写增量）—— 但注意 §2.3 的**后写覆盖**语义，二者会互相覆盖。→ 见 §6.9 的仲裁规则。

### 6.8 LED 轨迹设计

- **官方现状**：`NeonLight` 只有「整组同色 + 颜色缓动」；左右各 6 颗共 12 颗（`addons/neon_light/neon_light.h:55-78`）；底层已有**逐颗**原语 `Hal::setRgbColor(index, r, g, b)` 与 `Hal::refreshRgb()`（`hal/hal_io_expander.cpp:69-83`），IO 扩展器初始化时 `setLedCount(12)`（`hal_io_expander.cpp:51`）。
- **韵律 → LED**：
  - 亮度 = 能量（§6.3），左右两组可做**相位差**（左组领先右组 100 ms）→ 产生「流动感」，比整组同色生动得多。
  - 颜色 = 情绪标签的色相，`AnimateRgb_t` 自带 0.3s 缓动，天然平滑。
- **要做「跑马 / 波形」必须扩展 `NeonLight`**：新增 `setPixelColor(index, r, g, b)`（逐颗），`refresh_rgb_impl()` 一次性刷 12 颗。**成本很低**（底层原语已就位），列入 §九「混合」。
- 官方当前的 LED 语义是**状态指示**而非装饰：`LISTENING` → `setRgbColor(0, 0, 50, 0)`；`STANDBY` → 全灭；`SPEAKING` → `setRgbColor(0, 0, 0, 50)`（`hal/board/stackchan_display.cc:498-531`）—— 注意它**只写第 0 颗**。→ 韵律驱动应接管整组，但要在状态语义上区分（如：状态色占第 0 颗，韵律色占其余 11 颗）。

### 6.9 与官方修饰器的仲裁（§2.3「后写覆盖」模型的必然要求）

官方 Modifier 是**扁平池 + 后写覆盖**，所以新 Modifier 必须自己管仲裁，否则会与 blink / speaking / dance / idle 抢属性。

| 冲突对 | 仲裁方案 |
|---|---|
| Prosody vs `SpeakingModifier`（都写嘴部权重） | Prosody 接管嘴部；进入 Prosody 时 `removeModifier(speaking_id)`（官方 `stackchan_display.cc:499-517` 已有 remove+置-1 的先例） |
| Prosody vs `BlinkModifier`（都写眼/嘴 weight） | Blink 只写眼部权重（`blink.h:44-46` 写 leftEye/rightEye），嘴部不冲突 ✅；但 Prosody 写嘴部时须避开眨眼闭眼时刻（blink 闭眼时用 weight 25） |
| Prosody vs `IdleMotionModifier`（都写舵机） | **必须用 `Motion::setModifyLock(true)` 让 Idle 让位**（`idle_motion.h:70-73` 已实现该检查）——反之则 Idle 的 `moveWithSpeed` 会覆盖 Prosody 的目标角 |
| Prosody vs `DanceModifier`（都写舵机+眼+嘴） | 舞蹈播放期间 `setModifyLock(true)`；或采用**混合**策略：Prosody 只做 ±30 单位以内的「附随抖动」，舞蹈做主体 |
| Prosody vs `ImuEventModifier` | IMU 摇晃时官方已 `motion.setModifyLock(true)` + `goHome(300)`（`imu.h:88-91`）→ Prosody 检查 `isModifyLocked()` 自动让位 ✅ |
| Prosody vs `HeadPetModifier` | 抚摸时官方 `avatar.setEmotion(Happy)` + 装饰器；Prosody 应检测 `Motion::isModifyLocked()` 让位 |

**推荐实现约定**：Prosody 内部维护一个「目标角」缓冲，每帧 **只写一次** `motion.moveWithSpeed()`，且**在所有其他 Modifier 之后**执行（官方 `StackChan::update()` 是按池顺序遍历的，`stackchan.h:132` → 后加入的 Modifier 后执行 → **Prosody 最后加入即可最后写**）。这是**不改官方代码**就能获得「后写优先」的最小代价做法。

### 6.10 性能预算（ESP32-S3 @ 50 Hz）

| 项 | 计算 | 结论 |
|---|---|---|
| 特征提取 | ≈3.5 MMAC/s（YIN 自相关） | ✅ <2% CPU |
| 舵机下发 | 50 Hz × 2 舵机 × `WritePos` ≈ 22 B/帧 | ≈1.1 kB/s，占 1 Mbaud 约 **9%** ✅ |
| 舵机读回 | **必须避免**每帧 `ReadPos`；只在「基线自愈判定」时低频读（如 2 Hz） | 省掉 100 次/秒总线往返 |
| LVGL 表情更新 | 改几个对象属性（位置/尺寸/圆角/旋转） | ✅ 320×240 预算充裕（§2.6） |
| 内存 | 帧缓冲 256×16 B ≈ 4 KB | ✅ |

### 6.11 分阶段落地路线（每阶段都可独立交付）

| 阶段 | 内容 | 改动范围 | 产出 |
|---|---|---|---|
| **P0（零固件改动）** | 在 App / 服务端生成「韵律关键帧 JSON」（含 `leftEye/rightEye/mouth` + `yawServo/pitchServo` + `durationMs`），通过**官方现成的 WS 通道**下发 | **只改 App/服务端** | 立刻从「预设舞蹈」升级到「韵律编排」，复用 `animation::parse_sequence_from_json`（`json_helper.cpp:178-247`）+ `onWsDanceData`（`app_avatar.cpp:205-211`）。⚠️ 仍是离散关键帧，实时性受限于关键帧密度 |
| **P1（固件新增一个 Modifier）** | 固件本地解码 opus/PCM → 特征提取 → 50 Hz 连续目标角 | 新增 `modifiers/prosody.h`（新文件）+ `stackchan.cpp` 注册 | 真正的「实时连续轨迹」；核心是 §6.7 的算法 |
| **P2（表情 morph）** | 15 维表情参数插值器（新增 `avatar/avatar/elements/morph.hpp`），并给 LED 加逐颗控制 | 新增文件 + `NeonLight` 小改 | 表情连续化 + LED 流动效果 |

**P1 的最小可用配置**（若时间紧）：只做 `energy → 嘴部权重` + `onset → 偏航 impulse` + `Perlin idle 噪声`，不做 f0（省掉 YIN 的 3.5 MMAC/s 与对齐复杂度），即可消除大部分机械感。
