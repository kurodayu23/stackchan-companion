## 六、⭐ v1.6.0 局域网二进制协议（新增，MIT 许可可复用）

`firmware/main/hal/utils/local_network/local_network_protocol.h` 实测：

```cpp
constexpr size_t HeaderSize     = 20;
constexpr size_t MaxPayloadSize = UINT16_MAX;

inline bool isKnownType(uint8_t type) {
    // Keep these ranges aligned with the App's MsgType wire values.
    return (type >= 0x01 && type <= 0x07) || (type >= 0x09 && type <= 0x0E) || (type >= 0x10 && type <= 0x1B);
}

inline bool hasTargetPrefix(uint8_t type) {
    return (type >= 0x02 && type <= 0x06) || type == 0x12 || type == 0x13;
}

inline bool encode(uint8_t type, const uint8_t* payload, uint64_t len, uint64_t session,
                   uint32_t sequence, std::vector<uint8_t>& frame) {
    ...
    frame[0] = 0x53;   // magic
}
```

**要点**：
- 固定 **20 字节头**，magic `0x53`，**大端序**（`writeBigEndian`），payload 上限 65535。
- 头含 **session（8B）+ sequence（4B）** → 支持多路复用与丢包检测。
- `hasTargetPrefix` 覆盖 0x02–0x06 / 0x12 / 0x13 → 这几类消息**带目标设备前缀**（即带 deviceId 路由）。
- `isKnownType` 明确注释 **"Keep these ranges aligned with the App's MsgType wire values"** → **协议与 App 的 `MsgType` 一一对应**。

## 八、对我们路线的 3 个影响（需回填进 `00-总纲`）

### 8.1 ⭐ 后端策略：「自建」→「**fork 官方 server（MIT）替换认证层与 AI 层**」

| 维度 | 自建（旧设想） | **fork 官方 server（新）** |
|---|---|---|
| 账号/设备绑定/WS 协议 | 从零实现，协议细节必踩坑 | **已实现且刚加固过** |
| 工作量 | 数周 | 数天（改认证 + 换 TTS/Chat 层） |
| 求职作品叙事 | "我写了个后端" | "**我在一个 MIT 开源商业后端上做了二次开发，并替换了它的 AI 供应商**" —— 更可信 |
| 风险 | 协议对不上、设备连不上 | 需读懂 GoFrame v2 代码 |
| 许可 | 无约束 | MIT：**保留版权声明即可商用** |

**要做的事**：fork → ① 换掉 `loginUrl/registrationUrl/queryUsernameUrl` 指向我们自己的认证；

③ 剥离我们不做的 `post/friend/pano/dance/appstore`（或保留但不在 UI 里暴露）；
④ 保留 `device` v2 的 activate-and-bind（但把"工厂 MAC 校验"指向我们自己的白名单）。

### 8.2 ⭐ 配网工作整体取消

原计划「实现强制配网 / 替换配网流程」→ **取消**。
v1.6.0 已关闭全部三种传统配网并改走 App 配网，我们沿用官方路径。
**但要记住两件事**：① `OTA_URL` 必须改（否则仍回小智）；② `STACKCHAN_SERVER_URL` 用 `sdkconfig.defaults.local` 覆盖。

### 8.3 ⭐ 手势控舵机：不发明协议，走 LAN

- `controlMotion (0x04)` **官方已有**，设备端 HAL 也已有对应处理。
- v1.6.0 新增 LAN 二进制协议 + `appLanAddress (0x1B)` → iPhone 可告知自身局域网地址给设备。
- 官方自己把视频/远控改成 **LAN 优先 + 云回落**，等于**官方承认云端往返延迟不可接受**。
- **结论**：手势控舵机应设计为 **LAN 直连优先（目标 <30ms）**，云端 WS 作为设备不在同一局域网时的回落。
  这让「手势控舵机」从"锦上添花"变成**真正能用的功能**（舵机跟手是物理特性，延迟一高就假）。

## 九、给用户的 4 个新决策点（追加到 §8 待拍板）

1. **后端基座**：接受 **fork 官方 server（MIT）** 而不是从零自建？
   - 推荐：**接受 fork**。理由见 §八·1；风险是需读懂 GoFrame v2。
2. **固件基线**：把本地 v1.5.1 **同步到 v1.6.0** 再动手？
   - 推荐：**同步**。理由：① 含 BLE/Wi-Fi 安全修复；② 含 LAN 协议（手势控舵机要用）；③ 含配网路径变更；④ 官方已内置 `STACKCHAN_SERVER_URL` 开关。
   - 成本：重新编译 + 刷机（本机已有完整 IDF 5.5.4 链路与 16MB 全量备份，风险低）。
3. **功能减法确认**（官方有、我们不做）：看视频 `0x02` / 摄像头 `0x05-0x06` / 通话 `0x09-0x0C` / 手机屏幕镜像 `0x12-0x13` / 舞蹈 `0x14` / 拍照 `0x1A` + 社区动态 `moments` + 附近设备 `nearby` + 全景图 `pano` + 应用商店 `appstore` + MCP `mcp_page` + WebView + 3D。
4. **`OTA_URL` 与 `STACKCHAN_SERVER_URL` 都必须覆盖**（自建部署的两个必改项，一个都不能漏）。
