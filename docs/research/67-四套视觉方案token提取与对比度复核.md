# 67 · 四套视觉方案的 Token 提取与对比度复核

> **性质**：T4 自研实算。阈值来自 Apple HIG（T1），**色值来自本仓库原型文件的 CSS 变量**（T4 本仓事实），**比值由脚本实算**。
> **可复现**：`py -3.12 tools/check_contrast.py --root .`
> **本文不作产品决策**：4 套方案最终选哪一套由用户拍板（见 `docs/spec/07` §3.1b / §3.3）。

---

## 一、为什么要写这份文档

`docs/spec/07` §3.3 记录了用户拍板「**强调色 = 各方案自带**」。

但「自带」这件事有个前提：**每个方案的强调色在自己的底色上都得站得住**。
如果某套方案的强调色在自己的背景上是 2:1，那它就不是「一套可用的方案」，只是一张好看的图。

⇒ 所以在 4 套方案之间做选择之前，**必须先把每套方案的色值取出来、把对比度算出来**，
而不是靠眼睛看。

---

## 二、方法（可机器复现）

### 2.1 色值来源：不手抄，直接读原型

```powershell
py -3.12 tools/check_contrast.py --root .
```

脚本从 `prototype/variants/*.html` 的 `:root` CSS 变量里**读取**真实色值，
不手抄、不记忆 ⇒ 改了原型，重跑即得新结果。

| 方案 | 原型文件 | `:root` 变量 |
|---|---|---|
| `paperTerracotta` | `prototype/variants/01-paper-terracotta.html` | `--bg` `--surface` `--text` `--accent` `--on-accent` |
| `pureWhiteBlank` | `prototype/variants/03-pure-white-blank.html` | 同上 + `--surface2` `--text2` |
| `warmPaperSerif` | `prototype/variants/17-warm-paper-serif.html` | 同上 + `--surface2` `--text2` |
| `tuckDarkCalm` | `prototype/variants/18-tuck-dark-calm.html` | 同上 + `--surface2` `--text2` |

⚠️ 取的是 **`:root` 的第一次定义**（基础色板）。
`html[data-scheme=...]` 里的覆盖值是原型为「4 方案切换器」临时加的，不是方案本身。

### 2.2 对比度算法

WCAG 2.x 相对亮度公式：

```
L = 0.2126·R + 0.7152·G + 0.0722·B      (R/G/B 为线性化后的通道值)
ratio = (L_lighter + 0.05) / (L_darker + 0.05)
```

线性化：`c ≤ 0.03928 ? c/12.92 : ((c+0.055)/1.055)^2.4`（`c` 为 0..1 归一化值）

### 2.3 判定阈值（**T1，来自 Apple HIG**）

| 用途 | 阈值 | 出处 |
|---|---|---|
| 正文文字 | **≥ 4.5:1** | `docs/spec/08` §八（`hig-md/accessibility.md:60`） |
| 大字（≥18pt，或 ≥14pt 粗体） | **≥ 3:1** | 同上 `:62` |
| 非文本（图标、边框、分隔线） | **≥ 3:1** | 同上 |

## 四、⭐ 公开订正：`docs/spec/07` §3.3 里的 `≈ 4.3:1` 是错的

**订正内容**：

| 项 | 旧记录（`docs/spec/07` §3.3） | 实算值 | 判定 |
|---|---|---|---|
| `paperTerracotta` 强调色 `#AF4C37` 浅底对比度 | **≈ 4.3:1**（记为「正文级不够，只用于粗体/大字号与图标」） | **5.06:1** | ✅ **正文级合格** |

**为什么会错**：那个 4.3 是**目测估的**，不是算的。实算（WCAG 公式）结果 **5.06:1**，超过 4.5 阈值。

**订正的后果**：
1. `paperTerracotta` 的强调色**可以**用于正文级文字，不再局限于「粗体/大字号/图标」。
2. `docs/spec/07` §3.3 那张表的 `⚠️` 标记作废。
3. **不影响**「强调色 = 各方案自带」这个已拍板结论 —— 4 套的强调色全部正文级合格，
   所以「自带」这个选择在**无障碍上没有代价**。

⚠️ **旧记录保留在 `docs/spec/07` §3.3 里并标注了订正**，不偷偷改写。

## 五、4 套方案的横向对照（选型时用）

| 维度 | 纸感陶土 | 纯白留白 | 暖纸衬线 | 深色静谧 |
|---|---|---|---|---|
| 底色性质 | 暖白纸感 | 纯白 | 暖灰纸 | 近黑 |
| 正文对比度 | 15.39 | 16.83 | 12.45 | 15.99 |
| 强调色对比度 | 5.06 | 5.44 | 5.43 | **8.99** |
| 强调色饱和度感 | 中（陶土红） | 中（砖红） | 中低（赭红） | **高亮**（琥珀金） |
| 强调色 vs 正文对比 | **最弱** | 中 | 中 | **最强** |
| 深/浅 | 浅 | 浅 | 浅 | **深** |
| 系统外观约束 | 无 | 无 | 无 | ⚠️ **需强制深色外观** |
| 衬线/圆体 | 无衬线 | 无衬线 | **衬线** | 无衬线 |

### 5.1 三条选型提示（不是推荐，只是约束说明）

1. **`tuckDarkCalm` 的 `isDarkBased == true`** ⇒ 在 iOS **浅色系统外观**下不可直接用，
   必须强制深色外观或给用户提示（见 `docs/spec/07` §3.1b）。
2. **纸感陶土 vs 纯白留白 vs 暖纸衬线** 三者的无障碍表现都合格（全部 ≥ 4.5），
   ⇒ **选择依据应该落在「调性」而不是「无障碍」上**。
3. `warmPaperSerif` 是唯一带**衬线**的方案 ⇒ 若最终选它，
   `DesignSystem/Typography.swift` 需要引入衬线字族（当前 4 套共用系统 text style，不分衬线），
   **这是一个尚未实现的成本项**，选型时须知。

## 六、未验证 / 边界声明

| # | 未验证 | 说明 |
|---|---|---|
| 1 | **实际渲染的对比度** | 本文算的是**设计稿 CSS 变量**。真机上 SwiftUI 渲染是否一致（色彩管理、Display P3、Dark Mode 自动反色）**未验证** —— 本机无 Mac / 无 Swift 工具链 |
| 2 | **`paperTerracotta` 缺 `--surface2` / `--text2`** | 该方案原型没定义次级面与次级文字。补齐或明确「该方案无次级层」皆可，但**当前状态是缺失** |
| 3 | **大字阈值的具体应用** | 本文只按「正文级 4.5」判。实际 UI 里标题是否算大字（≥18pt / ≥14pt 粗体）要逐处看 |
| 4 | **状态色（ok / warn / danger）未查** | 4 套都有 `--ok` `--warn` `--danger`，但本文未纳入对比对（它们在浅底/深底上的表现需另查） |
| 5 | **原型切换器的覆盖值** | `prototype/ios/*.html` 里注入的 4 组 `html[data-scheme=...]` 覆盖值，本文**不查** —— 它们是演示用，不是方案定义 |
