## 0. 一句话结论

**iOS 26 的"好看"不是靠玻璃本身，而是靠三层结构：底层场景实拍 → 中层玻璃做介质 → 顶层信息永远绝对锐利地浮在最上层。**
一旦玻璃盖住了文字（谁在玻璃下面），可读性立刻崩；玻璃只承载"高识别度的极简动作"。

## 1. 主屏（Home Screen）—— 图标本身就是玻璃容器

### 1.1 结构事实
- **没有外层卡片**。app 图标 = 容器本身（经典连续曲率 squircle），不是"图标放在卡片里"。
- 图标内部符号（glyph）占容器 **45%–60%**。
  - 符号化图标（App Store / FaceTime / 设置 / 电话）：严格居中，四周留 **20%–25%** 等距负空间。
  - 拟物/图形类图标（时钟表盘 / 日历网格 / 相机镜头 / 地图路网）：按固有图形外扩，但仍在 squircle 内 padding 内，不溢出。
- **描边**：边缘约 **1px 物理像素**的高光微边框（rim highlight），浅白半透明反光，用于界定轮廓。
- **材质**：背景高斯模糊（backdrop blur），**无光学折射**（无边缘畸变 / 色散 / 位移）——纯"模糊 + 局部增白降暗"。
- 三种模式：
  - 全透（浅色壁纸）：图标底色半透白/浅灰，透光率约 **20%–40%**，不完全遮壁纸色相。
  - 深色模式：接近纯黑的极低透光底衬。
  - 标准浅色：除原生白底图标外，全彩实体填充。

### 1.2 壁纸上的可读性怎么保证（可抄）
1. **磨砂底衬是第一道屏障**：降低壁纸明暗对比，防止白色符号与浅色壁纸融为一体。
2. **文字用极轻微、大半径黑色漫反射投影**（不是硬阴影）—— App 名用纯白 + 柔和投影。
3. **Dock 用独立的大面积横条毛玻璃底衬**，与壁纸切断明暗关联；Search 按钮用胶囊状微型磨砂底衬 + 细描边。

### 1.3 栅格数值（可直接用）
| 项 | 实测值 |
|---|---|
| 列数 | 4 列（顶部 2 个 2×2 小组件 + 下方 4 行） |
| 屏幕左右页边距 | 略大于列间距，约列间距的 **1.1–1.2 倍** |
| 列间距 | 约单个图标宽度的 **35%–40%** |
| 图标底 → 文字顶 | 约图标高度的 **15%** |
| 文字底 → 下一行图标顶 | 与列间距视觉权重近似，**略大于横向缝隙** |

### 1.4 主次判定（Apple 自己怎么分）
- **主要**：2×2 小组件及其核心数据、图标内的彩色/半透符号、Dock 图标。
- **次要**：图标文字标签、小组件的辅助元数据（"Partly Cloudy"）、状态栏（灵动岛/时间/信号）、底部 Search 胶囊与 Home Indicator。

> **可复用判据**：主视觉承载数据与入口；文字标签只做识别，不承载信息。

## 2. Liquid Glass 的三层结构（最重要的一节）

### 2.1 结构
1. **底层**：真实场景 / 应用内容 / 波形 / 色彩。
2. **中间层**：玻璃板 —— 过滤器角色，超大半径色散模糊 + 边缘折射，形成"有物理厚度的空间阻隔"。
3. **顶层**：所有图标、文字、强调按钮 **绝对悬浮在玻璃最表层**，不受玻璃内部模糊影响，保持极致锐利。

> **这条是全篇最该抄的**：玻璃是**背景**，不是**内容的容器**。

### 2.2 嵌套与边缘
- 玻璃可以**嵌套**：大面积玻璃当"母容器"，内部再嵌更小的玻璃药丸。
- 嵌套不是简单叠加，靠**差异化透明度 + 模糊度 + 微弱内阴影**造出"嵌在凹槽里 / 浮在板上"的深度差。
- 边缘是**连续受光面**（模拟厚玻璃圆角的受光），不是 1px 机械线：迎光面通透柔白，背光面自然隐退。
- 边缘有**真实折射**：底层文字在玻璃边缘被弧形拉伸成环境光斑。

### 2.3 深浅两种模式的差异
| | 浅色模式 | 深色模式 |
|---|---|---|
| 质感 | 白水晶 / 磨砂亚克力，泛微弱白光与环境色 | 烟熏玻璃 / 高反射透镜，基底更黑更沉 |
| 阴影 | 极柔和 | 明暗反差极大，光晕聚光感强 |
| 环境色 | 通透轻盈 | **吸收并汇聚**底层环境色（绿背景在玻璃边缘折射出绿色荧光环） |

### 2.4 材质层级分化（这套设计的"主次"手法）
- **次级操作**：低饱和 + 高透光 + 冷调 → 弱化自身权重。
- **核心操作**：高饱和 + 半透 → 形成视觉锚点，明确"交互起点"。

### 2.5 玻璃的可读性妥协（Donny Wals 那张图给的解法）
1. **彻底放弃在玻璃上放长文本** —— 标题文字放在左侧纯黑实色区。
2. 玻璃**只承载高识别度的极简动作（图标）**，文字阅读与材质实验彻底分离。
3. **背景毛玻璃化**先把高频噪点抹平成低频平滑渐变。
4. **高对比单色扁平图标**（深海蓝单线条），与玻璃基底形成稳定明暗对比。
5. **内圈暗角/衬底加深** —— 玻璃中心略沉，给符号一个微弱"防眩光托盘"。
6. **主按钮提高不透明度 + 纯白高亮图标**，保证任何背景下的最高对比度。

## 4. Inset Grouped 设置式列表（最直接可抄的 iOS 结构）

### 4.1 尾部控件尺寸
| 控件 | 尺寸 | 颜色 | 距右边缘 |
|---|---|---|---|
| Chevron（`chevron.right`） | 宽 7–8pt × 高 13–14pt，Semibold/Regular | 次级灰 `tertiaryLabel` `#C7C7CC`→`#8E8E93` | **16pt** |
| 值文本 | 17pt（与标题一致）或 15pt，Regular | `secondaryLabel` | 紧靠 chevron 左 **6–8pt**；无 chevron 则右对齐 16pt |
| 对勾（`checkmark`） | 14–16pt，Semibold | 强调色（默认 `systemBlue` `#007AFF`） | 16pt |
| 开关 UISwitch | **51 × 31pt** 胶囊 | 开 `systemGreen` `#34C759` / 关中性灰 | 16pt（与 chevron 互斥） |

### 4.2 分组容器与行
| 项 | 数值 |
|---|---|
| 单行行高 | **44–52pt**（iOS 15+ 常用 **52pt** 换舒适留白） |
| 操作行行高 | 48–52pt |
| 屏幕左右外边距 | **16pt**（Pro Max 常 16 或展宽至 **20pt**） |
| 组间纵向间距 | **18–24pt** |
| 卡片圆角 | **10–12pt** |
| 分割线 | **0.5pt**；左侧缩进 16pt 或贴齐主标题起点；末行自动隐藏 |

### 4.3 它如何表达层级而不冗余（三条机制）
1. **用「空间卡片化（Chunking）」替代树状缩进**：移动端缩进会挤压文本，改用独立卡片分块 + 灰色背景槽隔离。
2. **左名词 / 右状态**：主轴严格左对齐 16pt 起点，可纵向快速扫描；副轴（右）承担全部交互反馈。
   - `纯文本 + Chevron` → 预告下一级是**深入页/选择器**
   - `Switch` / `Checkmark` → 预告**原地生效即终点**
3. **用色彩语义取代按钮边框**：行内操作剥离立体背景与描边，直接内联文字；蓝色 = 安全的新增/跳转，红色 = destructive。危险操作单独成组隔离。

## 5. Live Activity（锁屏 / 灵动岛）

### 5.1 形态与尺寸
- 轻量活动：**单行胶囊 / 矮扁卡片，高 44–48pt**。
- 复杂活动：**双行或三行大卡片**。
- 卡片圆角 **20–24pt**，与屏幕外框、Dock 曲率一致。

### 5.2 材质
- 超低饱和半透明深色磨砂，透出壁纸明暗变化。
- 边缘约 **0.5px 极细高光内描边**，在复杂暗色壁纸上勾出边界。

### 5.3 进度的表达方式
- **数字直给代替进度条**：跳动的大数字（`1:24`、`3:29`）靠字重传达"正在进行中"。
- **色彩作状态隐喻**：暖橙 = 提醒/倒数，荧光绿 = 运动中，深红底 + 队徽 = 主队归属。

### 5.4 信息密度控制
- **水平压缩**：低频操作的活动压成一行 `[图标] 3:29 [暂停键]`，纵向留给真正重信息。
- 卡片间距严格一致 **8–10pt**，宽度统一通栏。
- **分流次要数据**：运动卡片取消配速/心率/卡路里，只留时间，点按再展开。

### 5.5 三层信息分级
| 层 | 内容 | 手法 |
|---|---|---|
| **L1** | 核心指标（倒数 `1:24`、时长 `3:29`、比分 `54:63`） | 字号最大、字重加粗、纯白或高饱和功能色 |
| **L2** | 交互控件、节次时间、队徽 | 纯白/半透明圆形按钮，适中字重 |
| **L3** | 赛事名、队伍简称、文字战报 | 10–12pt，低透明度次级灰 |

### 5.6 值得抄的"克制"四点
1. **交互按钮极致退后**：去文字化 + 半透明低对比容器，不用大蓝纽/大红纽。
2. **拒绝分割线**：全靠严格 padding 与自动对齐拉开距离。
3. **大面积高亮色禁用**：荧光绿只一个小图标，橙色只一组数字，其余 80% 由白/灰/半透明黑统治。
4. **尊重系统层级**：顶部核心时钟以巨型字号半透明压底，Live Activities 在其下方自然浮动，不强行遮挡。

## 6. Six Colors 评测图的可读性判定（反例价值最高）

### 6.1 什么时候好看
- **大留白 + 暗调/纯净壁纸**（雪山、超人壁纸）：背景主体明确、色调统一，玻璃高光切边与柔和折射 = 高定科技艺术品。
- **单一功能的大控件**（全屏播放器卡片、单色大时钟）：面积大、层级少，充分展现材质光学美。
- **陀螺仪动态光影**：实机倾斜时高光与折射随角度微动。

### 6.2 什么时候崩
- **密集图标主屏**：20+ 个形态各异的玻璃图标，材质反射互相打架，**抹杀图标辨识度（glanceability）** → "摆满亚克力文具的杂乱陈列架"。
- **高对比杂乱色彩的现实壁纸**：半透明控件与高光文字瞬间融入背景，可读性灾难。

### 6.3 色彩使用观察
- 大量**放弃品牌固有色**（Slack 四色、Discord 亮紫），改用统一单色调（灰、冰蓝）。
- 色彩主要**靠壁纸透出**；播放器界面表现最佳 —— 黑色与红色壁纸微光自然渗入磨砂面板形成环境光晕。

> **结论：iOS 26 的玻璃是"背景材质"，不是"图标皮肤"。** 给每个图标套玻璃会立刻变丑。

## 7. AI 陪伴类 App 设计稿拆解（Dribbble）

### 7.1 层级结构
| 项 | 实测 |
|---|---|
| 主视觉（3D 机器人脸）占比 | **35%–40%**，位于黄金分割偏上 |
| 角色 vs 气泡权重 | 角色 **70%** / 气泡 **30%**。气泡不是全宽对话框，是极小的依附式 Tooltip（"Hey there! 👋 Need a boost?"） |
| 底部操作区 | **三件套**：左=机器人头像（切换人格/装扮）、中=蓝色呼吸圆环（语音唤醒/实时对谈）、右=三点菜单 |
| 形态定性 | **单一沉浸场景（Voice-First Immersive View）**，非列表信息流、非功能卡片阵列 |

### 7.2 做得好的
- 主次极分明，视线漏斗清晰：**看角色（建立情绪）→ 看提示语（了解意图）→ 点击/说话（发起交互）**。
- 圆润无锐角 3D 材质 + 可爱表情，天然亲和。
- 隐去键盘，用呼吸光环强化"语音优先"。

### 7.3 还差的（对我们最关键的两条）
1. **陪伴感不足 —— 定位撕裂**：玩具外壳却塞进生图 / Slack / Google Calendar 等严肃生产力能力；主屏只轻飘飘一句 "Need a boost?"，人设与功能脱节。
   - 陪伴感的核心是**记忆与上下文**。单向 Tooltip 像营销推送 / 首次引导，**没有基于时间段与历史状态的个性化表达**（"昨天那个会总结好了" / "今晚早点休息"）。
   - 没有这些，它只是"漂亮的 3D 摆件"，不是理解你的伴侣。
2. **主次承接断层**：主屏极简，但唤起后是高密度多模态卡片。**机器人去哪了？** 缩到角落 / 半透明化 / 被顶出屏幕？没有答案，沉浸陪伴瞬间瓦解。
3. **意图引导过弱**：底部三图标过于抽象；中间光环缺乏明确状态暗示（长按说话？点按唤醒？还是正在聆听？）。陪伴类 App 里过度含蓄 = "不知道该干什么"。

> **对我们的直接启示**：我们的 iOS App 必须同时解决三件事 —— ① 角色始终在，且不被人为遮挡；② 语音/文字的"正在听/正在说"状态要明确但克制；③ 主屏之外的高密度内容（历史、设置、动作库）走 **push 钻取**而不是叠层，保持"脸"永远在。
