## 二、⭐ 缺陷 #1 详记：眼睛旋转（这是「镜子原则」最硬的一块）

### 2.1 回源到固件才发现的事实

| 事实 | 出处 |
|---|---|
| rotation 施加在 **eye 容器**上（`_container->setRotation`） | `firmware/main/stackchan/avatar/skins/default/eyes.cpp:80-85` |
| 容器里同时装着**眼白与眼睑** ⇒ **两者一起转** | `eyes.cpp:32-44` |
| 容器 pivot = **容器中心**（`setTransformPivot(16,16)`，容器 32×32） | `eyes.cpp:29-30` |
| 6 情绪里 **4 个带非零旋转** | `eyes.cpp:103-122` |
| **左右眼镜像**：右眼 `setRotation(-rotation)` | `eyes.cpp:93-98` |

固件 6 情绪表（实测值）：

| 情绪 | weight | 左眼 rotation | 右眼 rotation | 左眼下发值 | 右眼下发值 |
|---|---|---|---|---|---|
| Neutral | 100 | 0 | 0 | 0 | 0 |
| Happy | 72 | +1550 | −1550 | 1550 | 2050 |
| Angry | 70 | +450 | −450 | 450 | 3150 |
| Sad | 70 | −400 | +400 | 3200 | 400 |
| Doubt | 75 | 0 | 0 | 0 | 0 |
| Sleepy | 35 | −50 | +50 | 3550 | 50 |

### 2.2 顺带记下一条容易看错的固件怪癖

`Element::setRotation`（`avatar/elements/element.h:43`）把**存储值**钳到 `0..3600`
⇒ **负角读回是 0**。但 `DefaultEyes::setRotation` 随后把**原始未钳位**的值
交给 `_container->setRotation(rotation)` ⇒ **渲染照常生效**，只是 `getRotation()` 读数失真。

这正是协议层「负角用 `3600 + θ` 表达」的原因（`docs/spec/06` §4.3）。
⇒ **Swift 侧本来就理解对了**（`AvatarGeometry.wireRotation`），**只有渲染层漏了**。

### 2.3 公开订正：「逐像素一致」的原记录需要收窄

**原记录**（spec/06 §9.2b 约束 3）：「镜像模式必须输出整数像素、无抗锯齿」。

**订正**：设备端（LVGL `transform_angle`）与 App 端（SwiftUI 矢量路径填充）
**都是抗锯齿光栅化** ⇒ 旋转眼睛的边缘**不可能逐像素相同**。

⇒ **收窄为**：镜像模式保证**几何一致**（中心点 / 直径 / 旋转角 / 眼睑偏移 / 层级 / 设备原色）；
**逐像素相同仅对未旋转元素成立**（嘴、位置，以及 rotation == 0 的 Neutral / Doubt）。

这不是放宽标准，是把「可判的」与「不可判的」分开写清楚。
已写进 `docs/spec/06` §9.2b.1（原文保留 + 订正段 + 新增约束 9）。

### 4.1 `tools/check_links.py` —— 命名空间感知的内部链接体检

**为什么需要**：人读文档能靠上下文分辨「这是我们仓的路径」还是「官方上游的路径」，**机器不能**。

**判定模型**（不靠前缀猜）：看**第二段目录是否真实存在于本仓**。

| 例子 | 判定 | 理由 |
|---|---|---|
| 「`docs/spec/07-xxx.md`」 | REPO | `docs/spec/` 是真目录 ⇒ 必须存在 |
| 「`docs/api.md`」 | EXTERNAL | `docs/api.md` 不是目录 ⇒ 上游 Ollama 的文档 |
| 「`server/api/dance/v1`」 | EXTERNAL | `server/api/` 不存在 ⇒ 官方 Go server |
| 「`firmware/main/hal/…`」 | EXTERNAL | `firmware/` 在本仓只是占位目录 |
| 「`tools/gone.py`」 | REPO | `tools/` + `.py` 扩展名亲和 ⇒ 必须存在 |
