# 87 · 韵律→身体 离线标定探针：把「情绪会不会被音频淹没」变成可判数据

> **一句话**：`docs/spec/09` §九 里长期挂着一条未验证项 ——「**情绪是否被音频淹没**」。
> 本轮用**合成韵律语料**离线跑真实管线 `server/stackchan_ai/prosody.py`，
> 把「淹没 / 可辨识 / 伪影 / 单调性 / 越界 / 带宽」全部变成**有数字的判据**，
> 并**当场抓到 1 个真缺陷**（`env` 边界补零 ⇒ **每句话第一帧嘴/眼/灯弹到满量程**），

> ⚠️ **诚实边界**：本文测的是**输出空间的可分性**，**不等于**「人能认出」——

## 二、方法（可复现）

### 2.1 语料：4 种受控韵律变体

不联网、不调真机、不用真实录音 ⇒ 每一处差异都是**人为设定**的，因果关系可追。

| 变体 | f0 轨迹 | 能量包络 | 停顿 | 用途 |
|---|---|---|---|---|
| `flat` | 恒 200 Hz | 恒 0.35 | 无 | 韵律零变化的基线 |
| `rise` | 190 → 260 Hz | 0.25 → 0.75 | 无 | 单调上行 |
| `fall` | 240 → 150 Hz | 0.70 → 0.25 | 中段 0.35 s | 下行 + 停顿 |
| `accent` | 恒 200 Hz + 3 个 +3 半音重音峰 | 起伏 | 中段 0.30 s | 重音 + 停顿 |

合成方式：**谐波合成 + 三共振峰包络**（700 / 1220 / 2600 Hz，采样率 16 kHz），
每条 2.0 s ⇒ 韵律特征由**真实**的 YIN / 能量 / 谱质心算出来，不是手填的。

### 2.2 走的是真实管线

```
合成 PCM → prosody.extract_prosody() → prosody.build_params() → prosody.compile_keyframes()
         → 0x14 关键帧 → 统计量
```

⚠️ **中间没有一步是替身**：探针直接 `import` 仓库里的 `server/stackchan_ai/prosody.py`。

### 2.3 三个度量的定义

| 度量 | 定义 | 为什么这样定义 |
|---|---|---|
| **淹没指标** | 韵律间中位距离 ÷ 情绪间中位距离 | 分子 = 换韵律带来的位移；分母 = 换情绪带来的位移。**> 1 ⇒ 韵律盖过情绪** |
| **可辨识度** | **留一韵律变体**交叉验证：训练集 = 其余 3 个变体的 18 个样本，测试 = 留出变体的 6 个样本，分类器 = 最近类心 | ⚠️ 每类只有 1 个样本时，留一最近邻**结构性全错**（见 §五.1）⇒ 必须换成「留一变体」 |
| **边界伪影** | `max \|env[:k−1] − energy[:k−1]\|` | `env` 是 dB 域的滑动平均；它与原始 `energy` 在**内部**必须逐点相等，只允许在边界因平滑方式不同而差 |

## 三、实测数据

### 3.1 淹没指标 —— 结论：**情绪没有被音频淹没**

| 特征集 | 韵律间中位距离 | 情绪间中位距离 | **比值** |
|---|---|---|---|
| 全特征（10 维） | 15.661 | 38.264 | **0.41** |
| 仅基线 3 维（`pitch_mean` / `eye_mean` / `mouth_mean`） | 9.303 | 30.855 | **0.30** |

⇒ **情绪间的位移是韵律间的约 2.4–3.3 倍** ⇒ 韵律变化**盖不过**情绪变化。
⇒ 且**只靠 3 个基线通道**（俯仰均值 / 眼睛均值 / 嘴均值）就足够区分 6 种情绪
⇒ 「情绪被音频淹没」这条**未验证项可以销账**（就输出空间而言）。

### 3.2 可辨识度 —— **83.3%**，`Happy` 与 `Doubt` 最弱

| 留出的韵律变体 | 全特征 | 仅基线 3 维 |
|---|---|---|
| `flat` | 83% | 100% |
| `rise` | 67% | 67% |
| `fall` | 83% | 83% |
| `accent` | 100% | 83% |
| **平均** | **83.3%** | **83.3%** |

混淆矩阵（全特征，24 个样本）：

| 真值＼预测 | Neutral | Happy | Angry | Sad | Doubt | Sleepy | 正确率 |
|---|---|---|---|---|---|---|---|
| Neutral | **4** | 0 | 0 | 0 | 0 | 0 | 4/4 |
| Happy | 1 | **3** | 0 | 1 | 0 | 0 | 3/6 |
| Angry | 0 | 0 | **3** | 0 | 1 | 0 | 3/4 |
| Sad | 0 | 0 | 0 | **4** | 0 | 0 | 4/4 |
| Doubt | 0 | 0 | 2 | 0 | **2** | 0 | 2/4 |
| Sleepy | 0 | 0 | 0 | 0 | 0 | **4** | 4/4 |

⇒ **Neutral / Sad / Sleepy 完全可分**；**Happy 最弱**（一半样本被吸进 Neutral 或 Sad）、
**Doubt 次弱**（被吸进 Angry）⇒ 这两对在**输出空间**里有重叠，是下一轮标定的重点。

### 3.3 ⚠️ 抓到 1 个真缺陷：`env` 边界补零 ⇒ **每句话第一帧都「弹一下」**

`server/stackchan_ai/prosody.py` 的 `env`（能量包络）用滑动平均算：

```python
env_smooth = np.convolve(env, np.ones(k_env) / k_env, mode="same")   # ← 边界补零
```

`mode="same"` 在首尾**补零**。而 `env` 是 **dB 域（负值）** ⇒
**补零 = 把边界往 0 dB 拉** ⇒ 凭空造出一个假能量峰：

| 变体 | `env[0] − energy[0]` | `env[1] − energy[1]` | 首帧 `e_norm` | 首帧嘴 weight |
|---|---|---|---|---|
| `flat` | **+10.1 dB** | +5.1 dB | **1.0（满量程）** | 39（基线 30） |
| `rise` | **+11.8 dB** | +5.8 dB | **1.0** | — |
| `fall` | **+7.2 dB** | +3.7 dB | 1.0 | 39 |
| `accent` | **+10.8 dB** | +5.4 dB | **1.0** | 39 |
| 静音 | **+96 dB**（−240 → −144） | +48 dB | 1.0 | 39 |

**后果（产品级）**：`e_norm` 饱和到 1.0 ⇒
`mouth_w = base_mouth + energyEyeGain × 45 × e_norm × gain` 直接把嘴顶到满量程，
眼睛（`energyEyeGain × 12`）与灯亮度（`energyLightGain`）同样被顶上去。
⇒ **机器人每次开口的第一个 40 ms 都会「瞪眼张嘴」，然后才收回去。**
静音时更荒唐：嘴 weight 从 30 跳到 39 再回 30（跨度 9）。

⚠️ **这类缺陷不会报错**：自检全绿、`audit` 0 问题、67 个测试全绿、门禁全绿。
**它只会在真机上看出来** —— 这正是它值得单独立一条门禁的理由。

### 3.4 修法与验证

修法 = **边界改成复制**（edge replicate），语义 =「信号在 `t=0` 之前是恒定的」，
这是平滑滤波在边界上的标准做法；**内部逐点与 `mode="same"` 完全一致**：

```python
env_pad = np.pad(env, (k_env // 2, k_env - 1 - k_env // 2), mode="edge")
env_smooth = np.convolve(env_pad, np.ones(k_env) / k_env, mode="valid")
```

| 指标 | 修复前 | 修复后 |
|---|---|---|
| 边界最大偏差 | 11.8 dB（静音 96 dB） | **≤ 0.32 dB** |
| 静音嘴 weight 跨度 | 9 | **0** |
| `flat` 首帧 `e_norm` | 1.0 | **0.0** |
| `accent` 首帧 `e_norm` | 1.0 | **0.06** |
| 67 个后端测试 | — | **全绿** |

⚠️ 两份实现**同步修改**：`server/stackchan_ai/prosody.py` 与 `tools/prosody_to_motion.py`
（后者是前者的来源实现，不同步就是新的分叉）。

⚠️ **诚实说明**：修复让**可辨识度从 91.7% 降到 83.3%** ——
因为伪影此前在**帮倒忙地提供区分度**（首帧满量程是个很好认的「特征」）。
⇒ **83.3% 才是真实的数字**，91.7% 是被伪影抬高的虚数。

### 3.5 `expressiveness` 的归因分解（**并公开订正我自己的一个错误结论**）

`expressiveness` 是**个性化组**的「表现力总量」旋钮。实测它把 `pitch_mean` 从 76.370 压到 68.118（`accent` 变体，跨度 **8.252°**）。
**这 8.25° 从哪来？** 逐项关掉再测：

| expressiveness | 全部开 | 关点头 | 关 F0 偏移 | 全关 |
|---|---|---|---|---|
| 0.00 | 76.370 | 76.370 | 76.370 | 76.370 |
| 1.00 | **70.898** | 75.468 | 71.802 | 76.370 |
| 1.50 | **68.118** | 74.984 | 69.474 | 76.370 |

⇒ 在 `e = 1.00` 处：**重音点头贡献 −4.568°（83%）**，**F0 均值偏移贡献 −0.902°（16%）**，
两者合计 −5.470°，与实测的 −5.472° 吻合。

⭐ **F0 偏移那一项与公式精确对得上**：`f0PitchGain (0.55) × f0_mean_semitone_rel (−1.6423) × gain (1.0) = −0.903°`
（`f0_mean_semitone_rel` 相对参考音高 `F0_REF_HZ = 220.0`；合成语料基准 200 Hz ⇒
`12 × log₂(200/220) = −1.642` ✓）。

⇒ **订正**（见 §五.2）：此前我把这个现象判成「`gain` 同时乘进 F0 偏移项 ⇒ 耦合缺陷」。
**归因是错的** —— F0 偏移只占 16%；真正的大头是**重音点头**（设计意图：表现力越强，点头越深），
而点头天然会把俯仰的**均值**也拉低。⇒ 这**不是缺陷**，是「表现力总量」旋钮的一阶放大。

## 五、公开订正（3 条）

### 5.1 「留一最近邻可辨识度」的第一版度量是**结构性错的**

第一版探针每类只取 **1 个样本**（4 变体 × 6 情绪 = 24 样本，每类 4 个）。
在这种样本量下做留一最近邻，**每个测试样本的最近邻必然来自同一类**
⇒ 准确率**必然是 0%**。初跑看到 0%，差点误判成「系统坏了」——
实际上分离比一直是 38~42，**系统没坏，是度量坏了**。
⇒ 换成**留一韵律变体**交叉验证后才得到有意义的数字（§2.3）。

### 5.2 「`expressiveness` 会平移俯仰基线 ⇒ 耦合缺陷」—— **归因错误**

现象是真的（俯仰均值随 `expressiveness` 移动 8.25°），
但我把它归因到「`gain` 同时乘进 F0 偏移项」是**错的**：逐项关断实测显示
**F0 偏移只贡献 0.902°（16%）**，**大头是重音点头 4.568°（83%）**（§3.5）。
⇒ **这不是缺陷**，是「表现力总量」旋钮对点头深度的正常放大。
⚠️ 若真要让俯仰均值不被表现力拉动，需要把点头做成**零均值**（点头后回补），
那是**设计改动**，不是 bug ⇒ 已登记为待定项（§六.4）。

### 5.3 修复缺陷后**可辨识度下降**（91.7% → 83.3%）—— 这是**修正**，不是退化

伪影此前在提供**虚假**区分度（首帧满量程太好认）。
⇒ **83.3% 是真实数字**。

## 六、诚实边界（没做到什么）

| # | 边界 | 说明 |
|---|---|---|
| 1 | ⭐ **输出空间可分 ≠ 人能认出** | 83.3% 只说明「6 种情绪在特征空间里分得开」。
**「人能看出小栈在表达什么」需要主观评测**，本文**没有**做 |
| 2 | ⭐ **语料是合成的，真实 TTS 未跑同口径测量** | 合成语音的共振峰/音高轨迹比真人 TTS 规则；

⇒ `e_rng = max(e_ref − e_min, 1.0)` 的 **1.0 dB 下限**在真实语音下几乎不会触发，
但**本轮未用真实 TTS 验证** ⇒ 登记为待验证项 |
| 3 | **12 颗 LED / 舵机 / 真机表现一律未验证** | 本轮全部是离线仿真；真机行为仍属未验证 |
