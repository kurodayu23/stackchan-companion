## 0. 结论速览（先读这段）

**一句话结论：陪伴型 App 好不好看，几乎完全取决于"角色是不是唯一的主角"，跟用了多少卡片、多少渐变没关系。**

1. **业界优秀案例的共同结构是 `角色大图 → 单次动作 → 极轻状态条`，而不是 `卡片列表`。** Replika / Character.AI / Talkie / aibo / LOOI / Rabbit R1 无一例外：角色脸或角色立绘占屏 15–80%，可点元素常只有 0–4 个，**六张图里五张没有底部 tab bar**。
2. **设备屏不是启动器，这是业界用真金白银验证过的。** Rabbit R1 的产品命题就是"interface without an interface"——整屏只有壁纸 + 角色，留白 **75–80%**；LOOI 更极端，屏上只有**两颗大眼 + 一条灯条**。**我们 320×240 的启动器页应该删掉。**
3. **"丑"的根源是"AI 味"三件套：纯黑 OLED 底 + 青/品红霓虹发光 + 24–28px 大圆角胶囊 + 弥散阴影堆叠。** 18 张图里 6 张中招，且**这些稿子全是深色 + 高密度 + 混搭插画**。我们反向取值：浅粉画布 + 奶油白表面 + 莓红单强调 + 16–20px 圆角 + 1px 描边。
4. **配色已经被真实验证过**：Justinmind 的强调色 `#FF5B84→#EE4266` 与我们的莓红 `#D94F78` 同族，"浅画布 + 白表面 + 唯一粉强调"是成熟配方（Heimdall / Justinmind / Apple Home 三方独立印证）。
5. **密度是有分水岭的**：被判"原型感/指挥中心"的样本，可点元素 13–43 个、留白 20–25%；被判"陪伴"的样本，可点元素 0–4 个、留白 50–80%。**我们的首页目标：可点 ≤4、留白 ≥55%、底部 tab ≤3。**
6. **底层别自创**：设置页用系统 Inset Grouped（发丝线 + 无阴影），开关/滑杆用系统控件，摇杆用开源 MIT 库。**审美主导的（画布/卡片/角色脸/气泡/图标）全部自造，非审美主导的（摇杆/BLE/动画曲线）直接复用。** 详见末节。

## 1. AI 陪伴 App 的界面

### 1.1 Dribbble "AI Companion" 概念稿（3D 角色 + 底部三键 dock）

- 原始页：https://dribbble.com/shots/26157905-Mobile-App-Design-AI-Companion
- 画布是**极浅的暖白→冷白渐变**（`#F5F7FA`–`#FFFFFF`），表面用**纯白不透明白**；圆角**极大（24–28px）**，气泡做成**全圆胶囊**。
- 分隔手段是**多层极淡弥散阴影（4–8% 透明、大模糊半径），完全没有 1px 描边** —— 这一点和我们"边框优先于重阴影"是**反向**的，必须有意识地反着做。
- 主视觉是 3D 机器吉祥物，占屏高 **35–40%**；屏幕留白 **55–60%**。
- 一屏可点元素**只有 3 个**：左圆形聊天键 / 中间发光语音球 / 右圆形更多键，加一个浮空白气泡做快捷语。
- 文字层级：主标题 28–32pt 粗体（"Your AI Companion for Everyday"），气泡微文案 12–13pt，比例约 2.5×。
- 强调色是**青蓝渐变 + 金色闪点**，只用在标题的 ✦、"AI"二字、机器人的表情发光和语音球上。
- **无底部 tab bar**，改为"浮动底部操作坞"。
- 视觉模型指出的廉价感：标题第三行只剩 "Everyday" 一个词（rag 不平衡）；**扁平 2D 气泡 vs 3D 角色材质不统一**。

### 1.2 aibo（Sony）—— 单角色 + 单目标标的极简范式

- 原始页：https://us.aibo.com/feature/feature3.html
- 这张实为 **App 图标/圆形头像**：**珊瑚粉实心圆（`#FF4B6E`）**作底，aibo 3/4 侧身插画占圆内 **75–80%**，**无描边无阴影**，靠高对比裁切分离。
- 角色本体用**米白/暖灰（`#ECE8E1`）哑光陶土质感**，关节、耳廓、眼用**深炭黑**，虹膜下缘一圈**柔和青绿**。
- 结论：**"一个圆形 + 一个角色 + 一个底色"就构成完整识别**，没有第二个元素。
- 对我们：App 图标与角色视觉语言应该同源——底色直接取我们的**樱花粉画布 / 莓红强调**。

### 1.3 Apple HIG 侧栏示例（粉彩配色 + 胶囊选中态）

- 原始页：https://developer.apple.com/design/human-interface-guidelines/navigation-and-search
- 画布是**暖粉彩（`#FED7D2` 附近）**，右侧主面板是**高饱和珊瑚红（`#F25C68`）**；选中项做成**全圆胶囊**（半径 = 行高一半，32–40px）；顶部切换是**正圆按钮**。
- **完全没有阴影、没有渐变、没有 1px 分隔线**，全部靠"纯色填充 + 留白"分层。
- 图标一律**单线（monoline），线宽 1.5–2px，圆头端点**，自始至终一致。
- 文字层级：区块标题 24–26pt 粗体深棕（`#531D19`），列表项 16–18pt 中等字重（约标题的 60–65%）。
- 留白 **50–60%**。
- 视觉模型点出的廉价感：**低饱和粉底与高饱和珊瑚面板硬碰，中间没有分隔线或柔和过渡，视觉上"打架"**。→ 对我们的教训：浅粉画布上不要直接怼一块高饱和莓红大色块，要么加 1px 描边过渡，要么降低饱和。

### 1.4 Apple Home（iOS 16）—— 系统级设备控制的信息密度基准

- 原始页：https://appleinsider.com/articles/22/07/21/hands-on-apples-home-app-in-ios-16-has-an-all-new-design
- 全屏**模糊渐变壁纸**，卡片用**磨砂玻璃（25–35% 白色填充 + 背景模糊）**；激活设备卡是**纯白不透明**以拉开层级。
- 圆角 **16–18px**（配件块）/ 12–14px（场景胶囊）。**无阴影、无 1px 描边**，靠填充对比 + 背景模糊分离。
- 一屏可点元素 **~13 个**；底部 tab **4 个**（Home / Rooms / Automation / Discover）；留白仅 **25–30%**。
- 文字层级是标准 iOS 比例：大标题 32–34pt Bold，分组标题 18–20pt Semibold，卡片标题 14–15pt，元信息 12–13pt 且降到 60% 透明度。
- 视觉模型点出的廉价感：**半透明卡上的深色文字对比度差、发脏**；**方形小卡里塞长名字导致三行折行**，显得像原型。

### 1.5 Character.AI（实机截图）—— "信息密度" 的反面教材

- 原始页：https://techcrunch.com/2023/05/31/character-ai-the-a16z-backed-chatbot-startup-tops-1-7m-installs-in-first-week/
- 画布**近黑（`#121214`–`#18181A`）**，卡片是**抬起的石墨灰（`#212126`–`#2A2A30`）**；用户气泡是**钴蓝（`#1D68BD`–`#2563EB`）**。
- 圆角 **12–16px**（消息卡）/ 10–12px（头像），**靠填充色阶分离，没有 1px 描边**；只有"Relationship Coach"那张浮起卡用了 `y6–10 / blur16–20 / opacity0.5` 的**弥散阴影**做叠压错觉。
- 聊天页里消息气泡占屏 **75–80%**；创建页角色立绘只占 **22–25%**。
- 创建页可点元素 **8 个**（返回、头像、可见性下拉、3 个编辑铅笔、更多选项、图片生成勾选）。
- 文字层级是标准 iOS 阶梯：导航标题 17–18px Medium、角色名 15–16px Semibold、表单标签 12–13px 灰色 `#8E8E93`、正文 14px、免责声明 10–11px。
- 留白只有 **20–25%**，气泡间距 8–12px，屏边距 16px —— **典型的"工具/效率"密度**。
- 视觉模型点出的廉价感：**同一信息流里混插动漫插画和照片级写实头像，视觉身份很乱**；**免责声明像网页弹条**；**右侧一排独立铅笔图标改深灰矩形，像 2010 年代安卓表单**；卡片底色橄榄绿/铁锈红/暗酒红**发浑、不精致**。
- **对我们的意义**：Character.AI 证明了"AI 陪伴"这一品类最容易滑向的方向 —— **密集、暗黑、混搭**。我们要做的正好相反。

### 1.6 Talkie（Web 版聊天 + 角色侧栏）—— 气泡配色与"角色即主视觉"

- 原始页：https://www.allaboutai.com/ai-reviews/talkie-ai/
- 聊天区是**近黑 + 暖棕径向渐变（`#0a0706`–`#241814`）**，右侧角色面板是**哑光深炭（`#161618`）**。
- **AI 气泡 = 焦糖陶土色（`#8c5839`）**，**用户气泡 = 暗石板蓝（`#2c3445`）** —— 靠**色相**而非明度区分说话人，不是靠深浅。
- 圆角分三档：主按钮/输入框/时长胶囊 **999px 全圆**，消息容器 **12–14px**，侧栏表单行 **8px**。**完全无阴影**，分层靠填充 + 竖向分割线。
- 角色是**写实 AI 生成肖像（Midjourney/Stable Diffusion realism 风格）**，在面板上半部柔和渐晕融进背景，占屏 **15–18%**。
- 可点元素高达 **~19 个**；留白 **50–55%**。
- 文字层级：角色名 "ANNA" **20–22px Bold 全大写**；区块标题 13–14px Semibold；聊天正文 13–14px Medium **全大写**；元信息 10–12px 灰 `#7e7e85`。
- 视觉模型点出的廉价感：**头像位置显示破图/未渲染的线框 SVG**；**气泡上叠半透明 "TALKIE" 水印**；**全大写聊天文案显得"吵"、像 2000 年代聊天机器人**；**纯白 Share 胶囊突兀**——它不是主流程动作却最抢眼，而真正的主动作（发送）按钮反而弱；**棕黑径向渐变发浑且有色带**。

### 1.7 本组范式小结

| 范式 | 学到什么 | 我们怎么用 |
|---|---|---|
| **角色即主视觉** | 陪伴 App 的可点元素常只有 1–4 个，角色占屏 35–60%（3D 概念稿 35–40%，aibo 图标 75–80%） | 首页让小栈的脸/立绘占上半屏，**只留 1 个主动作**（说话），其余交互收进动作表 |
| **留白优先** | 3D 概念稿留白 55–60%、Talkie 50–55%，而 Character.AI 只有 20–25%、Apple Home 25–30% | 我们的首页目标留白 **≥55%**；Character.AI / Home App 的高密度是"工具 App"范式，不是陪伴范式 |
| **浮层而非 tab 栈** | Character.AI、Talkie **都没有底部 tab bar**，导航靠顶部动作 | 底部 tab **≤3**（陪伴 / 遥控 / 设置），首页不放 tab 栏，用一个浮动主按钮 |
| **说话人靠色相区分，不靠明度** | Talkie 用焦糖陶土 vs 暗石板蓝 | 我们的气泡：小栈=**莓红系浅色**，用户=**奶油白/中性灰**，两条都保持低饱和 |
| **材质要统一** | Character.AI 混插动漫与写实头像被判定为"视觉身份混乱" | 小栈插画风格、头像、气泡、按钮**同一套材质语言**（哑光陶土 + 细线） |

### 1.8 本组要避开的坑

- ❌ **24–28px 超大圆角 + 弥散阴影堆叠** —— 这是 Dribbble "AI 味"的标准配置；我们要**16–20px 圆角 + 1px 描边**，与 02 的令牌表一致。
- ❌ **青蓝紫渐变 + 发光球** —— "AI 感"来自冷色渐变和光晕。我们的强调色是**莓红**，不要引入青蓝发光。
- ❌ **暗黑 + 高密度 + 混搭插画** —— Character.AI 实机就是这一组合，视觉模型直接判为"不精致、像原型"。我们走**浅色 + 低密度 + 单一插画风格**。
- ❌ **标题孤字行（orphan）**、**扁平元素与 3D 角色混搭** —— 视觉模型在最优的稿子里也指出了这两个问题，说明即使做得好也容易踩。
- ❌ **全大写文案**、**气泡上叠水印**、**破图占位**、**次要动作按钮比主动作更抢眼** —— Talkie 实机四连坑，主次关系没做对。
- ❌ **发浑的卡片底色**（橄榄绿/铁锈红/暗酒红 + 棕黑径向渐变）—— 低饱和不等于脏，脏是因为**色相不统一且叠加渐变**。

### 1.9 "AI 味"概念稿标本（Dribbble / Figma 套件）—— 我们要**反向**照抄的三张

> 这一节是最重要的避坑清单。AI 陪伴 App 的**概念稿**（不是实机）几乎形成了固定套路，用户说"丑得要死"大概率就是撞在这套套路上。
> 三个标本分别代表：**浅色但依然很 AI**、**深色霓虹**、**深色霓虹 + 玻璃拟态**。

**标本 A：AI Companion（Victoria Grinevich, Dribbble）** — https://dribbble.com/shots/27613774-AI-Companion-Mobile-App-Design

**标本 B：AI Character Chat Redesign（Dribbble）** — https://dribbble.com/shots/27766990-AI-Character-Chatbot-Companion-Mobile-App-UI-Redesign

**标本 C：AI Voice & Chat Assistant（Figma 套件）** — https://www.figma.com/community/file/1654936423525879297/ai-voice-companion-mobile-app-free-pro

| 套路特征 | 实测值（三个标本一致） | 我们的反向取值 |
|---|---|---|
| 画布 | **纯黑 OLED**（`#090A0F` / `#060813`） | **樱花粉画布** `#F1DFE5` |
| 主色 | **青 + 品红 + 电光蓝三色霓虹**（`#00D2FF` / `#B026FF` / `#2F6BE8`） | **莓红 `#D94F78` 单色** |
| 圆角 | 卡片 **24–28px**，按钮/胶囊 **999px** | 卡片 **16–20px**，胶囊按需 |
| 分隔 | **弥散外发光（neon bloom）+ 1px 10–15% 白内描边**，无实体阴影 | **1px 实色描边 + 极淡阴影**，无发光 |
| 主视觉 | 3D 发光球体 / 云朵 blob / 霓虹轨道球，占屏 **30–45%** | 小栈占屏 **35–40%**，但**哑光陶土**不发光 |
| 底部导航 | 悬浮玻璃药丸 **3 tab** 或 **5 tab + 中间发光 FAB** | **≤3 tab**，中间是**莓红实心**按钮，不是发光环 |
| 可点元素 | 创建/详情页 **13 个** | 首页 **1 个主动作**，其余收进二级 |
| 留白 | 35–40% | **≥55%** |

**视觉模型明确指出的廉价感（可直接当评审清单用）**

- ❌ **"glow-fi"过度**：背景弥散光晕在非 OLED 屏或白天户外会显脏、显噪。
- ❌ **微文案对比度不合格**：trait 胶囊小字、引导页副标题普遍低于 WCAG AA。
- ❌ **风格互斥**：写实 3D 角色旁边放扁平 2D emoji 行、扁平贴纸徽章；Replika 里"写实 3D 头像 + 手绘 doodle 徽章"并置被判为"身份冲突"。
- ❌ **悬浮 dock 压住内容**（第一张图底部卡片被 dock 截断，没有渐变遮罩）。
- ❌ **文案都没校对**（标本 B 出现 "Your Copmanions" 拼写错误）—— 概念稿常是 AI 生成未验收稿，**不能当规范抄**。
- ❌ **非主流显示器上不成立**：这些稿子全按 OLED 深黑调校。

## 2. 桌面机器人 / 硬件伴侣 App

> 本组是**最能决定我们方向**的一组：它回答"设备端那块 320×240 到底该显示什么"。

### 2.1 Rabbit R1 —— "没有界面的界面"

- 原始页：https://wccftech.com/rabbit-r1-runs-android-under-the-hood/ ・ 设计分析：https://uxdesign.cc/rabbits-r1-takes-a-shot-at-creating-an-interface-without-an-interface-747b7b2ef713
- **整屏只有一张全幅渐变壁纸**（顶部暖金 → 上三分之一暮紫 → 下半段去饱和石板灰蓝），**没有任何内容卡片**；唯一实体界面是底部 Google 搜索胶囊（`#F1F3F4`，全圆）。
- 前景元素只占屏 **20–25%**，**留白 75–80%** —— 全屏壁纸即"主视觉"。
- 可点元素 ~14 个（Android 启动器：日期挂件 + 若干 App 图标 + 4 槽 dock + 搜索胶囊），但**结构上完全"无界面"**。
- 文字层级：日期 "Tue, Apr 30" 是唯一主文案（18–20sp Regular 白字带柔投影），图标标签 11–12sp，**dock 标签直接省略**。
- 强调色**不是主题色，而是 Google 四色**，只出现在默认图标上。
- 视觉模型点出的廉价感：R1 Launcher 图标**圆角矩形塞在强制圆形容器里，双框叠套**；图标文字带投影显得**过时**。
- **对我们的意义（关键）**：Rabbit R1 的产品命题就是"interface without an interface" —— **它证明设备屏可以只是氛围 + 角色，不需要装 App 图标。** 我们在 04/02 文档里纠结的"启动器页"，业界答案是"**不要做**"。

### 2.2 LOOI —— "脸就是界面"

- 原始页：https://looirobot.com/products/looi-robot
- 画面主体是**两台桌面陪伴机器人**（深石墨黑 + 暖白），坦克履带底座，**手机形态的横屏显示条**上画着表情脸。
- 表情词汇极简：**深黑 OLED 面板上两颗超大青色发光圆眼**，加上底座上的**横向青色状态灯条**。**没有 UI 卡片、没有容器框、没有 1px 描边、没有数字阴影**。
- 机器人占屏 **55–60%**；留白 40–45%（上半部虚化的暖米色室内景 + 浅色台面）。
- 可点元素 **0 个** —— 这是宣传主视觉，不是功能屏。
- 强调色分工很干净：**暖橙**只用在标题 "A New Kind of Friend ." 的 "New" 和句号；**青色**只用在眼睛和机身灯条。
- 视觉模型点出的廉价感：标题 "Friend ." **句号前多了空格**（排版瑕疵）；贴上去的汉堡/饮料**卡通贴纸质感与整机渲染不匹配**。
- **对我们的意义（关键）**：LOOI 证明**"两颗大眼 + 一条灯带"就是一台陪伴机器人的全部表达**。我们 320×240 屏 + 12 颗 RGB LED 的硬件条件**完全够用**：屏上放脸，LED 做呼吸/情绪延伸。**不要在设备屏上放图标网格。**

### 2.3 Home robot control（Cuberto, Dribbble）—— "遥控页"的结构原型

- 原始页：https://dribbble.com/shots/6522152-Home-robot-control-app-design
- **三屏结构**：① onboarding 全身高举安卓机器人占屏 55–60% + 单一 "Start Now" 滑动 CTA；② dashboard 半身机器人被圆形 HUD 环框住占上部 35% + 数据卡；③ **摄像头视角：16:9 圆角实时画面占屏 ~40%，下方是方向操控**。
- 画布是深午夜蓝（`#0A1938`–`#061026`）+ 青色径向渐变 + 科幻 HUD 线框；卡片是**钴蓝线性渐变（`#1644B8`→`#0E2A72`）**，圆角 **20–24px**，靠 **1px 半透明内描边**（border glow）分离，**几乎没有弥散阴影**。
- dashboard 可点元素 **13 个**；留白仅 **20–25%** —— 典型"指挥中心"密度。
- 文字层级：问候语 18–20pt Semibold → 区块标题 14–15pt Medium → 卡片标签 13–14pt Semibold → 关键遥测值 **22–24pt Bold**（如 76%）→ 元信息 10–11pt 低对比淡紫 `#9FB3DE`。
- 强调色是**暖橘 `#FF9500`**：只用在 Start Now 滑块、头像环、开关开启态、中间 FAB `+`、以及**遥控页中央的"Move"摇杆按钮**。
- 视觉模型点出的廉价感：**早期 2010 年代素材库式科幻 HUD**（透视网格、圆形仪表盘）；**同一 App 里 3D 写实室内渲染与 2D 卡通机器人混用**；**自造胶囊开关（旋钮里有凹 "-" 号）违反 iOS UISwitch 规范**；白字压在饱和钴蓝渐变卡上**多处低于 WCAG AA**。
- **对我们的意义**：这一屏三屏结构里，**第 ③ 屏（摄像头 40% + 方向摇杆）就是我们 App"遥控页"该抄的骨架**；但配色与"HUD 科幻"必须全部丢掉，改成浅粉画布 + 莓红摇杆 + 奶油白卡。

### 2.4 aibo（Sony）—— 品牌色即角色

- 原始页：https://us.aibo.com/feature/feature3.html
- 见 §1.2：珊瑚粉实心圆 + aibo 侧身插画占圆内 75–80%，米白哑光陶土 + 深炭黑关节 + 虹膜下缘青绿。
- **对本组的意义**：aibo 把"机身配色"和"App 视觉"统一成一套 —— 粉圆 + 哑光白 + 深色细节。我们可以照此把**樱花粉画布 / 奶油白表面 / 莓红强调 / 深炭色五官**定为全链路色板（设备屏与 App 共用）。

### 2.5 本组范式小结

| 范式 | 学到什么 | 我们怎么用 |
|---|---|---|
| **设备屏不做启动器** | Rabbit R1 整屏只有壁纸 + 角色，界面元素占 20–25%，留白 75–80% | **删除设备端"应用启动器"这一页**，320×240 只承担：脸 + 一个状态 + 一个动作入口 |
| **脸 = 界面** | LOOI 只有两颗大眼 + 一条灯条；aibo 一个圆 + 一个角色 | 320×240 的视觉主体 = 小栈的**表情脸**（占屏 50%+）；12 颗 RGB LED 作为**情绪延伸**（呼吸/眨眼/回应），不是装饰 |
| **遥控页三段式** | Cuberto 第 ③ 屏：摄像头画面 40% + 方向操控 + 单色强调色 | 我们的遥控页 = **实时画面（≤40%）+ 一个莓红摇杆 + 一条状态条**；不要 13 个可点元素 |
| **一张屏一个概念** | LOOI / Rabbit R1 的界面元素少到可以一句话说完 | 设备屏同屏可点元素 **≤3**；App 端首页主动作 **1 个** |

### 2.6 本组要避开的坑

- ❌ **在设备屏上摆 App 图标网格** —— Rabbit R1 的教训相反：设备屏是"陪伴面"不是"功能面"。
- ❌ **强光发光眼在非 OLED 小屏上糊成一团** —— LOOI 的眼睛靠 OLED 对比度；我们的 320×240 不是 OLED，**眼睛应该是"深色底 + 白色/莓红高光"，不是"青色辉光"**。
- ❌ **卡通贴纸叠在精细渲染上**（LOOI 的汉堡/饮料）—— 角色所有附属物必须同材质同风格。
- ❌ **图标容器双框**（Rabbit R1 Launcher 圆角矩形塞进圆形）—— 自适应图标只保留**一种**遮罩形状。
- ❌ **正文带投影**（Rabbit R1 图标标签）—— 现代做法是 tonal 材质或纯色，不用投影扛可读性。
- ❌ **素材库式科幻 HUD**（透视网格、圆形仪表、全息环）—— Cuberto 被明确判为"2010 年代素材感"。
- ❌ **同一 App 内混用 3D 写实渲染与 2D 卡通角色** —— 艺术方向必须单一。
- ❌ **自造开关控件**（旋钮里塞符号）—— 用系统 `UISwitch` / SwiftUI `Toggle`，不要自绘。
- ❌ **遥控页做成"指挥中心"**（13 个可点、留白 20–25%）—— 那是"设备管理"范式，不是"陪伴"范式。

## 3. Apple 极简 + 粉彩 / 柔和风格

### 3.1 智能家居 App（Justinmind · 浅色底 + 粉强调）—— **强调色已经验证过我们想要的方向**

- 原始页：https://www.justinmind.com/ui-design/ios-app-design
- 画布是**极柔和的冷薰衣草白（`#F5F6FB`）**，卡片是**纯白（`#FFFFFF`）**；顶部容器是**皇家紫→紫罗兰线性渐变（`#5B64E8`→`#7F53E2`）**。
- 圆角 **16–20px**，靠**冷色低透明弥散阴影（blur 15–20px、Y 4–8px）**分离，**卡片无 1px 描边**。
- 图标一律 **monoline 矢量描边，线宽约 1.5pt、圆头端点**，装在**淡色圆形色块底**里 —— 与 §1.3 Apple HIG 侧栏的观察完全一致。
- 文字层级：导航标题 20–22pt Semibold → 区块标题 15–16pt Semibold 深板岩蓝 `#262646` → 区块操作链接 11–12pt 灰蓝 → **指标数字 22–26pt Medium/Bold**（`24°C`、`69%`）→ 卡片标题 12–13pt → 元信息 10–11pt 浅灰。
- **强调色是珊瑚粉→玫红渐变（`#FF5B84`→`#EE4266`）**，只用在：选中态底色、温控圆弧的激活起点、风速滑杆的激活轨道与滑块。
- 留白 30–35%（dashboard）/ 45–50%（详情页）；dashboard 可点元素 **18 个**，底部 **4 tab**。
- 视觉模型点出的廉价感：**白字压在亮鲑鱼粉按钮上、`avg house temp` 淡灰压白底，两处都不过 WCAG AA**；**"Smart Home" 幽灵大字水印**像未完工的稿子；**彩色投影（粉色光晕）**是 2010 年代末"soft UI / 新拟态"套路，在低对比屏上显脏。

> **对我们的直接价值**：这套的**强调色 `#FF5B84`→`#EE4266` 与我们要用的莓红 `#D94F78` 是同一族**，说明"**粉红做唯一强调色**"在真实产品里站得住。而它被判为廉价的三点（白字压浅粉、幽灵水印、彩色投影），正好是我们的三条禁令。

### 3.2 Apple Home（iOS 16）—— 系统级浅色 + 毛玻璃

见 §1.4。关键数据：毛玻璃卡（25–35% 白 + 背景模糊）、激活卡纯白不透明、圆角 16–18px、**无阴影无描边**、留白 25–30%、4 tab、~13 个可点元素、暖黄 `#FFD60A` 只用于"灯开着"的状态指示、琥珀 `#FF9500` 只用于 tab 选中。
- 视觉模型点出的廉价感：**半透明卡上的深绿/深灰文字发脏、对比度差**；**方形小卡里塞长名字导致三行折行**，像原型。

### 3.3 本组范式小结

| 范式 | 学到什么 | 我们怎么用 |
|---|---|---|
| **"浅画布 + 白表面 + 一个粉强调" 是成熟配方** | Justinmind `#F5F6FB` + `#FFFFFF` + `#FF5B84`；Heimdall `#F0F4FC` + `#FFFFFF` + `#5C8DF6`；Apple Home 背景模糊 + 白卡 + 暖黄 | 换成我们的：**樱花粉画布 `#F1DFE5` + 奶油白表面 `#FFFFFF` + 莓红 `#D94F78` 唯一强调**；结构照抄，价值照抄，色相照抄 |
| **monoline 图标 + 淡色圆底** | 1.5pt 圆头单线图标，装在淡色圆形色块里（Justinmind / HIG 侧栏 / Apple Home） | 图标统一 1.5–2pt 单线、圆头；**统一线宽**，禁止混用填充/描边/假 3D |
| **强调色只出现在"当前状态"上** | Apple Home 暖黄只给"灯开着"；Justinmind 粉只给"选中/激活"；RoboPilot 荧光绿只给开关开 | 我们的莓红只给：**主动作按钮、当前选中项、进行中状态**。不要给普通文字上色 |
| **数字要比正文大很多** | Justinmind 指标 22–26pt vs 元信息 10–11pt（≈2.3×）；RoboPilot KPI 26–28pt vs 11–13pt | 电量/温度/亮度这类数值直接给大号粗体，与正文明确分层 |

### 3.4 本组要避开的坑

- ❌ **浅粉底上压白字 / 淡灰字** —— Justinmind 两处 WCAG AA 不合格。**强调色做底色时，字必须够深**；浅粉底上的正文用深炭色，不用白。
- ❌ **彩色投影（pink glow）** —— "soft UI / 新拟态"遗留，2026 年看是旧感。
- ❌ **幽灵大字 / 大字水印做背景**（"Smart Home"）—— 未完工感。
- ❌ **磨砂卡上放深色文字** —— Apple Home 实测"发脏"。要毛砂就放图形，别放长文。
- ❌ **小方卡塞长名字导致三行折行** —— 标签要么缩写、要么换布局。
- ❌ **渐变顶部容器 + 大面积紫** —— Justinmind 顶部那一条渐变在粉色体系里会打架；我们的顶部应该是**纯色浅粉**，渐变最多用在 2 个 RGB LED 灯效上。

## 4. iOS 设置页 / 系统级界面组织

### 4.1 iOS 26 Inset Grouped（learnui.design 规范图）—— **设置页的标准答案**

- 原始页：https://www.learnui.design/blog/ios-design-guidelines-templates.html
- 画布是 **iOS 标准分组底色（`#F2F2F7`）**，单元格容器**纯白（`#FFFFFF`）**。
- 圆角 **10–12px**（原生 Inset Grouped 观感）。**分离完全靠明度对比（白 vs 浅灰画布），没有阴影**；组内行之间用**一条 1px 细发丝分隔线，且缩进对齐文字左边距**。
- 一屏 11 个可点行：导航行 / 选择器行 / 单选项 / 开关 / 行内文字按钮 / 破坏性按钮。
- 文字层级：**主行文字与右侧详情值同为 17pt**（正文尺寸），靠**颜色**区分（主 `#1C1C1E` 近黑，详情 `#8E8E93` 灰，右对齐 + chevron）；**不用缩字号**做次级。
- 强调色严格分工：**系统蓝 `#007AFF`** = 选中勾 + 主文字按钮；**系统绿 `#34C759`** = 开关开启；**系统红 `#FF3B30`** = 破坏性；**中性灰 `#C7C7CC`** = chevron + 关闭态轨道。**四个色各有唯一职责，不混用。**
- 留白 35–40%；图标为标准原生矢量（细发丝 chevron、单线勾、扁平开关滑块）。
- 视觉模型点评：无原生视觉缺陷，严格符合现代 HIG Inset Grouped；唯一问题是**这张图把日历元数据和家长控制混在一起，IA 不连贯** —— 教学图而已。

### 4.2 经典 iOS 分组表（Apple 官方旧版规范图）—— **结构活下来了，皮死了**

- 原始页：https://developer.apple.com/library/archive/documentation/UserExperience/Conceptual/TableView_iPhone/TableViewStyles/TableViewCharacteristics.html
- 结构：**每个分类一个独立圆角容器**（首尾单元格外角 **8–10px**，组内中间行直角）；**组与组之间靠画布留白分隔**；**组内行之间 1px `#D1D1D1` 发丝线**；容器外框 1px 细描边 + 极淡内外阴影。
- 列表占屏 75–80%；可点元素 10–11 个；底部 4 tab。
- 视觉模型点出的过时之处：**竖条纹底纹（iOS 7 之前）**、**高光玻璃质感（Aqua 时代）**、**浮雕文字（导航标题带投影、区块标题带白底高光）**、**粗灰 chevron**、**非 Retina 锯齿**。
- **结论**：这张 2008 年的图里，**唯一还值得留的是"分组容器 + 行间发丝线 + 组间留白"这套骨架；高光、浮雕、条纹底全部作废。**

### 4.3 本组范式小结

| 范式 | 学到什么 | 我们怎么用 |
|---|---|---|
| **Inset Grouped 是设置页唯一正解** | 浅灰画布 + 纯白容器 + 10–12px 圆角 + 行间 1px 发丝线（缩进对齐文字）+ 组间留白 + **无阴影** | 我们的设置页直接用 SwiftUI `List` 的 `.insetGrouped`，只换主题色：画布樱花粉、容器奶油白、发丝线用莓红 12% 透明度 |
| **主文字与详情值同号，靠颜色分** | 17pt 主文 + 17pt 灰详情（`#8E8E93`）右对齐 + chevron | 不要给次级信息缩字号，用**灰度**降级 |
| **颜色各有唯一职责** | 蓝=选中/主按钮，绿=开启，红=破坏性，灰=导航 | 我们的版本：**莓红=当前选中/主动作**，绿=在线/已连接，红=破坏性/断开，灰=导航与次级 |
| **破坏性操作单独成组、放在最后** | learnui 图里 "Turn off Screen Time" 独占末位 | "恢复出厂 / 解绑 / 清空记忆" 必须独立分组、红色、置于页面末尾 |
| **底部 tab ≤4 且只在一级** | 旧规范 4 tab、Home 4 tab | 我们一级页面 **3 tab**（陪伴 / 遥控 / 设置）；二级页面**隐藏 tab**，改用导航栏返回 |

### 4.4 本组要避开的坑

- ❌ **用高光/浮雕/玻璃质感做分组** —— 那是 2008 年 Aqua 皮肤，现在看是"仿古"。
- ❌ **自定义分组卡 + 重阴影** —— 系统原生 Inset Grouped 已经是"无阴影 + 明度对比"，再叠阴影只会脏。
- ❌ **组内用阴影分隔行** —— 发丝线 + 留白是正解，阴影会把列表切碎。
- ❌ **次级信息靠缩小字号** —— 同号 + 降灰度，符合 Dynamic Type。
- ❌ **设置项语义混装**（learnui 图里日历元数据 + 家长控制混排）—— 这是 IA 问题不是视觉问题，但同样致命。
- ❌ **二级页面还留着底部 tab** —— 层级一深，tab 就成了干扰。

## 5. 设备控制 App（舵机 / 摄像头 / 实时）

### 5.1 Heimdall 机器人车遥控（**浅色系最佳参考**）

- 原始页：https://dribbble.com/shots/19064197-Mobile-application-for-remote-control-of-the-Heimdall-robot-car
- **这是本次调研里唯一与我们目标色系同向的样本**：演示底板是**冰蓝/淡紫（`#F0F4FC`）+ 细连接线与节点**，App 画布是**淡灰蓝白（`#F5F8FD`）**，卡片是**纯白（`#FFFFFF`）** —— 正是"浅色画布 + 白表面"的经典三层。
- 圆角：内层指标卡 **16–20px**，英雄横幅与设备框 **24–28px**。**分离手段是纯弥散低透明阴影（Y=0、纯模糊），卡片和容器都没有 1px 描边**。
- 主视觉：onboarding 的机器人吉祥物占屏 **35–40%**；dashboard 的 "Camera Heimdall" 蓝色英雄卡占 **20–25%**，下面是 2×2 指标卡。
- 可点元素 **~11 个**；留白 **45–50%**。
- 文字层级：导航标题 20–22pt Bold 深炭 `#1E2432` → 区块标题 15–16pt Medium → 设置分类用**大写加字距的 11–12pt 灰字** → 卡片标题 13–14pt Medium → 正文 12–13pt 灰蓝 `#7A869A`。**层级主要靠字重与明度差，而不是字号断层。**
- 强调色是**柔和长春花蓝（`#5C8DF6`–`#6E9CFF`）**：只用在英雄卡填充、单色图标底容器、圆形 FAB、开关开启态、机器人身体装饰 —— **一处不漏地统一使用，没有第二个强调色**。
- 角色是**扁平矢量卡通 + 轻微 2.5D 渐变**：圆润造型、超大眼、极简关节、暖黄推进环。
- **没有底部 tab bar**，改为**浮动底部操作坞 + 居中大圆相机按钮（FAB）**，两侧快捷项在磨砂模糊下探出。
- 视觉模型点出的廉价感：**英文微文案语法生硬**（"With the help of a video camera, we can track the movement of the robot"）；底部模糊元素**没有交代是什么**（是信息流？抽屉？导航？），只顾好看不顾可用。
- **对我们的意义**：这一张是**"浅粉画布 + 奶油白卡 + 单一莓红强调 + 浮动 FAB"**整套语言的现成骨架，可以直接换色。

### 5.2 RoboPilot（自主机器人控制）—— 强调色分工与密度

- 原始页：https://dribbble.com/shots/26270940-RoboPilot-Autonomous-Robot-Control-App
- 画布深午夜蓝（`#0A1128`–`#0E1A38`），卡片深板岩蓝（`#142044`–`#1B2A59`）；**选中卡用青→电蓝渐变（`#00A3FF`→`#0070F3`）**。
- 圆角 **18–22px**；**靠表面色差 + 1px 10–15% 透明描边**分离，没有传统阴影，"阴影"是青色轮廓光。
- 3D 机器人主视觉占屏 **35–40%**；可点元素 **~14 个**；留白 **20–25%**（典型的仪表盘密度）。
- 强调色**分三层**：`#00E5FF` 电青（FAB、主 CTA、选中卡）、`#B9F73E` 荧光柠檬绿（**仅**开关开启态与充电柱状图）、`#FF4D4D` 珊瑚红（**仅**摄像头页的 "Live" 指示点）。
- 底部导航：**只有 2 个 tab（Home / Settings）+ 中间凸起的大 FAB**，比常见的 4–5 tab 克制得多。
- 视觉模型点出的廉价感：**任务卡里嵌的纯黑高对比开关显得粗糙**；**背景科幻房间插画与前景状态图标打架**；**自绘 PTZ 方向盘与底部 sheet 对比度过低**，实际用会看不清。

### 5.3 PanTiltZoom（真实在售的 PTZ 控制 App）—— **"设备控制"的密度反面**

- 原始页：https://www.pantiltzoom.cam/
- 画布**哑光深灰（`#242424`–`#2B2B2B`）**，控件格**中深工业灰（`#3D3D3D`–`#545454`）**，整体是广播级"硬件模拟器"观感。
- 圆角 **0px（全部直角）**，格与格之间用**1px 深灰硬描边**分隔，**没有阴影、没有浮起卡片**，整个界面是**边到边的平铺矩阵**。
- 上半屏 **50%** 是 6×4 的预设/信号源矩阵（16 个预设缩略图 + 8 路摄像机选择）；下半屏 **50%** 是硬件操控区，其中那个**拟物 PTZ 云台摇杆单独占 18–20%** 的屏面。
- **可点元素 41–43 个**；留白 **<5%**；**完全没有导航栏、区块标题、底部 tab** —— 所有功能并发堆在一屏。
- 文字层级**几乎没有变化**：所有标签一律 10–12pt 中性灰白居中；对比度极低。
- 强调色：tally 绿 `#00D800`/`#00FF00`（活动机位）、电蓝 `#0080FF`（旋钮弧段指示位置/速度）、纯白（激活的分段控件）。
- 视觉模型点出的廉价感：**金属推子与摇杆用重斜角 + 2008 年拉丝金属渐变，和旁边的扁平矢量图标风格打架**；**"网页安全绿" `#00FF00` 在灰底上刺眼**；**Camera 2 按钮的白色渐变像 iOS 4 的 Aqua 按钮**；**1px 灰线划出的编号空格像未上装的 Windows Forms 原型**。

> **对我们的意义**：PanTiltZoom 证明**"真实设备控制 App"天然会长成控制台**，因为它服务于专业操作员。**我们不是专业操作员** —— 我们要做的是"陪用户逗一只小机器人"，因此**只能取它的"摇杆这一个控件"，其余全部舍弃**。它同时提醒我们：**摇杆这类拟物控件一旦用金属/斜角质感，就会和扁平图标打架** —— 我们的摇杆应该是**扁平 + 1px 描边**的。

### 5.4 本组范式小结

| 范式 | 学到什么 | 我们怎么用 |
|---|---|---|
| **浅色三层：画布 / 白表面 / 单一强调** | Heimdall：`#F0F4FC` 底 + `#F5F8FD` 画布 + `#FFFFFF` 卡 + 一个 `#5C8DF6` | 直接换色为 **樱花粉画布 + 奶油白表面 + 莓红强调**，结构照抄 |
| **浮动 FAB 取代底部 tab** | Heimdall / RoboPilot / Rabbit R1 都没有传统 4–5 tab | 我们的底部：中间一个**莓红实心大圆 FAB**（主动作），左右最多 2 个文字/图标项 |
| **强调色严格三色分工** | RoboPilot：主色=动作、荧光绿=开启态、珊瑚红=Live | 我们：莓红=主动作、**状态绿只给"在线/已连接"**、警示色只给异常 |
| **遥测数字要比正文大很多** | RoboPilot KPI 26–28pt Bold vs 元信息 11–13pt（≈2:1） | 电量/亮度等数值直接给大号粗体，不要和正文同号 |

### 5.5 本组要避开的坑

- ❌ **仪表盘密度**（14 个可点、留白 20–25%）—— 设备管理 App 范式，不是陪伴范式。
- ❌ **自绘开关 / 摇杆对比度不足**（RoboPilot 的黑开关、PTZ 方向盘压底 sheet）—— 用系统控件，或保证控件与背景明度差 ≥ 3:1。
- ❌ **背景插画与前景状态打架** —— 要么纯色画布，要么插画只在角色区，不进内容区。
- ❌ **强调色超过 3 种** —— RoboPilot 已经用满 3 种，再加就乱。
- ❌ **只顾好看不顾可用**（Heimdall 底部模糊元素来路不明）—— 每个视觉元素都要能回答"它是什么、能点什么"。

## 6. "丑"的常见模式（我们要避开的坑）

> 本节是**在 18 张图上被视觉模型逐条点名**的问题汇总，不是通用建议。每条后面括注出处，可直接当评审 checklist 用。
> 与 06 文档第 5 节（50 条负例清单）互补：**06 是规则化清单，本文是"这些坑在真实业界产品里长什么样"**。

### 6.1 AI 味三大件（出现频率最高：18 张里 7 张深色底，其中 4 张叠加霓虹辉光）

| # | 坑 | 实测证据 | 我们怎么避开 |
|---|---|---|---|
| 1 | **纯黑 OLED 底 + 青/品红/电蓝霓虹三色发光** | AI Character Chat 概念稿（`#090A0F` + `#7FE5B4`/`#2F6BE8`）、AI Voice Companion Figma 套件（`#060813` + `#00D2FF`/`#B026FF`/`#2563EB`）、RoboPilot（`#0A1128` + `#00E5FF`/`#B9F73E`）、Cuberto Home robot（`#0A1938` + 青色 HUD）。另有 3 张深色但**无霓虹**：Character.AI（`#121214` + 钴蓝）、Talkie（`#0a0706` + 焦糖陶土）、PanTiltZoom（`#242424` 工业灰） | 浅粉画布 + 奶油白表面 + 莓红单强调，**全局禁用冷色霓虹与发光** |
| 2 | **大圆角 + 999px 胶囊 + 弥散阴影堆叠** | 24–28px 圆角（AI Character / Echo / Figma 套件）、全圆胶囊按钮、多层 4–8% 弥散阴影；**即使浅色的 AI Companion 概念稿也是 24–28px + 纯弥散阴影无描边** | 卡片 **16–20px**、按钮按需、分隔靠 **1px 描边**，阴影只留一层极淡 |
| 3 | **"glow-fi" 光晕堆叠** | 背景弥散光晕、Cuberto 的全息环、RoboPilot 的轮廓光、Justinmind 的粉色光晕、AI Companion 底部发光语音球 | 光效只允许出现在**设备端 12 颗 RGB LED** 上，App 端零发光 |

> **注意一个反直觉的事实**：AI 味**不是"深色专属"**。本次收到的浅色 AI 概念稿（AI Companion，奶油白底 + 暖光）照样中招 —— 中招的是**超大圆角 + 无描边的弥散阴影 + 发光球 + 3D 黏土角色 + 巨大标题**这一整套。所以"换成浅色"本身**救不了**，必须连圆角档位、阴影策略、光效一起改。

### 6.2 信息密度失控

- **Character.AI 留白 20–25%、Apple Home 25–30%、RoboPilot 20–25%、Cuberto 20–25%、PanTiltZoom <5%** —— 这五张全部被判为"密集 / 原型感 / 指挥中心"。
- PanTiltZoom 一屏 **41–43 个可点元素**，Justinmind **18 个**，RoboPilot **14 个**，Cuberto **13 个**，Character.AI 创建页 **8 个**。
- **对照**：Talkie 留白 50–55%、Heimdall 45–50%、Replika 日记页 50–55%、Rabbit R1 **75–80%**、AI Companion 概念稿 **55–60%** —— 这几张才是陪伴该有的密度。
- ❌ **我们的首页可点元素 ≤4，留白 ≥55%。**

### 6.3 风格互斥（角色/插画层面）

- Replika：**写实 3D 头像 + 手绘 doodle 徽章**并置 → 判为"身份冲突"。
- Character.AI：同一信息流**混插动漫插画与照片级写实头像** → 判为"视觉身份混乱"。
- Echo AI：3D 霓虹角色旁放**扁平 2D emoji 行** → 判为"风格割裂"。
- Cuberto：同一 App 内**3D 写实室内渲染 + 2D 卡通机器人** → 判为"艺术方向不一致"。
- LOOI：**低质通用贴纸**（汉堡/饮料）叠在精细渲染的机器人上 → 判为"素材质量不匹配"。
- ❌ **小栈只有一套插画/渲染语言，附属物（emoji、贴纸、图标）必须同源。**

### 6.4 主次关系颠倒

- Talkie：**纯白 Share 胶囊**是全屏最抢眼的元素，但真正的主流程动作是"发送"，其按钮反而弱 → 判为"突兀"。
- Apple Home：**方形小卡塞长名字导致三行折行** → "未打磨的原型感"。
- Heimdall：底部模糊元素**来历不明**（是信息流？抽屉？导航？）→ "只顾好看不顾可用"。
- ❌ **每屏必须有且仅有一个视觉焦点；主动作的视觉权重必须 ≥ 次动作。**

### 6.5 文字与排版

- **全大写**：Talkie 聊天正文全大写 → 判为"吵 / 像 2000 年代聊天机器人"。
- **拼写错误**：AI Character 概念稿出现 "Your Copmanions" → 稿子未验收。
- **排版瑕疵**：LOOI 标题 "Friend ." 句号前多空格；Rabbit R1 图标容器双框。
- **文案生硬**：Heimdall "With the help of a video camera, we can track the movement of the robot" → "降低成品感"。
- **标题孤字行**：AI Companion 主标题 "Your AI Companion for Everyday" 的 "Everyday" 独占一行 → "不精致"。
- ❌ **中文正文不要全大写/不要加字距；英文文案要过一遍母语校对；标题禁止孤字行。**

### 6.6 对比度与无障碍

- **Character.AI** trait 胶囊小字、**Echo AI** 引导页副标题、**Justinmind** 白字压鲑鱼粉 + 淡灰压白底、**Cuberto** 白字压钴蓝渐变卡 —— **视觉模型全部点名低于 WCAG AA**。
- **Apple Home** 半透明卡上的深绿/深灰文字 → "发脏"。
- **RoboPilot** 自绘 PTZ 方向盘与底部 sheet 对比度不足 → 实际使用看不清。
- ❌ **浅粉底上的正文用深炭色，绝不用白；半透明卡上不放长文；自绘控件与背景明度差 ≥3:1。**

### 6.7 控件与素材

- **自造开关**：Cuberto 胶囊开关旋钮里塞凹 "-" 号、RoboPilot 任务卡里的纯黑高对比开关 → "笨重、破坏语言"。
- **拟物与扁平混搭**：PanTiltZoom 金属推子/拉丝渐变摇杆 + 旁边扁平矢量图标 → "打架"。
- **旧质感残留**：Aqua 时代高光玻璃按钮、2008 拉丝金属、Web 安全绿 `#00FF00`、Windows Forms 编号空格格。
- **浮动层遮挡**：AI Character 概念稿的悬浮 dock 直接截断底部卡片，无渐变遮罩。
- **带投影的字**：Rabbit R1 图标标签投影 → "过时"。
- ❌ **用系统控件（Toggle / Slider / Stepper）；拟物控件一律不做；悬浮层必须带渐变遮罩。**

### 6.8 一句话版"丑"清单（贴评审墙上）

1. 黑底霓虹、2. 大圆角胶囊、3. 发光光晕、4. 卡片堆成仪表盘、5. 留白 <40%、6. 多种插画风格混用、7. 角色附属物是外来的通用贴纸、8. 主动作不突出、9. 全大写/错字/孤字行、10. 浅底浅字不过 AA、11. 自造开关与拟物金属、12. 底部 tab 超过 3 个、13. 悬浮层压住内容、14. 文字带投影、15. 渐变当背景主色。

## 7. 值得学的范式总结（3–5 条）

### 范式 1 · 设备屏是"陪伴面"，不是"功能面"

- **学到什么**：Rabbit R1 的产品命题是"interface without an interface"—— 整屏只有壁纸 + 角色，界面元素占 20–25%，留白 **75–80%**；LOOI 更极端，屏上只有**两颗大眼 + 一条灯条**，可点元素 0 个。
- **我们怎么用**：
  1. **删掉设备端"应用启动器"页**（02/04 文档里纠结过的那一页 —— 业界答案是"不做"）。
  2. 320×240 屏的视觉主体固定为**小栈的表情脸**（占屏 ≥50%），屏幕只承担三件事：**脸 + 一个状态 + 一个动作入口**。
  3. 12 颗 RGB LED 不是装饰，是**情绪的延伸**（呼吸 / 眨眼 / 听见时的回应），与屏上的脸同色同节奏。
  4. 眼睛**不要做霓虹辉光**（LOOI 靠 OLED 对比度，我们不是 OLED）—— 用**深底 + 白色/莓红高光**。

### 范式 2 · 浅画布 + 白表面 + 单一粉强调（已被真实验证）

- **学到什么**：三个独立来源给出同一个配方 —— Heimdall `#F0F4FC`+`#FFFFFF`+`#5C8DF6`；Justinmind `#F5F6FB`+`#FFFFFF`+`#FF5B84→#EE4266`；Apple Home 背景模糊+白卡+暖黄。**Justinmind 的强调色 `#FF5B84→#EE4266` 与我们的莓红 `#D94F78` 同族**，说明"**粉红做唯一强调色**"站得住。
- **我们怎么用**：
  1. **樱花粉画布 `#F1DFE5` + 奶油白表面 `#FFFFFF` + 莓红 `#D94F78` 唯一强调**，设备屏与 App 共用一套。
  2. 强调色**只出现在三处**：主动作按钮 / 当前选中项 / 进行中状态。
  3. 状态绿**只给"在线/已连接"**，警示红**只给异常/破坏性**，不要第三个彩色。
  4. 图标统一 **monoline 1.5–2pt、圆头端点、淡色圆底**，禁止混用填充/描边/假 3D。
  5. 抄 Justinmind 的一条禁令：粉底上**绝不用白字**，正文一律深炭色。

### 范式 3 · 一屏一动作：把"卡片仪表盘"换成"单一焦点"

- **学到什么**：所有被判为"原型感 / 指挥中心"的样本，共同特征是**可点元素 13–43 个、留白 20–25%**（Character.AI、RoboPilot、Cuberto、PanTiltZoom、Apple Home）；所有被判为"陪伴"的样本，共同特征是**可点元素 1–4 个、留白 50–80%**（aibo 图标 1 个、LOOI 0 个、AI Companion 概念稿 3 个、Rabbit R1 留白 75–80%）。
- **我们怎么用**：
  1. **App 首页：角色占上半屏 + 1 个主动作（按住说话）+ 底部一条状态条**，可点元素 ≤4，留白 ≥55%。
  2. **设备屏：同屏可点 ≤3**。
  3. 底部导航 **3 tab**（陪伴 / 遥控 / 设置），中间那个是**莓红实心 FAB**（不是发光环）。
  4. 二级页面**隐藏 tab**，用导航栏返回。
  5. 遥控页只保留 **实时画面（≤40%）+ 一个扁平描边摇杆 + 一条状态条** —— 抄 Cuberto 第 ③ 屏的骨架，丢掉全部 HUD。

### 范式 4 · 底层用系统语言：Inset Grouped + 发丝线 + 无阴影

- **学到什么**：iOS 26 规范图里，设置页的分隔**完全靠明度对比（白 vs `#F2F2F7`）+ 一条缩进对齐文字的 1px 发丝线，零阴影**；经典 iOS 分组表（2008）里唯一还活着的是"分组容器 + 行间发丝线 + 组间留白"，高光/浮雕/条纹底全部作废。
- **我们怎么用**：
  1. 设置页直接用 SwiftUI `List` + `.insetGrouped`，**只换主题色**（画布樱花粉 / 容器奶油白 / 发丝线莓红 12%）。
  2. **主行文字与右侧详情值同为 17pt**，次级靠降灰度而非缩字号。
  3. **破坏性操作独立成组、红色、置于页面末尾**。
  4. 颜色各司其职：莓红=选中/主动作，绿=在线，红=破坏性，灰=导航。

### 范式 5 · 材质统一 = 陪伴感的真正来源

- **学到什么**：5 张图上，**"同一个 App 里混了两种插画语言"都被单独点名**（Replika 的写实头像 vs doodle 徽章、Character.AI 的动漫 vs 写实、Echo AI 的 3D 霓虹 vs 扁平 emoji、Cuberto 的 3D 渲染 vs 2D 卡通、LOOI 的渲染机 + 贴纸）。反过来，**aibo（哑光陶土 + 深炭细节）、Heimdall（扁平矢量 + 2.5D 渐变）、AI Companion 概念稿（统一黏土 3D）都是"单一人设 → 干净"**。
- **我们怎么用**：
  1. 小栈的**唯一视觉语言 = 哑光陶土/黏土质感 + 细线条**，设备屏的脸、App 里的立绘、App 图标、加载动画**全部出自同一套**。
  2. 附属物（表情、emoji、图标）**只能来自这套语言**，不引入外部贴纸与通用 emoji。
  3. 边框优先于重阴影：主 CTA 用**实心莓红**，次级用 **1px 描边 + 透明底**，不用弥散阴影堆叠。

### 采用决策

- 摇杆组件 → **复用** kieranb662/Sliders-SwiftUI（MIT）　理由：直接映射双舵机，自造一个手感调不动的摇杆不划算；但样式必须**扁平 + 1px 描边**，不得沿用其拟物风（见 §5.3 PanTiltZoom 的教训）。
- BLE 层 → **复用** Bleu（MIT）或 BluetoothKit　理由：ESP32-S3 的重连 / MTU / 通知订阅是纯脏活，自研风险高。
- 动效曲线 → **复用** open-swiftui-animations 代码片段（Unlicense，零风险）+ dotlottie-ios　理由：待机呼吸 / 眨眼这类微动效是"陪伴感"的主要来源，手写弹簧曲线很难到位。
- 聊天 UI → **自造为主、复用为辅**　理由：SwiftyChat(Apache-2.0) 与 ChatBubbles(MIT) 许可干净，但没有一个是"陪伴型"观感 —— 我们要的是"小栈的脸 + 少量气泡"。只借"尾巴 / 分组 / 主题分层"规则，**气泡与输入栏自己画**。
- emoji 选择器 → **自造极简版**　理由：我们需要的是 12 个"表情动作"，不是通用 emoji 键盘；直接套整套键盘会过重。只参考 mpetrenco/EmojiPicker 的布局逻辑。
- 组件库（ShipSwift 等） → **不整体引入**　理由：02 文档结论是"审美主导时不引入现成组件库"，ShipSwift 体量大、气质不可控，作为**代码片段查阅源**而非依赖。
- **整体：混合**　理由：**审美主导的（画布 / 卡片 / 角色脸 / 气泡 / 图标 / 动效节奏）全部自造；非审美主导的（摇杆 / BLE / 动画曲线）直接复用**。"丑"的问题出在视觉层，不在组件层。

> 与 02 文档的关系：02 的结论是"不引入现成 SwiftUI 组件库（审美主导，气质不匹配）"。本文把这条**按组件拆开**——02 的判断在**视觉层**成立，在**基础设施层**不成立。

### A.7 检索过程中的踩坑（供后续复用）

1. `search_images` 返回的 `image_url` **不能直接喂给 `describe_images`** —— 必须先本地下载 → `mcode-tools upload_temp_url <path>` → 取 `temp_url`（有效期 1 小时）再传入。
2. `describe_images` **单次最多 10 张**，超过直接返回 400；实际建议 **4–5 张一批**。
3. 单张原图 > 2MB 极易触发 `UND_ERR_HEADERS_TIMEOUT`。先本地缩到 **最长边 1200px + JPEG q86**，体积降到 30–200KB 后稳定。
4. **文件扩展名会骗人**：GitHub/媒体站的 `.jpg` 可能是 WebP（RIFF 头）或 HTML 错误页。用 `System.Drawing` 读取失败时先看文件头字节。
5. 本机网络不可达 `miro.medium.com` 与 `play-lh.googleusercontent.com`（连接超时，非 403），需要 Google Play / Medium 素材时要在别处找替代源。
