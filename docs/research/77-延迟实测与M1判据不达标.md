# 77 · 三段延迟实测：M1 的「开始出声 < 2.5 s」判据**实测不达标**

> 建立日期：2026-10-25（第三轮夜间，07:00 前）
> 原始日志：`docs/research/runs/20261025-0700-bench-latency.log`（2255 B，未删改）
> 测量工具：`tools/bench_latency.py`（自检 10/10，已进 CI）

---

## 一、结论先行

1. ⛔ **M1 的完成判据「说话 → 它答 → 开始出声 < 2.5 s」在服务端侧就已经不达标。**
   实测合计 p50 = **3220 ms / 2812 ms**（两轮），p95 = 4715 / 3710 ms，max = **5065 ms**。
2. ⭐ **瓶颈完全不在我们自己的算法。** 三段分解：

   | 段 | p50（轮 1 / 轮 2） | 占比 |
   |---|---|---|
   | LLM（MiniMax-M3.1-Flash） | 2019 / 1398 ms | **约 55%** |
   | TTS（speech-02-hd） | 1098 / 1295 ms | **约 41%** |
   | **我们的关键帧编译** | **103 / 80 ms** | **1.5%–9%** |

   ⇒ 关键帧编译（`tools/prosody_to_motion.py` 的 PCHIP + 42 参数 + 关键帧编译）
   **永远不是瓶颈**。任何「优化我们的算法来提速」的方向都是错的方向。
3. ⇒ **优化必须动上游 API**，且**方案与 D2（音频承载方式）耦合**：
   - 流式 TTS / 首句先行的收益，**只有在 D2 选 A（WS 分片、可边收边播）时才存在**；
   - 若 D2 选 B（HTTP 拉整段），流式做出来也没有用 ⇒ **D2 不拍板，延迟优化无法开工**。
4. ⇒ 因此把「M1 的 2.5 s 判据怎么达标」登记为 **Q16**（`docs/spec/07` §3.5）。

## 四、⭐ 一个附带发现：**回复越长，越慢**

| 观察 | 证据 |
|---|---|
| 音频 2.3 s 的那次合计 **2161 ms**（**达标**） | 轮 2 第 1 行 |
| 音频 16.7 s 的那次合计 **5065 ms**（**翻倍**） | 轮 1 第 5 行 |
| 音频时长与总耗时**强相关** | 10 次样本里，没有一次「长音频 + 快合计」 |

⇒ **TTS 的耗时随输出长度线性增长**（生成式 TTS 的固有性质）。
⇒ 这直接给出**最便宜的优化手段**：**限制回复长度**。
但「回复要短」与「ENFP 陪伴型人格要热情」存在张力 ⇒ 这正是**需要用户拍板的产品取舍**（Q16）。

## 五、候选优化路径（供 Q16 拍板用）

| # | 路径 | 预期收益 | 代价 / 前提 |
|---|---|---|---|
| ① | **LLM 流式，首句先行**（先出声，后补全） | 可能省掉 1/3–1/2 的 LLM 等待 | 需要改 `run_pipeline`；且「先说一句」的内容选择要有策略 |
| ② | **流式 TTS**（边生成边播） | 可能省掉大部分 TTS 等待 | **必须 D2 选 A（WS 分片）**，否则 HTTP 拉整段让流式白做 |
| ③ | **限制回复长度**（如 ≤ 60 字 / ≤ 2 句） | 线性减少 TTS 时间 | 与 ENFP 热情人格有张力 ⇒ **需产品取舍** |
| ④ | **预生成问候语 / 常用回复** | 命中即 0 延迟 | 只覆盖开场/高频；需要缓存层设计 |

> ⚠️ 这四条**都不能在 D2 拍板前动手**：①③ 改的是 `server/stackchan_ai/server.py` 的管线顺序，
> ② 必须有 WS 分片通道才能验证收益 ⇒ **Q16 与 D2 是同一个工程的前后两段**。

## 六、未验证 / 诚实边界

- ❌ **未测端到端**（App 首片播放 + WS 传输 + 设备收帧）—— 本机无 Swift 工具链、无真机。
- ❌ **未测同一台机器上多次的方差分布**（只跑了 2 轮，n=10）⇒ p95 只有 10 个样本，**统计意义弱**。
- ❌ **未测网络抖动**（本机到 `api.minimaxi.com` 的 RTT 未单独测量）⇒ LLM 段里含网络时间，未拆分。
- ❌ **未测 MiniMax 是否有更快的模型 / 是否有流式 API 档位**（`DEFAULT_CHAT_MODEL = "MiniMax-M3.1-Flash"`，`DEFAULT_TTS_MODEL = "speech-02-hd"`；是否还有 `speech-02-turbo` 之类未查）。
- ✅ **已验证**：我们自己的编译段在 10 次样本里**全部 < 200 ms**，**不是瓶颈**。
