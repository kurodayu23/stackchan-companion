### ⭐ 最关键的一条澄清

> **「不上架」≠「不交会员费」。**

不审核、不上架运营、不用做通用产品、想改就改（这才是礼物场景的刚需）。

## 四、路径裁决（三条路）

| 路线 | 一次性/年度成本 | 朋友侧体验 | 能力上限 | 结论 |
|---|---|---|---|---|
| **A. 原生 iOS App + 付费账号 + Ad Hoc/TestFlight，**不**上架** | **$99/年**（≈¥700/年 ≈ ¥2/天） | Ad Hoc：登记 UDID、装一次、**一年不用管**；TestFlight：点链接装，但 **90 天要重传** | ⭐⭐ 唯一能做 **BLE**、**ANCS 通知转发**、**ARKit 表情镜像**、**离线本地推理** | **降级为二期可选项** |
| **B. Web / PWA（推荐主线）** | **¥0**（后端 + 静态页） | 发链接 → Safari「添加到主屏幕」→ 全屏、无地址栏 | 缺 BLE / 通知转发 / ARKit；**其余全有**（遥控、表情、对话、记忆、音乐、舞蹈、OTA 都在 Antigravity 那版里） | ⭐ **主线** |
| **C. 免费账号 + SideStore/AltStore** | ¥0 | 朋友要装 SideStore、后台跑 helper、**每 7 天自动重签** | 同 A | ❌ 实验阶段不值 |

### ⭐ 我的裁决（直接定，不反问）

> **主线 = B（Web 优先）；A 降级为「二期按需触发」；设备端 UI 不改（官方固件仍是真值）。**

理由三条：

1. **「不上架」省下的不是那 $99**（§1 已实测）⇒ 不该把「不上架」当成省钱的理由。
   真正省的是**不做通用化**：不审核、不做隐私标签/年龄分级/多语言/上架素材 ⇒ **省的是时间，不是钱**，
   而时间正是这个「给朋友的礼物」最该花的地方（花在体验上）。
2. **B 路线的成本是 ¥0，且能力几乎不缺**（§2.3 控制通道本来就走 Wi-Fi HTTP）⇒ 没有任何理由现在花 $99。
3. **A 的唯一不可替代能力是 BLE**。而 BLE 只在一种情况下才需要：**设备不在同一 Wi-Fi 时**。
   ⇒ 把 A 变成一个**明确的触发条件**，而不是默认路线。

## 五、与仓库既有决策的**两处冲突**（必须显式调和）

- `spec/02` §5 **D-1**「一屏一件事」· **D-2**「表情占屏幕 ≥ 60%」· **D-4**「**绝不做可滚动内容**」

⇒ **功能全部保留，但载体改到手机/Web 端**；设备屏继续只做脸 + 灯带。
这也正是仓库既有的「**手机出声 / 设备做身体**」决策。

### 冲突 2：仓库主线是「**原生 iOS App 从零写 SwiftUI**」，本轮裁决是「**Web 优先**」

- 仓库现状：43 个 Swift 文件 / 91 个测试函数，**但一行都没编译过**（本机无 Swift 工具链、无 Mac），
  43 个文件里的设计系统（`Tokens.swift` / `Shapes.swift` / `Typography.swift` / `Glass` / `Motion`）**已经写完了**。
- 本轮裁决：**这些资产不浪费** —— 它们是**设计真值**（token / 规范），无论最后是 SwiftUI 还是 Web 都能用；
  但**工程量**从「写两个 App」降为「写一个 Web App」。
- ⇒ **登记为待拍板项 Q24**（见 `docs/spec/09`），本轮**未擅自改动任何 Swift 文件**。
