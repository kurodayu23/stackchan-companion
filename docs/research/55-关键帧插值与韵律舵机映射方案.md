## 0. 一句话结论

**插值器选型**：舵机角用 **单调三次 Hermite（PCHIP / Fritsch–Carlson）** 做主插值（保形、不过冲、C¹ 连续 ⇒ 不会把 ±128.0° 的舵机顶到限位外，也不会在每个关键帧边界出现速度台阶）；**Catmull-Rom 只用于脸部的「弹性」通道且必须钳位**；**三次贝塞尔缓动只用在「落定 / 停顿」这类有意要停的边界**；**smoothstep 只用于 120~200 ms 的单次微动作（眨眼、点头脉冲）**。
**映射方案**：韵律用 6 个维度（F0 均值偏移、F0 重音峰、能量 RMS、语速、停顿、HNR）+ 谱质心做调制；情绪基线用 (valence, arousal) 二维潜变量 → 线性映射到 8 个通道；**全系统需要约 45 个可标定标量**。
**架构**：两段式——「稀疏语义路标（waypoint）」→「密集 0x14 关键帧」；帧率 **25 Hz（Δt=40 ms）**，这是 [引用] 已发表的语音驱动机械人脸编排速率。

## 1. 为什么必须自己做插值（引 53 号事实）

53 号文档已经用固件源码实读钉死了三个前提，本文不重复论证，只把它们翻译成算法约束：

| 53 号事实 | 来源 | 对插值方案的直接约束 |
|---|---|---|
| 关键帧通道（0x14）**绕过 modify lock** | 53 号 §5.4 | 表情/脸可以走 0x14，不存在「2 秒后被 blink/idle 覆盖」问题 ⇒ **0x14 是唯一主战场** |
| `Timeline::update()` **硬切无插值**，到 `durationMs` 边界直接换下一帧 | 53 号 §5.4 | 我们下发的每一个关键帧都是**阶跃指令**；顺滑必须由**我们自己生成足够密的关键帧**来伪造 |
| 舵机用 `moveWithSpeed(angle, speed)`，**无弹簧参数** | 53 号 §5.4 | 没有设备侧缓动可用 ⇒ **缓动曲线只能编进角度序列**；`speed` 只能当「速度档」用，不能当插值参数 |
| `rotation` 量程 0~3600（0.1°） | 53 号 §1.1 / §3.2 | 角度插值必须处理 **360° 回绕**，否则 3500→100 会插出 300° 的假扫掠 |
| `weight` 量程 0~100，eyes 侧 100=全睁、35≈闭 | 53 号 §2 / §3.2 | 眼睛 weight 与嘴 weight **不是同一个物理量**，不能共用一套"张开度"直觉 |
| 官方 4 条内置序列帧数 6/6/8/5 | 53 号 §5.5 | 官方自己就是**手写关键帧**（每帧 ~100~800 ms）⇒ 我们要做的是**把这条曲线自动化** |

### 1.1 关键推论：两级时间尺度

53 号 §5.4 的「硬切 + 舵机自带速度」组合，意味着设备实际执行的是：

```
设备收到 (目标角 θ_k, 速度档 s_k, 持续 d_k ms)
   → 舵机以 s_k 档位向 θ_k 运动（设备内部做速度规划，具体曲线未取得）
   → d_k 到点，设备瞬间把命令换成 θ_{k+1}
```

因此设备端轨迹 = **一串以 d_k 为间隔的阶跃目标 + 舵机自身的速度规划**。要让观感顺滑，必须满足：

1. **采样足够密**：帧间隔 Δt 要小于舵机自身完成一次目标切换所需的时间，否则每帧切换都会暴露成「跳一下」。
2. **离散速度连续**：相邻两帧的角度差 `|Δθ|/Δt` 变化不能剧烈 —— 这正是插值器要保证的 C¹ 性质。
3. **目标不越界**：插出来的角度必须始终落在合法行程内。

这三条分别对应 §2 的「帧率」「插值器选型」「钳位与限速」。

### 1.2 我们的架构选择（自研）

```
情绪基线 (valence, arousal)  ─┐
                              ├─►  稀疏语义路标 (waypoints)  ──►  插值器  ──►  密集 0x14 关键帧
韵律特征 (6 维)              ─┘         t=0..T, 5~12 个点              Δt=40 ms
```

**为什么分两层**：如果直接「韵律 → 密集帧」，韵律特征的抖动会 1:1 传到舵机（机器人会「抖得像坏了」）；先在语义层把韵律压成少数几个**有物理意义的姿态路标**（如「抬起下巴 5°」「向左看 8°」「落定回正」），再在渲染层做纯几何插值，抖动就被结构性地过滤掉了。

**路标层的「反抖动」规则（自研）**：
- 路标数量上限 **12 个 / 句**；超出的韵律细节只影响表情通道（weight/rotation），不影响舵机通道。
- 舵机路标的**最小角间隔 4.0°**：小于此值的相邻路标被合并（避免机器人在无意义的 1° 抖动上浪费行程）。4.0° 为 [自研] 设定，锚定于 CoreS3 舵机 0.1° 分辨率与实际可分辨角（待真机验证）。

## 2. 插值算法选型与参数

### 2.1 候选算法对比

| 算法 | 曲线性质 | 舵机上的过冲风险 | ±128° 边界安全性 | 结论 |
|---|---|---|---|---|
| **单调三次 Hermite（PCHIP / Fritsch–Carlson）** | 保形插值；C¹ 连续；二阶导在节点可跳变 | **无过冲**：单调段上曲线不超出数据范围 | **安全**：只要路标端点在限位内，插值结果必然也在限位内 | ✅ **主插值器（舵机 + 脸全部通道）** |
| **Catmull-Rom**（uniform α=0.5 / centripetal α=0.5） | C¹；uniform 参数化在点距不均时有尖点（cusp）与自交 | **有**：会在极值点附近冲出目标，产生「弹一下」 | **不安全**：必须外加钳位 | ⚠️ **仅用于脸部弹性通道 + 强制钳位** |
| **三次贝塞尔缓动** `cubic-bezier(x1,y1,x2,y2)` | 端点速度由控制点决定；`ease` 起点/终点速度为 0 | 无过冲（y 可越界，但标准 easing 的 y∈[0,1]） | 安全 | ⚠️ **仅用于「落定/停顿」边界** |
| **smoothstep** `3t²−2t³` | C¹（端点速度 0），C² 断 | 无过冲 | 安全 | ⚠️ **仅用于 120~200 ms 单次微动作** |
| **线性插值** | C⁰ | 无 | 安全 | ❌ 速度在每个关键帧边界跳变 ⇒ 舵机会「顿挫」 |

**为什么 PCHIP 是默认**：scipy 官方文档对 `PchipInterpolator` 的表述是「shape-preserving interpolator (C1 smooth)」「preserves monotonicity in the interpolation data and does **not** overshoot」「first derivatives are guaranteed to be continuous, but the second derivatives may jump」——[引用] https://docs.scipy.org/doc/scipy/reference/generated/scipy.interpolate.PchipInterpolator.html 。这条性质正好覆盖「舵机不得冲出限位」和「帧边界不得有速度台阶」两个硬需求。

该算法的学术出处与单调性充分条件见 arXiv:2102.11564（其参考文献列出 Fritsch & Carlson 1980《Monotone piecewise cubic interpolation》、Fritsch & Butland 1984、Hyman 1983，并明确指出 Matlab 的 **PCHIP 程序实现的是 Fritsch–Butland 公式 (39)**）——[引用] https://arxiv.org/abs/2102.11564 。另有专门讨论不同边界条件下三次样条插值保单调性界的论文——[引用] https://arxiv.org/abs/2402.01324 。

**Catmull-Rom 与三次贝塞尔的换算关系**（用于在两种插值风格之间迁移关键帧）见 SN Computer Science 2021《Conversion Between Cubic Bézier Curves and Catmull-Rom Splines》——[引用] https://arxiv.org/abs/2011.08232 。

### 2.2 Catmull-Rom 的安全用法（自研约束）

Catmull-Rom 的价值在于**表达力**：它能造出「预备（anticipation）→ 动作（action）→ 收势（settle）」这种带过冲的活物感，而 PCHIP 做不到。但它必须满足三条硬约束（均为 [自研]）：

1. **只用于脸部通道**（`weight` / `rotation` / `size`）：过冲在脸上是「弹性」，在脖子上是「撞限位」。
2. **必须用 centripetal 参数化（α=0.5）**，不能用 uniform α=0.5 —— uniform 在关键帧间距不均时会产生尖点与自交。
3. **输出必须钳位到通道量程**：插值结果 `clamp` 到 `[0,3600]`（rotation）/ `[-100,100]`（position, size）/ `[0,100]`（weight）。钳位是最后一道防线，不是插值保证。

### 2.3 舵机通道的额外安全层：软限位 + 限速

PCHIP 只保证**插值结果不越界**，它管不了舵机**机械本身的过冲**（齿隙、惯性、负载）。因此舵机通道要额外加两层（[自研]）：

| 安全层 | 规则 | 参数 | 来源 |
|---|---|---|---|
| **软限位** | 插值结果钳到「限位 − 裕量」 | yaw: ±(128.0 − 5.0) = ±123.0°；pitch: 3.0+2.0=5.0° ~ 87.0−2.0=85.0° | 裕量为 [自研] 设定；**限位值本身来自 53 号与本轮任务书** |
| **限速** | 任一路标的 `\|Δθ\| / Δt` 不得超过舵机能跟上来的速度；超限则**拉长该路标的驻留时间**而不是砍角度 | `v_max` 单位为 °/s，数值 **[未取得]**（53 号 §10 第 5 项：`moveWithSpeed` 的 `speed` 档位实际映射需真机扫参） | 待真机标定 |
| **落定余量** | 到达限位附近时，把最终目标从限位退回到软限位，避免「顶死」 | yaw 目标 ≤ ±115.0°，pitch 目标 ≤ 80.0° | [自研] |

**限速超限时的处理顺序（自研）**：① 延长 durationMs（首选，不改变姿态）→ ② 若总时长超预算，再降 soft-limit → ③ 最后才允许放弃该路标。永远不要为了赶时间直接砍角度，因为那会让目标值与插值轨迹脱节，产生阶跃。

### 2.4 帧率与时间常数

| 参数 | 取值 | 依据 |
|---|---|---|
| 关键帧间隔 Δt | **40 ms（25 Hz）** | [引用] arXiv:2403.12670《Driving Animatronic Robot Facial Expression From Speech》(IROS 2024)：音素 logits 以 49 Hz 输出后**重采样到 25 Hz 以匹配机器人编排速率**，滑动窗口 K=8（=320 ms），即 8 帧 × 40 ms。https://arxiv.org/abs/2403.12670 |
| 一句 3 秒的帧数 | **75 帧** | 3.0 s ÷ 40 ms |
| 脸通道低通滤波 | **8 Hz、5 阶 Butterworth** | [引用] 同上论文：推理时对 blendshape 系数序列施加 8 Hz 5 阶低通以保证「temporal stability」。https://arxiv.org/abs/2403.12670 |
| 滤波截止频率分档 | 姿态通道 8 Hz；嘴通道 15 Hz | [自研]：嘴需要跟音素，8 Hz 会把唇形削平（8 Hz 截止 @25 Hz 采样 ≈ 0.32×Nyquist，延迟不可忽略） |
| 音素对齐窗口 | 320 ms（K=8） | [引用] 同上 |

**「关键帧比插值帧更重要」这一工业实践共识**也是 [引用]：Animated Cassie 论文明确写道「the keyframe is more heavily weighted than the interpolated frame in terms of motion design in the animation field」，并据此在优化里对关键帧加权（普通帧 c=1500、关键帧 c=10⁴、结束帧 c=10⁵）——[引用] https://arxiv.org/abs/2009.02846 。该文还指出动画师可以自由选择 Bézier 或线性等插值方式，而帧间姿态由 Blender 自动插值——这与我们的「语义路标 + 自动插值」是同一种分工。

### 3.2 `rotation` 的解卷绕（最容易写错的一条）

53 号 §1.1 明确：`rotation` 上限 **3600 = 360.0° × 10**。这是一个**环形量**，直接线性插值会在跨越 0°/360° 时插出一条 300° 的假扫掠。

规则（[自研]）：

```
raw[0..n]                         # 设备侧原始序列
u[0] = raw[0]
for i in 1..n:
    d = raw[i] - raw[i-1]
    if d >  +1800: d -= 3600     # 1800 = 90.0°（0.1° 单位下的半个满量程）
    if d <  -1800: d += 3600
    u[i] = u[i-1] + d
# 对 u[] 做 PCHIP
out[i] = round(u_interp[i]) mod 3600
```

阈值取 1800（=90.0°）是标准做法：任何相邻两帧的真实旋转都不应超过 90°，超过即判为跨界并补偿。

### 3.3 颜色插值：应该在哪个空间做

四个候选空间，逐一评估：

| 空间 | 机制 | 在 LED 上是否物理有意义 | 结论 |
|---|---|---|---|
| **sRGB 直接插值**（gamma 空间线性插值） | sRGB 传输函数非线性（分段 gamma），数值线性 ≠ 感知线性 | 否：中间色会明显"发暗发脏" | ❌ 不用 |
| **线性 RGB**（先 sRGB→linear 解码再插） | 亮度路径物理正确 | 部分：绿通道仍非感知均匀；但**与 LED 物理亮度标定对齐**时最优 | ⚠️ 备选（需设备光谱响应，当前 [未取得]） |
| **HSV / HSL** | H 是**环形量**（0°≡360°） | 只有在显式指定最短弧时才成立 | ⚠️ 仅当必须保持色相名字时用，且必须 shortest-arc |
| **Oklab** | 矩形空间（L 感知明度 / a 绿-红 / b 蓝-黄），无环形分量，感知均匀 | 是：明度可独立控制 ⇒ 亮度包络不会带来色相偏移 | ✅ **默认** |

**依据**：
- Oklab 的设计目标即「predicting perceived lightness, chroma and hue」，并采用与 sRGB 一致的 D65 白点——[引用] https://bottosson.github.io/posts/oklab/
- CSS Color 4 §13.2 定义了 `color-interpolation-method`，其 `<rectangular-color-space>` 枚举含 `srgb | srgb-linear | display-p3 | ... | lab | oklab`，`<polar-color-space>` 枚举含 `hsl | hwb | lch | oklch`——[引用] https://www.w3.org/TR/css-color-4/
- CSS Color 4 **§13.5 "Hue Interpolation"** 明确把 H 通道插值策略分为 `shorter | longer | increasing | decreasing` 四种 ⇒ **H 通道插值必须显式声明策略**，不存在"默认安全"一说——[引用] https://www.w3.org/TR/css-color-4/
- CSS Color 4 **§14 "Gamut Mapping"** 给出色域外处理（§14.1.2 Clipping、§14.1.4 Chroma Reduction、§14.2 CSS Gamut Mapping to an RGB Destination）——[引用] https://www.w3.org/TR/css-color-4/

**我们的具体规则（[自研]）**：

1. **默认 Oklab 插值**：`#RRGGBB` → sRGB → linear → LMS → Oklab → 逐分量插值 → 逆变换 → sRGB → clip 到 [0,255] → `#RRGGBB`。
2. **亮度脉冲**（情绪强调的「闪一下」）**只改 L**：`a`、`b` 保持不变 ⇒ 同色变亮/变暗，不产生色相偏移。
3. **左右灯分离**：左右各自独立插值，但**共用同一条亮度包络 L(t)** ⇒ "呼吸/心跳"是同步的，"情绪着色"是分侧的。
4. **禁止 HSV 的 H 通道裸插值**。
5. **clip 而非 chroma reduction**：LED 是显示设备，clip 造成的色偏可接受，chroma reduction 的额外计算与不可控性不值得（与 CSS §14.1.2 Clipping 路线一致）。

### 3.4 离散 `speed` 档的处理

事实前提：53 号 §5.3 记 `speed` 为「舵机速度档位」(int)；53 号 §10 第 5 项明确「`moveWithSpeed` 的 `speed` 档位实际映射」**待真机扫参** ⇒ 档位与角速度的换算关系当前 **[未取得]**。

规则（[自研]，除注明外）：

1. **speed 永远不插值**。它是「这一帧走多快」的离散指令，插值出来的中间值在设备上不存在 ⇒ 设备要么取整、要么钳位，结果不可控。
2. **正确做法**：由插值后的角度曲线求每帧期望角速度
   `v[i] = |θ[i+1] − θ[i]| / Δt`（°/s），再映射到离散档：
   `speed[i] = clamp(round((v[i] − v_min) / v_ref · (S_max − S_min) + S_min), S_min, S_max)`。
   其中 `v_ref`、`S_min`、`S_max` **[未取得]**（真机扫参）。
3. **若真机发现 `speed` 的物理含义是「每步延迟毫秒」（与速度成反比）**，则上式改为取倒数后再量化——这是必须先做的判定实验。
4. **迟滞**：相邻帧的档位跳变需要连续 ≥2 帧才允许生效，避免 speed 抖动导致舵机抖。
5. **保底档**：speed 至少取最慢档，保证舵机每帧都能走完，不积压指令。

### 3.5 帧间低通滤波（最后一层保险）

| 通道 | 滤波器 | 依据 |
|---|---|---|
| 姿态（yaw/pitch） | 2 阶 10 Hz Butterworth（轻滤） | [自研]：路标层已抑制抖动，PCHIP 已 C¹；重滤会引入相位滞后，损伤"跟得上" |
| 脸（eye/mouth 的 weight/rotation/size） | **8 Hz 5 阶 Butterworth** | [引用] arXiv:2403.12670：推理时对 blendshape 系数序列施加 8 Hz 5 阶低通以保证 temporal stability。https://arxiv.org/abs/2403.12670 |
| 嘴（mouth.weight 单独） | 15 Hz 2 阶 | [自研]：8 Hz 会把唇形削平 |
| 颜色 | 不滤波（Oklab 插值本身已平滑） | [自研] |

**注意**：Butterworth 是 IIR，需要跨帧携带状态；滤波会带来群延迟，8 Hz 5 阶在 25 Hz 采样下的实际群延迟 **[未取得]**（需实测，因为 8 Hz 截止 ≈ 0.32×Nyquist，群延迟不可忽略）。

### 3.6 一次性微动作（眨眼 / 点头脉冲）

这类动作**不是**关键帧插值的产物，而是叠加在时间轴上的短事件：

| 动作 | 曲线 | 时长 | 依据 |
|---|---|---|---|
| 眨眼（闭→开） | smoothstep `3t²−2t³` 下降 + smoothstep 上升 | 闭 200 ms / 开 100 ms | 闭眼时长 200 ms 引自 53 号 §4.1（`BlinkModifier` 睁 5200 ms / 闭 200 ms）；开眼 100 ms 为 [自研] |
| 点头脉冲 | `cubic-bezier(0.42, 0, 0.58, 1)`（= CSS `ease-in-out`） | 上升 120 ms / 回位 200 ms | [引用] `ease-in-out` ≡ `cubic-bezier(0.42, 0, 0.58, 1)`，见 https://www.w3.org/TR/css-easing-1/ ；时长为 [自研] |
| 表情强调（眉毛/嘴角一抽） | Catmull-Rom（带过冲）+ 钳位 | 150~250 ms | [自研]；过冲在脸上是"弹性"，故此处允许 |

**关键提醒**：CSS 的 `cubic-bezier()` 语法中 `x1`、`x2` 被规范限定在 `[0,1]`，而 `y1`、`y2` **不受限**⇒ **cubic-bezier 本身是可以产生过冲的**（[引用] https://www.w3.org/TR/css-easing-1/ 的 `<cubic-bezier-easing-function>` production：`cubic-bezier( <number [0,1]> , <number> , <number [0,1]> , <number> )`）。因此把 cubic-bezier 用在舵机上时，**必须再叠一层 y ∈ [0,1] 的钳位**；本文只在"落定/停顿"场景用它，此时过冲无害但仍建议钳位。

## 4. 韵律 → 舵机映射

### 4.1 韵律用哪几个维度（文献依据）

| 依据 | 内容 | 来源 |
|---|---|---|
| 韵律的定义 | prosody 包含 **fundamental frequency (F0)、loudness、timing、spectral information** 四类元素 | [引用] arXiv:2403.08144《Prosody for Intuitive Robotic Interface Design》(HRI 2024 LEAP-HRI workshop)：https://arxiv.org/abs/2403.08144 |
| 维度的**最小可用集** | Skantze 用 LSTM 预测话轮转换，**只用「一组相当基础的五个韵律特征」**就能超过人类观察者 | [引用] 同上（转引 Skantze 2017） |
| 语音→头部运动的经典特征 | **F0 与 energy** 是头动的经典驱动因子；MFCC 是常见基线，**FBank 优于 MFCC** | [引用] arXiv:2002.01869（Interspeech 2020）：https://arxiv.org/abs/2002.01869 |
| 韵律**构式**（construct）分类 | Ward 归纳的四种构式：*interpolation*（缓升调 + 低音量 + 快语速 = 紧急）、*minor third*（两段平调 + 短促强度下凹 = 制止/呼唤）、*backchannelling*（拉长 + 轻 + 平调 + 微哑 = 鼓励继续）、*positive assessment*（高调 → 增强音量 → 收音强度骤降 = 正面评价） | [引用] arXiv:2403.08144：https://arxiv.org/abs/2403.08144 |
| 头部运动 ↔ 情绪的**可量化维度** | 「head motion corresponding to distinct affective states is described by different **motion activation, range, and velocity**」（用 PAD 模型评估情感语音中的头部运动） | [引用] arXiv:1607.05327《Emotional Storytelling using Virtual and Robotic Agents》（转引）：https://arxiv.org/abs/1607.05327 |
| 头朝向 ↔ 情绪 | 「Head orientation was suggested by Ekman and Friesen to be an indicator of gross affective state (positive/negative) as well as intensity of emotion」 | [引用] 同上：https://arxiv.org/abs/1607.05327 |
| 社交机器人头动的主流做法 | 对头转角做 **FIR 平滑**，blendshape 以 **25 fps**、舵机以 **125 fps** 下发 | [引用] arXiv:2109.01206《Mechanical Chameleons》(SCRITA 2021)：https://arxiv.org/abs/2109.01206 |
| 语义手势 vs 节拍手势 | 「rhythmic movements (**beat gestures**) are relatively common and easily synthesized, while gestures that convey specific semantic meaning (**semantic gestures**) are sparse in datasets」 | [引用] arXiv:2512.17183：https://arxiv.org/abs/2512.17183 |

**结论（[自研] 的维度选择）**：采用 **7 个可从音频实时算出的维度**——F0 均值偏移、F0 重音峰、能量 RMS、语速、停顿、HNR、谱质心。选它们的理由：
- F0 / 能量 / 语速 / 停顿 / HNR 都被上面的文献直接支持；
- 谱质心补上「音色明暗」这一维，用来驱动灯色亮度（机器人没有嗓子，明暗只能靠灯表达）；
- **刻意不用 MFCC**：它是 39 维的稠密向量，与我们只有 2 个舵机自由度的执行器严重不匹配；FBank>MFCC 的结论（2002.01869）也说明没必要上 MFCC。

### 4.2 归一化：全部相对说话人基线

**先决裁决（引 54 号，本文不重复论证）**：韵律特征**不在 ESP32-S3 上算**——官方固件只读不改，我们没有可插入的代码载体（54 号 §5.1）；**服务端本来就已经握着两段 PCM**：上行是用户麦克风的 Opus 解码结果，下行是 TTS 音频字节流（54 号 §5.2）。⇒ 本节的全部 7 个维度都**在服务端从 PCM 实时提取**，本文只负责「特征 → 时间轴」这一段。
⇒ 两路韵律各司其职（54 号 §5.2）：**下行（机器人自己的 TTS 韵律）驱动身体表达**（本文 §4.3 的主路径）；**上行（用户韵律）驱动反应**（如用户语调上扬 → 机器人歪头）。

**关键设计（[自研]）**：所有韵律量都相对**该说话人自己的基线**做 z-score，基线用最近 30 s 的指数滑动平均（EMA）维护。

```
z_pitch(t)  = (F0_median_voiced(t) − F0_base) / F0_scale      ∈ [-2, +2]
z_energy(t) = (RMS_dB(t)        − E_base)  / E_scale          ∈ [-2, +2]
rate(t)     = syllable_rate(t)                                ∈ [2, 10] syl/s
pause(t)    = 1 if VAD 静音持续 > 150 ms else 0
z_hnr(t)    = (HNR(t)            − HNR_base) / HNR_scale       ∈ [-2, +2]
z_cent(t)   = (centroid(t)      − C_base)  / C_scale          ∈ [-2, +2]
```

理由：设备面对的是 TTS 输出和用户说话，音色差异极大；用说话人内归一化 ⇒ 一套参数通吃，且天然做了「个体化」的一半。

### 4.3 定量映射表（**以下全部为 [自研] 方案，非研究结论**）

设情绪为 `(v, a)`（valence ∈ [-1,1]，arousal ∈ [0,1]），韵律调制幅度系数 `G_eff = 1.0 × (0.6 + 0.8·a)`。

| 韵律维度 | 目标通道 | 映射公式 | 幅度上限 | 时间常数 τ |
|---|---|---|---|---|
| `z_pitch` | `yawServo.angle` 目标偏移 | `yaw += G_eff · 12.0° · z_pitch` | ±12.0° | 250 ms |
| `z_pitch` 上升沿 | 点头脉冲事件（每句 ≤ 2 次） | 触发一次 pitch 通道的 cubic-bezier 脉冲 | 4.0° | 上升 120 ms / 回位 200 ms |
| `z_energy` | `pitchServo.angle` 目标偏移 | `pitch += G_eff · 6.0° · z_energy` | ±6.0° | 80 ms |
| `z_energy` | `mouth.weight` | `mouth.w += 18 · z_energy`（相对情绪基线） | ±18 | 60 ms |
| `rate` | **时间轴整体缩放**（节拍密度） | `Δt_eff = 40 ms / (0.85 + 0.03·(rate − 4))` | 缩放 0.80× ~ 1.25× | 整句 |
| `pause` | 舵机落定 + 嘴闭合 | 停顿开始时把 yaw/pitch 目标拉向 `pause_target`（= 情绪基线 + 0.3×当前位移量）；停顿内用 `cubic-bezier(0.42,0,0.58,1)` 落定 | 位移量 × 0.3 | 停顿即事件 |
| `z_hnr`（下降） | `eye.weight` / `mouth.weight` | `eye.w −= 15·max(0, −z_hnr)`；`mouth.w −= 15·max(0, −z_hnr)` | −15 | 200 ms |
| `z_cent` | LED 亮度（Oklab 的 L） | `L += 0.15 · z_cent` | ±0.15 | 120 ms |
| 全部 | `yawServo.speed` / `pitchServo.speed` | 由 §3.4 的角速度量化得到（**不独立调制**） | 设备档位 | — |

**为什么这样分配**（[自研] 推理）：
1. **yaw 跟音高**：高 pitch = 提问/惊讶 ⇒ 抬头/侧看；低 pitch = 确认/权威 ⇒ 低头正视。yaw 是"社交指向"，pitch 是"情绪强度"。
2. **pitch 跟能量**：音量冲击对应下巴抬起（人类在说重音时下巴会上抬）。
3. **语速不映射到角度，只映射到时间轴缩放**：语速是**时间维度**的信息，把它映射成角度会让机器人"语速快就摇头"，观感怪异；正确做法是让动作**节奏**跟着加快（节拍密度上升），幅度不变。
4. **停顿映射成"落定"而不是"不动"**：人类说话时停顿伴随头部回正/微沉，把停顿做成落定 ⇒ 机器人在"思考"，而不是"卡了"。

### 4.5 ⭐ 「一句话说了 3 秒，头应该怎么动」

**场景（[自研] 示例）**：设备用 TTS 说「今天天气真不错呢。」，时长 **3.0 s**；情绪 Neutral；韵律：语速 4.5 syl/s，句末有一个重音峰（`z_pitch` 末段升到 +0.8），能量中等偏上（`z_energy` 峰 +1.2），结尾 350 ms 静音。

**产出：75 帧 × 40 ms**（下表是路标层的结果，实际下发 75 帧密集关键帧）

| 时间 (ms) | 阶段 | yaw (0.1°) | pitch (0.1°) | mouth.weight | eye.weight | LED L | 动作语义 |
|---|---|---|---|---|---|---|---|
| 0 | 起 | 0 | 450 | 50 | 100 | 0.35 | 静止（情绪基线） |
| 80 | 预备 | −30 | 470 | 55 | 100 | 0.35 | **反向预备**：先微微后仰再起（anticipation） |
| 240 | 起势 | +60 | 460 | 70 | 100 | 0.36 | 第一个音节，随能量抬下巴、嘴角上扬 |
| 400→1200 | 主体 | +60 → +95 | 460 → 465 | 60 ± 12（随能量包络） | 100 | 0.36→0.41 | **一次**缓慢左移 4.5°（PCHIP 平滑） |
| 1200 | 重音峰 | +95 | 490 | 78 | 98 | 0.47 | 能量峰 ⇒ 下巴再抬 2.5°，嘴张开 |
| 1200→1300 | 点头脉冲 | +95 | 490→460→490 | 70 | 98 | 0.47 | pitch 做一次 cubic-bezier 点头脉冲 |
| 1300→2400 | 延续 | +95 → +20 | 460 → 450 | 55 | 100 | 0.44→0.38 | 慢慢回正 |
| 2400 | 收 | +20 | 450 | 45 | 100 | 0.38 | 音节结束，嘴开始合 |
| 2400→2700 | 停顿落定 | +20 → 0 | 450 | 45 → 30 | 100 | 0.38→0.35 | 350 ms 静音 ⇒ ease-in-out 落回基线 |
| 2700→3000 | 静止 | 0 | 450 | 30 → 50 | 100 | 0.35 | 回中，嘴恢复 |

**三条设计铁律（[自研]，也是本节最重要的结论）**：

1. **3 秒 = 3 个动作事件（起势 / 强调 / 落定），不是持续运动。**
   头部**静止的时间必须多于运动的时间**。活物的标志是"大部分时间不动，动的时候有明确的起点和终点"。
2. **幅度小、速度慢、有终点。** 3 秒内的 yaw 总位移 9.5°、pitch 总位移 4.0°，远小于行程（±128° / 84°）⇒ 永不接近限位 ⇒ 也不需要软限位频繁介入。
3. **大动作留给情绪极端时刻**（arousal > 0.8 时 `G_eff` 放大到 1.4×），日常对话保持克制。

### 4.6 与设备侧 `speed`、限速的联动

第 4.5 节的 yaw 变化率峰值出现在 1200→1300 的点头脉冲：4.0° / 200 ms ≈ **20 °/s**。按 §3.4 映射到离散 speed 档：
- 若 `speed` 是"速度倍率"，该帧取中档；
- 若 `speed` 是"每步延迟毫秒"，该帧取小延迟档。
两种解释都必须先做 §3.4 第 3 条的判定实验才能落地 ⇒ **`v_ref`/`S_min`/`S_max` 标记 [未取得]**。

### 4.7 冲突预警（来自 53 号）

- 设备自己会在收到含 `hello`/`hi`/`love` 的文本消息时设置 Happy 情绪 2000 ms（53 号 §2 事实 C / §6），这会**直接改写 `eye.weight` / `eye.rotation`**，与我们的 0x14 帧冲突。
  → **[自研] 规则**：情绪调度层必须拦截含这些词的 TTS 文本（或在 0x14 播放期间抑制该路径）；否则会出现"说着话突然换表情"。
- 0x14 播放期间设备**同时**在跑 blink / breath / idle_expression 三个 modifier（53 号 §4.1），它们也写 `weight` / `position`。因为 `Keyframe::apply()` 不查 modify lock，**modifier 仍会覆盖我们的帧**（我们只是不受锁限制，不是独占）。
  → **[自研] 规则**：需要真机确认这三者与 0x14 的写序与写频；若冲突不可解，则脸通道必须靠"保活重发"维持（退回 53 号 §4.3 的保活模型），舵机通道不受影响（modifier 不写舵机）。**[未取得：需真机验证写优先级]**

## 5. 参数量化与标定方法

### 5.1 三组参数与最少个数

| 组 | 内容 | 推荐结构下的个数 | 稠密结构下的个数 |
|---|---|---|---|
| **A · 情绪基线** | `(valence, arousal)` → 8 个执行通道的仿射映射 + 每情绪 1 个残差修正 | 2×8 = 16，加 6 个残差 = **22** | 6 情绪 × 8 通道 = **48** |
| **B · 韵律调制** | 7 个韵律维度 × 增益（快/中/慢三档时间常数共用）+ 情绪缩放系数 | 7 + 1 + 1 = **9** | 7 × 8 = **56** |
| **C · 个性化** | 全局幅度 / 表情夸张度 / 点头幅度 / 待机偏置 / LED 亮度上限 / 眨眼率 / 说话节奏偏好 | **7** | **7** |
| **D · 设备常量** | 软限位裕量、`v_max`、speed 档映射表、滤波截止 | **4** | **4** |
| **合计** | | **≈ 42** | **≈ 115** |

**结论**：
- **最少可用集（不做个性化、不做情绪×韵律交互）**：A 用 6 情绪 × 4 关键通道 = 24，B 用 7 + 2 = 9，D 用 4 ⇒ **37 个标量**。
- **推荐工程集**：**≈ 42 个标量**（本文后续按此设计）。
- **上界**：每情绪每通道独立 + 每维度每通道独立 ⇒ 115 个，但**不可维护**（用户没法理解 115 个旋钮，也没法归因）。

**文献支撑**：
- 参数化动作空间的做法即把「动作 = 离散选项 × 连续参数」，参数个数是显式设计量而非副产品——[引用] arXiv:1511.04143《Deep Reinforcement Learning in Parameterized Action Space》 https://arxiv.org/abs/1511.04143
- 任务参数化（task-parameterized）把「风格/任务」当作**条件变量**，而不是把风格硬编码进权重，于是少量样例即可覆盖多风格——[引用] arXiv:2201.09975《Learning Task-Parameterized Skills from Few Demonstrations》(RA-L) https://arxiv.org/abs/2201.09975 ；[引用] arXiv:1707.01696《Generalized Task-Parameterized Skill Learning》 https://arxiv.org/abs/1707.01696
- 头部运动对应不同情绪状态时，其差异可由 **motion activation / range / velocity** 三个属性描述——[引用] arXiv:1607.05327 https://arxiv.org/abs/1607.05327 。⇒ 这直接支持我们把"幅度（range）/ 速度（velocity）/ 激活度（activation）"**拆成三个独立参数**，而不是一个"表达强度"旋钮。

### 5.2 四步标定流程

#### Step 0 · 执行器表征（motor babbling）

**目的**：测出 ① `speed` 档 ↔ 实际角速度的换算；② 舵机真实行程与机械回差；③ 从指令到到位的时间延迟。

**文献方法**：受 [引用] arXiv:1906.09013《Local Online Motor Babbling: Learning Motor Abundance of a Musculoskeletal Robot Arm》(IROS 2019) 启发——用**目标导向 babbling** 先粗探动作空间，再用 **CMA-ES** 在局部精修；该文实验规模为 **T = 20000 个采样点、采样率 5 Hz、目标步长 δx = 0.02（对应目标速度 2 cm/s）**，整个学习实验（含在线评估）**实时不到 2 小时**；并用「凸包 + 离群点剔除」把目标数从 **179 降到 94**，平均误差从 3.5 cm 降到 1.8 cm。https://arxiv.org/abs/1906.09013

**我们的规模（[自研] 缩放）**：我们只有 **2 个自由度**，不需要 20000 采样。

| 项 | 我们的设定 | 依据 |
|---|---|---|
| 采样点数 | **200 点**（yaw 100 / pitch 100） | 自研：2 DoF 下足够拟合一张 `speed ↔ 角速度` 查找表 |
| 采样率 | **20 Hz**，每点持续 3 帧（150 ms） | 自研：需等舵机到位再测角 |
| 步进幅度 | yaw **5.0°** / pitch **3.0°** 分级 | 自研：0.1° 分辨率下的最小可分辨角 |
| 必须包含 | **软限位附近**（yaw ±123.0°、pitch 5.0°~85.0°） | 自研：用于测机械回差与顶死风险 |
| 总耗时目标 | **< 5 分钟** | 自研 |
| 产出 | `speed` 档 ↔ 角速度查找表（设备常量 D 的第 3 项） | — |

#### Step 1 · 韵律 → 舵机的回归（少量样例）

- **数据来源**：设备自己说话时我们同时拥有两条流——TTS 音频 与 我们下发的时间轴。**不需要额外录制**。
- **待估参数**：B 组的 7 个增益 + 1 个尺度参数 = **8 个待估量**。
- **方法**：**岭回归（带 L2 正则的最小二乘）**，目标 = 姿态重建误差 + λ·‖增益‖²。正则项**必须加**，否则样本少时会拟合出巨大增益（正是 PCHIP 要防的过冲的「参数版」）。
- **样本量（[自研]）**：**≥ 60 句**。覆盖 6 种情绪 × ≥ 5 句，外加若干含停顿、疑问、感叹的句子。理由：8 个待估量对应 60 样本 ≈ 7.5:1，岭回归下稳定。
- 与文献一致：用少量演示学任务参数化技能——[引用] arXiv:2201.09975 https://arxiv.org/abs/2201.09975

#### Step 2 · 情绪基线：手工锚定 + 主观评估（**不拟合**）

- **为什么不拟合**：① 只有 6 个情绪；② 设备固件**已经有**官方的情绪→眼参数（53 号 §2），我们的任务是与之对齐而不是重新学；③ 拟合需要大量被试，ROI 不成立。
- **评估手段**：主观量表。社交机器人性能评估普遍采用 GODSPEED 一类主观问卷，且**"perceived qualities such as naturalness or smoothness cannot be fully captured by predefined or task-driven metrics"**——[引用] arXiv:2606.18747 https://arxiv.org/abs/2606.18747
- **采集量（[自研]）**：每情绪 5 个展示样例 × 3 位评测者 = **90 次评分**；用**配对比较**（两两比「哪个更像活的」）而非绝对打分——配对比较的样本效率远高于绝对打分。

#### Step 3 · 偏好微调（个体化，闭环，只动 C 组）

- **做法**：用户对「这次点头幅度合不合适」的反馈（口头或 👍/👎）作为奖励信号，**只更新 C 组 7 个参数**，A/B 组冻结。
- **文献支撑**：[引用] arXiv:2606.18747 用**迭代 RLHF** 微调 Pepper 的共语音手势生成——**在线用户研究共 5 轮迭代、微调 GPT-4 共 4 次**，并把 LLM 与一个「低层动作原语库」耦合（"coupling the model with a library of low-level motion primitives"）。https://arxiv.org/abs/2606.18747
- **我们的对应（[自研]）**：**5 轮迭代，每轮只改 C 组 7 个参数**。每轮参数更新量小 ⇒ 可解释、可回滚、可审计。
- **必须单列的感知指标**：姿态重建误差 **不能** 当作"像不像活"的指标（arXiv:2606.18747 同上警示）。

### 5.3 明确否决「端到端学习」（自研决策，附文献理由）

| 论点 | 内容 |
|---|---|
| 数据量 | 一个用户一天可能只有几百句；2 DoF + 15 个脸字段 + 2 个灯通道的端到端模型会严重过拟合 |
| 可审计性 | 黑箱模型无法回答"这次为什么这么动"，与「设备即档案 + 可审计来源」护城河**直接冲突** |
| 语义手势数据稀缺 | "semantic gestures are **sparse in datasets**"，而 "rhythmic movements (beat gestures) are relatively common and **easily synthesized**"——[引用] arXiv:2512.17183 https://arxiv.org/abs/2512.17183 |
| 分工结论 | **语义交给 LLM（内容层），节拍交给参数化映射（运动层）**。这是数据条件下的正确分工，不是偷懒 |

## 6. 可积累资产形态

### 6.1 三层资产

| 层 | 内容 | 格式 | 谁可写 | 增长速度 |
|---|---|---|---|---|
| **L1 参数库** | 42 个标量 + 元数据（情绪标签、来源、标定日期、置信度、适用的 `speed` 档表） | 版本化 JSON | 云端标定 / 设备本地微调 | 每次标定 +1 条版本 |
| **L2 动作片段库** | 关键帧片段：官方 4 条 + 我们生成的 30~80 条 | 0x14 JSON 片段 | 云端 / 设备本地 | 用户收藏、情绪覆盖度扩展 |
| **L3 回放数据** | 四元组 `(韵律特征向量, 参数向量, 生成的 0x14 JSON, 时间戳)` | JSONL，追加式 | **仅设备本地** | 每次说话 +1 行 |

### 6.2 「设备即档案 + 可审计来源」的落法

**核心不变式（[自研]）**：**参数向量是唯一真相源，时间轴是它的纯函数。**

每条 L3 记录携带：

```
record_id   = SHA256(参数向量 ‖ 韵律特征向量 ‖ 合成器版本)
payload     = 下发给设备的 0x14 JSON 全文（逐字节）
ts          = 设备端时间戳
```

由此得到三条**可审计**性质（[自研] 设计，引用见下）：

1. **可验证**：任何人拿到一条记录，可重算哈希并与 payload 对齐。
2. **可重放**：用同一版本的合成器 + 同一条记录里的参数向量，可**逐字节复现**同一条 0x14 JSON ⇒ 证明"设备当时看到的输入就是这些"。
3. **可归因**：任何一个动作异常，都能反查到是哪个参数、哪个韵律维度导致的（因为只有 42 个标量）。

**引用支撑**：
| 借鉴对象 | 内容 | 来源 |
|---|---|---|
| W3C **PROV-O**（PROV-DM / PROV-N，2013-04-30 W3C Recommendation） | 提供 `entity / activity / agent` 三元 + `wasGeneratedBy` / `wasDerivedFrom` / `wasAttributedTo` 的标准溯源词汇 ⇒ 我们的每条记录天然可映射成 PROV 图 | [引用] https://www.w3.org/TR/prov-o/ |
| **Local-first software**（Kleppmann, Wiggins, van Hardenberg, McGranaghan, 2019-04） | 主张数据归用户所有、可离线协作、长期保存、"You own your data, in spite of the cloud" ⇒ 「设备即档案」是 local-first 的极端形态：**连中心服务器都不需要** | [引用] https://www.inkandswitch.com/essay/local-first |

### 6.3 「不入库」前提下如何变厚（[自研]）

**关键洞察**：资产的价值不在于集中存储，而在于**「可重算 + 可验证」**。只要合成过程是确定性的、参数是完整记录的，那么**我们不需要保存输入，只需要保存参数**。

| 我们不存的 | 为什么可以不存 | 存的替代物 |
|---|---|---|
| 用户原始语音 | 音频是隐私核心，且**不可重算**（丢失了就没了） | 只存 **7 个 z-score + 3 个原始标量**（韵律特征摘要） |
| 服务端渲染缓存 | 时间轴是参数与韵律的**纯函数**，可随时重算 | 参数向量 + 合成器版本 |
| 中央动作库 | 片段可以在设备本地生成与固化 | 设备本地的 L1/L2/L3 |

**⚠️ 隐私诚实声明（[自研] 必写进隐私政策）**：韵律特征摘要**虽然不是音频，但仍可能泄露情绪与生理状态**（HNR 泄露"气声/病态"，语速与停顿泄露"兴奋/疲惫"）。因此：
- 必须给用户**开关**（是否记录韵律特征）；
- 必须给用户**一键清除**；
- 设备本地存储，**默认不上传**；上传需 opt-in，且只上传参数向量与摘要哈希，**不上传韵律特征本身**。

### 6.4 资产变厚的三个可测指标（[自研]）

| 指标 | 定义 | 为什么可测 |
|---|---|---|
| **标定样本量 n** | Step 1 回归所用的句子条数 | 直接反映 B 组参数的置信度 |
| **语义覆盖度** | 片段库中（情绪 × 韵律构式）组合的已覆盖格子数 / 总格子数 | 韵律构式用 Ward 的四类（interpolation / minor third / backchannelling / positive assessment，来源见 §4.1） |
| **个性化收敛度** | 相邻两轮 RLHF 后 C 组参数的 L2 变化量 | 变化量趋 0 ⇒ 已收敛，可停止采样 |
