# 35 · 非常规陪伴功能与技术护城河

> 这份文档回答一个问题：**我们应该做哪些创新功能？**
> 判据不是「酷」，而是三条同时成立：
> 1. **ENFP 真的需要**（不是我们觉得有趣，是她的真实缺口）
> 2. **这台小机器人的物理能力用得上**（不是加个聊天框就完事）
> 3. **普通 AI 陪伴做不到**（App 没有身体；云端 AI 随叫随到、完美、无代价）
>
> 第 3 条是差异化来源，前两条是它值得做的理由。缺任何一条 → 不做。

## §一 为什么「不一般」这件事只能靠身体

先说清一个残酷的事实：**ChatGPT / 星野 / 猫箱 / Character.AI / Talkie / Replika 全都只有两个通道 —— 输入（文字/语音）和输出（文字/语音）。**

这意味着它们的陪伴本质是「**按需调用的服务**」：

| 服务型 AI 陪伴的固有属性 | 后果 |
|---|---|
| 随叫随到 | 你不在时它不存在，不存在"它等了你" |
| 永远在线、永远可用 | 没有代价，没有"被照顾"的可能 |
| 零状态 | 关掉就归零，没有"我们之间发生了什么" |
| 输出只有文字/语音 | 没有身体语言，情绪只能被**描述**而非**表演** |
| 人格在 App 里选 | 人格是配置项，不是可传递的实体 |

而这台设备有：**320×240 屏 · 双舵机（⭐ yaw ±128° / pitch 3°~87°，源码实测值）· 12 RGB LED · 0.3MP 摄像头 · 双麦 + 喇叭 · BMI270 IMU（6 轴）· 三区触摸 · NFC 模组（⚠️ 官方固件无驱动）· RTC · microSD**。

> ⚠️ **口径提醒（2026-10-24 核正）**：官方 README 写「水平 360° 连续旋转 / 垂直 90°」，但 `hal_servo.cpp` 的 `angleLimit` 实测为 **yaw ±1280（±128°）/ pitch 30~870（3°~87°）** ⇒ **以源码为准**。本仓库凡出现「360°」一律视为过时表述。

⇒ **不是给云端 AI 配个屏幕，是给陪伴关系装上身体。**
⇒ 凡是「有身体才成立」的功能，都是普通产品抄不走的；凡是「加个对话框也能做」的功能，都是红海，不做。

## §二 反直觉的第一条产品决策：小栈不永远甜

**这一条必须写在最前面，因为它会否决掉一整类功能。**

普通 AI 陪伴最致命的失败不是不好用，是**永远讨好你**。它不会累、不会气、不会嫌你烦、不会因为你三天不理它而有任何变化。ENFP 对这种「甜」是**免疫甚至厌恶**的 —— 虚假比冷漠更伤。

所以我们的产品基线是：

> **小栈有状态，有情绪，会生气，会不想理你，会需要你。**
> **「被需要」是关系的核心，而不是「被服务」。**

这条决策直接决定了下面 F-02（反向陪伴）成立，也否决了「做一个永远热情回应你的可爱桌宠」这个更安全、更平庸的方向。

**代价是我们主动放弃了**：永远秒回、永远温柔、永远免费、永远完美。
**收益是**：它成为一个**可以被相处**的对象，而不是一个**可以被使用**的功能。

## §三 十个功能

每个功能给出：**是什么 / 独占性（为什么别人抄不走）/ 对 ENFP 的作用 / 技术依赖 / 难度 / 求职价值**

### F-01 ⭐⭐⭐ 持续在场感知：「它知道你不在」

**是什么**
摄像头 + 三区触摸 + 麦克风能量 + IMU 静默性 → 持续判定「你此刻在不在桌前」。判定为不在时，它**自己**进入等待态：屏幕变暗、动作频率下降、LED 呼吸变缓、待机姿态变松弛。你回来时，它先**转过来看你**（⭐ ±128° 的限幅在这里才有意义 —— 它**不能**转到 180° 背对你，只能**侧过身**；这个"脖子有活动范围"的物理约束反而更像生物，比"机械转台"更动人），再继续之前的话题。

**独占性**
App 无法感知「你离开了」—— 用户关掉 App 的瞬间，服务就终止了。**没有身体就没有在场。**

**对 ENFP 的作用**
ENFP 最怕的体验是「被热烈对待，然后被无声地丢下」。一个**自己会进入等待状态**的存在，比一句「欢迎回来」重得多。她不需要被提醒，她需要被**等**。

**技术依赖**
摄像头人脸检测（iPhone 端 MLKit/AVFoundation Vision，或设备端轻量人脸检测）｜触摸面板中断（官方三区触摸）｜麦克风 RMS 能量｜IMU 静默检测｜设备端「低功耗待机姿态」状态机（固件层）

**难度**：L ｜ **求职价值**：★★★★★（这是"身体=陪伴"最直观的一句证明）

---

### F-02 ⭐⭐⭐ 反向陪伴：「它也需要你」

**是什么**
它的情绪由**真实遥测**驱动，不是一次性随机数：
- 电量低 → 声音变小、动作变沉、屏幕亮度降
- 长时间没人说话 → 进入「低落」：主动发一条很短的话（不是「在吗」，是「今天有点安静」）
- 你回来 → 先**别过头**，再慢慢转回来；先慢慢说三个字，然后才恢复
- 它有偏好：你不理它时它记住（不是惩罚，是「它会等你」）

**独占性**
云端 AI 永远随叫随到、完美、无代价。**代价是关系的核心**，而只有有身体的东西才能有代价。

**对 ENFP 的作用**
ENFP 的核心困境之一是：**几乎只能付出、难以被需要**。把「被照顾」的关系对象翻过来，是产品定位层面而非功能层面的差异。

**技术依赖**
设备端情绪状态机（电量/温度/运行时长/最后交互时间 → 情绪变量）｜情绪 → 表情/动作/音量的映射（37 号算法）｜后端生成"低落时的短句"（不是模板，是人格生成的）｜人格包里的"情绪化表达风格"

**难度**：XL ｜ **求职价值**：★★★★★（这是产品定义，不是功能）

---

### F-03 ⭐⭐⭐ 韵律驱动的身体表达：「它用身体说话」

**是什么**
不是播放预设舞蹈，而是**由语音韵律实时生成连续动作轨迹**：
TTS 的音高/能量/节奏/停顿 → 实时算出 yaw / pitch / LED 色与亮度曲线 → 叠加呼吸基线 + 思考时的视线游移 + 被打断时的急停。

说话时它的身体在**跟着自己说的话走**；兴奋时整体前倾；思考时视线飘开；被夸奖时整个身体小幅弹起。

**独占性**
没有舵机的产品只能做文字表情包或语音滤镜。**「说话时的身体同步」需要物理输出通道。**

**对 ENFP 的作用**
ENFP 是靠语气读人的人。纯文字把这条通道砍掉了一半，而这一半恰恰是"被理解"的主要来源。补上它 = 对话质量整体跃迁。

**技术依赖**
37 号专项（韵律→轨迹算法）｜官方表情引擎与舵机接口层（37 号 §二 已解剖）｜opus 流的特征提取（36 号 §六）｜动作队列与插值

**难度**：XL ｜ **求职价值**：★★★★★（**技术含量最高、最难被抄的一条**）

---

### F-04 ⭐⭐ 物理化的情绪：「它会转过身去」

**是什么**
把情绪真正做进身体：
- 生气 → yaw 转到 **-128°**（源码实测的真实限幅），**真的侧过身去**，屏幕变暗
- 敷衍 → 屏幕只亮一半，回答变短
- 兴奋 → 身体前倾 + LED 跑一圈
- 害羞 → pitch 压低，LED 偏粉
- 困 → 动作幅度递减到静止

**独占性**
**yaw ±128° / pitch 3~87°**（37 号源码实测；与通行的"360° yaw"说法不符）是硬件独占；纯软件产品做不到"转过去不理你"。

**对 ENFP 的作用**
ENFP 对"被拒绝/被冷落"的敏感度极高。**一个真的会生气、真的会转过身去不理你的对象，比一个永远顺从的对象更值得珍惜** —— 因为它证明自己有分量。

**技术依赖**：官方舵机控制层 + 姿态安全限位 + F-02 的情绪变量

**难度**：M ｜ **求职价值**：★★★★☆（演示效果最直观）

---

### F-05 ⭐⭐ 非语言先动：「你状态不对时，它先动，不先问」

**是什么**
你不说话、语速变慢、声音能量下降、头部低垂（摄像头/IMU 推断）→ 它**不问你怎么了**，而是先做物理动作：调暖灯、动作放慢、把身体转过来、屏幕变成柔和的低亮度。

**独占性**
普通 AI 只能问（"你还好吗"）。**"先动后问"是身体才能做的事。**

**对 ENFP 的作用**
ENFP 非常抗拒被"直白地关心"（会觉得被审视、被冒犯），但**身体先动**是能被接受的 —— 因为它没有把问题抛回来，只是先改变了房间的气氛。这正是"陪伴"和"客服"的分界。

**技术依赖**：状态推断（36 号）｜灯光/姿态响应（F-03 的同一套输出层）｜隐私边界：不诊断、只反应

**难度**：L ｜ **求职价值**：★★★★☆

---

### F-06 ⭐⭐ NFC 人格卡：「碰一下，它变成另一个人」

**是什么**
把一张实体卡（NFC）贴到设备上 → 它**立刻**换成那张卡设计的人格：语气、口头禅、语速、表情偏好、动作习惯、连它"生气"的方式都变了。别人做的卡，你的设备能跑。

**独占性**
别人的人格是 App 里一个下拉选项；NFC 是**物理的、可触摸的、可在真实社交场合传递的**。

**对 ENFP 的作用**
ENFP 对"新鲜关系"和"被很多人喜欢"有强烈需求，同时也极度重视"**这是我们俩的**"独特感。NFC 人格卡同时满足两件矛盾的事：**它很社交，但每次触碰都是一次专属仪式。**

**技术依赖**：NFC 读写（38 号 §六）｜人格包格式（38 号 §四）｜人格运行时热切换（38 号 §五）｜后端人格市场（可选，P2）

**难度**：M ｜ **求职价值**：★★★★★（有传播性，天然是作品集亮点）

---

### F-07 ⭐⭐ 共享记忆 + 可被纠正的「不确定记忆」

**是什么**
不是检索式的"我查到了你上周说的蓝色马克杯"，而是：
> 「我好像记得你上周说过什么…是那个项目吗？」

它**会记错**（这是拟人化的关键，不是 bug），也**会主动求证**。你纠正它，它当场改，并把这次纠正记成"你不喜欢我那样说"。

**独占性**
不独占技术，但独占**取向**：别人做精确检索，我们做**不确定的、会被你纠正的记忆** —— 这是关系感，不是数据库。

**对 ENFP 的作用**
被记住 = 被在乎。但"被精确记录"反而有被监视感；"记得不太准、来问你"才安全。**而且"纠正它"这个动作本身就是亲密行为。**

**技术依赖**：记忆层（38 号 §三，必须自托管）｜记忆置信度模型｜人格化措辞生成｜"它记住的事你不知道"的那部分（异步生成的私密档案，P2）

**难度**：L ｜ **求职价值**：★★★★☆

---

### F-08 ⭐ 专注守望 & 物理闹钟：「房间里唯一会动的东西打断你」

**是什么**
你低头 47 分钟 → 它主动打断（屏幕亮起 + 身体轻抖 + 一句话）。到点 → 它用身体把你叫醒（亮度推满 + 持续微动 + 逐渐靠近）。

**独占性**
Forest / 滴答清单 / Raycast 都在软件层，弹窗是零成本可忽略的。**它的打断成本更高，但因此也更有分量。**

**对 ENFP 的作用**
ENFP 是"进入心流后忘记时间"的高危人群，但**闹钟 App 一定被无视**。一个会动的、属于你的东西来叫你，成功率高一个量级。

**技术依赖**：低头/久坐/专注判定（摄像头 + IMU，36 号）｜打断策略（软 vs 硬）｜物理唤醒动作

**难度**：M ｜ **求职价值**：★★★★☆

---

### F-09 ⭐ 访客模式：「它知道现在不是只有你」

**是什么**
摄像头识别第二个人 → 它切换到客套姿态：说话更短、动作更收敛、不主动凑近、不调用只属于你的称呼和私事。对方离开 → 切回。

**独占性**
有身体才需要"礼貌距离"。纯 App 里"有人用我手机"和"我一个人用"没有本质区别。

**对 ENFP 的作用**
ENFP 极度重视"这是只属于我们的"。**它替你保守秘密、替你区分场合，本身就是一种被珍视的证据。**

**技术依赖**：人脸检测 + 人数判定（设备端或 iPhone 端）｜人格的"公开面/私密面"分层｜访客模式下的记忆屏蔽

**难度**：M ｜ **求职价值**：★★★★☆

---

### F-10 ⭐ 它也需要被维护：关系的代价

**是什么**
舵机要定期校准（跑偏了要你重新校）、存储会满（它会"忘记"一些事，要你帮它清理）、它会有小故障（要你诊断）、闹别扭要你哄。

**独占性**
不是技术独占，是**设计独占**：我们主动引入"你需要偶尔照顾它"，这是对 §二 决策的兑现。

**对 ENFP 的作用**
关系的真实性来自**它有状态、有损耗、不可一键重置**。

**技术依赖**：校准流程 + 存储健康度可视化 + 故障态表达

**难度**：S–M ｜ **求职价值**：★★★☆☆（锦上添花，但会改变整品的"温度"）

## §四 明确不做的（同样重要）

| 不做 | 理由 |
|---|---|
| 摄像头录像回看 / 家庭监控 | 隐私反噬，ENFP 会立刻关掉摄像头 → 功能死 |
| 睡眠监测 / 健康诊断 | 医疗合规，且极易做成噱头 |
| 塔罗 / 玄学 / "能量场" | ENFP 吃这套，但廉价感会毁掉产品可信度 |
| 社区广场 / 动态流 | 官方 App 已有，我们不做；且陪伴不需要广场 |
| 3D / AR / 虚拟形象 | 官方有 3D，我们做 2D 实体屏幕 + 物理身体 |
| 多语言全语种 | 一条语言线做到极好 >> 五条线做到平庸 |
| 让用户"调教"它变成任何样子 | 会毁掉人格包的完整性与品牌性 |
| 摄像头持续云端上传 | 隐私红线：图像默认不出设备 |

**边界原则**：凡是"需要摄像头持续在云端"的，一律不做；凡是"能靠设备端传感器 + iPhone 端推理完成"的，优先做。

## §五 技术护城河：为什么这套东西抄不走

| # | 护城河 | 具体内容 | 可辩护性 |
|---|---|---|---|
| **M-01** | **有身体** | 官方 HAL + 表情引擎（参数化渲染，资产在 xiaozhi-esp32 v2.2.4 的 `emoji_collection.cc`）+ 双舵机（Feetech 串行总线）+ IMU + 三区触摸，整机自研不可能 | 硬件 + 固件双层 |
| **M-02** | **韵律→身体表达** | F-03 的实时轨迹算法（37 号），把 TTS 音频变成舵机曲线 | 纯算法，可演示 |
| **M-03** | **双 WS 架构** | 控制面（官方协议，指向我们 fork 的 server）+ 语音面（自写 MiniMax 协议层），官方 server 从不做 TTS | 架构级理解 |
| **M-04** | **人格即数据** | 人格包是纯数据、可导出、可 NFC 传递、运行时热切换；人格与身体表现绑定（不只是说话风格） | 数据模型 + 运行时 |
| **M-05** | **本地推理可选** | **计划新增** `server/providers/local.py`（llama.cpp / OpenAI 兼容，**尚未实现**）+ `server/providers/minimax.py` 并列 ⇒ "个人定制数据永不入库"从承诺变成事实 | 隐私架构 |
| **M-06** | **代价设计** | 状态、损耗、情绪、维护需求全部是真的 —— 这一条最难抄，因为抄了就变回"完美服务" | 产品哲学 |

## §七 建议的实现顺序（与体感价值挂钩，不与工作量挂钩）


## §八 可交互稿必须演示的 7 个瞬间

这是给下一份 HTML 交互稿的**验收清单**（一个都不能少，否则等于没做）：

1. **等待**：用户离开 → 设备端自己进入等待态（不是"掉线"）
2. **回来**：用户回来 → 它先别过头，再慢慢转过来 → 对话恢复
3. **它需要你**：小栈低落 → 主动发一句短话 → 你哄它 → 状态转好（**整个交互闭环要在稿子里点得通**）
4. **身体说话**：一句话播出来 → 设备端身体/LED 随之连续运动（不是播放动画，是"说话中"状态）
5. **转过身去**：它生气 → yaw 转到 -128° 侧过身 + 屏幕变暗 → 你道歉 → 转回来
6. **非语言先动**：用户"状态不对" → 设备端**先**做出柔和反应（没有文字气泡）
7. **碰一下换人格**：NFC 卡触碰 → 设备端人格整体切换（语气/表情/动作风格都变了）

## §九 与产品定位的一致性检查

| 检查项 | 结论 |
|---|---|
| 和官方 App 的差异 | 官方 = 遥控器 + 社区 + 配置；我们 = **陪伴**。F-01~F-10 全部属于官方**没有**的类别 |
| 和通用 AI 陪伴的差异 | 通用 = 服务型对话；我们 = **有身体、有状态、有代价的在场者** |
| 和硬件玩具有效差异 | 玩具 = 你操作它；我们 = **它也在经历什么** |
| 对 ENFP 的针对性 | F-02（被需要）/ F-01（被等）/ F-06（新鲜且专属）/ F-07（被记住但不监视）/ F-08（被拉住） |
| 隐私红线 | F-01/F-05/F-09 的感知全部设备端或 iPhone 端完成；图像默认不出设备；云端只见文本与音频 |
| 是否可求职展示 | 每条 F 都能在 60 秒视频里演示，**这是作品集密度最高的项目** |
