## 三、⭐ 逐条取舍（这是本文档最有价值的部分）

### 3.1 ⭐⭐ 命中我们产品核心的 5 条

#### ① 「底栏嵌入常驻圆碟」（ep15 02:00）→ **这就是灵动岛 / Live Activity 的交互原型**

> 原文：*"底部导航右侧嵌着一个小圆碟，进行中轻轻浮动，暂停就停住，点击它都能回到当前面板。"*

**这不是一个 UI 技巧，这是我们 iOS 端最关键的那个系统表面，官方级的交互参照。**

| 抖音原型 | 我们的系统能力 |
|---|---|
| 底部导航右侧的小圆碟 | **灵动岛 / Live Activity**（`ActivityAttributes` / `ActivityContent`） |
| 进行中轻轻浮动 | 设备端/后台**正在听/正在想**时的活动状态 |
| ⭐ **暂停就停住** | ⭐ **这条直接印证我们的「不用跳动波形」**：**静止本身就是状态信号**。小栈不工作时灵动岛不该有任何律动 |
| 点击它都能回到当前面板 | 点击灵动岛 → 回到 App 对应页面 |

**→ 具体结论**：小栈在 iOS 上的存在感**不该由 App 内的文字标签承担**，而由灵动岛承担。App 内的脸是"近景"，灵动岛是"余光里还在"。**两处都不写字。**

#### ② 「刻度尺扫到今天」（ep13 00:47）→ ⭐ **修正了我们"不做曲线"的裁决**

> 原文：*"面板像纸质凭证滑出，时间刻度扫到今天，点击显示按钮展开完整编号。"*

我们此前的裁决是「**不做连续 7 天亲密度曲线**」（`00-总纲` 宪法 17 + `14` 号文档 §2.1 第 ② 条）。这条抖音实现给了**一个更克制的替代表达**：

| 形态 | 判定 | 理由 |
|---|---|---|
| 连续曲线（每天一个点，连成线） | ❌ **仍然不做** | 连续曲线 = 趋势 = 隐性 KPI 考核（"你今天比昨天低"） |
| ⭐ **一条时间刻度轴 + 一个"今天"的位置标记** | ✅ **可以做** | 这是**时间感**，不是**评分**。没有"昨天/前天"的对比数据，只有一个"现在在哪" |

**⭐ 具体结论**：设备端可以做「**时间刻度 + 今天的位置**」的单点表达；**绝不能**画出多天的点。
→ 这条同时**收紧了**"半圆转盘"的用法：转盘上的刻度是**档位**（亲密度/情绪强度），不是**历史**。

#### ③ 「刻度滑动调节」+「松手自动吸附到最近刻度」（ep16 00:34）→ **补强半圆转盘**

> 原文：*"拖动刻度尺调节参数，松手自动吸附到最近刻度，有清晰视觉反馈。"*

我此前只提了"设备端该用半圆转盘"，**没给出交互细则**。这条补上了：
- **必须有档位**（吸附到最近刻度）→ 连续可拖的值在 320×240 上既不精确也不优雅
- **松手必须有吸附动画**（不是松手就跳）→ 这也是我们「动效预算」里的一次性反馈动效的典型用例
- **必须有清晰视觉反馈**（当前档位高亮）

→ **设备端半圆转盘规格（草案）**：3–5 档、拖动时实时高亮、松手吸附并轻微回弹（≤200ms）、档位名以文字标出（1 个）。

#### ④ 「分步选择兴趣，每次只处理一个问题」（ep16 00:53）→ ⭐ **Onboarding 的正确形态**

> 原文：*"分步选择兴趣，每次只处理一个问题，选择过程更清晰。"*

我们的 **Onboarding 是 HIG 认可的唯一品牌位**（`20` 号文档 §2.3）。
→ **具体结论**：Onboarding **一次只问一件事**，逐屏推进；不要一次列 5 个兴趣让用户勾选（那正是我们禁的"六宫格"）。
→ 与 F9「空状态只给一个下一步动作」同构。

#### ⑤ 「进度展开 / 平时只展示关键信息」（ep16 00:13）→ 渐进披露的正确形态

> 原文：*"点击追踪展开路线，再次点击收回，平时只展示关键信息。"*

⭐ **这条几乎就是"陪伴型 App 该不该显示全部信息"的答案**：
- 平时**只展示关键信息**（默认收起）
- 点一下展开（就地展开，不跳页）
- 再点收起

→ **落到我们**：iOS 端「陪伴」Tab 的对话列表，**默认收起**：只显示"最近一句 + 一个小栈表情"；点开才显示完整对话。**不要一屏铺满气泡列表**（既违反一屏 80 字，也违反"简约 ≠ 元素少，而是元素少且其中一个很大"）。
→ 这也印证 `11-成品拆解` 里 Things 3 的「**就地展开 Expand in Place**」。

### 3.2 ⭐ 设备端可抄的 3 条

| 抖音原型 | 设备端落地 |
|---|---|
| **面板分层扶起**（ep11 00:06）<br>"按住面板，背景、图片、文字分层展开，松手后合回整块屏" | ⭐⭐ **正中我们的硬件**：官方固件有 `hal_head_touch.cc`（三区触摸 + 手势状态机）。<br>设备端：**按住小栈的头 → 表情层放大 + 状态层（情绪词）分层浮出**，松手合回。<br>这是"摸头"的视觉表达，比任何文字提示都直接。 |
| **堆叠滑动切换 + 票根左右滑整理**（ep11 00:23 / ep15 01:16） | 320×240 上的**叠卡列表**：一组同源的记忆（如"上周的 5 个片段"）叠成一摞，**左右滑分拣**（左滑=不重要 / 右滑=留下）。⚠️ 触摸目标 ≥44px，滑动需实测不误触。 |
| **按钮一分为二**（ep11 00:46）<br>"按钮一分为二，开始计时，暂停和结束操作方便" | ⭐ 我们**已经是物理版**：按住小栈说话 / 松手结束。iOS 端对应：**按住说话时**，底部浮出「发送 / 取消」两个动作按钮（不是取消整个手势）。<br>⭐ 且这条与我们的 iOS **Action Button / App Intent** 天然契合（`00-总纲` §5.2 第 6 项）。 |

### 3.4 ❌ 明确不抄的 6 条（并说明原因）

| 抖音原型 | 不抄原因 |
|---|---|
| **多选聚成一叠，可拖动操作**（ep11 00:32） | **多选 = 批量管理 = 工具型 App 范式**。陪伴产品没有"批量操作记忆"的需求，且会把界面变成"文件管理器" |
| **圆环技术弹出 / 圆环画到剩余天数**（ep13 00:32） | 圆环是**完成度/倒计时**语义 → 命中我们「不做 KPI 考核面」的禁区。设备端**不用圆环表达任何数值** |
| **标题逐行沉下再升起**（ep15 01:30） | ① 违反 F11（这是**内容替换**而非 transform/opacity）；② 我们 iOS 端没有"大标题翻页"场景；③ 与「每屏一动作」冲突 |
| **照片落下收拢成扇形 / 扇形叠滑动**（ep15 00:17 / 00:32） | 图库场景。我们是**对话**场景，没有照片流 |
| **点击翻面凭证**（ep13 01:16） | 同一位置表达第二层信息 → 与「每屏一动作 / 一屏一个想法」冲突。我们不做"翻面"型交互 |
| **拖波形调进度**（ep15 01:47） | 音频播放器场景。我们**音频是后台行为**，不做播放器 UI。<br>⚠️ 只保留它的**"松手吸附"原则**（见 3.1 ③） |

### 3.5 ⚠️ 两条需要拿捏的

| 抖音原型 | 拿捏方式 |
|---|---|
| **玻璃面板浮起**（ep13 00:16）<br>"页面模糊，半透明玻璃面板从底下浮起" | ⚠️ HIG 明确**内容层禁用 Liquid Glass**，但**浮层/Sheet 允许**。<br>→ 落地：**只用系统 material**（`presentationBackground`），**绝不手写玻璃**（HIG 官方也这么建议）。 |
| **拖波形调进度 / 圆环 / 票根**等一切"数据可视化"元素 | 我们的原则不变：**不编造数据、不做 KPI 面**。凡是"进度/完成度/剩余量"的表达，**默认不做**；只有当它表达的是**真实时间**（"现在在哪"）才做。 |

## 五、一句话总结

> 这 4 集里真正能改变我们产品决策的只有 5 条，其余 12 条对我们要么场景不符、要么撞禁区。
> ⭐ 但这 5 条的含金量很高：
> **「常驻圆碟」= 灵动岛的交互原型**（并顺手印证了"静止即状态"）；
> **「刻度尺扫到今天」= 把"不做曲线"换成了"可做单点时间标"**；
> **「松手吸附到最近刻度」= 半圆转盘的交互细则**；
> **「每次只处理一个问题」= Onboarding 的正确形态**；
> **「平时只展示关键信息」= 陪伴型列表该默认收起**。
