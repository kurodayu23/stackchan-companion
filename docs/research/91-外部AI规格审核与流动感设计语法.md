## §3 参考图设计语法（6 条）与「流动感」的物理基础

### 3.1 共同语法 G1–G6

| # | 语法 | 图上表现 | 物理来源 |
|---|---|---|---|
| **G1** | **大面积柔光网格渐变**（mesh gradient） | I1 紫→蓝→粉；I2 紫蓝；I3 绿；I4 米黄 | 3–5 个色斑叠加、边界柔和 ⇒ 视觉上「像在流动」 |
| **G2** | **玻璃/半透明瓦片** | I1 的 6 个圆角瓦片：毛玻璃 + **顶部边缘高光** + 彩色外发光 | 玻璃**折射底板** ⇒ 底板一动，瓦片上的光跟着动 |
| **G3** | **3D 渲染焦点物** | I2 耳机；I3 吉祥物+店面；I4 陶瓷花器 | 软三点布光 + 接触投影 ⇒ 有「场景感」而非「贴图感」 |
| **G4** | **有机大圆斑 / blob** | 各图底板上的柔性色块 | blob 就是网格渐变的单个色斑 |
| **G5** | **字号极端对比** | 超大标题（海报级）＋ 极小元信息（字距拉开） | 海报语法，**不是 App 语法** |
| **G6** | **极简导航 + 深色胶囊托底选中态** | I3 / I4 底栏：选中项是深色圆角托底 | ⭐ 与外部 AI 规格 N2 一致 |

### 3.2 ⭐⭐ 流动感的因果（本文最重要的一条）

> **流动感 ≠ 元素在飞。**
> **流动感 = 一个在持续变化的底板 + 若干折射它的透明层。**
> 观众看到的「动」，其实是**底板在动，被玻璃折射出来**。

推论（可执行）：
1. 要做出**很强**的流动感，**必须同时有底板和透明层**；只做其一 ⇒ 只剩「花哨」，不是「流动」；
2. ⭐ **我们已有的 `spec/02` 永远做不出流动感** —— 它规定的是「事件动效」（按下去有什么反应），**根本没有底板这个层**；
3. ⇒ 必须**给动效分两层**（事件层 / 环境层），各自独立判据 —— 这就是新增 **Q-26** 的由来。

### 3.3 采纳 / 不采纳

| 语法 | 采纳 | 说明 |
|---|---|---|
| G1 网格渐变底板 | ✅ **采纳但改造** | 我们的流体底板走**暖色相**（陶土→琥珀），**不抄紫→蓝**：C2 红线 + 用户对玫红/紫调的历史「丑」反馈 |
| G2 玻璃瓦片 | ✅ **采纳但限量** | 只给 3 个「呼吸位」；**不全屏玻璃化**（内容浮在噪声上 = 可读性风险 + C5） |
| G3 3D 焦点物 | ⚠️ **部分** | 我们**没有 3D 资产预算**，且 3D 焦点物在小屏挤压可操作区 ⇒ 用**设备端实时预览**代替（这本就是我们的差异化） |
| G4 blob | ✅ 采纳 | 底板由 3–5 个色斑构成 |
| G5 字号极端对比 | ❌ **不采纳** | Q-6 ≤ 3 级 + 必须取系统 text style；参考图是**海报**不是 App |
| G6 深色胶囊选中态 | ✅ 采纳 | 与 N2 互相印证 |

## §4 「很强的流动交互感」落地口径

### 4.1 三层模型

| 层 | 是什么 | 谁在动 | 受哪条判据管 |
|---|---|---|---|
| **L1 流体底板**（ambient） | 全屏柔光网格渐变 | **光在动**，元素不动 | **Q-26（新增）** |
| **L2 玻璃层**（material） | 浮在底板上的半透明卡片 | 自身不动，**折射出底板的高光** | `spec/02` §4.2 玻璃条款 |
| **L3 事件层**（event） | 按下/切换/转场 | 元素动 | **Q-1 / Q-2 / Q-3**（**一条都不改**） |

### 4.2 L1 流体底板的量化判据

| 项 | 数值 | 依据 |
|---|---|---|
| 周期 | **18000–24000 ms**（≤ 0.056 Hz） | 远低于 Q-5 的「持续振荡 ≥ 8 s」红线 |
| 色相跨度 | **≤ 30°**，且**跨色相**（陶土 ↔ 琥珀） | C2 的「禁止彩虹渐变」只针对 hero 卡片；底板是低饱和流体 |
| 饱和度 | **S ≤ 0.35** | 底板不能抢正文注意力 |
| 亮度极差 | **≤ 6%** | 保证任意时刻的文字对比度稳定 |
| 位移 | **≤ 4% 视口**；缩放 ≤ 1.02 | 越界会让人「找不到刚才那块颜色」 |
| 数量 | **每屏 ≤ 2 处**环境动画（底板 ＋ 最多 1 个装饰） | 「精致但杂乱 ≠ 有质感」 |
| 承载信息 | **0** —— 不得承载任何信息（Q-9） | 动效不能是唯一信息通道 |
| Reduce Motion | **完全静止**（不是降级成淡入，它是装饰，删掉不丢信息） | HIG 可访问性 |
| 降级链 | `MeshGradient`（iOS 18+）→ 多 `radial-gradient` + transform → **静态渐变**（低电量 / 省电） | Web 上每帧重绘 filter 是最常见掉帧源 |

> ⚠️ **实现红线**：底板动画**必须走 GPU 合成**（只动 `transform` / `opacity`），
> **禁止**每帧重绘 `backdrop-filter` 或 SVG `feTurbulence` ⇒ 否则中低端机必掉帧。

### 4.3 与已拍板条款的冲突裁决

| 冲突条款 | 参考图的做法 | 裁决 |
|---|---|---|
| **Q-1** 动效只有一个家族（3 档时长 / 2 曲线） | 底板持续动 = 「第 4 档时长」？ | **不算**。Q-1 管的是**事件动效**；底板是**环境动画**。⇒ **新增 Q-26：动效分两层，各有独立判据**，Q-1 一字不改 |
| **Q-5** 持续振荡周期 ≥ 8 s | 底板持续漂移 | **合规**：底板 18–24 s，且是「光场变化」不是「对象振荡」 |
| **C2** 禁止跨色相对角渐变（当 hero） | I1/I2 全是紫→蓝跨色相渐变 | **分层裁决**：<br>· **流体底板允许跨色相**（≤ 30°，低饱和）<br>· **hero 卡片渐变仍守 C2**（单色相明度渐变）<br>理由：C2 的本意是拦「廉价彩虹渐变」，不是拦「活的底板」 |
| **C1** 奶油/沙/米色默认背景 | I3/I4 正是米色/绿 | **不改**。我们的 canvas 仍是暖白纸感（`paper-terracotta` `#FAF8F5`）；参考图的米色来自「3D 渲染 + 柔光」，不是纯色底 |
| **§4.2** 玻璃只给导航与浮层 | I1 大面积玻璃瓦片 | **玻璃给「浮在流体底板之上的卡片」**，且**只有 3 个呼吸位**有流体底板 ⇒ 不做全屏玻璃化 |
| **§8.3 安静** | 图全是动态海报 | **事件层仍然安静**。⇒ 唯一的「流动作为反馈」例外：**首次进入控制台时底板从静止过渡到流动（T2 0.35 s）** |

### 4.4 L2 玻璃层的 3 个「呼吸位」

| 位 | 屏 | 为什么是它 |
|---|---|---|
| **R1** | 控制台顶部（设备实时预览 + 连接状态） | 整个 App 的「它在这儿」的锚点，最该有生命力 |
| **R2** | 对话输入区 | 唯一高频触碰区，玻璃 + 流动底板让「打字 = 有人在听」成立 |
| **R3** | 动作库顶部（当前动作 / 舞台） | 动作是「它要动了」的前一秒，最该有预兆感 |

> 其余屏（设置 / 记忆与个性 / 音乐）**纯静态底板**，保持 §8.3 的安静。

### 4.5 L3 事件层的 1 条新增纪律

> ⭐ **「合拍」纪律**：事件层的反馈动画**不得**与底板流动在视觉上打架。
> 判据：按下反馈期间，**底板不得同时发生突变**（色相/亮度阶跃）⇒ 两层各自动会互相抵消，反而显乱。
