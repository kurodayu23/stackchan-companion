## 三、⭐ 把 UI 规格变成机器可判的门禁

`tools/check_mobile_app.py`（**第 45 项门禁**）—— 15 条判据：

| ID | 判据 | 抓的是什么 |
|---|---|---|
| MO-01 | 全仓无 U+FFFD | 乱码 |
| MO-02 | Tab 恰好 3 个且是 对话/遥控/设置 | IA 漂移 |
| MO-03 | 不得再有 `pitchSlider` / `speedSlider` | 已删控件复活 |
| MO-04 | 速度 4 个圆圈、恰好 1 个默认选中 | 控件数漂移 |
| MO-05 | 初始俯仰 = 45°（JS 与 DOM 必须一致） | 三处不同步 |
| MO-06 | 摇杆死区 = 8% | 手感参数被改 |
| MO-07 | 摇杆 132 px、球 40 px | 尺寸漂移 |
| MO-08 | PWA 主题色暗色、不得回退旧浅色 `#f7f7fa` | 启动闪白 |
| MO-09 | 入口代码版本号三处一致（`index.html` / `*.js` / `sw.js`） | 改了前端用户看不到 |
| MO-10 | 摄像头面板必须 `.app-shell` 直接子级 | 被 Tab 栏压住（实测踩过） |
| MO-11 | **静态模块闭包 ⊆ `serve.py` 白名单** | 漏一个文件手机端白屏 |
| MO-12 | 图标按钮触控热区 ≥ 44 px | 触不到 |
| MO-13 | CSS 变量无「未定义且无兜底」的引用 | 计算值阶段非法 ⇒ 声明失效 |
| MO-14 | 摄像头面板默认 `hidden` | 进 App 抢注意力 |
| MO-15 | **SW 预缓存键必须与页面实际请求的 URL 完全一致（含查询串）** | 预缓存形同虚设 |

### 3.1 为什么 MO-15 要比对「查询串」

Service Worker 的缓存键是**完整 URL**。
预缓存写 `"./styles.css"`、页面请求 `"./styles.css?v=29"` ⇒ **两个键不同** ⇒ 预缓存那一份**永远命中不了**。
⇒ 判据必须比 `(路径, 查询串)` 二元组，而不是只比路径。

### 3.2 自检怎么做（不是摆设）

每条判据配一个**变异用例**：把**真实现件**复制到临时目录 → 改坏一处 → 该判据必须变红。

```
真实现件零 FAIL                       ← 健康夹具
MO-01 乱码被抓到
MO-02 Tab 数写错被抓到
MO-03 旧滑块复活被抓到
MO-04 速度档数写错被抓到
MO-05 初始俯仰写错被抓到
MO-06 死区写错被抓到
MO-07 摇杆尺寸写错被抓到
MO-08 主题色写错被抓到
MO-09 版本号漂移被抓到
MO-10 面板层级下沉被抓到
MO-11 白名单漏文件被抓到
MO-12 触控热区过小被抓到
MO-13 未定义变量被抓到
MO-14 面板默认可见被抓到
MO-15 预缓存缺件被抓到
MO-15 预缓存键缺查询串被抓到
────────────────────────
通过 17 / 17
```

> ⚠️ **写自检时踩到的坑**：变异一开始用**字面量**做（如 `'"?v=28"'`、`'"app.js",'`），
> 结果版本号一升级、清单一改格式，变异就**静默失效**（`_mutate` 返回 False 但没人看）⇒
> 全部改成**正则**驱动（`_mutate_re`），与具体版本号解耦。
> ⇒ 这正是「自检本身也要被审」的典型：**夹具失效不会被发现**。

## 四、⭐ 门禁当场抓到的 3 个真 bug

| # | bug | 后果 | 修法 | 出处 |
|---|---|---|---|---|
| **B-1** | `styles.css` 用了 `var(--text)`，**但 `--text` 从未定义** | 计算值阶段非法 ⇒ 该声明直接失效（浅色主题下拉框文字色丢失） | 改 `var(--ink)` | `prototype/mobile/styles.css` |
| **B-2** | `robot_3d.js` 引用 `GLTFLoader.js?v=27`，全局版本却是 `v=28` | SW 预缓存的那份**永远命中不了**，每次加载都走网络 | 统一到 `v=29` | `prototype/mobile/robot_3d.js:2` |
| **B-3** | SW 预缓存写 `./styles.css`，页面请求 `./styles.css?v=29` | **缓存键不同** ⇒ 预缓存形同虚设 | 预缓存键补上查询串 | `prototype/mobile/sw.js` |

修完把入口版本统一升到 **v29**（`CACHE_NAME` 同步 ⇒ 浏览器会清掉旧缓存）。
**两份副本（新仓 + 旧项目）同步修改**，避免漂移。

> ⚠️ **一个诚实的边界**：B-3 在**离线首访**场景才致命（页面请求 `?v=29` → 缓存未命中 → 断网）。
> 正常使用（先联网打开一次）之后运行时缓存会补上带查询串的副本 ⇒ **不是每天都在崩**。
> 把它写成门禁是为了**不让它继续恶化**，不是为了夸大严重性。

## 五、⭐ 新发现：Q27 两套后端

把手机端拖进仓里，一眼就看见一个**结构性问题**：

| | 提供什么 | 在哪 |
|---|---|---|
| 旧项目电脑后台 | `/gui/*`（**31 条路由**） | `D:\jss18\AI\StackChan`（跑在 17865） |
| 本仓 `server/` | 韵律 → 关键帧 → WS 设备通道 | `StackChan-main/server/` |

⇒ 手机端**依赖旧项目后台**才完整 ⇒ **作品集不能独立运行** ⇒ 求职演示时是硬伤。

**Q27 = 两套后端怎么合并**。我的建议 **③ → ①**：

1. 先把 `/gui/*` **砍到手机端真正用到的最小集**（31 → ≈ 12 条）：
   砍掉固件升级 / 音乐库 / 配网 / 工厂音色 —— 这些**本来就是桌面端的活**；
2. 最小集并进 `server/`，其余留在桌面端。

> 顺带一个数字：31 条路由里，手机端 UI **实际调用**的只有
> 设备状态 / 对话 / 屏幕程序 / 摄像头 / 固件状态 / 体验 / 记忆 —— 约 **12 条**。
> ⇒ **「砍到最小集」不是偷懒，是把职责边界画对**。
