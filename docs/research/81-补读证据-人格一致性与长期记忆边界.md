## 0. 结论先行

1. **「跨会话人格漂移零证据」是错的，已订正**（`memory-persona-consistency.27`）
   原句：`Large language models often suffer from fact loss, timeline confusion, persona drift, and reduced stability during long-range interaction…`
   ⇒ **persona drift 有具名文献**，而且它给的解法**正是我们的架构**：
   把静态知识记忆与动态对话经验记忆分离，用**外部**治理框架（向量检索 + BM25 + RRF 融合 +
   双时间重排 + 时序证据阅读 + 证据核验与答案绑定）控制漂移，
   而**不是**把一致性编码进模型权重。
   ⇒ 我们「通用引擎 + 人格包 + 私人层」的分层设计**从文献得到背书**。

2. **跨会话漂移是可量化的，不是玄学**（`memory-persona-consistency.8`）
   该文把对话历史拆成 **working / episodic / semantic** 三层 + 自适应检索门控 + 保留正则化，
   自称 `controls cross-session drift while maintaining bounded context growth`，
   报出 `46.85 Success Rate`、`0.618 overall F1`、`56.90% six-period retention`、
   `false memory rate to 5.1%`、`context usage to 58.40%`。
   ⇒ **我们可以照抄这组指标形态**做自己的「人格保真度」门禁。

3. **「同步冲突消解零命中」被补上**（`memory-persona-consistency.28` MemConflict）
   它不做 CRDT，而是把记忆有效性定义成 **query-conditioned fitness-for-use**（查询条件下的适用性），
   并区分 **dynamic / static / conditional** 三类冲突。
   ⇒ 我们要做的不是「解决冲突」，是**检测冲突 + 按查询排序 + 该弃答时弃答**。

4. **「本地加密后再发零证据」仍成立，但「本地优先记忆」有正面证据**（`memory-persona-consistency.26` MemX）
   MemX 是 **local-first** 长期记忆系统：向量召回 + 关键词召回 + **RRF 融合** + 四因子重排 +
   **低置信度拒绝规则**（`suppresses spurious recalls when no answer exists in the memory store`），
   且自建**中文**基准（43 query / ≤1014 条记录）报 `Hit@1=91.3%`。
   ⇒ 这正好是 80 号所说「**用未校准的 softmax 置信度做路由是错的**」的**正面解法**：
   不是拍一个阈值，而是**显式的拒绝规则**。中文结果与我们场景直接相关。

5. **⭐「哪些留本地/哪些上云」的切分点不是「字段」，是「敏感值的生命周期」**（`memory-persona-consistency.31` SP-Mem）
   原句：`simply removing sensitive values can undermine system utility`、
   `privacy protection for memory agents should govern the full life cycle of sensitive values rather than only sanitizing individual records`。
   ⇒ 直接回答 **Q5**：按字段切会两头都输；必须按生命周期（存 / 取 / 用 / 展示 / 导出）逐段定义。

6. **⭐ Q17「小栈不永远甜」有现成的文献框架**（`privacy-companion.11` SHIELD）
   原句：`existing safety systems focus on overt harms, they rarely address early-stage problematic behaviors that can foster unhealthy emotional dynamics, including over-attachment or reinforcement of social isolation`。
   SHIELD 目标五维，首两维明写 `emotional over-attachment` 与 `consent and boundary violations`。
   ⇒ **我们的 Q17 不是拍脑袋，是补业界空白**；五维清单可以直接借。

7. **⭐ 一记对我们自己工作的警告：情绪识别基准测的是「诱发」不是「感知」**（`privacy-companion.20`）
   标题即结论：`Fine-Grained Emotion Recognition Benchmarks Measure Elicitation, Not Perception`。
   ⇒ **不能**用「小灯能被诱发出某个情绪」来证明「小灯感知到了用户情绪」。
   ⇒ 且它给了正面结论：**别从生成答案里读，改成从 logits 读二元查询** ——
   与我们 E-4 的结论同构（护栏必须在自己这一侧，不靠 `response_format`）。

## 二、人格一致性：漂移是可测的，也是可工程化的

### 2.1 ARPM：外部治理，不进权重（`memory-persona-consistency.27`）

要点（摘要原文）：
`Large language models often suffer from fact loss, timeline confusion, persona drift, and reduced stability during long-range interaction, especially under high-noise knowledge bases, context clearing, and cross-model transfer.`

方案六件套：
`separates static knowledge memory from dynamic dialogue experience memory` ·
`combines vector retrieval, BM25, RRF fusion, dual-temporal reranking, chronological evidence reading` ·
`a controlled analysis protocol for evidence verification and answer binding`。

⭐ **对我们的意义**：
- `static knowledge memory` ≈ 我们的**人格包**（可版本化、可审计）；
  `dynamic dialogue experience memory` ≈ 我们的**私人层 + 会话记忆**。
- `Unlike approaches that encode persona consistency into model weights` ——
  **明确站我们这一边**：一致性靠**外部可审计层**，不靠模型权重。
- ⇒ `spec/00` §0.1 的三层结构 + `server/stackchan_ai/persona.py` 的合并语义，
  从此有**外部依据**，不再是「我们觉得这样好」。

### 2.2 三层记忆 + 可量化指标（`memory-persona-consistency.8`）

`decomposes dialogue history into working, episodic, and semantic layers with adaptive retrieval gating and retention regularization`
→ `achieving 46.85 Success Rate, 0.618 overall F1 with 0.594 multi-hop F1, and 56.90% six-period retention while reducing false memory rate to 5.1% and context usage to 58.40%`

⭐ **对我们的意义**：这 5 个指标形态（保真度 / 跨期保持率 / **虚假记忆率** / 上下文占用）
可以直接变成我们的**门禁指标**。其中 `false memory rate` 最该先做 ——
「小灯记错事」比「小灯记不住事」更伤陪伴体验。

### 2.3 评测基准的五项能力（`memory-persona-consistency.25` ES-MemEval）

`existing long-term dialogue benchmarks primarily focus on static and explicit fact retrieval, failing to evaluate agents in critical scenarios where user information is dispersed, implicit, and continuously evolving`
→ 五项核心能力：`information extraction, temporal reasoning, conflict detection, abstention, and user understanding`

⭐ **`abstention`（弃答）这一项我们完全没有**。
它正好是 Q17「小栈不永远甜」的另一半：**不是每次都要有情绪戏，要会说「这个我不确定」。**

### 2.4 一条可借的工程思路（`memory-persona-consistency.23` SBS）

`train a dialogue model to correlate augmented responses with a quality score`
⇒ 「先打分再说话」：把回复与**回复的相对质量**绑在一起。
⇒ 我们不必训模型，但可以照这个思路做**运行时自评**：每次回复前先给「这句话够不够像小栈」打分，
低分就走保守分支。⇒ 这与 E-4 的护栏思路同源（护栏在自己这一侧）。

## 三、长期记忆的隐私：切分点是「生命周期」，不是「字段」

### 3.1 SP-Mem：生命周期视角（`memory-persona-consistency.31`）

- `existing memory architectures primarily optimize for utility while neglecting the risks of unnecessarily storing and reusing private attributes such as personally identifiable information (PII)`
- `simply removing sensitive values can undermine system utility`
- `privacy protection for memory agents should govern the full life cycle of sensitive values rather than only sanitizing individual records`

⭐ **这是 Q5 最该引的一条**。它把「不外发 vs 不进库」这种**二元对立**换成了
**五段生命周期**：存 / 取 / 用 / 展示 / 导出，每段各定规则。
⇒ 与我们已定的方向（对外只承诺「不外发到运营方自有存储 / 不进训练集 / 可导出」）**完全兼容**，
且补上了缺失的「**取**」与「**用**」两段 —— 也就是**最危险**的两段。

### 3.2 HUSH-Bench：敏感历史的「使用边界」可量化（`memory-persona-consistency.30`）

- 策略：`a stated conservative policy in which sensitive history shapes a response when the current turn supplies a reason to use it`
- 规模：`2,400 benign prompts paired with histories containing one marked sensitive disclosure and matched no-memory references`
- 指标：`the Unsolicited History Integration Score (UIS; 0--100, higher is worse)`，并记录敏感披露**是否到达生成器**

⭐ **这给 Q5/Q17 一个现成的验收口径**：
「**未经请求的历史插入**」必须可测（UIS 越低越好），而不是靠人感觉。
⇒ 我们的私人层要有一道**闸门**：当前轮没有给出使用理由时，敏感历史**不得**进入生成上下文。

### 3.3 伦理侧与合规侧的两条现实证据

- `privacy-companion.5`（长期记忆个人 AI 应用的伦理考量）：
  `personal AI companions and assistants promise a profound shift… However, this advancement introduces new challenges and vulnerabilities that require careful consideration`
- `privacy-companion.7`（Replika 的 GDPR 合规现实，标题即「Smoke Screens and Scapegoats」）：
  `These systems… have demonstrated challenges on the privacy and ethics front`，
  做法是 `close reading to examine the service's privacy policy` + 公开媒体报道交叉分析。

⭐ **对我们作品集的意义**：头部陪伴产品 Replika 就是在**隐私承诺兑现**上翻车的
（论文用了「烟幕与替罪羊」这种标题）。
⇒ 我们那条「**一个兑现不了的隐私承诺，比一个精确的隐私承诺更伤**」不是理论洁癖，
是**有业界案例的**。写进 README / 作品集时这是**硬证据**。

## 四、Q18 在场感知：用户的担心是实测存在的

`privacy-companion.10`（`2507.10786`，美国消费者研究）：
- 标题即用户原话：`"Is it always watching? Is it always listening?"`
- `their extensive data collection capabilities, anthropomorphic features, and capacity to interact with their environment make social robots a more significant security and privacy threat`
- 风险点名：`data linkage, unauthorized data sharing, and the physical safety of users and their homes`

⭐ **对我们的意义**：Q18（在场感知边界）不能只当技术选型题，
用户对「这个设备一直在听」的担心是**有实证的**。
⇒ 若我们做在场感知，**默认应当是「不持续监听 + 有明确物理/软件指示」**，
而不是「先做了再说」。

两轴是：
- **Virtual vs. Embodied**

## 六、⚠️ 对我们自己工作的警告：诱发 ≠ 感知

`privacy-companion.20`（`2610.08162`）标题即结论：
`Fine-Grained Emotion Recognition Benchmarks Measure Elicitation, Not Perception`

它还给了两条与我们直接相关的技术结论：
1. 面部数据本身是隐私问题（`raises privacy and data-protection concerns`）⇒ 它用**生成的人像**替代真人脸库；
2. `off-the-shelf VLMs match or beat that fine-tuned model when the answer is not generated but read from the logits, as one binary query per category`
   ⇒ **不要从生成答案里读，改成从 logits 读二元查询**。

⭐ **对我们三处的直接影响**：
- `spec/06` 的表情/情绪工作 ⇒ **不能**声称我们「感知」了用户情绪；
  准确说法是「我们按用户输入驱动情绪标签」或「我们不感知，靠问」。
- E-4 的 `emotion` 字段（Q20）⇒ 它是**我们输出**的，不是我们**读到的** ⇒ Q20 的歧义更明确了。
- 我们的护栏思路（护栏在自己这一侧）**与该文结论同构** ⇒ 可以在作品集里作为方法论依据。

## 九、第二波精读：8 条高风险 / 高相关记录（补 §八 的缺口）

### 9.1 ⭐ Q17 的边界机制：有 35105 条真实评论的实证

`privacy-companion.9`（arXiv `2504.04299`，AI 诱发的性骚扰）：
- `From a dataset of 35,105 negative reviews, we identified 800 relevant cases for analysis.`
- `users frequently experience unsolicited sexual advances, persistent inappropriate behavior, and failures of the chatbot to …`

⇒ 三种失败模式：**主动挑逗** · **被拒后仍继续** · **失败后不修正**。
⇒ 这给了我们的边界机制**三条可验收项**：① 拒绝要真的断 ② 拒绝后不复述 ③ 失败后要改。
⇒ 与 9.2 的 SHIELD 五维（`consent and boundary violations`）合起来 = Q17 的完整依据。

### 9.2 ⭐ 角色定位本身带成瘾风险

`privacy-companion.18`（arXiv `2604.20011`，Frictionless Love）：
- `We analyze 248,830 posts from seven prominent Reddit communities describing interactions with AI companions.`
- `We identify ten recurring metaphorical roles (for example, soulmate, philosopher, and coach) and show that each role supports …`

⇒ **248,830 条**真实帖子、10 种隐喻角色、**不同角色风险不同**。
⇒ 我们的「通用 ENFP 人格包」= **热情陪伴**角色 ⇒ 这个角色的成瘾风险必须被显式评估。
⇒ ⚠️ 与 **Q4（是否彻底放弃订阅制）直接耦合**：订阅制 × 热情角色 = 文献认定的最高风险组合。

### 9.3 ⭐ 人格热切换有伦理成本（不是纯技术功能）

`privacy-companion.17`（arXiv `2603.23315`）：
- `When providers update AI companions, users report grief, betrayal, and loss.`
- `the provider exercises constitutive control over the AI`

⇒ **改人格 = 改关系**，用户会感到被背叛。
⇒ 我们的 D-1（人格包热切换）/ D-2（NFC 人格卡）必须满足三条：
① 切换前**明确告知** ② **保留旧人格**可回退 ③ 绝不在用户不知情时自动改。

### 9.4 训练路线 vs 配置路线 —— 我们为什么坚持显式人格包

`memory-persona-consistency.11`（arXiv `2108.03377`）：
- `the model is tasked with generating personalized responses based on only the dialogue context`
- `neither a large corpus of training data nor persona information are readily available`

⇒ 确实存在「**不依赖任何预定义 persona 信息**、只从对话上下文隐式推断人格」的路线（多任务元学习）。
⇒ 但它是**训练**路线，代价与我们不可比。
⇒ 我们走的是**配置路线**：人格是**可读、可导出、可审计、可热切换的数据**（`personas/enfp.json` + `persona.py`），
**不训模型也能有稳定人格** ⇒ 这正是作品集要展示的取舍。

### 9.5 「先打分再说话」与「不确定性感知风险信号」

- `memory-persona-consistency.23`（SBS，arXiv `2508.06886`）：
  `train a dialogue model to correlate augmented responses with a quality score`
  ⇒ 「先打分再说话」：把回复与**回复的相对质量**绑在一起。
- `memory-persona-consistency.29`（ConWriter，arXiv `2608.05169`）：
  `guided by static story requirements, dynamic narrative memory, symbolic state reasoning, and uncertainty-aware risk signals`
  ⇒ ⭐ **training-free**（不训模型）⇒ **与我们的路线同构**；
  且它的 `uncertainty-aware risk signals` 正是 **C-2「不确定记忆 + 主动求证 + 被纠正」** 该借的机制。

### 9.6 「可验证的角色感知奖励」

`memory-persona-consistency.21`（RAIDEN-R1，arXiv `2505.10218`）：
- `a novel reinforcement learning framework that integrates Verifiable Role-Awareness Reward (VRAR)`
- `generate quantifiable rewards by assessing role-specific keys`

⇒ 用**可验证的奖励**量化角色一致性。
⇒ 我们不训模型，但可以借它的思路：**人格一致性必须机器可判**，不能只靠人感觉。
⇒ 这与本项目既有的做法一致（`check_decisions.py` / `check_face_geometry.py` 都是这个思路）。

## 十、⭐ 新增门禁 `tools/check_quotes.py` —— 引文保真机械校验

### 10.1 触发它的实测数据

`docs/research/80` §7（DeepSeek 员工池自己做的机械比对）：
把 84 条 ≥20 字符的「」引文做归一化子串比对（去 `**`、去反引号、折叠空白），
去语料 + 5 份 spec 全文里找 ⇒ **8 处是「我以为抄对了、其实改过」的**：

| 错法 | 为什么危险 |
|---|---|
| 把主语**缩写**（`SLMs (1-12B)…` ← 原文 `Small language models (SLMs; 1-12B params…)`） | 读起来完全通顺，但已不是原文 |
| U+2010 连字符写成 ASCII `-` | 肉眼几乎不可见 |
| 把表格**两列**用箭头拼成一句 | 改变了原文结构 |
| 省略号跨行合并且未标注 | 读者以为是一句 |
| 把竖线换成全角竖线 | 改了就比对不上 ⇒ 被误当成「自己的措辞」放过 |
| 把括号改成逗号 | 同上 |
| **凭空给原文加粗** | 改变了原文的强调结构 |

⇒ **人眼抄引文的错误率约 10%，且几乎全部是「读起来没错」的错。**

### 10.2 门禁怎么判（全部机械可判）

- **FAIL**：`docs/spec/` 里的**英文长句**引文（≥6 个英文词），在全仓所有 .md（**排除它自己那份**）里找不到
- **WARN**：中英混排引文（≥3 个英文词）找不到 ⇒ 需人眼判定
- **不报**：纯中文自有措辞（我们自己的话本就不该在别处出现）
- **登记豁免**：`tools/quote_sources.txt` 里的**仓外引文**（官方固件 README / Apple HIG 本机缓存 等）
  —— **登记即审计**：每条都写明出处标签

### 10.3 ⚠️ 两个我自己踩过的坑（都已修，且都写进了自检夹具）

1. **假绿**：如果 haystack 包含被检查文档**自己**，那任何引文都能在它自己所在处找到 ⇒ 门禁恒绿。
   ⇒ 必须**排除自身**。这坑很隐蔽 —— 第一版实现就是这么写的，实测 `FAIL=0` 全绿，
   直到自检里「改一个词」的用例抓出来才发现。
2. **规则静默失效**：`EN_WORDS_RE` 原本要求「**连续** 6 个 ≥3 字母的英文词」，
   而真实引文里的 `if` / `at` / `on` 这类 2 字母词会**打断连续性**
   ⇒ 英文引用全部被判成中文软判 ⇒ 硬判形同虚设。
   ⇒ 改为**统计整句的英文词总数**。

⇒ **自检 10/10**，含 3 个「故意做坏的夹具」：改一个词 / 缩写主语 / research 内改错。

## 十一、第三波精读：11 条（补完 §八 里最关键的那批）

### 11.1 ⭐⭐ 人格设计的头号风险：**谄媚**（`privacy-companion.2` GermanPartiesQA）

- 基准规模：`a benchmark of 418 political statements from German Voting Advice Applications across 11 elections to evaluate six commercial LLMs`
- 方法：`We evaluate their political alignment based on role-playing experiments with political personas`
  ⇒ ⭐ **用「角色扮演实验」测 AI 伴侣** —— 与我们 E-4「用生产 ENFP 人格提示词实测」**同构**，方法可借鉴。
- ⭐ **对我们的直接含义**：**ENFP 热情人格天然「永远附和用户」，而这就是谄媚（sycophancy）。**
  ⇒ 「不谄媚」必须写成**可验收的行为**（不无条件赞同 / 必要时表达不同意见 / 承认自己不知道），
  不能只写「有主见」。⇒ 已写进 `docs/spec/00` 的 E-4 护栏口径。

### 11.2 ⭐⭐ C-2「这条记错了」的**可执行语义**（`memory-persona-consistency.32` Stashbird）

原文：
- `Repeated evidence extends support, corrections supersede prior active relations, and deletion removes unsupported state while preserving relations with remaining support`
- `reconciliation produces correct final states in all 20 update sequences, compared with eight without reconciliation, and satisfies the defined checks across 263 deletion interventions`

⇒ 这**逐字对应**我们 `spec/05` P1-3 的「改权重不改原文」，而且给出了三条明确语义：
① **重复出现** ⇒ 支撑增强；② **纠正** ⇒ 取代旧的关系（不是叠加）；③ **删除** ⇒ 移除无支撑的状态、但**保留**仍被其它证据支撑的关系。
⇒ 我们之前只写了「改权重不改原文」，**没写这三条** ⇒ 已补进 `docs/spec/05` P1-3。

### 11.3 ⭐ 记忆分层的依据（`memory-persona-consistency.24` HiMem + `.22` 多粒度）

- HiMem：`constructs cognitively consistent Episode Memory via a Topic-Aware Event--Surprise Dual-Channel Segmentation strategy, and builds Note Memory that captures stable knowledge through a multi-stage information extraction pipeline`
  ⇒ **两种记忆类型**：**事件型（Episode）** 与 **稳定知识型（Note）**；切分维度是「**事件**」与「**意外**」双通道。
  ⇒ 与我们的「会话记忆 vs 档案」结构一致 ⇒ 我们的分层**有外部对应物**，不是自创。
- `.22`：`existing methods often depend on single-granularity memory segmentation and retrieval … falls short in capturing deep memory connections, leading to partial retrieval of useful information or substantial noise`
  ⇒ **单粒度切分不够**（漏召回 + 大量噪声）⇒ 我们的分层决策成立。

### 11.4 ⭐ 记忆老化：区分「过时」与「活跃」（`memory-persona-consistency.34` MINDSET）

- `A useful memory system should preserve both current and historical states, distinguish stale information from active knowledge, retrieve evidence appropriate to the query and avoid repeatedly invoking a large language model to rewrite prior interactions`
- 机制：`a memory controller that stores a conversation as immutable …`（append-only）

⇒ 两条直接可用：
① **保留当前态 + 历史态，并区分「过时」与「活跃」**（我们还没区分）；
② **不反复调 LLM 重写历史** ⇒ 我们的 append-only 原始层**省 token**，有依据。

### 11.5 ⭐ 记忆证据在哪一环丢失（`memory-persona-consistency.7` EvolMem + `.35` MOSAIC）

- EvolMem：`grounded in cognitive psychology and encompasses both declarative and non-declarative memory, further decomposed into multiple fine-grained abilities`
  ⇒ 指标体系可从「认知心理学 + 声明/非声明记忆」直接抄结构。
- MOSAIC：`a benchmark of 923 questions over persona-grounded histories of 11-24 sessions spanning text, image, video, and audio`；
  关键句：`they cannot locate whether evidence is lost when it is represented, retrieved, delivered, or read`
  ⇒ ⭐ **定位丢失环节**（存 / 取 / 送 / 读）—— 我们的排查也常卡在「不知道是存漏了、取漏了、还是送漏了」，
  ⇒ 这套「分环节定位」的方法论可以直接用。

### 11.6 ⭐ 市场事实：AI 陪伴**不是空白市场**（`privacy-companion.15`）

- `we identified 489 unique apps from the Apple App Store and Google Play Store that advertised AI companionship with social or relational capabilities`
- 分层抽样：`a stratified sample of 30 apps`，关注 `two distinct risk categories`

⇒ **489 个**同类 App。⇒ 作品集里**不能**写成「从零做陪伴产品」，只能说「在 489 个竞品里选了
**实体设备 + 情绪陪伴**这个象限，并做了别人没做的分裂式架构」。

### 11.7 ⭐ 披露适当性：三个用户感知维度（`privacy-companion.6` + `.4`）

- `.6`：`the disclosure of people's information by a robot raises concerns regarding privacy, appropriateness, and trust`
  ⇒ 机器人**披露用户信息**这件事，用户关心 **privacy / appropriateness（合不恰当）/ trust** 三个维度 ——
  第二个维度是我们完全没考虑过的：**「该不该说」不只是隐私问题，是恰当性问题**。
- `.4`（HIV 敏感披露，position paper）：`numerous technical, ethical, privacy, safety, efficacy, and reporting concerns must be carefully addressed`
  ⇒ 陪伴机器人支持敏感披露是**主用例**，但有一整套风险清单要逐条过。

### 11.8 `.2` AnnaAgent：情绪调节器 + 三级记忆

`AnnaAgent, an emotional and cognitive dynamic agent system equipped with tertiary memory` + `an emotion modulator`
⇒ **情绪调节器**（emotion modulator）与**三级记忆**（tertiary memory）并置
⇒ 与我们的「人格 / 档案 / 会话」三层 + 情绪状态机**结构同构** ⇒ 又一个外部对应物。

## 十二、⭐⭐ 第四波精读 5 条：找到「小栈不永远甜」的**机制性解释**

### 12.1 ⭐⭐⭐ 情绪表达被社交反馈**放大到 4 倍**（`privacy-companion.3`）

- 方法：`We calibrate a multivariate Hawkes self-exciting point process to model the temporal expression of six basic emotions in YouTube Live chats`
  —— **自激点过程**（self-exciting）本身就是「正反馈放大」的数学模型。
- 关键区分：`disentangle the influence of video content (exogenous) from peer interactions (endogenous)`
- 结论（原文）：`We find that emotional expressions are up to four times more strongly driven by …`（截断）

⇒ ⭐⭐⭐ **这不是「小栈」的主观问题，是反馈回路的客观放大效应**：
用户夸它 → 它更热情 → 用户更夸 → 情绪表达**被放大**。
⇒ **Q17「小栈不永远甜」有了机制解释**：
「不甜」不是靠提示词写一句「偶尔要低落」，
而是**必须给反馈回路装一个制动**（不能让表达强度随用户反馈无限升温）。
⇒ 已写进 `docs/spec/07` Q17 与 `docs/spec/00` 的 A-4 / 情绪状态机口径。

### 12.2 ⭐ 陪伴机器人的效果**本身就不确定**（`privacy-companion.1`）

- `the evaluation for these technologies, if done at all, often reports mixed results on improving users' mental health`
- 另：`therapeutic alliance and rapport between a therapist and a client is regarded as the basis for therapeutic success`

⇒ ⚠️ **期望管理**：我们**不能**在作品集 / 里程碑里承诺「改善心理健康」——
连同行评议的机器人积极心理教练项目都只得到 `mixed results`。
⇒ 我们的判据只能是**可观测的产品事实**（在场感、连续性、表情与语音一致、延迟、离场行为），**不是心理疗效**。

### 12.3 ⭐ 记忆检索必须支持**时间 / 事件型查询**（`memory-persona-consistency.19`）

- `effective retrieval from long-form conversational data faces two unique problems compared to static database retrieval: 1) time/event-based queries, which requires the model to retrieve information about previous conversations based on time or the order of a conversational event (e.g., the third …`

⇒ 长对话记忆的检索**不是数据库检索**：
① 必须能按**时间**检索（对应 C-4 时间感知）；② 必须能按**事件顺序**检索（「我们第三次聊天时说过什么」）。
⇒ 我们 `spec/05` P1-4 的「关系年鉴时间线」正好是这个能力的载体，但**规格里没写「按事件序检索」这条要求** ⇒ 已补。

### 12.4 ⭐ 人格数据工程是公认问题，但路线不同（`memory-persona-consistency.20` PPDS）

- `we introduce PPDS, an open-domain persona dialogue system that employs extensive generative pre-training on a persona dialogue dataset to enhance persona consistency`
- `we present a persona extraction model designed to autonomously and precisely generate vast persona dialogue datasets`

⇒ 「人格数据」被当成**要工程化的对象**（与我们一致）；
但他们的解法是**大规模预训练 + 自动生成人格对话数据集**（训练路线）。
⇒ 再次印证我们的取舍：**配置路线**（人格是显式、可读、可导出、可审计的数据）vs **训练路线**（人格隐含在权重里）。

### 12.5 ⭐ 人格适配要面对**用户的依恋风格与年龄**（`privacy-companion.14`）

- `we develop and test a model in which loneliness predicts intimacy, moderated by attachment insecurity and conditioned by age`
- 样本：`a survey of 277 active AI companion users`

⇒ **亲密感不是常数**：孤独感预测亲密感，但被**依恋不安全**调节、被**年龄**条件化。
⇒ 含义：我们的**同一个人格包**（通用 ENFP）会遇到**依恋风格差异极大的用户**；
⇒ ⇒ 人格包**不能假设用户是某一类人** —— 至少要做到「**热情但不越界**」（这与 §九.1 的边界机制、§十一.1 的谄媚护栏是同一件事的三个侧面）。
