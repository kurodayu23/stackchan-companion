# 96 · 设备屏表情几何真值订正与「weight 两档」发现

> **一句话结论**：我们早期关于眼睑的两条结论**都是错的** —— 「正方形盖圆眼 ⇒ 四角漏白 27.3%」与「weight = 0 ⇒ 全闭」都来自**同心误模型**；
> 固件真值是**容器内绝对定位** ⇒ weight = 0 时露出的是**下缘月牙 25.23%**，**不会露角**。
> 顺带挖出一条更有工程价值的发现：**官方 6 情绪的 eye weight 只有两档**（全睁 / 眯眼），
> 且 **Neutral 与 Doubt 的眼睛渲染结果逐像素完全相同** ⇒ 官方表情差异其实只由 **rotation（眼角倾斜）** 承担。

- **采集日期**：2026-10-28
- **性质**：对官方固件源码的**实读 + 解析真值推导 + 逐像素渲染比对**（不是美术稿，是可与真机对拍的证据件）
- **证据件**：`tools/device_screen_sim.py`（12 条判据，含**负向对照**）＋ `assets/screenshots/device-screen/`（11 张）
- **落点**：`docs/spec/06` §0.1 新增 **C-5**、§1.2、§2.1、§9.1 #2 同步订正

## 一、为什么要做这个

`docs/spec/06` 是「小栈的脸跨端一致」的唯一规范，但它里面关于**眼睑几何**的写法一直是一句**未经实测的推测**：

> 「眼睑是**正方形**盖在**圆眼**上，中间 weight 时眼睑方角会露在圆外」——`docs/spec/06` §9.1 #2

这句话看起来合理（正方形盖圆，确实会露角），**但它假设眼睑与眼白同心**。
固件不是这么画的。于是我回源把 `eyes.cpp` 全文读了一遍，建了一个**按固件几何逐像素渲染**的仿真器，
结果推翻了自己的规范 —— 并且顺手发现了官方表情表里一条没人注意到的结构性事实。

## 二、结论一：眼睑几何的三条公开订正

### 2.1 固件真值（实读 `eyes.cpp`）

| # | 事实 | 源码出处 |
|---|---|---|
| F-1 | 眼容器恒为 **32×32**，变换锚点 (16,16) = 眼白圆心 | `firmware/main/stackchan/avatar/skins/default/eyes.cpp:29-30` |
| F-2 | 眼白是**圆**，眼睑是**正方形**（边长 = 眼白直径）；**眼睑后建 ⇒ 画在眼白之上** | 同上 `:32-44` |
| F-3 | 眼睑 y 偏移 = `-map_range(weight, 0, 100, 0, 眼睑高)` ⇒ **weight 越大越上移越睁** | 同上 `:75` |
| F-4 | 眼睑定位方式 = `align(CENTER)` 之后 **`setY(offset)`** ⇒ **容器内绝对定位**，不是「相对眼白圆心」 | 同上 `:68`、`:77` |
| F-5 | 眼白直径 = `map_range(size, -100, 100, 8, 32)`，size=0 ⇒ **20 px** | 同上 `:137` |

**F-4 是全部误解的源头**：眼白**居中于** 32×32 容器，眼睑也**居中于**容器再整体 `setY(offset)`，
所以眼睑相对**眼白圆心**的位移 = `offset − (32 − 直径) / 2` = `offset − 6`（直径 20 时）。
两者**并不同心**，差一个 6 px 常量 —— 而这 6 px 恰好决定了「露角」还是「露月牙」。

### 2.2 三条订正

| # | 原表述 | 错在哪 | 订正 |
|---|---|---|---|
| **R-1** | 眼睑正方形盖圆眼 ⇒ **四角漏白 27.3%** | 建模成「以眼白圆心为心的同心盖板」，与 F-4 不符 | 固件是绝对定位 ⇒ 眼睑只从**上方**压下来 ⇒ weight=0 露出的是**下缘月牙 25.23%**，**不会露角** |
| **R-2** | weight = 0 ⇒ 眼睑正好盖满眼白 ⇒ **全闭** | 同 R-1，是同心模型的推论 | weight=0 **不是全闭**，露出 25.23%；**weight ≥ 70**（眼白直径 20 px）才完全睁开 |
| **R-3** | weight ≥ **74** 时眼睑整体移出容器 | 阈值算错了 | 阈值是 **70**：`h = int(weight/5) + 6 ≥ 2r = 20` ⇒ `int(weight/5) ≥ 14` ⇒ weight ≥ 70 |

### 2.3 解析真值（可复算，不用跑代码）

眼白半径 `r`、眼白直径 `s`（默认 20 ⇒ `r = 10`）、容器边长 `C = 32`：

```
offset(w) = -int(s * w / 100)                      # LVGL map_range 整数截断
shift(w)  = offset(w) - (C - s) / 2                # 相对眼白圆心的位移
h(w)      = -shift(w)                              # 露出帽高
leak(w)   = cap_area(r, h) / (π r²)                # 圆被水平切线切出的帽形面积占比
```

| w | offset | shift | h | leak |
|---|---|---|---|---|
| 0 | 0 | −6.0 | 6.0 | **0.2523** |
| 25 | −5 | −11.0 | 11.0 | 0.5636 |
| 35 | −7 | −13.0 | 13.0 | **0.6881** |
| 50 | −10 | −16.0 | 16.0 | 0.8576 |
| 69 | −13 | −19.0 | 19.0 | 0.9813 |
| **70** | −14 | −20.0 | 20.0 | **1.0000**（饱和起点） |
| 100 | −20 | −26.0 | 26.0 | 1.0000 |

> 帽形面积解析式：`cap_area(r,h) = r²·acos((r−h)/r) − (r−h)·√(2rh − h²)`（`h ≤ 0` 取 0，`h ≥ 2r` 取整圆）。

## 三、结论二：⭐ 官方 6 情绪的 eye weight 只有「两档」

固件情绪表（`eyes.cpp:103-120`）与按 §2.3 推出的露出率：

| 情绪 | eye weight | rotation（原始 0.1°） | 折算角度 | 露出率 | 实际观感 |
|---|---|---|---|---|---|
| Neutral | 100 | 0 | 0° | **100%** | 全睁、平视 |
| Happy | 72 | 1550 | **155°** | **100%** | 全睁、眼角上扬 |
| Angry | 70 | 450 | **45°** | **100%** | 全睁、眼角下压 |
| Sad | 70 | −400 | **−40°** | **100%** | 全睁、眼角下垂 |
| Doubt | 75 | 0 | 0° | **100%** | 全睁、平视 |
| Sleepy | 35 | −50 | **−5°** | **68.81%** | 眯眼（唯一非全睁） |

**三条推论：**

1. **weight 只分两档**。6 个情绪里 5 个的 weight ≥ 70 ⇒ 全部落在**饱和区（100% 全睁）**；
   只有 Sleepy（35）是「眯眼」档。⇒ **weight 这个参数在官方情绪表里几乎不承载情绪信息**。
2. **情绪差异几乎全部来自 rotation**（眼角倾斜 −40° ~ 155°）。
   ⇒ 想要细腻表情，**不能指望 weight**，得用 rotation + 嘴 + 灯带。
3. **Neutral 与 Doubt 的眼睛渲染结果逐像素完全相同** —— 同为全睁、同为 0°。
   实测 SHA-256 前 16 位一致：`815e50f31f8777bf`。
   ⇒ 官方 6 情绪在**眼睛**上其实只有 **4 种**不同画面（Neutral/Doubt 合并 + Happy + Angry + Sad + Sleepy）。

> ⚠️ **这条对产品有直接影响**：风格化模式下若照抄固件情绪表，「Neutral」与「Doubt」会**看起来一模一样**，
> 用户会读成 bug。⇒ 风格化模式必须靠**嘴 / 灯带 / 气泡**把 Doubt 与 Neutral 拉开（P-1 表 B 的取值必须覆盖这一点）。

### 3.1 附带的固件事实（早已确认，本次再核）

- **嘴不受情绪影响**：`Avatar::setEmotion` 对 4 个关键元素都调 `setEmotion`，但 `DefaultMouth` **没有覆写**它，
  基类 `Element::setEmotion` 是空实现 ⇒ 6 情绪的嘴恒为 `weight = 0`（90×6 细线）。
- 嘴的 `weight = 0` ⇒ 宽 90 / 高 6 / 圆角 0 ⇒ **闭嘴**（`mouth.cpp:52-54`）。

## 四、结论三：脸只占屏 1.5%，气泡会溢出屏

| # | 实测 | 解析真值 | 含义 |
|---|---|---|---|
| F-6 | 脸占屏 **1.61%** | `(2·π·10² + 90·6) / (320×240) = 1.52%` | 屏幕**绝大部分是黑的**；「脸占屏 ≥ 60%」在**镜像模式**下根本不成立 |
| F-7 | 气泡底边 **溢出 6 px** | 容器底边 y=246 > 屏高 240 | 官方气泡**超出屏底** |
| F-8 | 气泡最大宽 **340 > 屏宽 320** | 左右各溢出 **10 px** | 长句子会**左右出屏** |
| F-9 | 两眼中心距 **140 px** | 2 × 70 | |
| F-10 | 呼吸周期 **6600 ms = 0.1515 Hz** | HIG 敏感区上限 0.125 Hz | 官方呼吸**高于**敏感阈值 ⇒ 我们的镜像是「照抄一个已知问题」 |

> F-6 的实测 1.61% 与解析真值 1.52% 差 0.09 个百分点，来自旋转矩形的**抗锯齿边缘像素**（判据容差 0.4 个百分点）。

## 十、这条发现对产品的三个直接影响

1. **风格化模式不能照抄固件情绪表的 weight**：照抄会让 Doubt 与 Neutral 同脸 ⇒ 读成 bug。
2. **细腻表情的主战场是 rotation，不是 weight**：官方 6 情绪的 weight 只分两档 ⇒ 我们的表情参数化要**优先用 rotation**。
3. **「脸占屏 ≥ 60%」这条规范只对风格化模式成立**：镜像模式的官方事实是 **1.52%**（屏几乎全黑 + 一张小脸）⇒
   规范里凡是引用「占屏比例」的文案，都必须写明是哪个模式（对应 `docs/spec/06` §7.2 的双模式分叉）。
