#### 证据 1 — ESP-DL 官方人脸检测延迟表（本轮实际抓取）

来源：`https://raw.githubusercontent.com/espressif/esp-dl/master/models/human_face_detect/README.md`

官方 Model Latency 表原文数据：

| name | input(h*w*c) | preprocess(ms) | model(ms) | postprocess(ms) | mAP50-95 |
|---|---|---|---|---|---|
| msr_s8_v1_s3 | 120*160*3 | 3.7 | 32.5 | 0.3 | / |
| mnp_s8_v1_s3 | 48*48*3 | 0.6 | 5.9 | 0.1 | 0.367(msr + mnp) |
| espdet_pico_224_224_face_s8_s3 | 224*224*3 | 7.3 | 129.4 | 0.7 | 0.504 |
| espdet_pico_416_416_face_s8_s3 | 416*416*3 | 21.8 | 422.1 | 1.1 | 0.598 |

测试条件原文：`ESP32-S3: CPU 240 MHz, data cache 64 KB, octal PSRAM 80 MHz. ESP32-S31: CPU 320 MHz, PSRAM 250 MHz. ESP32-P4: CPU 400 MHz, L2 cache 256 KB, PSRAM 32 MB at 250 MHz. int8, CONFIG_COMPILER_OPTIMIZATION_PERF.`

**与上游 41 号结论对齐**：msr(32.5+3.7+0.3=36.5ms) + mnp(5.9+0.6+0.1=6.6ms) = **43.1 ms/帧**，与上游实测的「≈43ms/帧可行」完全吻合。

**关键隐私结论（属于推断，但基于官方模型定义）**：esp-dl 的 `human_face_detect` 只输出**人脸框**，不做 identity embedding（那是另一个 example `human_face_recognition`）。因此「我们不认人，只知道有人」这一叙事**可以由官方引擎直接满足**——检测不产生可识别个人的数据。⚠️ 但注意：人脸框检测 ≠ 「有人靠近」的距离感知，人在画面里即触发。

**关键优势（属于推断）**：CoreS3 自带 Wi-Fi，**不需要新增任何硬件**，且天然满足「不认人，只知道有人」——CSI 只反映信道扰动，不含图像。与 41 号已实测的摄像头人脸检测（43ms/帧、耗电）相比，CSI 是「零新增 BOM」路线。

**关键风险（属于推断，但有 README 原文佐证）**：

1. **需要第二个 Wi-Fi 节点**（路由器/另一台设备）做收发分离，`wrlxavier` 的方案明确是「two ESP32-S3 nodes」；单机单天线 CSI 的存在判别能力受限。
2. **AGC 是已知致命干扰源**。`wisense` README 原文：

> commodity WiFi radios like the ESP32 apply automatic gain control (AGC) per packet, which can look similar to genuine motion to a naive variance-based detector. `normalize_frame_amplitude` (see `wisense/core/filters.py`) partially compensates for this, but a full correction isn't possible from the data ESP32-CSI-Tool's packet format exposes.

3. **`wisense` 本身未在真机验证**。README 原文：

> **This has been validated with unit and integration tests against synthetic CSI data, but not yet against real ESP32 hardware** — the maintainer doesn't currently have a device to test with.

4. **`WaveSight` 有部署约束**（README 原文）：必须**设备最终就位后**再标定，且路由器与 ESP32 **大致同高**，否则灵敏度下降；标定期间不能有人走过。

**WaveSight 具体可调参数（README 原文）**：

> - Someone Timeout (seconds) – how long after the last movement the system considers the room empty.
> - Move Threshold – jitter value above which movement is detected.
> - Filter Window & Filter Count – moving‑window parameters for noise reduction.
> - Click Start Calibration – the system samples for the set duration (default 60 s) and learns the background threshold.

**WaveSight 硬件前提（README 原文）**：

> - **ESP32** or **ESP32‑S2** or **ESP32‑S3** or **ESP32‑C3** board (tested on ESP32‑S3‑DevKitC‑1)
> - Wi‑Fi router (2.4 GHz) – the radar monitors the connection to your access point
> - ESP‑IDF v5.4.4 (recommended) or later

→ **ESP32-S3 官方已验证支持**，且用 `idf.py set-target esp32s3` 即可构建。

**wisense 的算法基线（README 原文表格）**：

| Module | What it does | Statistical baseline | ONNX upgrade path |
|---|---|---|---|
| `wisense.presence` | Binary presence detection | Variance-of-amplitude thresholding against a calibration baseline | Yes |
| `wisense.fall` | Fall event detection with severity/confidence | Sudden-amplitude-drop-then-stillness signature | Yes |
| `wisense.vitals` | Passive breathing-rate estimation | FFT peak detection in the 0.15-0.5 Hz respiration band | No (statistical-only) |
| `wisense.activity` | Coarse activity classification | Variance + periodicity + transient-level-shift heuristics | Yes |
| `wisense.people` | Occupant count estimation | Multipath/frequency-diversity clustering | No (statistical-only) |

依赖固件：**[StevenMHernandez/ESP32-CSI-Tool](https://github.com/StevenMHernandez/ESP32-CSI-Tool)** 兼容固件（USB 串口）。⚠️ `wisense` **不附带任何预训练 ONNX 权重**（README 明说是刻意的设计决定）。

#### ⭐ 证据 F — 🔴 源码级核查：desk-emoji **完全没有韵律驱动**，且**没有真正的关系记忆**

本轮直接读了 `desk-emoji-v3/firmware/Arduino_Esp32s3/esp32s3_v2.0.1/` 下的源码（`act.cpp` / `head.cpp` / `sensor.cpp` / `sensor.h` / `head.h` / `llm.h`），结论如下。

**F-1. 头部运动的全部来源只有两个，且都不是韵律**（`act.cpp` 原文）：

```cpp
void random_act() {
  int random_num = random(100);
  int x = random(-25, 25);
  int y = random(-10, 25);
  if (random_num < 10) { eye_happy(); }
  else if (random_num > 80) { head_move(x, y, 10); ... head_center(); }
  else { eye_blink(); }
}

void speech_act() {
  int random_num = random(100);
  ...
  if (random_num > 70) { eye_happy(); if (random_num > 90) { head_shake(); } else { head_nod(); } head_center(); eye_blink(); }
  else if (random_num > 40) { head_move(x, y, 10); ... }
  ...
}
```

⚠️ **`speech_act()` 名字里有 "speech"，但它内部是 `random(100)` —— 完全是随机，与语音内容/韵律无任何耦合。**

**F-2. 第二条路径是「LLM 直接输出动作名数组」**（`llm.h` 的 `LLM_PROMPT` 原文）：

```
## Functions
Emoji: eye_blink, eye_happy, eye_sad, eye_anger, eye_surprise, eye_left, eye_right
Animation: heart, calendar, face_id, cola, laugh, dumbbell, skateboard, battery, basketball, rugby, alarm, screen, wifi, youtube, tv, movie, cat, write, phone, sunny, cloudy, rainy, windy, snow, beer, walk, shit, cry, puzzled, football, volleyball, badminton, rice, gym, boat, thinking, money, wait, plane, rocket, ok, love
Head: head_left, head_right, head_up, head_down, head_nod, head_shake, head_roll_left, head_roll_right, head_center, delay

## Output Format
{"answer": "First-person reply in Chinese", "actions": ["function_names"]}

## Rules
- List emoji, animation, and head functions without explanation.
- First action: animation function
- Include 4-8 actions
- Return head_center after direction changes
- End with "head_center" and "eye_blink"
- Match actions to emotional content
- Eye_left/right typically follow head_left/right
- Head_nod = affirmation, head_shake = negation
- Responses: 3+ sentences, childlike enthusiasm
- Responses should be creative and humorous
- Each response should be different
```

→ 这是**「LLM 语义 → 离散动作序列」**的完整可抄模板（动作库 + 输出格式 + 规则）。**它走的是文本语义，不是韵律。**

**F-3. 舵机参数（`head.h` 原文，可直接对标我们的 yaw ±128° / pitch 3~87°）**：

```c
#define X_PIN 12
#define Y_PIN 13
#define STEP 1
#define SERVO_DELAY 10
#define X_CENTER_FILE "/X_CENTER.txt"
#define Y_CENTER_FILE "/Y_CENTER.txt"
#define X_OFFSET 25
#define Y_OFFSET 45
```

→ 中心角 90，yaw ±**25°**（65~115），pitch ±**45°**（45~135）；每步 1°，每度 10ms。`head_nod` = pitch ±20°×2 次；`head_shake` = -10/+20/-20/+20/-10（各 50ms）。**标定值存 FFat 文件**（`/X_CENTER.txt`），这是可抄的「出厂校准 + 持久化」做法。

**F-4. 存在感知用的不是雷达/摄像头，而是 PAJ7620 手势传感器**（`sensor.h` 原文）：

```cpp
#include <RevEng_PAJ7620.h>
RevEng_PAJ7620 sensor = RevEng_PAJ7620();
```

→ `handle_gesture()` 处理 `GES_FORWARD/BACKWARD/UP/DOWN/LEFT/RIGHT/CLOCKWISE/ANTICLOCKWISE/WAVE`。**这是额外的外挂手势模块，不是「有人/没人」的存在检测。**

**F-5. 记忆只有 10 轮对话历史**（`llm.h` 原文）：

```cpp
const char* HISTORY_FILE = "/chat_history.json";
const uint8_t MAX_MEM_LEN = 10;
```

→ **没有任何关系建模、没有长期记忆、没有亲密度状态。**

```json
{"type":"affection.sync.state","characterId":"char_shared_001",
 "affection":530,"syncedBaseAffection":500,"unsyncedDelta":30}
```
> ファームウェアは `characterId` ごとに `syncedBaseAffection` を保存します。未登録の `characterId` では、現在の `affection` を同期基準値として初期化します。`unsyncedDelta` は `affection - syncedBaseAffection` です。

### 4.3 `ChatCompletionsLanguageModel` 如何接任意 OpenAI 兼容 provider（源码实测）

来源：`https://raw.githubusercontent.com/apple/foundation-models-utilities/main/Sources/FoundationModelsUtilities/LanguageModels/ChatCompletionsLanguageModel.swift`

**关键实现细节（全部来自源码原文）**：

| 细节 | 源码行为 |
|---|---|
| 类型关系 | `public struct ChatCompletionsLanguageModel: Sendable, LanguageModel`；内部 `public struct Executor: LanguageModelExecutor` |
| URL 拼接规则 | 若 baseURL 路径中已含匹配 `/v\d+/` 的段 → 追加 `/chat/completions`；否则追加 `/v1/chat/completions` |
| 默认请求头 | `Content-Type: application/json`、`Accept: text/event-stream`、`User-Agent: <bundleIdentifier ?? "com.apple.FoundationModels">` |
| 自定义头 | `additionalHeaders` 合并在默认头之上，**冲突时自定义覆盖默认**（`uniquingKeysWith: { _, custom in custom }`）→ 传 `["Authorization": "Bearer \(apiKey)"]` 即可 |
| 传输方式 | SSE 流式（`data: ` 前缀逐行解析），`stream = true`、`stream_options.include_usage = true` |
| 请求体字段 | `model`、`messages`、`temperature`、`top_p`、`max_completion_tokens`、`tools`、`tool_choice`、`response_format` |
| **Reasoning 支持** | 解析 `delta.reasoning_content`，转发为 `.reasoning(entryID:action:.appendText)`；缓冲后附到下一条 assistant 消息的 `reasoning_content` 字段 → **兼容 MiniMax 的 reasoning 输出** |
| Tool calling | `delta.tool_calls` 按 `index` 路由，累积 `id`/`name`，参数增量走 `.appendArguments` |
| 结构化输出 | `response_format` = `{type: "json_schema", json_schema: {name, schema, strict: true}}`；仅当 `supportsGuidedGeneration == true` 时声明 `.guidedGeneration` 能力 |
| 能力声明 | `supportsGuidedGeneration` 为真 → `[.vision, .toolCalling, .reasoning, .guidedGeneration]`；为假 → `[.vision, .toolCalling, .reasoning]` |
| 图片输入 | Apple 平台内联为 `data:image/jpeg;base64,...`；非 Apple 平台需 URL |
| 采样限制 | Top-K 采样**不支持**（抛 `invalidRequest`）；`randomProbabilityThreshold` 带 `seed` 时抛 `invalidRequest` |
| 错误处理 | HTTP 非 200 → `RequestError.httpError(statusCode:data:)`；body 里的 error 信封 → `APIError(message:type:param:code:)` |

**最小接入代码（据源码可直接写成）**：

```swift
import FoundationModels
import FoundationModelsUtilities

let model = ChatCompletionsLanguageModel(
  name: "minimax-m2.5",                                  // 送进 model 字段
  url: URL(string: "https://api.minimax.example")!,       // 无 v<n> 段 → 自动拼 /v1/chat/completions
  additionalHeaders: ["Authorization": "Bearer \(apiKey)"]
)

let session = LanguageModelSession(model: model)
let response = try await session.respond(to: "你好")
print(response.content)
```

### 三条最关键的结论（供决策）

1. **存在感知（专题 1）**：ESP-DL **行人检测**在 ESP32-S3 上官方 **125.0 ms/帧**（ESP32-S3 CPU 240MHz / octal PSRAM 80MHz / int8），比单级人脸检测（137.4ms）更快，且**天然不含身份信息** → 直接满足「我们不认人，只知道有人」。mmWave（LD6002B）更准但需 **>1A** 供电，与 550–700mAh 电池硬冲突、且不改 PCB 不能加；Wi-Fi CSI 零新增 BOM，但 ESP32 的 **AGC 会伪装成运动**，且 `wisense` 自述**未在真机验证** → 建议**行人检测为主 + 触摸/IMU 为辅**做多源融合。
