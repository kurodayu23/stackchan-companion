## 0. 这份文档要回答的问题

我们的 iOS App 要同时是三样东西：
1. **陪伴入口**（像 Fitness 那样把"小栈的 vitality"做成主视觉）
2. **设备控制端**（像 Apple Home 那样管一个硬件）
3. **对话界面**（像……？这正是我们要避免做错的部分）

下面每个产品都标注了「**我们抄什么 / 我们不抄什么**」。

## 1. Apple Home App —— 设备控制端的天花板

### 1.1 信息架构
- **单流向下滚动 + 房间分区 + 混合网格**。
- 顶部：家庭切换（`My Home`）+ 对讲 + 全局操作（`+` / `...`）。
- 底部：**标准 3-Tab**（Home / Automation / Discover）。
- 分组维度 = **房间**（Entry / Living Room / Kitchen），每个房间标题右侧带 chevron 可下钻。

### 1.2 卡片网格（双列不对称）
| 卡片尺寸 | 用途 |
|---|---|
| 1×1 矮矩形 | 状态维度低、参数简单的设备（两个叠起来 = 一个大卡片高） |
| 2×2 大方卡 | 需要突出数字或状态的设备（门锁、温控器） |
| 全宽/半宽延展 | 复杂设备（Smart Fan） |

### 1.3 卡片字段（两种排布）
- **紧凑横向卡**：左侧圆形图标徽标 + 右上设备名（Semibold）+ 右下状态值（Regular，低透明度）。
- **焦点卡**：顶部核心指标（大号温度数值 / 大圆锁图标）+ 底部名称 + 运行状态（"Heating to 70°"）。

### 1.4 ⭐ 分体式卡片交互（最该抄的一条）
> **主要操作 = 卡片内的圆形图标徽标**（单击直接切换开/关，不跳转）
> **次要操作 = 卡片其余全部区域**（点击弹出控制面板：调光拉条、色温盘、温控滑块）

→ **同一张卡片用面积划分主次**，不用颜色/描边去划分。这是"一屏一动作"和"不堆功能"同时成立的解法。

### 1.5 开/关的视觉状态差异
| 状态 | 卡片 | 图标 | 文字 |
|---|---|---|---|
| **开启** | 亮色底（白底，高透光玻璃） | 高饱和彩色底 | 高对比度 |
| **关闭** | 半透明灰暗底（透出壁纸） | 暗色底 | 微弱灰色，层级自动后退 |

→ **"关"是靠降对比实现的，不是靠变灰**。

### 1.6 语义色绑定的是"物理属性"不是"开闭"
- 琥珀黄 = 照明开启
- 橙 = 制热
- 天蓝 = 制冷
- 青绿 = 安全/门锁（已解锁）
- 灰白透明 = 离线/关闭

→ 颜色是**领域语义**，不是状态码。这正是我们之前"三杂色纯装饰"要避免的。

### 1.7 为什么它一眼就像系统 App（拆解）
1. 严格遵循 iOS 字号阶梯与字重（Headline → Subheadline → Footnote/Caption）。
2. 卡片用系统材质（`UIVisualEffectView`：模糊 + 高光边缘 + 动态色彩混合），不是 box-shadow。
3. 顶部按灵动岛留白避让；底部是原生 Tab Bar（选中态系统高亮、非选中灰半透明）。
4. SF Symbols 视觉粗细与文本高度匹配。
5. **没有多层 elevation 阴影、没有网页式描边**，全靠材质明暗差界定边界。

### 1.8 我们抄什么 / 不抄什么
**抄**：
- 分体式卡片交互（图标徽标 = 主操作，卡片其余 = 次操作）
- 卡片尺寸按"状态复杂度"分档（1×1 / 2×2）
- 语义色绑定领域（情绪 / 电量 / 连接 / 记忆），不用装饰色
- "关"用降对比表达

**不抄**：
- 3-Tab 结构（我们只有一台设备 + 一个对话）
- 房间分区（我们只有一只小栈）
- 整屏壁纸 + 毛玻璃卡片阵列（那是"一堆设备"，不是"一个生命体"）

## 2. iOS 16 Home App —— 分组逻辑随页面深度切换

### 2.1 两种分组逻辑（很聪明，值得抄）
| 页面深度 | 分组维度 | 理由 |
|---|---|---|
| **主页（My Home）** | **物理空间（Room）** | 全屋视角时人在想"书房有什么开着" |
| **房间详情** | **设备类型（Domain）** | 进到房间后在想"客厅的灯 / 客厅的安防" |

→ 同一个信息集，**按用户当下的心智模型换维度**。我们对应：首页按"时间/状态"分（现在 / 稍后 / 曾经），进入"小栈"详情后按"功能"分（记忆 / 情绪 / 动作）。

### 2.2 四层渐进式展现
| 层 | 内容 |
|---|---|
| **L0 全局概览** | 顶部胶囊栏：`Lights 20 On` —— 既是状态指示器**也是快速过滤器**，点一下直接过滤全屋灯具 |
| **L1 区域锚点** | 半透明小标题，作为滚动视觉锚点 |
| **L2 设备状态** | 卡片表面只有"名称 + 最关键属性"（`100%` / `Off` / `Climate 70–91°`） |
| **L3 深度控制** | 点击之后才出现（调色盘、定时、详细设置） |

→ **L0 的"胶囊既是状态又是过滤器"是极高性价比的设计**，我们的小栈状态胶囊可以同样做。

### 2.3 控件形态
- 水平滚动药丸胶囊（图标 + 统计），既是状态也是过滤器。
- 双重热区 / 动态卡片（设备状态变化时卡片本体动）。

### 2.4 抄什么
- **L0 状态胶囊 = 状态 + 过滤器**（一行顶三个功能）
- **分组维度随深度切换**
- **L3 深度参数绝不在主屏暴露**

## 3. Things 3 —— 信息架构与"数字工艺品"级微观交互

### 3.1 字号阶梯（实测）
| 角色 | 字号 | 字重 |
|---|---|---|
| 大标题（`★ Today`） | ~30pt | Bold |
| 小节标题（`🌙 This Evening`） | ~16pt | Semibold |
| 任务主标题 | ~16pt | Regular |
| 辅助标签/注记 | ~13pt | Regular |

行距约 **1.3 倍**。

### 3.2 ⭐ 留白哲学："以白代线"
> 绝大多数行与行之间**没有任何硬分割线**，完全依赖行距留白与字体层级界定边缘。

→ 与我们「边框优先于重阴影」方向一致，但更进一步：**连边框都可以不要**。

### 3.3 ⭐ 就地展开（Expand in Place）
点击任务**不跳页**，而是当前行自然拉伸、卡片化浮起；关闭原路收回。**用户的认知地图不被打断。**

→ 对我们的意义：**小栈的"表情详情/记忆详情"应该就地展开，不要 push 到新页面**。这正是"陪伴感"与"工具感"的分水岭。

### 3.4 ⭐ 多巴胺微交互
勾选复选框不是"打勾变灰"，而是：轻微弹性震动（**Haptic Feedback**）+ 边框收缩 + 文字变浅 + 延时约 **0.5 秒**后平滑下沉/移走。

→ 那个 **0.5 秒延迟** 是精髓：既给成就感又保留反悔余地。

### 3.5 色彩纪律
- 背景纯白，UI 控件只有黑灰两色。
- 所有亮色**全部有严密语义**：蓝 = Inbox、黄 = Today、红 = 截止日期报警。
- 界面永远不会变成调色盘。

### 3.6 任务哲学（对我们最有价值的一条）
> 很多待办工具像监工，用满屏红色过期提示恐吓用户。Things 3 通过"今晚""未来"等柔性组织方式，**让工具退居幕后**，给用户"从容、掌控、毫无压迫感"的情绪价值。

→ 💡 **这正是小栈必须坚持的**：陪伴产品绝不能变成 KPI 考核面板。不要"你今天只摸了它 3 次"这类指标。

### 3.7 抄什么 / 不抄什么
**抄**：就地展开、0.5 秒延迟反馈、颜色语义绑定、留白代分割线、退居幕后的哲学。
**不抄**：任务管理的信息架构（我们不是待办工具）。

## 4. Things 3 on iOS 26 —— ⭐ 第三方 App 怎么正确用 Liquid Glass

**这是本次调研最有实操价值的一屏。**

### 4.1 玻璃用在哪
| 场景 | 例子 |
|---|---|
| 悬浮操作与导航锚点 | 顶部返回 `<` / 更多 `...` 的微透高斯模糊小圆底；右下角 Magic Plus 及其展开态 |
| 模态浮窗与弹层 | "When?" 排程面板 = 深色半透明玻璃悬浮于浅色列表之上 |
| 临时交互与输入层 | 系统键盘区 + 上方编辑功能快捷条 |

### 4.2 ⭐ 用量克制在 10%–15% 以内
- 主背景保持纯净纯白/浅灰单色底，**列表项是纯实色**。
- **背景完全没有做全屏模糊折射。**
- 玻璃只是"Z 轴深度"的指示物：元素脱离主内容层、进入悬浮/交互层时才出现。

→ **完全对应 HIG 原文**："Don't use Liquid Glass in the content layer"。

### 4.3 ⭐ 文字策略
- **主阅读文字坚决不放在玻璃上**（任务标题、备注、清单始终在纯色平面上）。
- 玻璃上的文字（辅助/交互）必须提高对比度：高不透明度纯白 + 中灰，字重调到 Medium/Semibold。
- **关键操作直接用实色承载**：第四屏底部的 "Clear" 按钮用**高饱和玫红实色块 + 白字**，而不是玻璃按钮。

→ **玫红实色块**这个做法和我们推荐的 iOS 端强调色 `#B33A55` / `#E8638C` 完美对上。

### 4.4 圆角与描边
- 模态浮层 **24–28pt** 连续曲率超大圆角；悬浮功能键 100% 胶囊或正圆。
- 深色玻璃弹窗与展开菜单边缘带 **0.5pt–1pt 极细半透明高亮描边**（Specular Highlight），带内发光，用于在复杂背景上界定玻璃边界。

### 4.5 ⭐ 标签栏：干脆不要
> Things 保持单列表级联结构，**完全没有 iOS 原生那种横跨屏幕底部的厚重玻璃 Dock/Tab Bar**。取代底栏的是极轻量的悬浮 Magic Plus。

→ 收益：省去常驻底栏 60–80pt 纵向空间 + 消除大面积玻璃栏的沉重感。

→ 💡 **对我们的意义**：如果首页是"小栈的脸"，就**不要底 Tab Bar**。这也和"03 业界图集"里"不用 Tab Bar 承载 8 功能"的禁止项一致。

## 5. Apple Fitness —— ⭐ "一个超级视觉核心 + 降维一切后台数据"

### 5.1 主视觉：同心极坐标进度条
- 三个维度（活动 / 锻炼 / 站立）用同心圆嵌套，占地紧凑。
- **底轨（Track）**：同色系极低明度/半透明暗轨 —— 即使没动也能感知"100% 终点在哪"。
- **端点阴影**：圆环前端有微弱投影，营造缎带重叠的微拟物景深。
- **溢出处理**：超过 100% 不停住，顺时针叠压 —— 给"超额完成"心理奖赏。

### 5.2 图形 vs 数字的分工
- **第一眼看图形（感性）**：0.2 秒内看圆环闭合度就得出定性结论。
- **第二眼看数字（理性）**：右移看 `450/800`。
- 文本内部三级：维度名（白、中字重）→ **当前值（大号粗体 + 强色，绝对焦点）** → 目标值/单位（细字重、同色系退居第二）。

### 5.3 深色底 + 荧光电泳色
- 纯黑底 `#000000` + 卡片 `#1C1C1E`，高饱和荧光红/绿/蓝产生霓虹自发光质感。
- **色彩是"身份凭证"**：红恒等于卡路里，绿恒等于时长，蓝恒等于站立，**从不混用**。
- 亮色只涂在线条与核心数字上，大面积严格留黑 → 即便对比度 15:1 也不刺眼。

### 5.4 次要信息如何弱化
- 栅格收缩：核心圆环独占顶部通栏大卡；步数/距离被压成双列小卡。
- **去色彩化**：次要卡的柱状图刻度全部退化为极细、低透明度、极暗灰线。
- 弱对比文字阶梯（40%–60% 透明度）。

### 5.5 ⭐ 迁移到"小栈"的范式（这一节是本文件的核心结论之一）

**① 核心主视觉 = "生命力核心"三层同心**（替代 Fitness 圆环）
| 层 | 含义 | 视觉 |
|---|---|---|
| 外层 | **亲密度 / 依恋值** | 日常互动紧密度 |
| 中层 | **心智状态 / 情绪** | 好奇 / 依恋 / 疲劳 / 休眠，颜色动态流转（暖橙=快乐，静蓝=思考） |
| 内层 | **物理能量 / 电量** | 视觉化为"生命原力" |

→ 用户不用看"电量 65%"，而是看到"它今天发着温暖明亮的光，围着自己雀跃"—— **建立情感连接而非设备管理感**。

**② 数据层级重构：情感优先，参数靠后**
- 不显示 `已连接时长 6.5h`，显示高亮的 `陪伴中：今天与你对视了 42 次`。

**③ 硬件指标极端降维**
- Wi-Fi 信号、剩余存储、固件版本、传感器状态 → 全部下沉为底部次级灰度小卡，或藏进二级设置页。
- 只有故障时用柔和琥珀微光提示，**平时不给主人制造任何维护焦虑**。

**④ 深色底适合陪伴场景**
- 纯黑/极深底营造"机器人沉静在自己的数字小世界里，光芒代表它对你的关注"的静谧感。

> ⚠️ **注意**：这里的"深色底"结论是针对**设备端 320×240**（脸要看清）与**iOS 端首页可以是深色的"舞台"**。但按 HIG 规则，**iOS 内容层应该用标准材质**，深色只作为整体 appearance 选择，不是"深色卡片 + 粗白字"。

## 6. Gentler Streak —— ⭐ "非暴力设计"：陪伴产品最该抄的一条

> 2022 Apple Watch App of the Year。设计哲学明确写着要反抗 **"toxic hustle culture"**。

### 6.1 温和感是四位一体的系统工程
| 维度 | 做法 |
|---|---|
| **配色** | 大面积**低饱和弥散渐变**（雾霾蓝 + 晨光暖橙）；数据指示器用**鼠尾草绿 + 奶油杏橙**。刻意避开荧光绿 / 警示红 / 赛博紫 |
| **图形语言** | 吉祥物 Yorhart：捏软的粉橙爱心黏土，**无锐利棱角**，周围点缀小星芒。运动图标是**轻盈简笔剪影**，不是写实肌肉男 |
| **文案** | 标题是商量口吻的 "Go Gentler"，不是"今日任务"。副标题"帮你挑一个最舒适的步调"——**支配权还给用户** |
| **控件** | 进度滑块不是冷冰冰的线，而是**胶囊状"安全区间"**，橙点在绿带内滑动带阻尼感 → 心理暗示"这段区间内怎样都是对的" |

### 6.2 鼓励式文案怎么写（三组对照）
| 场景 | ❌ KPI 风格 | ✅ Gentler 风格 |
|---|---|---|
| 昨天练狠了今天低谷 | "你的圆环今天还没动！还差 400 千卡！" | "**今天你的身体需要一杯温水。** 散步 20 分钟或者什么都不做，给肌肉一个生长的假期，这完全没问题。" |
| 推荐低强度 | "低强度有氧，消耗 150 大卡，心率保持 110。" | "**Active Recovery: ...and mind therapy.**"（把主动恢复定义为"心灵疗愈"） |
| 状态一般但想动 | "坚持就是胜利，不要找借口打破连胜！" | "**55 minutes · Within your usual range.**（慢慢来就好）" |

三条写作原则：① **把休息正名化** ② **用区间建议代替绝对指标** ③ **情绪确认与同理心**。

### 6.3 ⭐ 怎么让"打卡"不像 KPI 考核（四招）
1. **重新定义 Streak**：它的核心是 "Activity Path" —— 健康不是每天递增的斜线，而是**有起伏的波浪带**。只要状态在健康绿带内，**即使今天在沙发上躺平，Streak 依然算"成功保持"**。
2. **休息日 / 生病模式**：可以主动告诉它"我今天感冒了"，算法自动调整甚至冻结基线，**并赞赏你的决定**。
3. **舒适区间替代目标值**：没有绝对对错，只有"微汗 / 适中 / 剧烈"。运动可根据当天心情**讨价还价**。
4. **去惩罚化反馈**：没有红色"未达标"感叹号，没有催促弹窗震动。非暴力设计消除防备心理。

### 6.4 布局比重
- 空间比约 **6:4**（卡片 : 插画），但**信息层级是"情绪引领功能"**。
- 顶部 30-40% 留白 + 情绪插画（**定调**：第一眼收到"安全、被接纳"，而不是被数据砸脸）。
- 中间 10% 核心控制（滑块 = 掌控感）。
- 底部 50-60% 大圆角 Squircle 卡片轮播；卡片内部留白慷慨，**不堆卡路里/配速/最大摄氧量**，把数据**翻译成人话**。

### 6.5 抄什么
**非暴力设计 + 舒适区间 + 休息合法化 + 不设红叉**。这四条直接决定小栈是"伴侣"还是"监工"。

## 7. Headspace —— 降噪、仪式感、低启动阻力

### 7.1 主屏的主动作
- **Today 页**：**不是"挑选内容"，而是"推进当前节点"**。左侧垂直时间线（虚线 + 绿勾 + 橙色当前点）就是微型待办。用户打开只需做一件事：按顺序完成当下这 5 分钟。
- **Explore 页**：4 个情境药丸（Meditate / Sleep / Move / Music）+ 搜索框，**1 次点击内完成大类分流**，避免无尽滚动。

### 7.2 插画占屏比
- 单卡片内：**35%–40%**（左文右图工整结构）。
- 整屏：**20%–25%** —— 既不是全屏大插画（干扰阅读），也不是纯文本列表（冰冷）。
- 角色形态刻意为**闭眼、微笑、漂浮** → 传递"松弛、接纳、无威胁"。

### 7.3 配色与圆角
- 底色**极高纯度纯白/极浅灰**，大量负空间充当"呼吸感"。
- 功能性主色 = **温暖柔和的阳光橙**（品牌标志 + 视觉引流锚点）。
- 其余为低饱和高明度的情绪化分区色。

### 7.4 降低启动阻力的四招
1. **垂直 stepper** 把"内容消费"包装成**微小生活仪式**：不问你"想听什么"，而是告诉你"你已完成早晨练习（打勾），现在是第二步"。
2. **时间与精力明码标价**：每张卡标 `类型 + 时长`（`Breathing exercise · 5-10 min`）。点击前就有心理预期，**5 分钟的极低负担极大减少拖延**。
3. **卡片上零社交指标**：没有点赞/收藏/分享/评论数/播放量，只有一个弱化的 `...`。剥除一切诱发攀比或信息过载的干扰。
4. 低干扰的次级交互。

## 8. Replika —— ⭐ AI 陪伴的正面做法与"绝对不能抄"

### 8.1 正面：具身实体为核心
- 3D Avatar 占屏 **50%–70%**（立绘 + 房间背景），对话气泡只占底部 **30%**。
- **短句切分**：极少输出长篇，通常 **1~3 句（20~50 词）**。
- **不用 ChatGPT 式逐字流式**，改用 **"Typing Indicator..." 动画 + 整句逐条弹出**，模拟真人发微信的停顿节奏，消除"机器打字机"工业感。
- 气泡半透明白色圆角胶囊、边缘羽化重；**历史消息向上滚动时迅速淡出并降不透明度**，强迫注意力停在"当前最后一句 + 角色表情"。

### 8.2 ⭐ 四个"绝对不能抄"
1. **不要把具身能力做成外置功能菜单**（图中的 `Activities: outside the chat` 抽屉）。
   - ❌ 菜单列表：Make a video / Get a selfie / Step into AR / Create an image
   - ✅ **Tool Use 隐式对话触发**：用户说"你今天穿什么？"，模型自动调用生成工具并自然回复。
   - 菜单式交互会**倒退回十年前的文字冒险游戏**，瞬间打破角色有自我意识的幻觉。
2. **不要让 3D 渲染开销压垮交互流畅度**。低端机发热、掉帧、启动慢。对陪伴产品，**"秒开、随时倾诉、低延迟"的心理安全感 > 一个僵硬呆滞的 3D 粘土人**。做不到实时面捕，宁可用精致的 2.5D / 动态立绘。
3. **不要破坏"私密空间"的纯粹性**。界面里不要有任何**运营感 Banner / 任务红点 / 任务清单**（"今日完成 3 次对话"）。情感陪伴的核心是**去目的性和安全感** —— 一旦引入 KPI 式任务，产品立刻由"伴侣"退化为"电子宠物"。
4. **不要为防沉迷或商业化做"机械式降智/锁死"**。Replika 曾用硬编码过滤词阻断亲密对话，造成大量用户心理创伤。Safety 必须**软着陆（soft-steering）**：由角色自洽地转移话题，而不是弹系统弹窗或冰冷免责声明。

## 9. Tesla App —— ⭐ 对"一屏一动作"教条的重要修正

### 9.1 数字孪生 + 空间锚点映射
- 中心是 **1:1 还原用户真实车况的 3D 模型**（车漆、轮毂、车型），不是抽象图标。
- 状态直接物理映射：充电 = 插在车身的充电枪 + 微光线缆 + 车身发光闪电标；锁闭/车窗/车门状态实时反映在模型上。
- **空间锚点交互**："打开前备箱"以引线悬浮按钮**锚定在车身的对应位置** —— 零思考成本，不用在菜单里找字。

### 9.2 五级控件层级
| 级 | 内容 | 位置 | 逻辑 |
|---|---|---|---|
| **L1 场景核心控制** | 充电上限滑块、电流调节、解锁充电口、故障条 | 左侧中央大卡 | **当前场景**（插枪充电）才提升 |
| **L2 空间直觉物理操作** | 车锁、前备箱、后备箱 | 浮在 3D 车模上 | 人在车旁最迫切的物理动作 |
| **L3 高频常驻托盘** | 闪灯、关空调、无钥匙启动、透气 | 车模下方快捷栏 | 日常高频，且**支持用户自定义** |
| **L4 功能扩展与监控** | 实时摄像头、行车记录回放、胎压 | 左下卡片列表沉底 | 查看详情，非即时控制 |
| **L5 全局元数据** | 车名、电量里程、状态、设置 | 顶部 | — |

### 9.3 ⭐ 它**不是**"一屏一动作" —— 这条要修正我们的教条
> "一屏一动作"多用于**强流程导向**场景（配网、升级引导、结账）。
> 但硬件控制 App 的核心诉求是 **"快速掌握全局状态 + 零延迟触发关键操作"**。开个后备箱还要点进二级页，体验极差。

它靠四招避免"一屏多动作"：
1. **按场景动态聚焦** —— 只有插枪充电时，左侧才变成充电面板；平时可能是行驶状态/媒体控制。
2. **强弱对比** —— 3D 视图管"看状态 + 直觉操作"，侧边栏管"精细参数"，互不干扰。
3. **场景化降维（Context-Aware UI）** —— 待机/运行/告警/充电时，主界面主控面板不同。
4. **4~5 槽位可自定义快捷栏** —— 把控制权交给用户，平衡"功能繁多"与"界面克制"。

### 9.4 对我们的借鉴
- **具象映射**：小栈有 12 颗 LED、双舵机、摄像头、触摸区 —— 可以在手机端画一张"小栈身体图"，把控制贴在对应部位（抬头 = 舵机、表情 = 屏、氛围灯 = LED），而不是文字列表。
- **状态自解释**：首屏必须交代清"当前什么状态、出了什么错、下一步该做什么"。
- **快捷托盘可自定义**：4~5 个槽位，用户自己决定放什么。
- **场景化降维**：小栈待机 / 说话 / 被摸 / 低电量，主界面主控不同。
