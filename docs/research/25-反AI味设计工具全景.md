# 25 · 反 AI 味设计工具全景：impeccable / nongeneric / hallmark / ui-skills 对比与采用决策

> **一句话**：这一轮最大的发现不是"又一个设计技能包"，而是 **8.5 万 star 的 `pbakaus/impeccable`**，它的 **62 条确定性检测器不需要 LLM、不需要 API key**，而**我们已经在本机跑通了（v4.7.0）**。
> **对本项目的意义**：我们此前设计的"设计宪法"（`19` 号 Floor 文档）一直缺一个**执行者**。现在有两个现成的、可在本机跑的、跨平台的执行者。

### 1.1 ⭐ `impeccable` 的核心机制（README 原文要点）

```
Design guidance for AI coding agents.
1 skill, 24 commands, live browser iteration, and 62 deterministic detector rules.
```

**它自己说的 AI 味清单**（⭐ 这段是本轮最值钱的一句原文）：

> *"Every model trained on the same SaaS templates. Skip the guidance and you get the same handful of tells on every project:*
> ***Inter for everything, purple-to-blue gradients, cards nested in cards, gray text on colored backgrounds, the rounded-square icon tile above every heading.**"*

⭐ **这 5 条里有 3 条是我们宪法早就禁的**（紫蓝渐变 / 卡片套卡片），**2 条是我们没写的**（Inter 到处都是 / 灰字配彩色底），**1 条是我们完全没意识到的**（⭐ **标题上方那个圆角方形图标砖** —— 这就是"AI 味"的招牌动作）。

**产品真相分层**（⭐ 与我们"人格三层分离"同构）：

> *"`/impeccable init` records **durable product truth** in `PRODUCT.md`, so later commands know the **audience, purpose, operating context, constraints, voice, and evidence** without confusing those facts with surface-level visual direction."*
> *"`init` … writes `PRODUCT.md`. Visitor mode and visual direction are chosen later for each surface; **incumbent or newly built visual systems are recorded separately in `DESIGN.md`**."*

⭐⭐ **这就是我们要写的两个文件的模板**：
- `PRODUCT.md` = **产品真相**（受众 / 目的 / 运行场景 / 约束 / 语气 / 证据）→ **不可被视觉决策污染**
- `DESIGN.md` = **视觉系统**（令牌 / 规则 / 禁止项）→ **可被替换**

⭐ 这与我们已有的 `00-总纲`（宪法）+ `19` 号 Floor（规则）+ `personas/enfp.json`（人格）**是同构的**，只是我们还没把"产品真相"独立成文。**这是本轮的一条明确待办。**

**24 个命令里和我们需求对得上的**：

| 命令 | 作用 | 对我们的意义 |
|---|---|---|
| `init` | 写 `PRODUCT.md` | ⭐ **我们要做** |
| `document` | 从现有代码生成 `DESIGN.md` | ⭐ **我们要做**（我们的宪法就是手写的 DESIGN.md） |
| `shape` | 写码前先规划 UX/UI | ✅ 与我们的"先想清楚再动手"一致 |
| `craft` | shape-then-build + 视觉迭代 | 参考 |
| `critique` | UX 设计评审：层级 / 清晰度 / **情绪共鸣** | ⭐ **"情绪共鸣"正是陪伴产品的评审维度** |
| `audit` | 技术质量检查（a11y / 性能 / 响应式） | ✅ 用我们的 `detect` 替代 |
| `polish` | 收尾对齐 | ✅ |
| `bolder` / `quieter` / `distill` | ⭐ 加码 / 减码 / 提炼本质 | ⭐ **`distill` = 做减法**（我们的核心） |
| `harden` | 错误处理 / i18n / **文本溢出** / 边界情况 | ⭐ 我们 iOS 端的中文长文本溢出正是这个问题 |
| `onboard` | 首次运行流程 / 空状态 / 激活路径 | ⭐⭐ 对应我们 `22` 号 §3.1 ④ 的 Onboarding 结论 |
| `animate` | **有目的的**动效 | ⭐ 与我们"动效预算"呼应 |
| `colorize` | **策略性**用色 | ⭐ 与 HIG Branding 的"品牌色只用在主操作/状态"呼应 |
| `typeset` / `layout` | 字体 / 布局 | ✅ |
| `adapt` | 适配不同设备 | ⭐ **iPhone Duo 折叠屏适配** |
| `live` / `generate` | 浏览器里实时迭代 / 生成变体 | ⚠️ 需要生产站点，不适用我们 |

**⭐⭐ 关于"先出稿还是先写码" —— 它给了官方级回答**：

> *"**Comp-first** composes bolder and takes longer; **code-first** is leaner and faster. … **App screens and documents are built code-first either way, because they come out better built than pictured.**"*

⭐⭐ **官方说：App 界面就应该 code-first（写码），不要先画图。**
这**正面印证**了我们早就定下的 **B 路线（HTML/CSS 代码即设计稿 → 截图评审 → 转 SwiftUI）**，而且给了它一个来自第三方的理由。

**⭐ 检测器用法（可直接进我们的 CI）**：

```bash
npx impeccable detect src/                    # 扫目录
npx impeccable detect index.html              # 扫 HTML 文件（我们的设计稿就是 HTML）
npx impeccable detect https://example.com     # 扫 URL（用已装的 Chrome/Chromium/Edge）
npx impeccable detect --json .                # 机器可读
npx impeccable detect --github src/           # GitHub Actions annotations
npx impeccable detect --list-rules            # 规则目录
npx impeccable detect --no-config src/        # 忽略项目配置裸扫
npx impeccable ignores add-value overused-font Inter --reason "Brand font"
```
- **退出码：`0` = 无主要问题 / `2` = 有主要问题 / `1` = 目标无法扫描** → **天然就是 CI 门禁**
- **逐文件豁免**：`<!-- impeccable-disable overused-font: exported brand doc -->`
- **62 条规则涵盖**：AI slop（side-tab borders / purple gradients / **bounce easing** / **dark glows**）+ 通用质量（**line length** / **cramped padding** / **small touch targets** / **skipped headings**）
- ⚠️ **它自己的免责声明**（值得抄进我们的评审规范）：*"A clean detector run is **evidence, not proof** of visual or accessibility quality."*

### 1.2 ⭐ `nongeneric` 的独有价值

> *"Anti-slop design + GSAP motion skill pack for AI coding agents, with an **82-rule UI detector**."*

| 它的独有价值 | 原文 | 对我们 |
|---|---|---|
| ⭐⭐ **`/nongeneric:harden` 的不变量** | *"Enforce **320px–1440px** responsive invariants, **44px tap targets**, and **WCAG AA+**"* | ⭐⭐ **320px 正是我们设备端的宽度！44px 正是我们的触摸目标！** |
| ⭐⭐ **「Anti-Chat-Bubble Slop」** | `docs/playbooks/domain-ai-native-workspaces.md` | ⭐⭐ **专治 AI 原生工作区的"聊天气泡流"** —— 正是我们要避开的 |
| ⭐⭐ **4 个 Visitor Mode 的"世界预算"** | `operate` 模式：*"World lends **up to four things**: type, palette, density, and **at most one signature detail**"*；`experience` 模式：*"**At most one dominant expressive treatment; stillness when appropriate**"* | ⭐⭐ **这是"主次"的工业化判据**。我们的产品是 `experience` → **"最多一个主导表达，必要时保持静止"** = **"小栈的脸是唯一被注视的东西"** 的通用表述 |
| ⭐⭐ **0–100 分 + P0–P3 整改计划** | `audit` 输出 | ⭐⭐ 我们"可判定评审"想要的 |
| ⭐⭐ **双角色盲评** | *"unanchored **Dual-Persona Critique** (Design Director + Target Visitor)"* | ⭐⭐ 与我们的"子代理冷评"同构，可加一个"目标用户"视角 |
| ⭐ **交互形态选型库** | `interaction-patterns.md`：modal / side panel / sidebar / popover / menu / tooltip / inline disclosure / toast / banner / full page 的取舍表 + 验收检查 | ⭐ **我们的 IA 决策可以逐条对照** |
| ⭐ **浏览器验证协议** | *"check keyboard access, **reduced motion**, and runtime behavior. **Report tested scope and unavailable evidence explicitly.**"* | ⭐ 与 HIG Reduce Motion 呼应；**"明确报告未验证的部分"** = 我们的诚实交付纪律 |
| ⚠️ 诚实声明 | *"Even an empty-body HTML page can score 100 when no patterns are detected; **that is not a design-quality certificate**."* | ⭐ **必须抄进我们的评审规范**：分数不是质量证书 |

**⭐⭐ 它自己点名的 slop（我们的禁区清单可直接扩写）**：

| 类别 | 原文点名 |
|---|---|
| **Visual Slop** | `Inter`/`Roboto`；紫→靛渐变（`#8b5cf6`→`#6366f1`）；`background-clip: text` 彩虹标题；弥散霓虹 `box-shadow` 光晕；**`border-l-4` 侧边条纹 + 圆角卡片**；**3 列彩色圆形图标网格** |
| **Copy Slop** | ✨ 闪光 emoji；"Unleash the power of next-generation seamless workflows"；**破折号滥用（—）**；**"Not a X. A Y." 格言句式** |
| **Motion Slop & Jank** | `animate-bounce`；`transition: all`；GSAP 动画 `width/height/top/left`；嵌套 `ScrollTrigger`；`useEffect` 内存泄漏；**缺 `prefers-reduced-motion`** |
| **Responsive Breakage** | `100vw` 横向滚动；裸 `100vh` 跳变；**flex/grid 子项缺 `min-width: 0`**；**<16px 输入框触发 iOS Safari 自动放大** |

⭐ **两条我们从没写过的**：
1. **"Not a X. A Y." 句式** —— 这是 AI 文案的招牌动作。**我们的 ENFP 人格文案必须避开**，否则人格会被 AI 腔污染。
2. **<16px 输入框触发 iOS Safari 缩放** —— 这是 **iOS 端的真实可用性问题**，我们宪法第 1 条（≥11pt）在**输入框**上需要更严（≥16pt）。

### 2.1 ⭐ 由此产生的新 Floor 条目（待并入 `19` 号文档）

| # | 规则 | 来源 |
|---|---|---|
| **F33** | **禁止标题上方的"圆角方形图标砖"**（rounded-square icon tile above every heading） | `impeccable` README 原文点名的第 5 条 AI 味 |
| **F34** | **文案禁 "Not a X. A Y." 格言句式、禁营销词、禁 ✨ 闪光 emoji、禁破折号滥用** | `nongeneric` Copy Slop |
| **F35** | **输入框字号 ≥16pt**（避免 iOS Safari 自动放大导致布局跳动） | `nongeneric` Responsive Breakage |
| **F36** | 禁 `border-l-4` 侧边条纹 + 彩色圆形图标网格；禁 `background-clip: text` 彩虹标题 | `nongeneric` Visual Slop |

| **F38** | **禁 `animate-bounce` / 弹性缓动**（过时感）；禁 `transition: all` | `impeccable` detector + `nongeneric` Motion Slop |

> ⚠️ **F34 特别重要**：我们的 ENFP 人格包最容易出的问题就是"人格文案被 AI 腔污染"（"我不仅仅是你的助手，而是你的伙伴"）。这条直接堵住。

## 三、⭐⭐ 对我们的工作流的改变（这才是本轮真正的产出）

### 3.1 设计稿流程：从"靠自觉"改成"有执行者"

```
第 0 步  写 PRODUCT.md（产品真相：受众 / 目的 / 运行场景 / 约束 / 语气 / 证据）
第 1 步  写 DESIGN.md（视觉系统：令牌 / 层级 / 动效预算 / 禁止项；= 我们已有的 19 号 Floor + 宪法）
第 2 步  只做首屏 → 渲染成 HTML → ⭐ 双检测器扫描：
            npx impeccable detect <file> --json          （62 条，退出码 2 = 有问题）
            npx --yes github:Kyaa-A/nongeneric audit <file> （82 条 + 0–100 分 + P0–P3）
         → 修完所有 FAIL / P0–P1
第 3 步  冷评：新上下文子代理（双角色：设计总监 + 目标访客）看渲染图，按 Floor→Reflex→Finish 过
第 4 步  扩其余页面，重复 2–3
第 5 步  记录：两个检测器都干净 · Floor 0 FAIL · Reflex N（豁免理由）· 未验证项如实写
```

⭐ **第 2 步是全新的**：我们此前所有"设计稿"评审都是**人眼 + 文字规则**，现在有**两个独立实现的确定性检测器**。两个都过才算过 —— **这比任何一次口头评审都硬。**
