### 过程中发现的真实缺陷（非推测，已复现）

`ios/prototype/index.html` 的 `<script>` 块**整体解析失败**：
- `index.html:510` `let rec=false;`（首页语音按钮）
- `index.html:595` `function rec(btn){...}`（动作页录制按钮）
- 同一顶层作用域重复声明 → `SyntaxError: Identifier 'rec' has already been declared`（Chrome 控制台实测）

**后果**：该脚本块内**全部**代码未执行 —— `show()`、`go()`、`tickClock()`、tab 点击绑定、聊天发送、摇杆、表情/灯光/设置列表渲染全部不存在。实测 `typeof show === "undefined"`，`.tab` 点击后 `active` 屏不变。
**视觉后果**：B2 遥控页的「表情」「氛围灯·12灯」「动作」三段只剩标题、内容为空；**B3 设置页 4 个分组（设备/人格/交互/隐私与数据/关于）全部只有标题和一条分隔线，没有任何设置项**，整屏 60% 以上是空白。
> 截图说明：B1/B2/B3 是通过直接切换 `.screen.active` 类完成的（即 `show()` 本应做的事），因此画面忠实反映设计意图，但**这份初稿目前不可交互**。

## 1.5 A 组 apple-minimal 批稿到底好在哪（可执行描述）

> 这条要回答的是"凭什么我们之前那批是好的"，而且必须落到可复制的具体动作上，而不是"简洁""高级"。

1. **它把"小栈"当成一张海报的主角，不是当成一个控件。**
   A1 屏里眼睛+腮红+嘴的矢量组占屏 **15%**，A4 表情屏占 **40–50%**，A2 角色占 **12%** 但独占一整张白色卡片（该卡占屏 20%）。
   → **可执行**：新 App 每个屏都必须有角色形象，且**角色所在的容器必须占屏 ≥30%**；角色不能缩成一个图标色块。

2. **每屏只做一件事，元素数量有硬上限。**
   A1=4 个色块 / A2=6 个 / A3=4 个 / A4 单屏 3–8 个、**可点元素仅 1–3 个**。
   → **可执行**：新 App 单屏可交互元素上限 **4 个**；超过就必须折叠进二级页或长按菜单。

3. **零描边，层级靠色块明度差硬切。**
   A1 是纯黑 `#000` 与纯白 `#FFF` 的 **0px 直角硬切**（视觉模型原话「像两块拼接的内容」——它甚至把这当扣分项），A2/A3 **完全没有 1px 描边**。
   → **可执行**：新 App 删掉所有 `border:1px solid var(--line)` 式的容器描边，改用底色明度差（±5% 明度）切层。

4. **阴影是稀缺资源，只给最重要的那一个控件。**
   A1 全屏只有 1 处阴影（右下粉钮，同色 blur12/35%）；A2 只有 1 处（白卡 blur12–16/10%）；**C1 全图 blur=0，一处投影都没有**。
   → **可执行**：**每屏阴影数量上限 1 处**，且必须是"主行动按钮"或"主容器"二选一。

5. **强调色少而准，每个颜色有职能。**
   A3 的显式 UI 里强调色**只出现 1 处**；A1 的绿色只表示"在线"；A2 的 4 处强调色**同属一个色相**（桃粉）。
   → **可执行**：新 App **主色相 1 个 + 功能色 1 个（绿=连接/开启）**，其余全部灰阶；不允许出现"只为好看"的第三个色相。

6. **字号只有 4 级，且文字永不压在图形上。**
   A1/A2/A3/A4/C1 全部满足「文字与图形并列或浮层加衬底」，无一例外；B 组也守住了这条（✅ 保留）。
   → **可执行**：这条**不用改**，继续守住。

7. **文案短到近乎口语。**
   A1「依偎，我在」(4 字) / A2「陪伴」(2 字) / A4 标题 2–4 字、说明 8–15 字。
   → **可执行**：新 App 主标题 ≤4 字，说明文案 ≤15 字，超出就拆。

8. **它认得清自己的硬件形态。**
   A1 的纯黑底 + 高反超大眼睛 = OLED 省电 + 远距扫视可读性；A4 的 24:59 巨型计时压在两眼中。
   → **可执行**：设备屏沿用**深底 + 角色占据主画面**；App 端可以浅底，但**必须把深色回归到"设备状态"这一处**（B1 的纯黑实时活动卡方向是对的，尺度是错的）。

### 1.6 B 组做对了、必须保留的 6 点（不要在改写时误伤）

1. **文字绝不压在复杂图形上**（B1/B2/B3 全部成立，与 A 组纪律一致）。
2. **单条文案 8–15 字**，长度控制与 A 组同档。
3. **4 级字号阶梯**（32/16/13/11），层级数量与 A 组一致。

### 2.2 一句话根本差异

> **A 组是"角色 + 1 个动作" 的海报式界面（每屏 2–5 个元素、角色占 30–50%、深底或纯色块、零描边）；B 组是"卡片 + 列表" 的信息流 App（每屏 12–26 个元素、角色占 0–16%、浅米底、1px 描边 + 多重弥散阴影）。**
> **A 组把"小栈"当成画面主角，B 组把"小栈"当成了一个待展示的功能项。**

### 2.3 三条最致命的根因

1. **主角缺席**：A 组每个屏都有小栈（大眼睛、弧线嘴、腮红），占屏 40–50%；B 组首页只有 16% 的"机器人硬件外壳"，遥控页和设置页**一个角色都没有**。用户打开 App 看到的是一堆卡片，不是伙伴。
2. **强调色没有职能**：B 组 3 个快捷入口图标用了粉/蓝/橙三色纯装饰，加上黑色「实时活动」卡，整屏出现 5 个色相；A 组虽然 A4 被判"主色混乱"，但**绿色永远是"在线/开启"、粉色永远是"情感"**，是可推断的。
3. **描边 + 弥散阴影的双重叠加**：A 组是"零描边 + 最多一处弱阴影"；B 组是"1px 描边 + blur20-28 的多重阴影 + 拟物内发光"。这是典型的**通用后台管理模板**做法，不是陪伴硬件的做法 —— **这正是"丑得要死"的来源：它长得像一个 CRM 系统，不像一个伙伴。**

## 4. 开源设计质量自动校验工具调研

> 调研时间 2026-10-23。许可与星标数取自 GitHub REST API 当日返回，均为**开源许可 / 归档状态实测**，非记忆。

| 项目 | 链接 | 许可 | 接入成本 | 能卡住我们哪类设计问题 |
|---|---|---|---|---|
| **axe-core** | https://github.com/dequelabs/axe-core | MPL-2.0 | 极低：`<script src="axe.min.js">` 一行注入，或 npm 装 @axe-core/playwright | 文本对比度不足（`color-contrast` 规则）、可点击元素无 `aria-label`、标题层级跳跃、图片无 alt。<br>⚠️ 只查**机器可判定**的问题，查不出"丑" |
| **pa11y** | https://github.com/pa11y/pa11y | LGPL-3.0 | 极低：`npx pa11y http://127.0.0.1:8848/index.html --standard WCAG2AA` | 把 axe-core 包成 CLI + HTML 报告 + 退出码，可直接进 CI 卡门禁。支持对 URL 批量跑 |
| **stylelint** | https://github.com/stylelint/stylelint | MIT | 低：`npm i -D stylelint`，配一份 `.stylelintrc` | CSS 硬性规范：禁止写死 hex（强制走 CSS 变量）、统一 `border-radius` 量级、禁止 `!important`、命名规范。<br>这是**把"设计语言"变成可 lint 规则**的最小载体 |
| **Playwright**（内置视觉对比） | https://github.com/microsoft/playwright | Apache-2.0 | 中：需装浏览器（~300MB）+ 写 `toHaveScreenshot()` 基准图 | `expect(page).toHaveScreenshot()` 做像素级视觉回归；**还能在同一套测试里挂 @axe-core/playwright**，一次跑完"回归 + 无障碍"。<br>⚠️ 基准图需人工审核（`--update-snapshots`），否则会变成"自动接受烂设计" |
| **style-dictionary** | https://github.com/style-dictionary/style-dictionary | Apache-2.0 | 中：先定义 `tokens.json`（颜色/圆角/阴影/字号），再构建出 CSS/TS | 把 A 组设计语言**固化成唯一真源**：改 token 全局生效；可加自定义 `transform`/`filter` 校验"禁止新增未登记色值"。<br>这是解决"两套设计语言并存"的结构性方案 |
| **Lighthouse** | https://github.com/GoogleChrome/lighthouse | Apache-2.0 | 低：`npx lighthouse <url> --preset=desktop`，或用 CI Action | 审计报告含颜色对比度、tap target 尺寸、可访问名称；兼做性能回归 |
| **lost-pixel** | https://github.com/lost-pixel/lost-pixel | MIT | 中高：需接 Storybook/Histoire/Ladle | 视觉回归编排（对标 Percy/Chromatic），可配阈值忽略区域。<br>⚠️ **该仓库已 archived（2026-04 停更）**，不建议新项目采用 |
| Percy CLI（对照） | https://github.com/percy/cli | **proprietary**（GitHub API 返回 `license: null`） | 低但**需付费账号** | 托管式视觉回归，成熟稳定；我们目前体量不需要 |
| Chromatic（对照） | 商业 SaaS（`chromatic-com/chromatic-cli` 在 GitHub API 返回 404，**未能核实仓库许可**，按商业产品处理） | proprietary / 付费 | 低但需账号 | 同上 |

**结论：真正缺的不是"审美检测器"（不存在），而是三件可自动化的机械校验：**
1. **对比度** → axe-core / Lighthouse 能完全覆盖（我们 B 组的 `--muted:#857a71` on `--surface:#fffdfb` 已在临界区，值得实测）；
2. **设计令牌一致性** → style-dictionary + stylelint 把"只能用已登记的色值/圆角"变成 CI 报错；
3. **视觉回归** → Playwright 自带 `toHaveScreenshot`，零第三方依赖，**这是我们最该先上的**（我们已有 CDP 截图脚本，等于半成品）。

## 可复用方案
- **axe-core** 用途：无障碍自动检测（对比度/可访问名称/tap target） 许可：MPL-2.0 接入成本：极低（1 行注入 / npm） 替代自造的：手写对比度取值脚本
- **pa11y** 用途：把 axe-core 包成 CI 可用的 CLI + HTML 报告 许可：LGPL-3.0 接入成本：极低（`npx pa11y <url>`） 替代自造的：自建 a11y 检查任务
- **stylelint** 用途：把"只用 CSS 变量、圆角只准取已登记档位"写成 lint 规则 许可：MIT 接入成本：低 替代自造的：靠人眼 review 配色/圆角
- **Playwright `toHaveScreenshot`** 用途：像素级视觉回归（我们已有 CDP 截图脚本可直接迁移） 许可：Apache-2.0 接入成本：中（装浏览器 + 维护基准图） 替代自造的：每次改 UI 手动截图肉眼比对
- **style-dictionary** 用途：设计令牌的唯一真源与多端输出（CSS/TS），A 组设计语言固化载体 许可：Apache-2.0 接入成本：中 替代自造的：`:root{--xxx}` 手写色值散落在 CSS 各处
- **Lighthouse** 用途：整体审计报告（对比度 + 性能） 许可：Apache-2.0 接入成本：低 替代自造的：自建评分脚本
- **lost-pixel** 用途：视觉回归编排（开源替代 Percy） 许可：MIT 接入成本：中高 替代自造的：自建 CI 截图流水线 —— **⚠️ 已 archived，不采用**
- **Percy / Chromatic** 用途：托管式视觉回归 许可：proprietary / 付费 接入成本：低（需账号） 替代自造的：同上 —— **本阶段不采用，成本不匹配体量**

采用决策：**混合**（自造令牌体系 + 复用校验工具链）
理由：
- **审美本身无法自动化**——没有任何开源工具能判断"丑不丑"。所以 A 组设计语言必须由人（A 组稿子）**先定义成设计令牌**，这是自造的部分，也是不可替代的部分。
- 但令牌一旦定义，"有没有偷偷用别的颜色/圆角/对比度不达标"是**纯机械问题**，交给 axe-core（对比度）+ stylelint（令牌外溢）+ Playwright（视觉回归）即可。
- 优先级：**先上 Playwright 视觉回归**（我们已有 CDP 截图脚本，改造成本最低，且直接解决"改完 UI 不知道有没有变丑"）；再上 axe-core（纯 npm 一行）；style-dictionary 放在 A 组令牌定稿之后做。
- 明确不做：lost-pixel（archived）、Percy/Chromatic（付费，当前体量不匹配）。
