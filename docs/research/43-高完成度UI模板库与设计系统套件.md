## §一 结论摘要

1. **两个反味检测器在本机都能真跑，且已跑出真实数据**。`npx impeccable detect`（Rust 引擎，Apache-2.0，v4.7.0，**62 条确定性规则**）与 `nongeneric`（零运行时依赖 TS CLI，MIT，v1.1.0，**82 条规则**）均在 Windows + Node v24.14.0 上实跑成功。对**现有 v1 原型** `prototype/index.html`：impeccable **13 项反模式 + 3 项 bounce 建议**，nongeneric **44/100（Grade D）、31 项命中**；对**已产出的 16 个原型变体**：impeccable **157 项**、nongeneric **178 项**（明细见 §4.6）。[本机实跑输出]
2. **nongeneric 的 82 条规则清单已完整提取**（rule id 全量见 §四），其中数十条与我们的硬线一一重合（`nested-cards` / `gradient-text` / `purple-blue-gradient` / `bounce-easing` / `glassmorphism` / `undersized-ui-text` / `missing-reduced-motion` / `wide-tracking`）——**可以直接当验收清单用**，不需要自研 lint。
3. **⭐ 16 个原型的实跑结论（用户"丑爆了"的机器化解释）**：impeccable 命中的 **110/157 条全是 `low-contrast`**，且**集中在暖色系与深色系**（`#b4afaa` on `#faf8f5` 仅 **2.1:1**、`#5e5e66` on `#161618` 仅 **2.8:1**）——**问题不是强调色，是次级文字 token 没验证**。另一条：15/16 个变体共享**完全相同的 10 项脚手架基线**（`wide-tracking`×3 / `ios-input-zoom` / `legacy-viewport-height` / `missing-focus-ring` / `missing-reduced-motion` / `rigid-desktop-width` / `unsafe-dom-sink`×2）→ **改一次共享脚手架，16 个文件同时受益**。详见 §4.6.3。
4. **不要用 admin dashboard 模板**。Cruip / Tailwind UI / Tremor / Preline 的主打形态都是「营销页 + 后台表格」，移动端优先度低，且 Cruip（$49–129）与 Tailwind UI（`/plus/login`）**是付费非开源**。[官网原文]
5. **真·能直接产出静态 HTML 原型的只有 5 个**：`saadeghi/daisyui`(43k★, MIT)、`picocss/pico`(17k★, MIT)、`markmead/hyperui`(12k★, MIT)、`htmlstreamofficial/preline`(6.5k★, MIT + Fair Use)、`argyleink/open-props`(5.6k★, MIT)。其余（React Bits / Magic UI / shadcn / Tremor / Motion Primitives）都是 **React 源码，只能"读结构抄思路"**。[仓库 README 原文]
6. **最值得抄的不是组件，是「组件的克制方式」**：React Bits(50k★) 与 Magic UI(23k★) 都是「一个组件四种口味（JS/TS × CSS/Tailwind）」的**单文件可粘贴**结构，这个「组件自包含 + 无依赖」的组装法比组件本身更适合静态原型。**但 React Bits 的许可证不是纯 MIT，而是 MIT + Commons Clause**（可用于产品，**不得单独转售/再分发组件本身**）。[LICENSE 原文]
7. **移动端/iOS 专属的开源件里，可用的是 `ionic-team/ionic`(53k★, MIT) 与 `framework7`(npm v9.2.0, MIT)**，但两者都要框架（Angular/React/Vue/Vanilla），**不能直接产静态 HTML**，只能抄其 iOS 交互范式（侧滑、列表分组 inset、Tab Bar 语义）。[npm 元数据] [我的推断]
8. **组件站现状**：Cult UI **MIT 免费**且**自带 Apple iPhone 17 设备框**（官网原文："Free and MIT licensed … 154 animated components"），是少数直接对位「苹果交付感」的开源件，但形态偏桌面；**Aceternity 官网已变成接单服务站**（组件库 license 未取得）、**`originui.com` 302 → `coss.com/ui`**、**`kelvinui.com` 抓取失败**。[官网原文]
9. **token → 代码的标准管线是「Tokens Studio → GitHub JSON → Style Dictionary → CSS 变量 / Swift」**。Style Dictionary v5.7.0（Apache-2.0）+ `@tokens-studio/sd-transforms` v2.0.3（MIT）官方打通；Tailwind v4 的 `@theme` 天然就是 CSS 变量层，浏览器版 CDN 可直接在静态 HTML 里用。**这是「一套结构 → 十几个变体」的唯一低成本机制。** [仓库 README 原文] [npm 元数据]
10. **变体机制应该是「1 份 DOM + N 份 token 文件」，不是 N 份 HTML。** 结构不动、只换 `--bg/--ink/--accent/--radius/--font/--divider`，12–16 个方案才能在同一基准上被用户公平比较，也才能一次性跑完两套检测器（§4.6.3 结论① 已实证这套结构确实让基线问题只出现一次）。
11. **视觉参考站可免登录抓取情况**：land-book ✅、godly ✅（302 → recent.design）、mobbin ⚠️（首页可抓，**内容页需登录**）、pageflows ❌（403 Cloudflare）、awwwards ❌（本机 000）、dribbble ⚠️（202 空响应）、pinterest/behance ❌（000）。**结论：能稳定当"选方向"用的是 land-book + godly，Mobbin 只能看公开首页截图。**
12. **视觉方向候选 14 个**（§六，已按「底色 / 强调色 HEX / 圆角 / 字体 / 分隔 / 图形语言 / 动效 / 适合内容」逐项写死，可直接落成 token 文件）+ **反面清单（§七）**：高级但 AI 味的 9 类形态均已标注对应 rule id，**可被机器检测，不是靠人眼把关**。

### 3.2 token 分层（我们该怎么切）

```
Layer 0  primitive   color.paper.50 / color.ink.900 / space.4 / radius.md / motion.fast
             ↑ 所有方向共用，只在结构变化时改
Layer 1  semantic    surface.base / surface.elev / ink.primary / ink.secondary /
                      accent.default / accent.ink / line.hairline / radius.control
             ↑ 结构变量，与方向无关
Layer 2  direction   dir-01-white-sfblue : { --sc-bg: #FFFFFF; --sc-accent: #007AFF; ... }
                      dir-02-dark-amber   : { --sc-bg: #0B0B0C; --sc-accent: #FF6B35; ... }
             ↑ 每个视觉方向一份，只覆盖 Layer 1 的取值，不新增结构
```

**关键约束**：Layer 2 **只允许改值，不允许改结构**。这样 12–16 个方案才能在同一基准上比较，且检测器的规则命中差异只来自"风格"，不来自"实现不同"。

### 3.3 落地路径 A：代码侧主导（**本轮原型直接用这个**）

不需要 Figma。三步：

```bash
# 1) 依赖
npm i -D style-dictionary

# 2) style-dictionary.config.mjs
import StyleDictionary from 'style-dictionary';
export default {
  source: ['tokens/**/*.json'],
  platforms: {
    css: {
      transformGroup: 'css',
      buildPath: 'prototypes/tokens/',
      files: [
        { destination: 'base.css',      format: 'css/variables' },
        { destination: 'dir-01.css',    format: 'css/variables', filter: t => t.path[0] === 'dir01' },
        // …每个方向一行
      ],
    },
  },
};

# 3) 构建
npx style-dictionary build
```

产物是一堆纯 CSS 变量文件，**零构建、双击即开**，完全符合"HTML/CSS/JS 放进浏览器就能点"的交付形态。

> **强烈推荐零依赖方案**：原型里**不引 Tailwind**，只写约 15 个语义 class（`.btn-accent` / `.card` / `.row` / `.divider` / `.title` …），这些 class 内部全部读 `var(--sc-*)`。换风格 = 换一行 `<link>`。Tailwind v4 的 `@theme` 方案更优雅，但 v4 的 `@theme` 对"运行时换值"有约束，`@theme inline` 的行为需实机验证，属于 [我的推断] 未验证项。

### 3.4 落地路径 B：设计侧主导（后续 SwiftUI App 用）

```
Figma
 └─ Tokens Studio for Figma（定义 token / 主题集 / 别名）
     └─ 同步到 GitHub 仓库（JSON，可 diff、可 review）
         └─ Style Dictionary + @tokens-studio/sd-transforms
             ├─ → prototypes/tokens/*.css     （HTML 原型）
             ├─ → Tokens.swift               （SwiftUI，自定义 format）
             └─ → tokens.json                 （运行时/文档）
```

`@tokens-studio/sd-transforms` 提供的 transform 覆盖：尺寸补 `px`、opacity `%`→number、lineHeight `%`→无单位、fontWeight 名字→数字、颜色修饰符、letterSpacing `%`→`em`、颜色→`rgba()`、innerShadow→`inset`、typography→Android Compose 简写。`[仓库 README 原文]`

**跨端一致性收益**：同一份 token 生成 `Color.accentDefault`（Swift）与 `--sc-accent`（CSS），**原型里看到的强调色就是 App 里真正的强调色**，不会出现"原型好看、App 走样"。

    └── check_prototypes.py  ← 现有结构契约检查器

**方向切换机制**（无框架、30 行 JS）：

```html

<link rel="stylesheet" href="tokens/base.css">
<link rel="stylesheet" href="tokens/dir-01-white-sfblue.css" data-theme="dir01">
<link rel="stylesheet" href="tokens/dir-02-dark-amber.css"   data-theme="dir02">
```
```js

```
（多份 CSS 同时加载时，靠**后加载者覆盖前者**实现切换；更稳的写法是动态 `link.href` 替换单文件。两种都可，**推荐动态替换单文件**避免 CSS 体积叠加。）

```css

  --sc-ink-2:#6E6E73;     /* 次文字 */

```

**每个方向文件必须额外声明的"硬线合规声明"**（便于自动验收）：

```

--sc-tap-min:44px;      /* 最小点击区 */
--sc-depth:2;           /* 层级深度上限 */
--sc-visible-max:12;    /* 一级可见元素上限 */
```

> ⚠️ **与现状对齐的提醒**：本轮调研结束时，`prototype/variants/` 下**已有 16 个成品原型**（每份 33–50 KB 的完整 HTML）。上表的"1 份结构 + N 份 token"是**对现有做法的改进建议**，落地路径应是**把 16 份重复 HTML 收敛成 1 份 shell + 16 份 token**，而不是另起一套。§4.6.3 已用实测数据证明这条路径的价值：15/16 份文件命中**完全相同的 10 项脚手架基线**——说明重复的正是结构层，而结构层本该只写一遍。
> **另注意**：每份变体的次级文字（`--ink-2`）取值必须**逐方向实测对比度**，不能照抄 §6 的建议值——§4.6.3 已实测出现 `#b4afaa on #faf8f5 = 2.1:1` 这类违规。**建议用 `npx impeccable detect` 逐文件验证后再定稿。**

| `ios-input-zoom` | 15 | | | |
| `transition-all` | 1 | | | |

#### 4.6.3 三个可直接行动的结论

**① 15/16 个变体共享同一份「10 项脚手架基线」，与视觉方向无关。**
03–16 号的 nongeneric 命中**逐条完全一致**：

```
wide-tracking x3 + unsafe-dom-sink x2 + ios-input-zoom x1 +
legacy-viewport-height x1 + missing-focus-ring x1 +
missing-reduced-motion x1 + rigid-desktop-width x1 = 10
```

→ **改一次共享脚手架，16 个文件同时受益**。这正是 §3.5「1 份结构 + N 份 token」机制的价值兑现：**结构问题不该在 16 个方向里各修一遍**。

**② 真正的"方向级差异"是 `low-contrast`，且集中在暖色系与深色系。**
impeccable 的 157 条命中里 **110 条是 `low-contrast`（占 70%）**，且分布极不均：

| 方向类型 | 变体 | `low-contrast` | 实测违规对（原文摘录） |
|---|---|---:|---|
| 暖纸色系 | `01-paper-terracotta` | 12 | `#b4afaa` on `#faf8f5` = **2.1:1**；`#b7b2ad` on `#fffdfa` = **2.1:1**（含 placeholder "说点什么"） |
| 纯灰深色 | `02-graphite-mono` | 16 | `#8e8e93` on `#ededf0` = 2.8:1；`#5e5e66` on `#161618` = **2.8:1** |
| 暖终端深色 | `08-warm-terminal` | 16 | `#5e5e66` on `#1e1e21` = **2.6:1** |
| 纯黑高对比 | `12-noir-contrast` | 11 | 存在 `#5e5e66` 类次级文字 |
| **冷白 / 墨黑 / 珊瑚 / 暖纸（冷白版）** | `05` `06` `14` `16` | **各 2** | 基本干净 |

→ **判定：用户说"强调色没验证过"其实指错了对象。** 强调色不是问题，**次级文字（`--ink-2`/`--ink-3`）在暖底与深底上系统性偏亮，是 16 个方向里唯一真正的"色彩未验证"**。修复只需**改次级文字 token 亮度**，不动强调色、不动结构：

- 暖纸底：`#b4afaa` → 建议 `#6E6A66` 区间（与 `#faf8f5` 对比需 ≥4.5:1）
- 深底：`#5e5e66` → 建议 `#9A9AA2` 区间（与 `#161618` 对比需 ≥4.5:1）
- placeholder 文字同样按 4.5:1 处理（impeccable 明确把 placeholder 计入）

**③ `01-paper-terracotta.html` 与其余 15 个不同源，应单独处理。**
它命中 **26** 项（`unsafe-dom-sink` **18** 次、`missing-focus-ring` **2** 次、`wide-tracking` **2** 次、`rigid-desktop-width` **2** 次），**规模是其余 15 份的 2.6 倍**；且与 `docs/research/46-原型方案自动体检报告.md` 记录的"缺 6 个一级元素、六态 = 0"一致 → **它是上一版草稿，不是与其余 15 个同批生成的**。**建议从方案集里剔除或单独重生成**，否则会拉高整体体检噪音。

| 优先级 | 事项 | 覆盖命中数 | 改法 |

**方向 01 · 白瓷 · 一点蓝（Things 3 / iOS 设置 风）**

- **底色**：`#FFFFFF`；次级面 `#F5F5F7`；分隔色 `#C6C6C8`；主文字 `#1C1C1E`；次文字 `#6E6E73`。

## §七 反面清单：什么叫「高级但 AI 味」

> 每一类都给出**机器可检的 rule id**（来自 §四 nongeneric 82 条 / impeccable 实跑命中），所以不用靠人眼把关。

### 7.1 卡片套卡片（最常见）

- **长什么样**：一个外层白卡圆角 16px 阴影，里面再套一个灰底圆角 12px 的"信息卡"，信息卡里还有一个小标签胶囊。层层递进到三层。
- **为什么 AI 味**：模型默认「信息 = 装进盒子」，盒子里面还得再装盒子。真人做 iOS 界面几乎不套两层。
- **对应规则**：`nested-cards`（impeccable 实跑命中）、`card-grid-monotony`（三张等宽等高卡片并排）、`uneven-card-heights`、`monotonous-spacing`。
- **正确做法**：**一层容器 + 分隔线 + 留白**。层级靠 `--sc-ink` / `--sc-ink-2` / `--sc-line` 的层次表达，不靠盒子。

### 7.2 紫→蓝对角渐变 + 发光

- **长什么样**：`linear-gradient(135deg, #8b5cf6, #6366f1)` 铺在标题或按钮上；标题文字用 `background-clip:text` 做彩虹渐变；背后一个 `radial-gradient` 的紫色光晕。
- **为什么 AI 味**：这是训练语料里"高级感"的最高频均值，**每个模型的第一反应都是它**。
- **对应规则**：`purple-blue-gradient`、`gradient-text`、`animated-gradient-text`（流光标题）、`dark-glow`、`radial-halo`、`neon-accent`、`cyan-on-dark`、`ai-color-palette`。
- **正确做法**：**一个纯色强调**。想要"有设计"就换**强调色本身**（墨绿 / 琥珀 / 珊瑚 / 靛蓝），而不是给强调色加渐变。

### 7.3 玻璃拟态滥用

- **长什么样**：到处 `backdrop-filter: blur(20px)` + `rgba(255,255,255,.08)` 背景 + 1px 白描边，导航栏、弹层、按钮、标签全玻璃。
- **为什么 AI 味**：2020 年代 Web 风被模型当成"高级"通用解；**且在 390pt 小屏上玻璃层会降低文字对比度**，正好撞我们"彩色底上禁低对比灰字"的硬线。
- **对应规则**：`glassmorphism`、`gpt-thin-border-wide-shadow`（1px 细边 + 超宽阴影的"AI 卡片"特征组合）、`low-contrast-near-bar`。
- **正确做法**：**层级用底色明度差表达**（`#FFFFFF` ↔ `#F5F5F7`），不用模糊。

### 7.4 emoji 当图标

- **长什么样**：`✨` `🔥` `💡` `🎉` 直接当功能图标；每个标题上方一个小圆角彩色底托里塞一个 emoji。
- **为什么 AI 味**：emoji 是**跨平台系统字体**，渲染结果不受控，不同设备长得不一样——和"苹果交付感"直接冲突。
- **对应规则**：`sparkle-icon-ai`（✨）、`icon-in-colored-circle`（彩色圆圈图标）、`pill-badge-above-heading`（标题上方的胶囊小标）、`generic-avatar-stack`。
- **正确做法**：**SF Symbols（iOS 原生）/ 单一线性 SVG 集，全站一套**；图标底托若必须用，用**中性色**不用彩色。

### 7.5 插画风格不统一

- **长什么样**：页面里混着 2.5D 等距插画、扁平几何插画、手绘线稿、以及一张纯照片素材；每张的描边粗细、圆角、配色都不一样。
- **为什么 AI 味**：素材来源不同 = 拼凑感；这正是用户说"丑爆了"的直觉来源（说不清哪里怪，但一眼就是不像一个产品）。
- **对应规则**：`faux-3d-tilt`、`decorative-blob`、`buried-raster`（低质量位图）、`distorted-image-aspect`、`unsized-image`、`broken-image`。
- **正确做法**：**要么全无插画（几何 + 排版）**，要么**一套插画系统**（同描边宽度、同圆角、同 2 色配色），二选一。

### 7.6 假终端 Chrome + 跑马灯

- **长什么样**：一个画着 `~/projects $` 的黑框，里面其实是普通按钮；或顶部一条无限滚动的 logo 墙 / 客户 logo 条。
- **为什么 AI 味**："终端"和"logo 墙"是**用装饰冒充技术感/可信度**的典型 AI 套路。
- **对应规则**：`fake-terminal-chrome`、`marquee`、`logo-wall-soup`、`buried-raster`。
- **正确做法**：**不要装饰性终端框**。真要展示日志，就直接展示日志（无 `~/projects $` 提示符）。

### 7.7 排版假高级

- **长什么样**：标题全大写 + `letter-spacing: .12em`；正文用衬线体但行宽拉到 1200px；文案里满是破折号 "—"，以及 "Empower your team with seamless workflows." 这种市场词。
- **为什么 AI 味**：`wide-tracking` + `all-caps-body` + `wide-line-measure` + `em-dash-overuse` + `marketing-buzzword` + `aphoristic-cadence`（"Not a tool. A companion." 这种对仗金句）是**同一套模板的六个指纹**。
- **正确做法**：中文界面里**全大写与宽字距基本不可用**；标题用句式大小写（Title Case），字距 0 到 -0.02em；文案用**具体名词**代替抽象词。

### 7.8 移动端假桌面（本次原型实测重灾区）

- **长什么样**：写死 `width: 392px`；`minmax(360px, 1fr)` 不包 `min()`；`min-height: 100vh`；输入框 `font-size: 14px`。
- **为什么 AI 味**：桌面模板直接塞进手机宽度 → 横向溢出 → **构图失焦**。**用户说的"构图失焦"在机器上就是 `rigid-desktop-width` + `unbounded-grid-track`**（nongeneric 该 pillar 实测 **0/20**）。
- **对应规则**：`rigid-desktop-width`、`unbounded-grid-track`、`legacy-viewport-height`、`viewport-width-overflow`、`missing-min-w-0`、`ios-input-zoom`、`fixed-height-text-box`。
- **正确做法**：`width: min(100%, 390px)`、`repeat(auto-fit, minmax(min(100%, 320px), 1fr))`、`min-height: 100dvh`、输入框 `font-size: max(16px, 1rem)`。

### 7.9 动效失控

- **长什么样**：`cubic-bezier(.34, 1.2, .4, 1)` 回弹；`transition: all .35s`；`will-change: transform` 常驻；20 个元素依次入场。
- **为什么 AI 味**：回弹曲线 + 全属性过渡 = **2015 模板感**，与我们"禁 bounce"硬线一致。
- **对应规则**：`bounce-easing`、`transition-all`、`will-change-abuse`、`missing-reduced-motion`、`stagger-overload`、`linear-ui-entrance`、`pinned-root-transform`。
- **正确做法**：**3 档时长（120 / 180 / 300ms）+ 2 种曲线（标准 `cubic-bezier(.25,.1,.25,1)` 与 expo `cubic-bezier(.22,1,.36,1)`）**，只动 `transform` / `opacity` / `color`，且必须写 `@media (prefers-reduced-motion: reduce)`。

### 7.10 一句话判据

> **如果一个界面能被描述成"深色渐变卡片 + 三个图标 + 一段 emoji 文案"，它就是 AI 味；如果它能被描述成"某种纸、某种光、某种字体、某种分隔"，它就是设计。**
> —— 前者是模板均值，后者是选择。

### 8.2 风险与注意事项

1. **星标是 shields 快照**，非 GitHub API，且**仓库迁移频繁**（daisyui 的正确地址是 `saadeghi/daisyui`，43k★；`daisyui/daisyui` 只有 8★）。本文件里的仓库名请以**实际抓通的那一个**为准。

3. **nongeneric 分数不是设计分**：README 原文明确"空 body 也能 100 分"。**不可向用户宣称"检测通过 = 设计好"**。

5. **许可证风险分级**：
   - ✅ 可自由使用：daisyui / hyperui / pico / open-props / tailwindcss / shadcn / flowbite / motion-primitives / style-dictionary / sd-transforms / impeccable / nongeneric / ionic
   - ⚠️ 有附加限制：**React Bits（MIT + Commons Clause，不得再分发组件本体）**、**Preline（MIT + Fair Use）**
   - ❌ 不可用：**Tailwind UI（付费需登录）**、**Cruip（付费非开源）**
6. **Google Fonts 在国内网络不稳**（虽然本机实测 200）。方向 04/10 依赖衬线字体，**必须做本地字体兜底或系统衬线降级**。
7. **daisyUI CDN 1.14MB**，14 个方向全挂会显著拖慢；**建议只让"需要组件皮肤"的方向用它，其余走自写 token**。
8. **Tailwind v4 `@theme` 的运行时换值行为未实机验证**（标注为 [我的推断]）。若要稳妥，用**纯 CSS 变量 + 语义 class**，不依赖 `@theme` 动态切换。
