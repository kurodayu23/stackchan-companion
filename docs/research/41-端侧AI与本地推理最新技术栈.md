## §一 结论摘要（10 条判断）

| # | 判断 | 能不能用 | 用在哪 | 风险 |
|---|---|---|---|---|
| 1 | **Apple Foundation Models 框架已 GA 且可用**，iOS 26.0+ 起提供端侧模型 `SystemLanguageModel` | ✅ 能用 | iOS 端「本地小脑」：意图分类、情绪标注、人格化改写、本地摘要 | 需 Apple Intelligence 机型；**中国大陆不提供** |
| 2 | **中文是 Apple Intelligence 官方支持语言**（简体/繁体均列） | ✅ 能用 | 本地中文对话与结构化输出 | 护栏只在受支持语言上生效；非美式英语需在 Instructions 首句声明 locale |
| 3 | **Foundation Models 不在中国大陆可用**（无论设备购买地与账号区域如何组合） | ❌ 大陆不可用 | 无 | **产品级致命风险**：主打国内用户的项目不能把 FM 当唯一本地大脑 |

| 6 | **本地开源模型可经 `Core AI` 或 `MLX` 桥接进同一会话 API**（`CoreAILanguageModel` / `MLXFoundationModels`） | ✅ 能用（需 iOS 27 / Xcode 27） | 不依赖 Apple Intelligence 的本地 LLM 路径，中国大陆也能走 | 导出/量化流程重；Core AI 要求约 0.6B 量级模型起步 |
| 7 | **ESP32-S3（8MB PSRAM）跑不了通用 LLM**；官方 DL 栈只有 CNN，无任何 Espressif LLM 仓库 | ❌ 不可行 | ESP32 只做感知/唤醒/动作，不做语言 | 若坚持端侧小模型，最小可行单位是「规则+关键词+嵌入式分类器」 |
| 8 | **ESP32-S3 端人脸检测可行：两阶段 MSR+MNP 实测约 43ms/帧**（120×160 + 48×48） | ✅ 能用 | 在场感知、人脸朝向→舵机 yaw 跟随 | 帧率上限约 20fps；不能同时跑 YOLO |
| 9 | **ESP32-S3 端人体姿态不可行**：YOLO11n-Pose 单帧约 4.48s，且需 8MB PSRAM（吃掉全部 PSRAM） | ❌ 不可行 | 姿态识别改放 iPhone 端 | 官方 README 明确要求 PSRAM ≥16MB 才可放 SD 卡 |

**一句话结论**：**大脑必须放在 iPhone（且不能只依赖 Apple Intelligence，因为中国大陆不可用）；ESP32-S3 降级为「感知+执行」终端**；MiniMax 走云端但用 Apple 官方的 provider 接口接进同一套会话抽象，这样本地/云端切换只是换一个 `LanguageModel` 实例。

## §二 Foundation Models framework 深度核实（最高优先级）

### 2.1 可用性矩阵（2026-10 实际状态）

**框架平台要求** `[Apple 官方文档原文]`（`developer.apple.com/tutorials/data/documentation/foundationmodels.json`）：

| 平台 | 最低版本 |
|---|---|
| iOS / iPadOS / Mac Catalyst / macOS / visionOS | **26.0** |
| watchOS | **27.0** |

**关键子系统的平台门槛不同** `[Apple 官方文档原文]`（各符号页 metadata.platforms）：

| 能力 | 符号 | 起始版本 |
|---|---|---|
| 端侧模型 | `SystemLanguageModel` | iOS 26.0 / iPadOS 26.0 / Mac Catalyst 26.0 / macOS 26.0 / visionOS 26.0 |
| 自定义 provider | `LanguageModel` / `LanguageModelExecutor` / `LanguageModelCapabilities` | **iOS 27.0** / iPadOS 27.0 / Mac Catalyst 27.0 / macOS 27.0 / visionOS 27.0 / watchOS 27.0 |
| 工具 | `Tool` | iOS 26.0 起（watchOS 27.0） |
| 私有云 | `PrivateCloudComputeLanguageModel` | iOS 27 / macOS 27 / watchOS 27 / visionOS 27 |

**端侧模型版本** `[Apple 官方文档原文]`（`systemlanguagemodel` 页）：Apple 会随系统更新替换端侧模型，当前存在 **3 个模型版本**，分别对应
`26.0–26.3` / `26.4` / `27.0`。2026-02 更新说明：26.4 改进「指令遵循与工具调用能力」；2026-06 更新说明：iOS 27 的模型「更准确地遵循指令」。
→ **含义**：提示词必须按模型版本分叉维护，官方文档专门给了 `updating-prompts-for-new-model-versions` 一页来管理这件事。

**可用性判定 API** `[Apple 官方文档原文]`：

```swift
private var model = SystemLanguageModel.default
switch model.availability {
case .available:                                  // 可用
case .unavailable(.deviceNotEligible):           // 机型不支持
case .unavailable(.modelNotReady):               // 模型正在下载 / 系统原因未就绪
case .unavailable(let other):                    // 未知原因
}
```
`PrivateCloudComputeLanguageModel` 的 availability 则是 `.available / .deviceNotEligible / .systemNotReady / 其他` `[Apple 官方文档原文]`。

### 2.2 支持机型与「中国大陆不提供」

来源：`support.apple.com/en-us/121115`（页面标注 Published Date: **October 22, 2026**）`[Apple 官方文档原文]`

**机型要求（iOS 27 一代）**：
> iPhone Duo, iPhone 16 models or later, iPhone 15 Pro, iPhone 15 Pro Max, iPhone Air, iPad mini (A17 Pro), iPad models with M1 or later, MacBook Neo (A18 Pro), Mac with M1 or later, Apple Vision Pro, Apple Watch Series 9 or later, Apple Watch Ultra 2 or later, and Apple Watch SE 3

**系统要求**：iOS 27 / iPadOS 27 / macOS 27 Golden Gate / visionOS 27 / watchOS 27；
存储占用「最多 8GB」（多数机型），iPhone Duo、iPhone 17 Pro 及以后、iPad M4 及以后、Mac M3 及以后、Vision Pro (M5) 为「最多 14GB」；
**设备语言与 Siri 语言必须设为同一个受支持语言**；改 Siri 语言后 Apple Intelligence 可能暂时不可用。

**语言清单（原文摘录）**：
> Apple Intelligence is available with support for these languages: English, Danish, Dutch, French, German, Italian, Norwegian, Portuguese, Spanish, Swedish, Turkish, Vietnamese, **Chinese (simplified)**, **Chinese (traditional)**, Japanese, and Korean.

→ **中文在册**（简体/繁体共 17 种受支持语言）。

**⚠️ 中国大陆限制（原文摘录，本项目最高风险项）**：
> Apple Intelligence features will **not currently work** for supported devices purchased in China mainland. For supported devices purchased outside of China mainland, Apple Intelligence features will not currently work if you are in China mainland **and** if your Apple Account Country or Region is also in China mainland.
>
> When Apple Intelligence is available in China mainland, previously-purchased devices that support Apple Intelligence will be able to activate and start using a core set of Apple Intelligence features in that region. New Apple Intelligence features will not be available in China while Apple works through regulatory requirements.
>
> 官方口径明确是「**尚未开放、正在推进监管**」，不是「不支持」。

**工程结论** `[我的推断]`：
1. 对中国大陆用户，Foundation Models 的端侧模型**当前不可用**，且是「未开放」而非「机型不支持」——无法靠换机解决。
2. 因此**本地推理 provider 必须自建**（MLX/Core AI/llama.cpp），不能只依赖 `SystemLanguageModel`。
3. `PrivateCloudComputeLanguageModel` 同样受此限（文档明确 PCC 需要「支持 Apple Intelligence 的设备」），因此**PCC 不是国内方案的备选**。
4. 隐私叙事上这反而有利：国内用户走「自建本地模型 + MiniMax 云端」，我们完全掌控数据流向，不依赖 Apple 的服务可用性。

### 2.3 能做什么（API 形态）

全部 `[Apple 官方文档原文]`。

| 能力 | API | 要点 |
|---|---|---|
| 文本生成/会话 | `LanguageModelSession(instructions:tools:)`、`respond(to:options:)`、`respond(to:options:contextOptions:)`、`streamResponse(to:options:)`、`respond(to:generating:)` | `GenerationOptions` 含 `toolCallingMode`、`samplingMode`（`.greedy`）；`ContextOptions(reasoningLevel:)` = `.light/.moderate/.deep`（**仅 PCC 支持推理**） |
| 结构化输出 | `@Generable` / `@Guide(description:)` / `DynamicGenerationSchema` | 文档称框架提供「**strong guarantees**」生成你的类型的实例；→ 舵机指令、人格参数、情绪标签都应走强约束而非解析自由文本 |
| 工具调用 | `Tool`（`name` + `description` + `call(arguments:)`），参数用嵌套 `@Generable struct Arguments`，返回 `PromptRepresentable` | 必须 `Sendable`；框架分六阶段处理；工具定义占上下文；可并发、可背靠背串联 |
| 工具模式 | `ToolCallingMode` = `.allowed` / `.required` / `.disallowed`（2026-06 新增） | `.required` 必须配退出条件（工具抛错或用 DynamicProfile 动态切换），否则模型会一直调 |
| 工具错误 | `LanguageModelSession.ToolCallError`（`.tool` + `.underlyingError`）、transcript 自动回滚、`.transcriptErrorHandlingPolicy(.preserveTranscript)` | 可保留出错时的部分生成 |
| 多模态（图像） | `Attachment(image, orientation:)` 支持 `CGImage/CIImage/CVPixelBuffer/URL`；`ImageReference`；`Attachment.label(_:)` | 框架自动缩放与色彩转换；Vision 的 `OCRTool`/`BarcodeReaderTool` 可直接挂载；可配 `@Generable enum` 做图像分类（配 `.greedy`） |
| 内容标签 | `SystemLanguageModel` + `UseCase.contentTagging` | 官方专用模型：识别话题/动作/对象/**情绪** → 情绪识别不必自训 |
| Transcript | `session.transcript` 可观察，条目 `.instructions/.prompt/.toolCalls/.toolOutput/.response/.reasoning` | 可作为路由与出网审计的第一手证据 |
| 会话状态 | `SessionProperty` / `@SessionPropertyEntry` / `SessionPropertyValues`（2026-06 新增） | 在 profile、dynamic instructions、tool 之间共享自定义状态（如「工具已调用次数」「本次是否已上云」） |
| 动态装配 | `LanguageModelSession.DynamicProfile`、`Profile`、`DynamicInstructions`、`DynamicInstructionsForEach` | Apple 开源包另提供 `Skills`（按需注入避免上下文污染）与 `.rollingWindow/.summarizeHistory/.droppingCompletedToolCalls` |

`@Generable` 示例（唯一必背的用法）：

```swift
@Generable(description: "Basic profile information about a cat")
struct CatProfile {
    var name: String
    @Guide(description: "The age of the cat", .range(0...20)) var age: Int
}
let r = try await LanguageModelSession().respond(to: "Generate a rescue cat", generating: CatProfile.self)
```

### 2.4 端侧 vs 私有云的能力/额度对照

`[Apple 官方文档原文]`（`adding-server-side-intelligence-with-private-cloud-compute` 页，原文表格）

| Capability | `SystemLanguageModel` | `PrivateCloudComputeLanguageModel` |
|---|---|---|
| Preserves privacy | ✅ | ✅ |
| Works offline | ✅ | 🚫 |
| Usage limits | Unlimited | **Limit per day** |
| Reasoning | Not supported | Multiple levels（light/moderate/deep） |
| Context size | **4K** | **32K** |

PCC 需要**申请受管 entitlement**（`com.apple.developer.private-cloud-compute`），且需要网络；断网时文档建议**回落端侧模型**。配额用 `model.quotaUsage`（`.isLimitReached` / `.belowLimit(info)` / `.isApproachingLimit`）、`limitIncreaseSuggestion`、`resetDate` 处理。

### 2.5 自定义 provider（本次调研的决定性发现）

`[Apple 官方文档原文]`（`languagemodelexecutor` 页原文）：

> An executor is the bridge between the framework types and the system that actually generates the tokens, **like a server API or a local inference engine**. A LanguageModel pairs with exactly one executor type and the framework instantiates the executor from the Configuration the model provides.

`[Apple 官方文档原文]`（`languagemodel` 页原文）：

> Implement this protocol to create a bridge between a model and the framework. The protocol describes the capabilities and the configuration for your model. An Executor does the work of translating framework types into the types your platform expects, and streams results back through `LanguageModelExecutorGenerationChannel`.
>
> （要义：协议只描述「能力 + 配置」，翻译与流式回传由 Executor 负责。）

```swift
let session = LanguageModelSession(model: MyCustomServerLanguageModel())
let response = try await session.respond(to: "Tell me a joke!")
```

`[Apple 官方文档原文]`（`languagemodelcapabilities` 页原文）：
```swift
var capabilities: LanguageModelCapabilities {
    LanguageModelCapabilities([.toolCalling, .guidedGeneration, .reasoning])
}
```
能力不匹配时框架会拒绝派发并抛 `unsupportedCapability(_:)`。
executor 需实现 `respond(to request: LanguageModelExecutorGenerationRequest, model:, streamingInto channel: LanguageModelExecutorGenerationChannel)`；文档示范了「模型只支持 temperature 时如何用 temperature=0 近似 greedy」的**降级适配**。

**两条已验证的具体落法**：

1. **接云端 MiniMax** `[开源仓库 README 原文]`（`apple/foundation-models-utilities/README.md`）：
   ```swift
   let model = ChatCompletionsLanguageModel(
     name: "minimax-m2.5",
     url: URL(string: "http://localhost/v1:8000")!,
   )
   let session = LanguageModelSession(model: model)
   let response = try await session.respond(to: "How many folds does it take to make a paper crane?")
   ```
   包内还有 `supportsGuidedGeneration: false` 这类能力声明开关——**正好适配「MiniMax 不支持 guided generation 时只关这一项」**。
   注意：**该仓库的 LICENSE 文件 404（未取得）**，README 也未声明许可证 → 商用前必须自行确认授权。

2. **接本地开源模型** `[开源仓库 README 原文]`：
   - `apple/coreai-models`（BSD 3-Clause）：`CoreAILanguageModel` 遵循 `LanguageModel` 协议，用 `uv run coreai.model.registry --list-models` 列模型、`uv run coreai.llm.export HF_ID --platform iOS` 导出 `.aimodel`（含 tokenizer），再 `try await CoreAILanguageModel(resourcesAt: modelURL)` → `LanguageModelSession(model: model)`。文档建议「**0.6B 参数左右是很好的起点**」。要求 macOS/iOS **27.0+**、Xcode **27.0+**。
   - `ml-explore/mlx-swift-lm`（MIT）：`MLXFoundationModels` —— 「Bridge MLX models into Apple's `FoundationModels.LanguageModel` for use with `LanguageModelSession`. (Requires the macOS/iOS/visionOS 27.0 SDK.)」；同包 `MLXGuidedGeneration` 提供 JSON Schema / EBNF 语法约束生成；`MLXScriptedLM` 可做测试桩。

**推论** `[我的推断]`：把「本地 vs 云端」抽象成**一个 `LanguageModel` 协议家族**后，
- 本地 = `SystemLanguageModel` / `CoreAILanguageModel` / `MLXFoundationModels`；
- 云端 = `ChatCompletionsLanguageModel`（MiniMax）；
- 切换 = 换实例，上层代码（工具、@Generable 结构化输出、transcript 审计）**完全不变**。
这直接满足「本地推理 provider 能不能落地」：**能，且是官方一等公民路径**。

### 2.6 中文能力细则

`[Apple 官方文档原文]`（`supporting-languages-and-locales-with-foundation-models` 页）：

- 端侧模型是多语言的，「the same model understands and generates text in **any language that Apple Intelligence supports**」；prompt / instructions / 输出可各用不同语言。
- **所有输入都必须使用受支持语言，包括所有 `Generable` 类型与描述**（属性名与 `@Guide` 描述同等重要）。
- 运行时用 `supportsLocale()`（默认取当前语言与 App 专属设置）判断，进阶用 `supportedLanguages`；近缘 locale 视为等价（`en-AU` ≈ `en-NZ`）。不支持 → 抛 `unsupportedLanguageOrLocale(_:)`。
- ⚠️ 原文警告：**护栏只对受支持语言生效**；混入一小段不支持语言的内容**可能既不报错也不被护栏标记**。
- 非美式英语 locale：Instructions **必须以英文原句开头** `"The person's locale is \(locale.identifier)."`（该短语来自模型训练，降低多语幻觉）；默认输出语言跟随输入，需固定时写 "You MUST respond in …"。

### 2.7 端侧模型的实测口径缺失（诚实声明）

- 端侧模型参数量、量化格式、tokens/s、下载体积：**未取得**（Apple 未公开）。
- `contextSize` / `tokenCount(for:)` 为运行时 API（2026-02 起提供），**需真机读取**；文档对照表为端侧 4K / PCC 32K。
- 中文输出质量、tool calling 稳定性的**版本差异**需真机验证（2026-02 / 2026-06 变更说明均强调模型换代会改变行为）。

**算子级加速（ESP32-S3 相对 ESP32，esp-dl v3.3.10）** `[开源仓库 README 原文]`：
Conv **22.9×**、ConvTranspose 31.8×、MaxPool 37.1×、Resize 8.03×、Requantize 7.07×、PRelu 5.2×；**全部 955 个用例总耗时：esp32 11,492,626.6µs → esp32s3 963,491.2µs（≈11.9×）**，esp32p4 320,828.7µs。

### 3.3 结论：能跑什么 / 不能跑什么

**能跑（有实测支撑）** `[开源仓库 README 原文]`（ESP-DL Model Zoo 支持芯片列）

| 能力 | ESP32-S3 | 备注 |
|---|---|---|
| Human Face Detect（MSR/MNP/ESPDet） | ✅ | **~43ms/帧两阶段** → 在场与朝向 |
| Human Face Recognition（特征+ID） | ✅ | 256/468ms，TAR 90%+ |
| Person ReID | ✅ | 106ms |
| Hand Gesture（8+ 手势） | ✅ | 74ms（需先 HandDetect） |
| Pedestrian Detect | ✅ | 125ms |
| Motion / Color Detect | ✅ | 全 ESP32 系列 |
| COCO Detect（YOLO11n）/ YOLO26 | ✅ 支持但**不实用** | 991–4006ms，且吃满 8MB PSRAM |

**不能跑（明确否定）**

| 能力 | 结论 | 依据 |
|---|---|---|
| **人体姿态（YOLO11n-Pose）** | ❌ 不可行 | ESP32-S3 单帧 **4.48 秒**；且 Flash 8MB + **PSRAM 8MB**（占满全部 PSRAM）；README 明写「When using YOLO11n-pose, do not set model location to sdcard **if your PSRAM size is lower than 16MB**」 |
| **中文 OCR（PP-OCRv6）** | ❌ 不支持 S3 | Model Zoo 中 OCR 的 Supported Chips 仅列 **ESP32-P4**（2026-07-30 加入，中英+46 拉丁语种） |
| **说话人声纹验证** | ❌ 不支持 S3 | Speaker Verification 仅 **ESP32-S31 / ESP32-P4** |
| **通用 LLM / 小语言模型** | ❌ 不可行（见 3.4） | 无官方运行时 + 内存量级差 2 个数量级 |

**性别 / 年龄推断**：ESP-DL Model Zoo **没有**性别年龄分类模型 `[开源仓库 README 原文]`（逐项核对 Model Zoo 表）。
→ 在 ESP32-S3 上做性别年龄，既没有官方模型，也不建议自训（内存与数据都吃紧）。
**建议**：这类「外观推断」整体**上移到 iPhone 端**或**直接不做**——产品上用「人脸朝向 + 距离 + 停留时长」表达注意力，比性别年龄更安全也更省电 `[我的推断]`。

### 3.4 LLM 在 ESP32-S3 上的可行性取证

**负面证据（实际抓取）**：

1. `espressif/esp-llm` —— `raw.githubusercontent.com/.../esp-llm/HEAD/README.md` 返回 **404**；jsdelivr 包解析 `data.jsdelivr.com/v1/packages/gh/espressif/esp-llm` 同样 **404**。→ **该仓库不存在**（至少不以这两个名字存在）。
2. `espressif/esp32-llm` —— 同样 **404**。
3. Espressif 官方推理栈 `esp-dl` / `esp-nn` 的 Model Zoo 与算子表 **全部是 CNN/分类/检测/分割/OCR**，无 transformer/LLM 运行时 `[开源仓库 README 原文]`。
4. `tensorflow/tflite-micro` README 自述适用对象为「bare-metal systems, DSPs, and microcontrollers with limited memory (**tens to hundreds of kilobytes**)」 `[开源仓库 README 原文]`。
5. `espressif/tflite-micro-esp-examples`（`esp-tflite-micro` 组件）示例只有 **ESP32-S3-EYE Person Detection** 一类经典 CV 任务，无 LLM；该仓库 ESP-IDF 支持矩阵含 `release/v5.5` ✅（与本项目 ESP-IDF v5.5.4 兼容）`[开源仓库 README 原文]`。

**内存量级算术** `[我的推断]`（基于上文 8MB PSRAM 硬约束）：
- 0.5B 参数 LLM 即使 4-bit 量化，权重也需 **≈250MB** 量级；加上 KV cache 与运行时，**比 8MB PSRAM 大两个数量级** → 物理不可能。
- 能塞进 8MB PSRAM 的神经网络，量级上限在 **百万级参数**（如上表的手势模型 74ms、行人模型 125ms 档位）。
- 结论：**8MB PSRAM 上唯一可接受的「语言能力」是规则/关键词/小分类器/嵌入式检索**，而不是生成式 LLM。

**未取得**：用户提到的 `Qwen2.5-0.5B`、`SmolLM`、`Duino`、`MicroLLM` 四项，本次**未能取得任何一手页面**——
`huggingface.co` 与 `huggingface.co/api` 在本机 **连接超时**（python urllib 与 web_fetch 双向失败）；
GitHub 直连（`github.com`）同样超时，**星标数因此全部无法取得**；
`Duino` / `MicroLLM` 的确切仓库归属未确证（按多种命名探测均 404）。
→ 这四项在本节只作为「候选模型名」保留，**不做任何参数/性能断言**。

### 3.5 ESP32-S3 的定位建议（工程结论）

`[我的推断]`，基于 §3.2/3.3/3.4 硬数据：

| 层 | 职责 | 技术 |
|---|---|---|
| ESP32-S3 常驻 | 摄像头取流（QVGA）、人脸检测（~43ms/帧）、人脸朝向→舵机 yaw、BMI270 姿态、音量/唤醒、双麦降噪、RGB LED、舵机控制 | ESP-DL `HumanFaceDetect`（MSR+MNP 两阶段），每 N 帧跑一次，其余时间走轻量运动检测 |
| ESP32-S3 可选 | NFC 配对、电池/电源管理、离线唤醒词 | 现成 HAL 保留 |
| **不做** | 语音识别、对话、LLM、姿态识别、中文 OCR、性别年龄 | 内存/算力不足（见上） |
| iPhone 端接管 | 语音转写、对话、姿态、手势、注视、3D 预览、隐私路由 | Apple Vision / MediaPipe / Foundation Models / MLX |

**内存红线**：YOLO11n 系模型单模型就要 8MB PSRAM，与「人脸检测 + 摄像头缓冲 + FreeRTOS 任务」冲突；**不要同时启用**。

## §五 隐私分层架构的落地设计

### 5.1 四层路由

| 层 | 位置 | 承担 | 出网 |
|---|---|---|---|
| **L0 感知层** | ESP32-S3 | 人脸在场/朝向、唤醒词、运动、音量、IMU、舵机动作 | **永不出网**（ESP32 无公网通道） |
| **L1 本地语义层** | iPhone（设备内） | 意图分类、槽位抽取、情绪/话题标注、人格化措辞改写、本地摘要、敏感词判定 | **不出网**（本地模型） |
| **L2 私有云层** | MiniMax API | 长文本对话、复杂推理、TTS | 出网，**受 §5.2 白名单约束** |
| **L3 边缘层（可选）** | 自建服务器 | 自托管模型、ENFP 人格包热更新、遥测（去标识） | 出网，仅自建域名 |

### 5.2 路由判定（单一决策点）

`[我的推断]`，判定顺序：

```
1. 本地模型可用？（availability == .available 或本地 MLX 已加载）→ 否：L2 云端（UI 明示）
2. 本轮请求命中 PersonalDataClassifier 敏感类别？→ 是：L1 本地作答，不进 L2
3. 需要长上下文 / 复杂推理 / 外部知识 / TTS？→ 是：L2 云端；否：L1 本地
```

**落地上必须注意的两个陷阱** `[我的推断]`：
- **本地判定不能只靠关键词**：真正的边界应由「**本轮请求携带的字段**」决定，而不是「用户说了什么」。§5.3 的结构化白名单才是硬边界。
- **切到云端时不能把本地上下文整包带上**：路由决策要产出「**云端可见视图**」，而不是「本地 transcript 全文」。

### 5.3 「个人数据永不入库」如何在代码层可验证

这是本项目对外的核心承诺，必须能写成**可自动执行的测试**，而不是口头纪律。六条硬约束 `[我的推断]`：

| # | 约束 | 实现要点 |
|---|---|---|
| ① | **单一出口** | 所有出网请求只能由 `CloudGateway` 构造；其余代码禁止直连远端。`URLSession` 注入自定义 `URLProtocol`，`CloudGateway` 之外的请求在测试中一律 fail |
| ② | **类型级白名单** | 云端请求体由独立类型序列化，其 `Encodable` 合成代码里**不存在**个人记忆字段 → 类型系统层面不可能序列化上去 |
| ③ | **工具边界** | 本地模型可挂 `Tool` 读个人记忆（如 `RecallPersonalMemoryTool`）；**切云端时工具集合为空** → 云端模型在能力上读不到。路由时重建 session，不复用工具列表 |
| ④ | **只读本地存储** | 个人记忆落本地（SwiftData/SQLite/Keychain），永不同步任何服务器；提供导出/清空入口；日志不出现记忆原文 |
| ⑤ | **审计 ≠ 内容** | 审计只留 `route(local\|cloud)`、`intentClass`、`payloadByteCount`、`payloadHash`、`personaVersion`、`latencyMs`；Hash 用于事后比对，不用于反推内容 |
| ⑥ | **CI 可跑测试** | 见下方四条测试 |

```swift
struct CloudRequestBody: Encodable {
    let personaId: String          // 通用 ENFP 人格包 ID
    let sessionId: String
    let utterance: String          // 本轮用户输入（已过 PII 清洗）
    let localSummary: String?      // 本地模型生成的摘要，非原文
    let personaVersion: String
}
```
个人记忆存于**另一个模块**（`PersonalStore`），上表结构中根本没有它的位置。

**自动化测试** `[我的推断]`：
- `testNoPersonalDataInCloudPayload`：构造含个人记忆的本地状态 → 走一次云端路由 → 断言序列化 body 中**不出现**命中个人数据字段名模式的键，并断言字节数上限。
- `testNoEgressFromLocalLayer`：L1 处理期间注入 `URLProtocol` 桩，断言**零请求**发出。
- `testEgressOnlyFromCloudGateway`：全局桩断言所有出网请求均经 `CloudGateway`（host 白名单 + 签名头）。
- `testServerRejectsPersonalFields`：服务端 schema 遇到 `user_data` / `memory` / `profile` 字段**直接拒绝**（防客户端漏改）。

**风险提示** `[我的推断]`：第 ② 条是这套设计的地基。若未来为「让云端更聪明」给 `CloudRequestBody` 加一个 `context: String` 字段，隐私边界会在一次 review 疏忽中破掉。建议把 `PersonalStore` 与 `CloudRequestBody` 放在**不同的 Swift Package target**，用 module 边界而非命名约定来隔离。

### 5.4 与 Foundation Models 的契合点

§2.3「Transcript / 会话状态」两行的 `SessionProperty` / `@SessionPropertyEntry` 可承载「本次会话是否已上云」「已触达记忆条数」等**可审计状态**；
`transcript` 可观察且条目类型明确（`.instructions/.prompt/.toolCalls/.toolOutput/.response/.reasoning`），是**路由与出网审计的第一手证据**。两者结合 → 隐私承诺可从「设计约定」升级为「运行时可观测事实」。`[Apple 官方文档原文]`

### 7.2 风险登记

| 等级 | 风险 | 触发条件 | 缓解 |
|---|---|---|---|
| 🔴 **高** | **中国大陆 Apple Intelligence 不可用** → `SystemLanguageModel` / PCC 全部不可用 | 用户在大陆境内 + 大陆账号区域，或设备大陆购入 | **主线必须自建本地模型**（MLX/Core AI/llama.cpp）；Apple FM 降级为「海外增强」 |
| 🔴 高 | `foundation-models-utilities` 授权不明 | 商用发布 | 落地前取得书面确认；否则自研等价 `LanguageModel` + `LanguageModelExecutor` 实现（协议本身来自 Apple 官方文档） |
| 🟠 中 | **端侧模型换代会改变行为**（26.0-26.3 / 26.4 / 27.0 三个版本） | 用户升级 iOS | prompt 按模型版本分叉维护（官方给了专门文档页）；建立「按版本」的 prompt 变体与回归集 |
| 🟠 中 | **护栏只在受支持语言上生效**，混语短句可能既不报错也不被拦 | 中文里混入英文/方言短句 | 上云前做本地敏感词/敏感语义过滤（L1 本地模型），不依赖云端护栏 |
| 🟠 中 | **非美式英语需在 Instructions 首句声明 locale** | 中文（zh_CN） | Instructions 以固定英文原句开头：`"The person's locale is \(locale.identifier)."`；并在 Instructions 中显式声明输出语言 |
| 🟠 中 | **PCC 需申请受管 entitlement + 每日配额** | 想用 32K 上下文/推理 | 不作为主线；仅海外可选增强；配额用 `quotaUsage` UI 兜底 |
| 🟡 低 | **ESP32-S3 内存红线**：YOLO11n 单模型占 8MB PSRAM | 同时启用检测 + 大模型 | 菜单配置里只允许一个人脸模型 + 一个分类模型；启动时做 PSRAM 占用断言 |
| 🟡 低 | **MediaPipe 包体膨胀**（运行时 + 模型） | 引入 MediaPipe | 优先 Apple Vision；MediaPipe 按需引入并做包体预算 |
| 🟡 低 | **ESP-DL / esp-dl 版本更新频繁**（2026 年内多次重构量化 schema，v3.1.0 起 schema 不向后兼容） | 升级组件 | 锁定 esp-dl 版本；模型 `.espdl` 与框架版本强绑定 |

### 7.3 建议的落地顺序（直接指导开发）

1. **iOS 骨架**：定义自建 `protocol LanguageModelProvider`（不直接依赖 Apple 协议），提供 `LocalModelProvider`（先接 `SystemLanguageModel`，大陆场景预留 MLX/Core AI）与 `MiniMaxProvider`（`ChatCompletionsLanguageModel` 或自研 executor）。先把抽象立住，避免返工。
2. **隐私闸门**：`CloudGateway` + `CloudRequestBody` + `PersonalStore` 分离 + §5.3⑥ 的 CI 测试。
3. **ESP32 端**：只接 `HumanFaceDetect`（MSR+MNP，~43ms/帧）做在场与朝向→舵机；官方 HAL 与表情引擎不动。
4. **感知上移 iPhone**：Apple Vision（人矩形/人脸/landmark/手部姿态/显著图）承接手势控舵机与注视近似。
5. **再谈本地 LLM**：待 `foundation-models-utilities` 授权明确后，比较 MLX / Core AI / llama.cpp 三条自建路线的包体与维护成本。
