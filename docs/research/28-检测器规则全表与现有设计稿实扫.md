## §零 · 本文解决的是什么

`25-反AI味设计工具全景.md` 的 T1/T2 待办是「**导出 impeccable 62 条 + nongeneric 82 条的完整规则目录**」——一直空着。

**本文的三个交付**：

### 1.3 覆盖情况小结

- **有官方 Floor 对应**：34 条（其中 10 条直接对应 `19` 号 §1.8 新增的 F33–F38 反 AI 味条款）。
- **标注「无对应」**：31 条 —— 这些要么是我们的规范没覆盖的**新型 AI 味**（`over-round` / `gpt-thin-border-wide-shadow` / `icon-in-colored-circle`），要么是**工艺层**（`cramped-padding` / `monotonous-spacing`），要么是**工程缺陷**（`broken-image` / `script-error`）。
- **⚠️ 最大的规范缺口**：`low-contrast`（对比度）**在我们 39 条宪法和 F1–F46 里都没有编号条目**。它在 `00-总纲` §3（实测色板）和 `19` 号 §4.1（CI 检查项）里以「数据/机制」形式存在，但没有一条可被引用的**硬约束编号**。本文 §五 把它列为 P1 提案（新增 **F47**）。
- **第二个缺口**：`missing-focus-ring`（焦点环）同样无编号 —— 而 `19` 号 §0 明确说 Floor 层是「事实正确性与可用性底线…**不可豁免**、**阻塞发布**」。焦点环缺失显然属于这一层，却没有编号条目。§五 列为 P0 提案（新增 **F48**）。
- ⭐ **编号口径说明**：本文定稿时（2026-10-23 22:xx）`19` 号 Floor 文件已被并行任务扩充到 **F46**（F39–F46 为 AppIcon / 隐私 / App Intents 新增条款），故本文两条提案编号取 **F47 / F48**，避免与既有条目冲突。F1–F38 的内容与编号在本次实扫期间**未发生变化**，本文 §四 的全部映射按此口径。

### 2.3 ⭐ 0–100 分是怎么算出来的（源码 `src/auditor.ts` 实读，非推测）

```
5 柱 × 20 分 = 100 分基线
每条命中按 severity 扣分：error = -6   warning = -3   advisory = -1
每柱扣分后下限钳到 0（Math.max(0, ...)）
overallScore = 5 柱得分之和
```

**等级（源码 `auditTargets()` 的 `grade` 判定）**

| 等级 | 条件 |
|---|---|
| **S** | `overallScore >= 95` **且** `primaryCount === 0` |
| **A** | `overallScore >= 85` |
| **B** | `overallScore >= 72` |
| **C** | `overallScore >= 58` |
| **D** | `overallScore >= 40` |
| **F** | 其余 |

> ⚠️ **这个分数的三个限制，必须写进我们的评审纪律**（`audit` 输出自己也印了这句）：
> `Scope: source patterns only; scores do not certify design quality or accessibility.`
> `Visual quality: not-verified` / `Usability: not-verified` / `Accessibility: not-verified` / `Runtime behavior: not-verified`
>
> **它只统计静态源码模式。** 我们的稿子里有大量「色彩语义 / 信息层级 / 陪伴感」是它**结构上看不见**的。**「99 分」不等于设计对，「42 分」也不等于设计差** —— 它衡量的是「AI 味 + 硬伤模式的密度」。

### 2.4 ⭐ P0–P3 整改计划是怎么算出来的（源码 `auditTargets()` 实读）

```
P0  ← severity === 'error'                （硬伤：安全 / 布局崩坏 / 资源缺失 / 焦点丢失）
P1  ← category ∈ { slop, motion, responsive }   （AI 味 + 响应式硬化 + 动效）
P2  ← severity === 'warning'（且不属于上面两类）
P3  ← 剩余（advisory）
```

排序按 P0→P3 升序；每条给出 `{ priority, ruleId, location(文件:行号), action(规则自带的 fix 文案) }`。
**注意 `location` 的行号来自 `nongeneric` 自己的扫描器**——这是我们目前**唯一**能拿到行号的检测器。

- **有官方 Floor 对应**：52 条；**无对应**：30 条（其中 12 条属工程/安全层，不该塞进设计宪法）。

### 3.2 ⚠️ 关于 `ios/prototype/index.html` 的 JS 挂掉这件事

**本轮已独立复验**（把 `<script>` 块抽出跑 `node --check`）：

```
SyntaxError: Identifier 'rec' has already been declared
  at function rec(btn){   ← script 块内第 124 行
```

对应 HTML 绝对行号：**HTML L510 `let rec=false;`** 与 **HTML L595 `function rec(btn){`** 同名同作用域 → 整块 `<script>` 解析失败 → **所有交互不执行**（与 `00-总纲` §5.5 第 6 条的既有记录一致）。

**但这不影响 CSS 层检测结论的有效性**：

- `impeccable` / `nongeneric` 对 HTML 文件走的是**静态 HTML/CSS 分析**（`impeccable detect --help`：`HTML files → Static HTML/CSS analysis (default, catches linked CSS)`），**不执行 JS**。
- 本文件 28 条 primary 命中里，**26 条是 CSS 层**（对比度、字号、padding、卡片嵌套、色板、辉光、径向光晕），**2 条是 DOM 结构层**（`skipped-heading` h1→h3、`nested-cards`）。
- ⚠️ **但有 2 类结论会失效**：`unsafe-dom-sink`（8 处 `.innerHTML`）依赖脚本文本扫描，**结论仍然成立**（静态正则命中）；而**任何依赖运行时布局/渲染的结论不成立** —— 所以本文**没有**对 `index.html` 给出「渲染后是否溢出」这类判断。
- **一句话**：**JS 挂掉 ≠ 文件没诊断价值**。CSS 诊断完全可用；但**不能把它当交互骨架复用**（`00-总纲` 已定性）。

3. ⭐ **两处「检测器与我们的规范冲突」需要裁决**（不是改代码，是改规范或改写法）：

## §七 检测器怎么接进我们的工作流

### 7.1 退出码语义（两个工具实测一致）

| 码 | 语义 | CI 里怎么理解 |
|---|---|---|
| **0** | 扫过，**无 primary 命中** | ✅ 通过 |
| **2** | 扫过，**有 primary 命中** | ❌ **不通过 —— 但这是「发现问题」，不是「工具坏了」**。⚠️ **绝对不要把 2 当失败重试或吞掉** |
| **1** | **扫不了**（目标类型不支持 / 目标不存在） | ⚠️ **真失败**，必须报警 |

- `impeccable detect --help` 原文：*"0 Scan completed with no primary findings (advisories may still be listed) / 1 At least one requested target could not be scanned / 2 Scan completed with primary findings"*。
- `nongeneric` 实测：`detect` → `primaryCount > 0 ? 2 : 0`；`audit` → `scannedFiles === 0 ? 1 : (primaryCount > 0 ? 2 : 0)`。
- ⭐ **nongeneric 的 1 与 impeccable 的 1 含义一致**（扫不了）。这让两个工具的退出码可以在同一个 CI 判断里合并。

### 7.2 两条命令的正确姿势（实测过的）

```powershell
$env:DO_NOT_TRACK='1'; $env:IMPERFECTABLE_NO_TELEMETRY='1'

# impeccable：抓「有没有」+ 色值 + 对比度比值 + 元素语义
npx --yes impeccable@latest detect <文件或目录> --json 1> findings.json
$impExit = $LASTEXITCODE          # 0 / 1 / 2

# 拆分 primary 与 advisory（JSON 混在一起，必须跑两遍做差）
npx --yes impeccable@latest detect <文件或目录> --json --no-advisory 1> primary.json

# nongeneric：抓「在哪一行」+ 0–100 分 + P0–P3 计划
node <nongeneric>/scripts/nongeneric.js detect <文件或目录> --json 1> ng.json
node <nongeneric>/scripts/nongeneric.js audit  <文件或目录> --json 1> audit.json
```

⚠️ **两条纪律**：
1. **impeccable 永远拿不到 HTML 的行号**（JSON `line` 恒 0，文本模式也不打行号）。要行号**只能靠 nongeneric**。
2. **`npx --yes github:Kyaa-A/nongeneric` 在本机拉不下来**（github.com 直连被拦，见 §八 第 6 条）。本轮是**下载 tarball 手工解压**后用 `node scripts/nongeneric.js` 跑的（解压后的路径见附录）。

### 7.3 GitHub Actions 片段（可直接抄）

```yaml

on:
  pull_request:
    paths:
      - 'ios/prototype/**'
      - 'output/design/**'
      - 'DESIGN.md'
      - '.github/workflows/design-detectors.yml'

jobs:
  detectors:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-node@v4

          node-version: '20'

      - name: impeccable detect (source scan)
        env:
          DO_NOT_TRACK: '1'
          IMPERFECTABLE_NO_TELEMETRY: '1'
        run: |
          set +e
          npx --yes impeccable@latest detect ios/prototype output/design --json > impeccable.json
          code=$?
          set -e
          echo "impeccable exit=$code" >> "$GITHUB_STEP_SUMMARY"

            echo "::error::impeccable could not scan a target (exit 1)" ; exit 1
          fi
          if [ "$code" -eq 2 ]; then
            echo "::error::impeccable found primary findings (exit 2) — see impeccable.json"

          fi

            const a=require("./nongeneric-audit.json");

            for(const x of a.remediationPlan) p[x.priority]++;
            console.log("score",a.overallScore,"grade",a.grade,JSON.stringify(p));
            if(p.P0>0){console.error("::error::P0 命中 "+p.P0+" 条");process.exit(1);}
          '

      - name: nongeneric detect (line numbers)
        run: |
          set +e
          node "$NONGENERIC_DIR/scripts/nongeneric.js" detect ios/prototype output/design --json > nongeneric-detect.json
          set -e
          exit 0        # 行号明细用于评审，不单独阻塞
```

> ⚠️ **CI 里最容易写错的地方**：把 `exit 2` 当成「工具崩了」→ 于是加 `|| true` → 于是**真问题被吞掉**。正确做法是**显式区分 1 和 2**：1 = 报警，2 = 打回。
> ⚠️ **建议的阻塞策略**（本文建议，未替主会话拍板）：**只让 nongeneric 的 P0 阻塞合并**；impeccable 的 exit 2 先只出报告不阻塞，跑两周看噪声量再决定是否升级为阻塞。

### 7.4 逐文件豁免：语法与我们的豁免纪律

**语法（官方文档原文，`impeccable detect --help`）**

```html
<!-- impeccable-disable overused-font: exported brand doc -->
```
- `impeccable-disable`：**整文件**豁免。
- `impeccable-disable-line` / `impeccable-disable-next-line`：**行级 / 下一行**豁免。
- 可列一个或多个 rule id（逗号分隔），或省略 id / 用 `*` 表示全部。
- CSS / JS 里用 `/* impeccable-disable-line overused-font */`；JS 用 `// impeccable-disable-next-line bounce-easing: intentional bounce`。
- nongeneric 同样支持**行内**豁免注释（`nongeneric-disable` / `impeccable-disable`），`--no-inline-ignores` 可关闭。

**项目级豁免（`.impeccable/config.json`）** —— 更适合「这个文件整体不是设计稿」：

```powershell
npx impeccable ignores add-file "output/design/archive/**"
npx impeccable ignores add-value overused-font Inter --reason "Brand font"
npx impeccable ignores add-value design-system-color "*" --file "src/demo.css"
npx impeccable ignores list
```

**⭐ 我们的豁免纪律（本文建议，需主会话确认后写进 `19` 号 §7）**

| 规则 | 内容 |
|---|---|
| **D1** | **只允许「逐文件 / 逐行 + 具体 rule id」豁免，禁止 `*`**（`*` 会把该文件所有问题一起关掉）。 |
| **D2** | 每条豁免必须**带理由**，理由要具体到情境（例：`"品牌规范文档，非产品界面"`），**禁止写「因为好看」**。 |
| **D3** | 豁免必须**同时登记在 `19` 号 §7 的豁免记录模板**（规则 / 位置 / 理由 / 复核人 / 日期 / **失效条件**）。 |
| **D4** | **Floor 层（对比度、焦点环、触摸目标、字号下限、320px 不变量）不可豁免。** 检测器给出 error 级的项**不得**用行内豁免压掉，只能改代码。 |
| **D5** | **误报 ≠ 豁免。** `DESIGN.md` 被自己的禁令文本命中（§3.3.8），正确处置是**改写法**；只有「确实是 intentional」才豁免。 |
| **D6** | 豁免**必须写失效条件**：什么条件变化后必须重新评审（例：品牌字体换了 / 文档不再引用被禁写法）。 |
| **D7** | 每轮评审结束，**过一遍 `impeccable ignores list`**，确认没有「僵尸豁免」还在生效。 |

### 7.5 `check-design.ps1`（可直接抄）

```powershell
#!/usr/bin/env pwsh
# StackChan 设计稿检测器闸门
# 用法: pwsh -File check-design.ps1 [-Target <路径>] [-Json <输出目录>]
# 退出码: 0 = 无 P0；1 = 有 P0（打回）；2 = 工具/参数错误
#         （注意：检测器自身的 exit 2 = 有命中，不是错误）

[CmdletBinding()]
param(
  [string[]]$Target = @(
    'ios/prototype',
    'output/design'
  ),
  [string]$Json = 'artifacts/design-detectors',
  [string]$NongenericDir = $env:NONGENERIC_DIR,
  [switch]$FailOnAdvisory
)

$ErrorActionPreference = 'Stop'
$env:DO_NOT_TRACK = '1'
$env:IMPERFECTABLE_NO_TELEMETRY = '1'

if (-not $NongenericDir) {
  Write-Error 'NONGENERIC_DIR 未设置（指向 nongeneric 仓库根目录）。'
  exit 2
}
if (-not (Test-Path $Json)) { New-Item -ItemType Directory -Force -Path $Json | Out-Null }

$targets = @()
foreach ($t in $Target) {
  if (Test-Path $t) { $targets += $t }
  else { Write-Warning "跳过不存在的目标: $t" }
}
if ($targets.Count -eq 0) { Write-Error '没有可扫描的目标。'; exit 2 }

function Invoke-Detector {
  param([string]$Name, [scriptblock]$Cmd)
  & $Cmd | Out-Null
  $code = $LASTEXITCODE
  Write-Host "[$Name] exit=$code"
  return $code
}

# ---- 1. impeccable：有没有 + 色值 + 对比度比值 + 元素语义 ----
$impAll = Join-Path $Json 'impeccable.json'
$impPri = Join-Path $Json 'impeccable-primary.json'
$impErr = Join-Path $Json 'impeccable.err.txt'

$impCode = Invoke-Detector 'impeccable' {
  npx --yes impeccable@latest detect @targets --json 1> $impAll 2> $impErr
}
if ($impCode -eq 1) {
  Write-Error 'impeccable 无法扫描目标（exit 1）—— 目标类型不支持或路径不存在。'
  exit 2
}
# primary / advisory 拆分：JSON 混在一起，必须跑两遍做差
npx --yes impeccable@latest detect @targets --json --no-advisory 1> $impPri | Out-Null

# ---- 2. nongeneric：在哪一行 + 分数 + P0-P3 ----
$ngJson = Join-Path $Json 'nongeneric-audit.json'
$ngDetect = Join-Path $Json 'nongeneric-detect.json'
$ng = Join-Path $NongenericDir 'scripts/nongeneric.js'

$ngCode = Invoke-Detector 'nongeneric audit' {
  node $ng audit @targets --json 1> $ngJson
}
if ($ngCode -eq 1) {
  Write-Error 'nongeneric 未扫到任何支持的文件（exit 1）—— 检查扩展名白名单。'
  exit 2
}
node $ng detect @targets --json 1> $ngDetect | Out-Null

# ---- 3. 汇总 ----
$summary = [ordered]@{}
if (Test-Path $ngJson) {
  $a = Get-Content $ngJson -Raw -Encoding utf8 | ConvertFrom-Json
  $prio = [ordered]@{ P0 = 0; P1 = 0; P2 = 0; P3 = 0 }
  foreach ($p in $a.remediationPlan) { $prio[$p.priority] = [int]$prio[$p.priority] + 1 }
  $summary.score = $a.overallScore
  $summary.grade = $a.grade
  $summary.priorities = $prio
  $summary.pillars = @($a.pillars | ForEach-Object { "$($_.label) $($_.score)/$($_.maxScore)" })

  Write-Host ''
  Write-Host "nongeneric: score=$($a.overallScore)/100 grade=$($a.grade)"
  Write-Host "  P0=$($prio.P0)  P1=$($prio.P1)  P2=$($prio.P2)  P3=$($prio.P3)"
  foreach ($p in $a.pillars) { Write-Host "  - $($p.label): $($p.score)/$($p.maxScore)" }
  if ($prio.P0 -gt 0) {
    Write-Host ''
    Write-Host 'P0 明细:'
    foreach ($p in ($a.remediationPlan | Where-Object priority -eq 'P0')) {
      Write-Host "  [$($p.ruleId)] $($p.location) -> $($p.action)"
    }
  }
}
$summary | ConvertTo-Json -Depth 5 | Set-Content (Join-Path $Json 'summary.json') -Encoding utf8

# ---- 4. 判定 ----
# 注意: 检测器 exit 2 = 有命中, 已在上面消化; 这里只看我们自己的 P0 闸门
if ($summary.priorities.P0 -gt 0) {
  Write-Host ''
  Write-Error "发现 $($summary.priorities.P0) 条 P0 —— 阻塞。"
  exit 1
}
if ($FailOnAdvisory -and $impCode -eq 2) {
  Write-Error 'impeccable 有 primary 命中（-FailOnAdvisory 模式）。'
  exit 1
}
Write-Host 'OK: 无 P0。'
exit 0
```

> ⚠️ **这个脚本刻意把「检测器 exit 2」和「闸门 exit 1」分开了**：检测器的 2 被消化成报告，闸门只在**我们自己的 P0 判定**上返回 1。这样 CI 里看到的红，永远是「我们该改的东西」，不是「工具退出了 2」。
