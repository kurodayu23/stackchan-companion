## 0. 一页结论

1. **「嵌入苹果系统」有官方答案，不用猜。** Apple HIG 原文写得很死：
   - **内容层禁用 Liquid Glass**（`Don't use Liquid Glass in the content layer`）→ 玻璃只给导航栏/标签栏/浮层。
   - **手写玻璃效果要"克制"** → 系统组件自动获得玻璃观感，我们几乎不需要手写。
   - **不要硬编码系统色值**，自定义色必须给 浅/深 × 默认/高对比 **4 个变体**。
   - **iOS 最小字号 11pt**，**禁用 Light/Thin/Ultralight 字重**。

2. **Google 那边能抄的是"结构"不是"皮"。**
   - 能抄：token 化的三层结构（reference palette → system role → component）、**tone-based surface 取代阴影层级**（5 级容器靠明度分层）、shape 7 档、type 15 档、motion 4 档 + 缓动 token。
   - 抄不了：**Material You 的壁纸动态取色**（Android 系统独有能力，iOS 没有）——我们只能抄"角色化"，把 seed 换成**设备状态**。
   - Google 的 AI 界面是"对话框/卡片流"，苹果是"把 AI 藏进系统"。**我们是陪伴机器人，用户不是来用 AI 的，是来陪小栈的 → 苹果那派更对，但苹果那派没有现成范式，要自己把"AI 感"藏好。**

3. **我们的三套视觉是历史遗留冲突，必须裁决**（见第 2 节）。
   **推荐：iOS 端走「Apple 原生骨架 + 单一暖色强调」，设备端保留深色（脸要看清），把「柔雾樱花」的规则内核留下、色值重做。**

4. **实测打脸了旧契约色板。** `#D94F78`（柔雾樱花强调色）在浅色表面上只有 **3.80:1**，白字按钮只有 **3.93:1**，**两项都不达 WCAG AA**。必须重做色板（第 3 节有实测数据）。

5. **发现一个真 bug（不是审美问题）**：`ios/prototype/index.html:510` `let rec=false` 与 `:595 function rec(btn)` 在同一脚本块重复声明 → 整个 script 块 SyntaxError → **初稿完全不可交互**。已复核源码确认。

6. **本机设计工具链够用，且不用花钱**：Penpot Desktop 0.23.1（开源 Figma 替代，已装）+ matrix 连接器 12 个多模态工具（找图/看图/生图/**生带音轨视频**/TTS）+ Playwright（视觉回归）+ chrome-devtools MCP（Lighthouse/a11y/截图）。**没有 Figma，也没有 Figma MCP 连接器**（实测 232 个连接器工具，provider 只有 matrix/notion/qichacha/email_workbench）—— ⚠️ **2026-10-27 订正**：本条是 2026-10-25 的时点事实。用户已接入 Figma Connector（provider `figma`，2 个**只读/导出**工具），「没有 Figma MCP 连接器」已失效；「没有 Figma 桌面版」仍成立。详见 `docs/research/89`。

7. **⭐ 追查"苹果十七"查出了超出预期的东西**：当前最新系统是 **iOS 27（2026-09）**，iOS 26 才是 iPhone 17 那一代；而 **iOS 27 随 iPhone Duo（苹果折叠双屏机）发布**，SwiftUI 新增了 `DeviceHinge`（铰链角度 `.closed`/`.partiallyOpen`/`.fullyOpen`）、`ReservedRegion`（`.occlusion` 相机遮挡 / `.division` 铰链分割）、`CameraCaptureAccessory`（外屏内容）、`ArrangementView`（主次自适应 split/overlay）。
   **对"桌面陪伴机器人"这是天然契合的形态**：合上时外屏就是小栈的一只眼睛；展开时铰链角度直接驱动它的姿态；拍照时外屏显示"小栈视角"。详见 `12-iOS27与iPhoneDuo.md`。

8. **读官方文档的通用技巧（本轮新发现）**：Apple 文档站每个页面都有 **`.md` 纯文本版本** ——
   `https://developer.apple.com/design/human-interface-guidelines/<page>.md` 与 `https://developer.apple.com/documentation/<path>.md`。
   普通 URL 抓回来只有 `<noscript>This page requires JavaScript</noscript>` 空壳；`.md` 版本能直接拿到正文与 API 元数据。本轮据此实抓 **25 页 HIG** 与 **166 个框架文档**，76 个 API 名逐一对官方语料校验通过。

9. **⭐ 9 个真实成品拆解出三条会改变产品决策的结论**（详见 `11-成品拆解.md`）：
   - **Tesla 推翻了"一屏一动作"的教条**：硬件控制场景的核心诉求是"**状态感知 + 零延迟关键操作**"，塞进主界面的只能是"状态 + 关键动作"，靠**场景化降维**（待机/说话/被摸/低电量，主控不同）来保主次，不是靠砍功能。
   - **Gentler Streak 给出陪伴类产品的"非暴力设计"范式**：舒适区间替代绝对指标、休息合法化、**没有红色未达标感叹号、没有催促震动**。Break streak 不叫失败。
   - **Replika 是最好的反面教材**：外置功能菜单（Activities 抽屉）、金币商店、触发词脚本、运营 Banner、硬编码过滤词 —— 每一条都会把"伴侣"降格成"电子宠物"。能力必须**隐式由对话触发**。

> ⭐⭐ **39 + 40 号合起来的核心结论**（已回填 `docs/spec/01` 与 `docs/spec/02`）：
> **质感 = 折叠 + 令牌化 + 状态完备 + 多模态反馈**，**与配色无关**。
> - **折叠**：Antigravity 没为 AI 新造一级导航 → 我们硬线「新增能力先问能否挂已有入口」。
> - **令牌化**：一切视觉值来自 token → 我们 `DESIGN.md` + `DesignTokens.swift` 单一真源。
> - **状态完备**：6 态通用要求，每态必须有恢复动作 → 我们 13 态（6 通用 + 7 设备特有）。
> - **多模态**：Antigravity 把状态做成听觉事件 → 我们的加强版是**声音+表情+运动三通道同步**（纯 App / 纯硬件都抄不动）。
> ⚠️ **明确的反证**：VS Code 系令牌服务**桌面高密度编辑器**，照搬会得到"密、满、工业感"——**可搬运的是方法，不是数值**。

### 2.2 建议方案（推荐项）

> 按用户偏好「方案选择直接走推荐项，不停下来问」，这里给推荐 + 理由，交付时一并说明。

**iOS 端 = 「Apple 原生骨架 + 单一暖色强调」（新方案 C）**
- **骨架用系统语义色**：`systemBackground` / `secondarySystemGroupedBackground` / `tertiarySystemGroupedBackground` / `label` / `secondaryLabel` / `separator` / `tint`。→ 自动适配深浅色、Dynamic Type、高对比度、玻璃自适应。
- **唯一的自绘主视觉 = 小栈的脸/表情**（这是品牌表达，系统控件做不到）。
- **强调色只留 1 个**，按深浅两套给值（见第 3 节实测）。
- **玻璃只给导航/浮层**，内容层用标准材质（`regular`）。
- **不用 emoji 当图标**，全用 SF Symbols。

**设备端 320×240 = 保留深色**
- 机器人的脸是主角，深底能让表情 PNG 的对比最大化（CoreS3 是 LCD 不是 OLED，但深底仍是最稳的表达）。
- **青色 `#00D2FF` 降级为"状态色/在线态"，不当主色** —— 实测它在浅底只有 1.74:1，完全不可读；而且青色是技术色，与"陪伴"气质不符。

**「柔雾樱花」保留什么、丢弃什么**
| 保留（规则内核） | 丢弃（具体数值与用法） |
|---|---|
| 边框优先于重阴影 | 画布 `#F1DFE5` 整屏暖粉底 |
| 每个画面只保留一个主要动作 | 强调色 `#D94F78`（实测对比度不达标） |
| 4/8/12/16/24 间距节奏 | 次文字 `#7B626C` 直接放画布上（4.32:1 差一点点） |
| 圆角 10–16pt 的克制量级 | 「粉 = 陪伴」的整屏粉色策略 |
| 禁用装饰性渐变球 / 六宫格 / 多功能堆叠 | — |

**为什么不是 B（StackChan OS 深色）**：深色科技风适合"工具"，不适合"陪伴"。而且 iOS 端用深色 + 青色 = 立刻回到"通用后台模板感"，正是被否掉的观感来源。

### 2.3 业界实证支持哪些方向（来自 03 号文档）
`03-业界参考图集.md` 把 5 组参考（AI 陪伴 App / 桌面机器人伴侣 / 粉彩极简 / iOS 设置页 / 设备控制）逐图拆完，提炼出 5 条范式，**其中 3 条与本节推荐一致**：

| 范式 | 内容 | 与本节推荐的关系 |
|---|---|---|
| **1 · 设备屏是"陪伴面"不是"功能面"** | 小栈屏显示脸和状态，不是图标网格 | ✅ 一致 |
| **2 · 浅画布 + 白表面 + 单一粉强调**（已被真实智能家居 App 验证） | 大面积浅底 + 白色表面 + 只用一种强调色 | ✅ **一致** —— 支持"柔雾樱花的规则 + 单一暖色强调"，但底色用系统语义色而不是写死粉底 |
| **3 · 一屏一动作：把"卡片仪表盘"换成"单一焦点"** | — | ✅ 一致（但被 Tesla 修正：设备控制页可保留"状态 + 关键动作"） |
| **4 · 底层用系统语言：Inset Grouped + 发丝线 + 无阴影** | — | ✅ 一致 |
| **5 · 材质统一 = 陪伴感的真正来源** | 全 App 一种材质，不要混搭 | ✅ 一致 |

**⭐ "AI 味"的量化**：在 18 张 AI 陪伴类概念稿里，**7 张是深色底，其中 4 张叠加霓虹辉光**。
→ 深色 + 霓虹是当前 AI 陪伴设计稿的**视觉通货膨胀**，我们避开它反而是差异点。
（这也从数据上支持了"设备端深色"与"iOS 端浅色"可以共存 —— 深色留给小屏的脸，浅色留给手机。）

### 2.4 ⭐ 可直接用的量化判据（18 张图统计得出，可写进评审表）
| 指标 | 被判"陪伴"的样本 | 被判"原型/指挥中心"的样本 | **我们的目标** |
|---|---|---|---|
| 单屏可点元素数 | **0 – 4** | 13 – 43 | **首页 ≤ 4** |
| 留白率 | **50% – 80%** | 20% – 25% | **≥ 55%** |
| Tab 数 | — | — | **≤ 3**（实际取 2） |
| 设备端可点元素 | Rabbit R1 整屏只有壁纸+角色（留白 75–80%）；LOOI 只有两颗大眼+一条灯条（**可点 0**） | — | 建议**直接删掉设备端启动器页** |

**已验证的"浅底 + 唯一粉强调"真实案例**（说明这个方向不是我们自嗨）：
- Heimdall 机器人遥控：`#F0F4FC` 画布 + `#FFFFFF` 表面 + `#5C8DF6` 强调
- Justinmind 智能家居：`#F5F6FB` 画布 + `#FFFFFF` 表面 + `#FF5B84 → #EE4266` 强调
→ 后者的粉与我们的莓红 `#D94F78` **同族**，说明"粉做唯一强调色"在真实产品里站得住。

### 2.5 ⚠️ 一个反直觉的坑：AI 味不是深色专属
> **浅色稿照样中招，只换底色救不了。**
> 元凶是：24–28px 大圆角 + 999px 胶囊 + 弥散阴影堆叠 + **glow-fi 光晕**（Justinmind 的粉光晕就是）。

→ 所以**不能用"改成浅色"来修复"丑"**，必须同时处理圆角量级、阴影、发光三件事。

### 2.6 材质统一 = 陪伴感的真正来源
5 张图上"同一 App 混两种插画语言"（Replika 写实头像 + doodle 徽章、Character.AI 动漫 + 写实、Cuberto 3D 渲染 + 2D 卡通）**全被点名**。
→ 我们的小栈**只有一套视觉语言**：一张脸、一套表情帧、一套图标（SF Symbols）。

### 2.7 ⭐ Liquid Glass 的真实 API 与落地边界（2026-10-23 已核实，风险表 #2 关闭）

**API 名（Apple 官方 SwiftUI 符号页实读原文，均 iOS 26.0+）**：

```
Glass                                  // struct，Liquid Glass 材质配置
Glass.regular                          // 默认变体
Glass.clear                            // 另一变体
Glass.interactive(Bool) -> Glass
Glass.tint(Color?) -> Glass

View.glassEffect(_ glass: Glass = .regular,
                 in shape: some Shape = DefaultGlassEffectShape()) -> some View

GlassEffectContainer(spacing: CGFloat?, content: () -> Content)
```

- `glassEffect()` 默认 = `.regular` 变体 + `Capsule` 形状；material 锚定在 view bounds（含 padding）。
- `GlassEffectContainer` 把多个玻璃形状**合并渲染**（性能更好）并支持形状互相 morph；`spacing` 越大越早融合。

**HIG `materials.md` 原文（逐字）**：

> *"Liquid Glass forms a distinct functional layer for controls and navigation elements — like tab bars and sidebars — that floats above the content layer, establishing a clear visual hierarchy between functional elements and content."*

> *"**Don't use Liquid Glass in the content layer.** … Instead, use standard materials for elements in the content layer, such as app backgrounds. **An exception to this is for controls in the content layer with a transient interactive element like sliders and toggles**; in these cases, the element takes on a Liquid Glass appearance to emphasize its interactivity when a person activates it."*

> *"**Use Liquid Glass effects sparingly.** Standard components from system frameworks pick up the appearance and behavior of this material automatically. If you apply Liquid Glass effects to a custom control, do so sparingly… Limit these effects to the most important functional elements in your app."*

> *"**Only use clear Liquid Glass for components that appear over visually rich backgrounds.** Liquid Glass provides two variants — `Glass/regular` and `Glass/clear`…"*

**⭐ 这四条原文把我们的视觉裁决从"我的判断"升级为"官方要求"**：

| 我们的裁决 | HIG 原文背书 |
|---|---|
| 玻璃只给导航/浮层，内容层用 standard material | *"Don't use Liquid Glass in the content layer"* —— **直接要求**，不是发挥 |
| 玻璃效果要少用，不给系统控件手动套 `glassEffect` | *"Use Liquid Glass effects sparingly… Standard components… pick up the appearance automatically"* |
| 品牌暖色不铺控件 | 落地方式 = `glassEffect(.regular.tint(warm))` —— **tint 是玻璃材质的属性，不是控件的背景色** |
| `Glass.clear` 我们默认不用 | *"Only use clear Liquid Glass for components that appear over visually rich backgrounds"* —— 我们的背景是内容层（小栈的脸 + 文字），**视觉不丰富** → 判据成立 |

**设备端不适用**：320×240 LCD（ILI9342E）没有 Liquid Glass 材质，只有深色底 + 自绘像素。

## 5. 系统能力：怎么才算"真的嵌进苹果系统"（读法 B）

> 完整版：`09-iOS系统能力清单-如何嵌入苹果系统.md`（86 KB，76 个 API 名逐一对官方 `.md` 语料校验通过）。

### 5.1 核心判断
「嵌入苹果系统」= **让小栈的能力出现在系统该在的地方**，而不只是"长得像 iOS"。
> 每做对一个系统表面，就"更像系统的一部分"；每做成 App 内的一个功能面板，就"又做了个遥控器"。

### 5.2 最该做的 8 项（按「用户会不会更觉得这是系统的一部分」排序）
| 序 | 做什么 | 官方 API | 最低 iOS | 成本 |
|---|---|---|---|---|
| 1 | **Live Activity + 灵动岛** | `ActivityAttributes` / `ActivityContent` / `ActivityConfiguration(for:content:dynamicIsland:)` | 16.1 | 中 |
| 2 | **App Intents + App Shortcuts**（一次点亮 Siri / 快捷指令 / Spotlight / Action Button） | `AppShortcutsProvider` / `AppShortcut` / `AppShortcutPhrase` | 16.0 | 中 |
| 3 | **首页 = 小栈的脸（自绘）+ 唯一主要动作** | 系统控件全用（`NavigationStack` / `List(.insetGrouped)` / 语义色 / SF Symbols） | 13+ | 中 |
| 4 | **Interactive Widget**（桌面/锁屏小组件） | `StaticConfiguration` / `AppIntentConfiguration` / `WidgetFamily` | 14 / 17+ | 中 |
| 5 | **Core Haptics 自定义波形**（摸头 / 生气 / 被夸） | `CHHapticEngine` / `CHHapticPattern` | 13.0 | 中（调参久） |
| 6 | **Action Button 接入** | **无独立 API**，走 `AppShortcut` 供用户指派 | 16.0 | 低 |
| 7 | **控制中心 Control** | `ControlWidget` / `ControlWidgetButton` / `ControlWidgetToggle` | 18.0 | 中 |
| 8 | **按需权限 + Privacy Manifest** | `NSMicrophoneUsageDescription` / `NSLocalNetworkUsageDescription` + `NSPrivacyCollectedDataTypes` | 7–14+ | 低 |

### 5.3 哪些功能**不该**进 App（要做成系统表面）
| 功能 | 错的做法 | 对的做法 |
|---|---|---|
| 小栈实时状态 | App 顶部状态条 | **Live Activity**（锁屏 + 灵动岛） |
| 情绪变化 | App 内轮播卡片 | **Widget** + Live Activity 里的表情 |
| 待办提醒 | App 内列表页 + App 内弹窗 | **系统通知** + 通知动作 |
| 番茄钟 | App 内计时器页 | **Live Activity 跳动数字** |
| 静音 / 叫醒 | App 内设置开关 | **控制中心 Control** + **Action Button** |
| 「摸摸小栈」 | App 内按钮 | **App Shortcut** + Live Activity 交互按钮 |
| 拍照给小栈看 | 自绘完整相机页 | **PhotosPicker** + 相机藏进 `sheet` |
| 历史对话 | 首页塞聊天列表 | 陪伴 Tab 的 1 层钻取（首页留给脸） |

### 5.4 IA（Tab 只留 2 个）
```
Tab1 小栈(Home)              Tab2 陪伴(Companion)
┌──────────────────┐        ┌──────────────────┐
│   ╭────────╮      │        │ 今日心情 (横向)    │
│   │ 小栈的脸 │      │        │ 悄悄话            │
│   ╰────────╯      │        │ 待办提醒          │
│ "早，有点困"      │        │ 主要动作：[记一下今天]
│ ● 正在听…         │        └──────────────────┘
│ ┌──────────────┐  │          1层钻取 → 某天心情 / 某次对话
│ │ ◎ 叫醒小栈   │  │
│ └──────────────┘  │          1层钻取 → 设备(电量/信号/连接)
│  (底部不放功能宫格) │
└──────────────────┘
设置 = 独立 Settings Scene（不做 Tab）—— 这是"像系统 App"最强的信号之一
```
**Tab 只 2 个**：设备 / 游戏 / 相册 / 待办全部降级为 1 层钻取或系统表面。
**独立 Settings Scene**（iOS 13+ `Settings` 场景）是 Apple 明确支持的机制 —— 系统 App 都有独立设置页，而不是自己画一个设置 Tab。

### 5.5 部署建议
最低 iOS **17**、主力 iOS **18**；iOS 26（`glassEffect(_:in:)` / `Glass` / `GlassEffectContainer`）与 iOS 27（`ArrangementView` / `ToolbarOverflowMenu`）按 `#available` 渐进增强。
> ⚠️ **当前 OS 是 iOS 27（2026 年 9 月更新），iOS 26 是 iPhone 17 那一代。**

## 6. Google 能抄什么 / 不能抄什么

### 6.1 能抄（实测 token 值见 `05-Google设计体系与AI产品设计.md`）
| M3 机制 | 抄法 |
|---|---|
| **三层 token 结构** | `reference palette`（tone 0–100）→ `system role`（语义）→ `component`。**我们照抄这个结构**，但把调色盘换成人格包驱动 |
| **tone-based surface 取代阴影层级** | 5 级容器色（lowest/low/container/high/highest）靠**明度差**分层，不靠阴影。iOS 侧对应 `secondarySystemGroupedBackground` / `tertiarySystemGroupedBackground` + 极轻分割线 |
| **shape 7 档** | 0 / 4 / 8 / 12 / 16 / 28 / full —— 与 iOS 惯例（8/10/12/16/20/28/连续）几乎重合，**直接采用 M3 的 7 档最省事** |
| **type 15 档** | 只抄档位结构，字族用 SF Pro（**不要 Roboto**，会和系统打架） |
| **motion 4 档 + 缓动 token** | short 50–200ms / medium 250–400ms / long 450–600ms / extra-long 700–1000ms；`(0,0,0,1)`≈`curveEaseOut`、`(0.3,0,1,1)`≈`curveEaseIn` |

### 6.2 抄不了
- **Material You 壁纸动态取色**：Android 系统独有能力（seed → HCT/CAM16 → tonal palette），iOS 没有。**我们只能抄"角色化"，把 seed 换成"小栈当前状态"**（情绪色 / 电量 / 温度）——这反而更符合陪伴主题。
- **M3 Expressive 的 spring 动效**：iOS 无 1:1 对应，需用 `UIViewPropertyAnimator` 自造。

### 6.3 苹果 vs 谷歌的 AI 界面哲学（对我们最关键的一节）
| | 苹果 | 谷歌 |
|---|---|---|
| 做法 | 把 AI **藏进系统**（App Intents / 快捷指令 / Live Activity / 灵动岛），不打断 | 把 AI **做成主角**（对话框、流式卡片、生成式 UI） |
| 用户感知 | "系统本来就该这样" | "我在用一个 AI 工具" |
| 对我们 | ✅ **主方向** —— 小栈不该像一个聊天框，应该像"桌面上多了一个有生命的东西" | ⚠️ 只在**需要展示复杂内容**时借用（如记忆回顾列表） |

→ **落地**：语音入口用 App Intents / 快捷指令（系统级），对话用**小栈的脸 + 少量气泡**（不是聊天气泡流），长内容走 `NavigationStack` 钻取而不是叠层。

### 6.4 ⭐ 谷歌自己就反"AI 主角"（本轮最有价值的一条引用）
Google Design 官方文章原文：
> *"It's important to **not heroize technology**."*

→ 所以**不是二选一**。正确姿势是：
> **苹果为壳 / 谷歌为过程 / 小栈的脸为 AI 的化身。**

### 6.5 ⭐ Gemini Live 的实测发现（反直觉，值得单独抄）
视觉模型对 Gemini Live 摄像头态的实测结论：
> **零文字状态、零波形。** Google 自己说 *"inner activity conveys thinking"*（内在活动传达思考）。

→ 落地：**"正在听/正在想"不要用文字标签，也不要用跳动波形** —— 交给**小栈的脸**（动眼、动腮红、瞳孔微移）。
→ 这条直接推翻我们初稿里的 `● 正在听…` 文字标签。

### 6.6 Google 官方文章库（可达，重要资料源）
`design.google` 的文章库本机可达，官方有 *Design for AI*、*Demystifying AI*、*Motion Principles by Google* 等篇目 —— 可作为后续 AI 交互设计的补充读物。
> ❌ **不可达**：`developer.android.com`（超时）、`pair.google.com`（DNS 不通）、`labs.google.com` / `gemini.google.com` / `notebooklm.google.com` 产品内实测（超时）。

   - 备选：自建。代价是把协议细节重新踩一遍坑，且求职叙事变成"我手写了个后端"，反而不如"我在成熟开源后端上做了二次开发"可信。
5. **固件基线**：把本地 v1.5.1 **同步到 v1.6.0** 再动手？
   - 推荐：**同步**。理由：① 含 BLE/Wi-Fi 两个安全修复（不再明文打印 WiFi 密码）；② 含 LAN 二进制协议（手势控舵机要用）；③ 官方已内置 `STACKCHAN_SERVER_URL` Kconfig 开关（改后端不用改 C++）；④ 官方已关闭三种传统配网，改走 App 配网（我们的配网工作量直接归零）。
   - 成本：本机已有完整 IDF 5.5.4 编译链 + 16 MB 全量备份，重新编译 + 刷机风险低。
6. **功能减法确认**（官方有、我们故意不做）：看视频 `0x02` / 摄像头 `0x05-0x06` / 通话 `0x09-0x0C` / 手机屏幕镜像 `0x12-0x13` / 舞蹈 `0x14` / 拍照 `0x1A` + 社区动态 `moments` + 附近设备 `nearby` + 全景图 `pano` + 应用商店 `appstore` + MCP `mcp_page` + WebView + 3D。
   - 这不是"我们做不完"，是**产品定位的有意分歧**：官方 App 是「遥控器 + 社区 + 配置」三合一工具堆，我们是「陪伴」。`21` 号文档已给出竞品反证（Loona 从宠物改助理，评分 4.26 → 1.82）。

> **另外两条我已自行裁决（不占用你的决策带宽）**：
> - **iOS 端不用"系统默认蓝"禁令** —— `02` 文档 §5.4 #17 的"不用系统蓝"在 **iOS 端已被推翻**：系统蓝是原生感的一部分，自造色相是露馅的开始。`00` 文档 §3 的暖色只作为**品牌强调色**（`.tint`），不是替代系统语义色。
> - **设备端青 `#00D2FF` 降级**为状态色，不当主色（实测浅底仅 1.74:1，且是技术色，与陪伴气质不符）。
> - **配网工作整体取消** —— v1.6.0 已关掉热点/声学/BLUFI 三条路，改走官方 App 配网路径（`26` 号 §四）。我们只需在 `sdkconfig.defaults.local` 里同时覆盖 `STACKCHAN_SERVER_URL` **和 `OTA_URL`**（后者默认仍指向小智 `api.tencent.net/xiaozhi/ota/`，漏了就会开机回小智）。
